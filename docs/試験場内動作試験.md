## 1 第1回試験場内動作試験

- 実施日: 2026年9月14日
- 会場: クリエイティブラボ（5つのブースを配電盤 `panel_1`〜`panel_5` に見立てた）
- ブランチ: `feat/demo-teach-replay`（`stage:=4`）

![第1回試験場内動作試験: クリエイティブラボの会場地図。待機場所(home)から panel_1〜5 が横一列に登録されている](試験場内動作試験地図.png)

### 1.1 試験条件

| 項目 | 内容 |
| --- | --- |
| 会場 | クリエイティブラボ。5ブースを配電盤5箇所に見立てた |
| ピン登録方式 | **5箇所すべて「いまの姿勢で登録」を使用**（2点指示は今回未使用） |
| 起動 | `stage:=4`。N-27（起動時ESTOP）は発生せず、「解除」操作も不要だった |

### 1.2 実施内容と結果

**起動・健全性（T-1）**: `stage:=4` で起動。N-27 の発生なし、フォルトなし。

**前日準備 — 地図作成・ピン登録（T-2・T-3・T-3b）**: 待機場所 → panel_1 → panel_2 →
panel_3 → panel_4 → panel_5 の順にジョグで一周しながら、各ブースで**「いまの姿勢で登録」**
を使って5箇所すべてを登録した。所要時間 3分55秒。**壁近接警告は一度も出なかった**
（会場の配電盤役がいずれも壁から十分離れていたため、警告条件に該当しなかったとみられる）。
panel_5 の登録直後、S-20 の**「1ボタンで待機場所に戻す」**で自律移動させ、待機場所付近まで
問題なく戻れた（到着精度の詳細計測はなし）。

**保存・読み直し・宣言（T-4・T-5）**: 同一セッション内で保存 → 「保存した会場地図を開く」で
読み直し、続けて「宣言する」を押した。**いずれもズレ警告なし。** 前日準備の自律移動
（panel_5→待機場所）を挟んだあとでも、保存・読み直し・宣言の整合性チェックに引っかからな
かったことになる。

**当日 — panel_2 への自動移動・到着精度（T-6）**: 中央入口から panel_2 ブース内へ自動移動。
到着まで **40秒**、到着位置のズレ **7cm**、向きのズレ **4°**。停止せず完走し、向き合わせも
機能した。

**当日 — panel_1 への自動移動中の安全機能一連試験（T-7・T-12）**: panel_1 への自律移動中に、
以下を連続して実施。**すべて衝突なし。**

1. 進路に人が飛び出す → 自動停止 → 人が退避 → 自動再開
2. 少し進んだ先で段ボール障害物を設置 → `BLOCKED` → 撤去 →
   **自動で再計算・再開**（停止から接触までの余裕 約30cm、退けてから再開まで約1.5秒、
   「再検索」の手動操作は不要=0回）
3. 再開した**直後にもう一度**同じ段ボール障害物を設置（二重BLOCKED） → 再度自動停止

過去に実機で見つかっていた「障害物を退けても永久にBLOCKEDのまま」というバグは、今回の
条件では再現しなかった。再開直後の再ブロックという厳しめの条件でも自動再開の仕組みは
機能した。

**当日 — 呼び寄せ・対象選び直し（T-9・T-11）**: 簡易的な動作確認を実施。退避待ち →
自動発進の流れ、および対象の選び直しは**いずれも正常に動作**したが、詳細な時間計測・
再現性の記録は取っていない。

**物理非常停止ボタン（T-13）**: 動作試験を始める前に押下し、システムが認識して非常停止
状態に入ることを確認した。**自律移動中に押した場合の即時停止・解除後の復帰動線は今回は
確認していない。**

**気づき**: panel_1 への移動経路上、中心に1本足がある丸椅子のすぐ近くを通過した際、
LiDARの設置高では脚部分しか見えていなかった。接触はなかったが、余裕距離は未計測。
背の高い/上部が張り出した什器では、この理屈で細く見える可能性がある。

### 1.3 未検証（今回対象外とした項目）

- **T-8（中断導線）**: `BLOCKED` からの「中断して待機場所へ」— T-7 で自動再開が確認できたため、
  長時間 `BLOCKED` が続く状況を意図的に作らず未実施
- **T-10（当日 S-21 の「行き先」タブからの待機場所復帰）**: 同じ `HOME_NAV` の仕組み自体は
  前日準備側（S-20の1ボタン復帰）で確認できたが、当日画面からの経路は未実施
- **壁近接警告の実発生**（T-3の一部）: 会場の配電盤役が壁から十分離れていたため、警告が
  出る条件を作れなかった。2点指示方式そのものの成立確認も未実施
- **走行中の物理非常停止ボタン**（T-13の一部）: 静止状態での押下確認のみ

### 1.4 考察・次回への持ち越し

- **今回の会場条件では、フェーズ2の一連動作（地図作成→ピン登録→保存→読み直し→宣言→
  盤前移動→障害物/人物回避→呼び寄せ→前日側の待機場所復帰）が通しで、事故なく動作した。**
  実機での通し検証が一度もできていなかった状態から、主要経路の実現可能性は示せた。
- 一方で、**安全機能の中でも「動いている最中に非常停止ボタンを押す」という最も基本的な
  確認が今回は取れていない**。次回最優先で実施する。
- `BLOCKED` からの中断導線・当日画面からの復帰経路・壁近接警告の実発生は、いずれも
  「起きなかった／作らなかった」だけで、機能自体を否定する結果は出ていない。次回、
  意図的にこれらの条件（塞ぐ配置・壁際登録・S-21からの復帰操作）を作って確認する。
- 丸椅子の脚のような細い什器への接近余裕は目視評価のみだったため、次回は実測を伴う
  接近試験を検討する。
