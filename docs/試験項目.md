## 1. この試験のねらい

WS-9K でループ閉じ込みを切ったあと、「教示で保存すると地図も保存され、再生で経路を
選ぶと地図が読み直されて自己位置が経路の始点に合う」という**新しい流れの実機確認**。

いきなり 1 周に戻ると原因の切り分けができなくなるため、まず**短距離（30〜50m）**で
新しい流れが通ることを確かめる。今回見るのは次の 3 つ。

1. **地図の保存・再読込が通ること**（教示「保存」で `.posegraph` / `.data` ができ、
   再生で経路を選ぶと自己位置が経路の始点に一致すること）
2. **再生が経路を外れずに完走すること**
3. **終点誤差の実測**（短距離での基準値を作る）

## 2. 事前条件

- [ ] 床に**始点マーク**（ビニールテープの十字）を貼り、機体の向きも合わせられる状態にした
- [ ] 走らせる**短距離（30〜50m）**のルートを下見した（扉が閉まっていないか、段差・
      カーペットの継ぎ目が無いか）
- [ ] 走行中に人が付き添える（いつでも止められる位置に居る）

- [ ] 健全性確認 5 項目がすべて通った（[使い方.md](使い方.md) §2）
- [ ] **教示と再生は同じ起動セッションで行う**（[使い方.md](使い方.md) §4-6）

## 3. 試験項目

### T-1. 起動の安定性

| | |
| --- | --- |
| やること | `enable_route_slam:=true` で起動し、5 分間放置する |
| 見るもの | `[FAULT]` が出るか。「非常停止中」の窓が出るか。CPU に余裕があるか |
| **合格** | 起動から 2 分以内にすべて `[FAULT CLEARED]` になり、以後 3 分間フォルトが出ない |
| 記録 | 「非常停止中」が出た回数: ____ 回 |

CPU の確認（別ターミナル・コンテナ内）:

```bash
docker exec th_robot ps -eo pcpu,args --sort=-pcpu | head -8
```

> 合計が常時 100% を大きく超えているようなら記録して報告する。

---

### T-2. 教示（短距離 30〜50m）

| | |
| --- | --- |
| やること | 始点マークから出発し、**30〜50m のルート**を走って終点で停止・保存する（[使い方.md](使い方.md) §3-3） |
| 速度 | **低速（0.15 m/s）または中速（0.30 m/s）**。速いと記録が粗くなる |
| **合格** | 途中で止まらず走り終え、「**保存しました**」が出る |
| 記録 | 記録距離: ____ m ／ 点数: ____ 点 ／ 経路名: ________ |

「保存」を押すと**経路と一緒に地図も保存される**（書き出しのため**数秒かかる**）。
「保存しました」が出るまで待つこと。

走行中に**地図が伸び続けている**ことを画面で確認し続ける。伸びが止まったら
その場所を記録する（長い直線廊下で起きやすい）。

- [ ] 地図が最後まで伸び続けた
- [ ] 伸びが止まった場所があった → 場所: ________________

---

### T-3. 地図が保存されたか ★今回の主目的 ①

| | |
| --- | --- |
| やること | 教示の「保存」後、地図ファイルができたか確認する |
| **合格** | `th_ws/data/routes/<経路名>.posegraph` と `<経路名>.data` が**2 つとも存在する** |
| 記録 | `.posegraph` のサイズ: ____ ／ 存在した ／ しなかった |

確認コマンド（コンテナ内）:

```bash
docker exec th_robot ls -l /root/th_data/routes/<経路名>.posegraph /root/th_data/routes/<経路名>.data
```

> 経路 JSON（`<経路名>.json`）と一緒に保存される。地図が自動保存されていれば、
> 次の再生で読み直して自己位置が経路の始点に合う（[使い方.md](使い方.md) §4-4）。

---

### T-4. 再生で方法を確認する ★今回の主目的 ①②

| | |
| --- | --- |
| やること | **ロボットを始点マークに戻してから**、一覧で経路を選び再生する（[使い方.md](使い方.md) §3-4） |
| 見るもの | 経路選択で地図が読み直され、「推定できました」になるか |
| **合格** | 経路を外れずに完走し、「一時停止（記録の終端に達しました）」が出る |
| 記録 | 完走した ／ 途中で止まった（場所: ____________） |

**手順の順序が重要**: 経路を選ぶと**その時点の自己位置が経路の始点に合わせられる**ので、
**先に機体を始点マークに置いてから経路を選ぶ**こと（逆だと意味がない）。

- [ ] 機体を始点マークに戻してから経路を選んだ
- [ ] **選択直後に自己位置（始点）が経路の始点に合った**（合わなかった場所: ____________）

> 経路を選んでも「推定できました」にならない・数十秒で別セッション経路の手がかり
> 文言が出た場合は**地図の読み直しが失敗している**（[使い方.md](使い方.md) §4-6 / §7）。

走行中に見るもの:

- [ ] 教示した通り道からの**横ずれ**が目視でどれくらいか（最大: 約 ____ cm、場所: ________）
- [ ] 障害物での自動停止が働いたか（____ 回）
- [ ] 「非常停止中」が出たか（____ 回）
- [ ] **地図のスクリーンショットを撮る**（再生直後）

---

### T-5. 終点の誤差を測る ★今回の主目的 ③（短距離での基準値）

| | |
| --- | --- |
| やること | 停止した位置で、機体の基準点（前面中央）から**始点マークまでの距離**をメジャーで測る。向きのずれも測る |
| **合格の目安** | 位置 **30cm 以内**・向き **10 度以内**（初回なので参考値。実測することが目的） |
| 記録 | 位置のずれ: ____ cm ／ 向きのずれ: ____ 度 |

この値から「短距離でも地図の読み直しで始点が合っているか」を判断する。1 周（185m）に
進む前に、この短距離での基準値を先に作る。

### T-6.（余力があれば）逆再生

**画面の「逆再生」ボタンは現在ボタンが押せない状態になっている**（デモ範囲外として
未配線）。ノード側の逆再生は実装済みなので、試すならコンテナ内から直接指示する。

やり方: 「教示再生」画面で経路を選ぶところまでは同じ。**「この経路で進む」は押さず**、
代わりにコンテナ内で次を実行する（`<経路名>` は T-2 で付けた名前）。

```bash
docker exec -it th_robot bash
source /root/th_ws/install/setup.bash
ros2 service call /system/trigger th_system_msgs/srv/UiTrigger \
  "{trigger: 'ui.route_select', arg_json: '{\"id\": \"<経路名>\", \"reverse\": true}', requester: 'cli'}"
```

`accepted: true` が返れば受理。あとは画面が「推定できました」に変わるのを待って
**「再生」**を押す。

| | |
| --- | --- |
| **合格** | 完走する |
| 記録 | 受理された ／ されなかった（`reject_reason_key`: ________） |
| 記録 | 完走した ／ 途中で止まった（場所: ____________） |

> うまくいかなければ**飛ばしてよい**。この試験の主目的は T-3〜T-5。

---

## 4. 中止の条件

次のどれかに当たったら**その場で試験を止めて報告する**。無理に続けない。

- ロボットが人・壁に向かって進み、「停止」で止まらない
- 「非常停止中」が短時間に 3 回以上繰り返し出る
- 教示中に地図が壊れる（壁が四方八方に散る）
- ESP32 との通信が途切れ続ける（`ESP32_DISCONNECTED` が消えない）
