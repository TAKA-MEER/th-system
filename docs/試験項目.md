## 1. この試験のねらい

前回はピン登録に**「いまの姿勢で登録」**（`ROBOT_POSE`）のみを使い、**「2点指示」**は未使用
だった。今回はこの2方式を同一条件で比較し、次の2点を確かめる。

1. **絶対評価**: それぞれの方式は「実用ライン」（下記§2）を超えているか
2. **相対評価**: 超えている場合、どちらが優れているか。超えていない場合、どちらがより
   実用に近いか

この比較は [Spec-onsite.md](plan/spec/Spec-onsite.md) §3.3 の未決事項
（`O-c3`「2点指示の実際の角度精度」・`O-a1`「カメラ昇降が要求する位置決め許容差」）に
直結する。Specは2点指示の向き精度を**理論値・未実測**として次のように見積もっている。

```
① 2点指示が与える「目標の向き」自体の誤差 = ±8〜11°（L=1m・人物位置推定誤差σ=0.1mから計算。未実測）
② Nav2 がその目標にどれだけ着けるか        = ±0.25m / ±0.25rad(±14°)（現行設定値）
盤前で出る向き誤差 ≒ √(①²+②²) ≒ ±16〜18°（最悪の重なりで±22〜25°）
```

**今回の試験で①②合成の実測値を取り、この理論値が妥当か検証する。** 「いまの姿勢で登録」は
このSpecの原設計にない後発の方式（人物追跡に依存しない）で、同じ理論的枠組みが無いため、
実測でしか評価できない。

## 2. 実用ラインの定義

### 2.1 共通の実用ライン（両方式に同じ基準を適用）

| 段階 | 基準 | 満たさない場合の意味 |
| --- | --- | --- |
| **Tier 0（必須）** | 登録したピンへ自律移動し、`BLOCKED` にならず `AT_PANEL` まで到達する（3回中3回成功） | その方式は**この用途で使い物にならない**。以降の精度評価は無意味 |
| **Tier 1（実用ライン・位置）** | 到着位置誤差の**平均が10cm以下** | 10cm超は前回実測（panel_2で7cm）の水準に届いていない |
| **Tier 1（実用ライン・向き）** | 到着向き誤差の**平均が15°以下** | Specの2点指示合成理論値（±16〜18°）をわずかに下回る水準。**ここを2点指示が超えられるかが今回最大の論点** |
| **再現性ライン** | 同一地点・同一方式で3回試行した際の**標準偏差が位置5cm未満・向き5°未満** | ばらつきが大きい方式は、平均がTier1を満たしても信頼できない |

> 10cm/15°は「カメラ昇降が要求する位置決め許容差」(`O-a1`。フェーズ2範囲外で未確定)の
> 代わりに**今回暫定的に置く基準**。正式な許容差が判明したら差し替える。10cmは前回の
> 実測1件（7cm）が根拠、15°はSpecの2点指示理論値（16〜18°）をわずかに下回る値を意図的に
> 選んでいる（2点指示が自分自身の理論限界を実測で超えられるかを直接問う設定）。

### 2.2 方式特有の評価軸（優劣判断の材料。単独では合否を決めない）

| | いまの姿勢で登録（`ROBOT_POSE`） | 2点指示 |
| --- | --- | --- |
| 誤差の源 | 操作者が機体（0.55m角）を目標位置・向きへ目視で整列させる精度＋その場のSLAM自己位置精度 | 人物追跡の推定誤差（σ≒0.1m）＋一歩の向き変換の幾何誤差（±8〜11°、Specの理論値） |
| 人物追跡への依存 | **無し**（人物追跡が不安定でも登録できる） | **有り**（ロスト中・信頼度低は登録拒否。§3.5） |
| 機体の取り回しへの依存 | **有り**（狭所では機体自体を精密に位置決めする必要） | **無し**（人が動くだけでよい） |
| 追加で見る指標 | 狭所での位置決めに要した時間・切り返し回数、操作者の死角・視認性 | 登録拒否率（`two_point_too_close`・ロスト・信頼度低）、複数候補存在下の誤選択有無、ステップ距離Lと向き精度の相関 |

## 3. 比較方法（測定手順）

### 3.1 地点の準備

**3地点**にビニールテープで**目標位置（×印）と目標の向き（矢印線）**を貼る。位置は
メジャーで、向きは分度器またはスマホの角度計アプリで、あらかじめ壁や既知の基準線から
測って記録しておく（この印自体が「正解」になるため、印の位置決めは慎重に行う）。

| 地点 | 狙い |
| --- | --- |
| 地点1: 開けた場所 | 基準条件。両方式とも有利なはず |
| 地点2: 狭い場所・角 | 「いまの姿勢で登録」に不利な条件（機体の取り回しが難しい） |
| 地点3: 人が近くにいる／視界の端 | 「2点指示」に不利な条件（人物追跡の頑健性） |

### 3.2 各地点・各方式での試行

各地点で、**先に登録する方式を地点ごとに入れ替える**（地点1: A→B、地点2: B→A、地点3: A→B。
練習効果・疲労の偏りを避けるため）。

1. 方式Aまたは方式Bでその地点のマークに合わせて登録する
   （登録に要した時間・拒否/やり直し回数を記録）
2. 機体を1〜2m離す（ジョグで可）
3. 登録したピンへ自律移動させ、停止位置・向きをマークと比較して実測する
   （メジャー＋分度器。位置cm・向き°を記録）
4. 手順2〜3を**計3回**繰り返す（同じピンへの再アプローチ。Nav2自体の再現性を見る）
5. 別方式でも同じマークに対して手順1〜4を行う（既存ピンは上書き登録でよい）

**計測項目（毎回）**: 到着位置のズレ(cm) ／ 到着向きのズレ(°) ／ 到着までの時間(秒) ／
`BLOCKED`の有無

### 3.3 時間が許せば追加する試験

- **登録プロセス自体の再現性**: 地点1つだけ選び、同じマークに対して方式ごとに
  もう一度**登録からやり直し**（3.2の手順1から）を行い、1回目の登録と結果が大きく変わるか見る
  （3.2の手順4は同一登録に対する**Nav2の**再現性、こちらは**登録プロセス自体の**再現性）
- **2点指示のステップ距離を変える**: 通常の一歩（目安0.7〜1m）と、意識して大きく踏み出した
  場合（目安1.5m以上）で向き精度を比較する。Specの理論（誤差 ∝ σ/L）どおり、歩幅を
  伸ばすと向き精度が改善するなら、UIの案内文を変えるだけで2点指示の精度を上げられる可能性がある
- **2点指示の頑健性**: 対象選択候補が複数（誤検知含む）ある状態で登録を試み、誤った候補への
  登録が起きないか確認する

## 6. 中止の条件

- ロボットが人・壁に向かって進み、「停止」でも物理非常停止でも止まらない
- 誤ったピンへ登録されたまま気づかず自律移動を続けている（地図・ピンの整合性がおかしいとき）
- 「非常停止中」が短時間に3回以上繰り返し出る
- `ESP32_DISCONNECTED` が消えない
