## 1. この試験のねらい

`DRIVE_RUNAWAY`（指令と実速度の乖離が続いたら非常停止）は、台帳 `W-06` で**無効化したまま**になっている
（`bringup.launch.py` の `SAFETY_ENABLED_TARGETS` に `runaway` が無い）。戻すには次を**実データで**決める必要がある:

| 台帳 | 決めること | 疑っていること |
| --- | --- | --- |
| ③ | その場旋回（指令の `linear.x`=0）をどう扱うか | 左右の車輪が逆向きに回るため、左右平均が 0.02 m/s を超えて「停止指令中なのに動いている」と誤判定する |
| ④ | `wheel_radius_scale`（今は 1.0 の未較正） | 指令に対する実速度の比がもともとずれている |
| ⑤ | `runaway_ratio`（1.5）・`runaway_hold_ms`（500 ms） | 発進・停止の加減速（実測 ≈1.0〜1.3 m/s²）で、実速度の追従が保持時間を超えて遅れる。**高速（0.55 m/s）の停止で約 0.5 秒＝保持時間ぎりぎり** |
| ⑥ | `SAFETY_ENABLED_TARGETS` に戻す | ③〜⑤が決まり、**検知そのものが動く**ことを確かめてから（次回。§7） |

**今回は安全設定を何も変えない。**`runaway` は無効のまま走らせ、走行中の「指令」と「実速度」を
**購読だけの計測スクリプト**で記録する（[使い方.md](使い方.md) §3-7）。スクリプトは `safety_monitor` と同じ式・同じ周期で
乖離を評価し直すので、**今の設定なら何回・どの動作で発火していたか**が分かる。決定と実装は記録を解析してから。

**やらないこと**: `runaway` を有効にする／設定値を変える／ロボット側のコードを変える。

## 6. 中止の条件

- ロボットが人・壁に向かって進み、「停止」でも物理非常停止でも止まらない
- 「非常停止中」が短時間に 3 回以上繰り返し出る
- `ESP32_DISCONNECTED` が消えない
- 記録ターミナルが止まった／エラーで終了した（記録が無いと今回の意味が無い。走行を止めて原因を見る）
