## 1. この試験のねらい

前回はピン登録に**「いまの姿勢で登録」**（`ROBOT_POSE`）のみを使い、**「2点指示」**は未使用
だった。今回この2方式に加えて、当日実装した**「地図タップ」**（`MAP_TAP`。地図をタップして
位置・向きを直接指定する第3の方式。[Spec-onsite.md](plan/spec/Spec-onsite.md) §3.7）を加えた
**3方式**を同一条件で比較し、次の2点を確かめる。

1. **絶対評価**: それぞれの方式は「実用ライン」（下記§2）を超えているか
2. **相対評価**: 超えている場合、どの方式が優れているか。超えていない場合、どれがより
   実用に近いか

この比較は [Spec-onsite.md](plan/spec/Spec-onsite.md) §3.3 の未決事項
（`O-c3`「2点指示の実際の角度精度」・`O-a1`「カメラ昇降が要求する位置決め許容差」）に
直結する。Specは2点指示の向き精度を**理論値・未実測**として次のように見積もっている。

```
① 2点指示が与える「目標の向き」自体の誤差 = ±8〜11°（L=1m・人物位置推定誤差σ=0.1mから計算。未実測）
② Nav2 がその目標にどれだけ着けるか        = ±0.25m / ±0.25rad(±14°)（現行設定値）
盤前で出る向き誤差 ≒ √(①²+②²) ≒ ±16〜18°（最悪の重なりで±22〜25°）
```

**今回の試験で①②合成の実測値を取り、この理論値が妥当か検証する。** 「いまの姿勢で登録」と
「地図タップ」はこのSpecの原設計にない後発の方式（いずれも人物追跡に依存しない）で、
同じ理論的枠組みが無いため、実測でしか評価できない。

**地図タップに固有の着眼点**: いまの姿勢で登録は「操作者が機体を目視で整列させる精度」に、
2点指示は「人物追跡の推定誤差」にそれぞれ誤差源を持つ。地図タップは**そのどちらにも
依存しない**（Spec-onsite.md §3.7）。今回の試験で2方式がTier1に届かなかった場合、
地図タップが有力な代替になり得るかがこの回最大の論点になる。

## 2. 実用ラインの定義

### 2.1 共通の実用ライン（3方式に同じ基準を適用）

| 段階 | 基準 | 満たさない場合の意味 |
| --- | --- | --- |
| **Tier 0（必須）** | 登録したピンへ自律移動し、`BLOCKED` にならず `AT_PANEL` まで到達する（3回中3回成功） | その方式は**この用途で使い物にならない**。以降の精度評価は無意味 |
| **Tier 1（実用ライン・位置＝登録誤差）** | 登録された座標と**印の真の座標**（後述の方法で独立に実測）の差の**平均が10cm以下** | 登録方式そのものが不正確。**3方式の優劣を最も直接測る指標**（2026-09-15改定。理由は下記） |
| **Tier 1（実用ライン・向き）** | 到着向き誤差の**平均が15°以下** | Specの2点指示合成理論値（±16〜18°）をわずかに下回る水準。**ここを2点指示・地図タップが超えられるかが今回最大の論点** |
| 到達誤差（参考。合否ラインではない） | 登録座標と実際の停止位置の差が、概ねNav2の設定許容差（現行`xy_goal_tolerance`=±0.25m/±0.25rad）の範囲に収まっている | 大きく超えていればNav2側のチューニング課題。**登録方式の優劣とは切り離して扱う** |
| 総合（参考記録。合否ラインではない） | 停止位置と印の差（登録誤差＋到達誤差の合成。従来のTier1・位置はこれだった） | カメラ昇降が実際に使う許容差（`O-a1`判明時）と比較する対象。**現時点では絶対評価に使わない**（下記参照） |
| **再現性ライン** | 同一地点・同一方式で3回試行した際の**標準偏差が位置5cm未満・向き5°未満** | ばらつきが大きい方式は、平均がTier1を満たしても信頼できない |

> 15°はSpecの2点指示理論値（16〜18°）をわずかに下回る値を意図的に選んでいる（2点指示が
> 自分自身の理論限界を実測で超えられるかを直接問う設定）。
>
> **【2026-09-15改定】位置Tier1を「停止位置 vs 印」から「登録座標 vs 印」に変更した。**
> 経緯: 旧定義（10cm、根拠は前回実測1件=n1）に対し、地点1試験（n=12）が3方式とも一貫して
> 超過した（T-7参照）。原因を調べたところ、「停止位置」という指標はNav2の到達誤差
> （§1の②、現行`xy_goal_tolerance`=±0.25m）を必ず含んでしまい、**登録方式がどれだけ
> 正確でもNav2の許容差より小さい値には原理的に届かない**ことが分かった（T-5補足で
> 地図タップの登録誤差だけを分離すると9.6cmとTier1にほぼ到達）。10cmという数値ではなく
> 「何を測るか」自体が誤っていたため、旧「10cm/総合」は参考記録に格下げし、位置Tier1は
> **登録誤差**（Nav2を介さない、方式そのものの正確さ）で判定するよう改める。10cmの数値は
> そのまま維持する（このn=1のタップの結果がほぼ達成しているため、達成可能な水準として
> 妥当と判断。正式な`O-a1`が判明したら差し替える）。
>
> **印の真の座標の測り方（改定）**: 壁や基準線からのメジャー計測は、どこを原点に取るか
> 分かりにくく実施が難しかった（2026-09-14に発生）。代わりに**ロボット本体を印の位置に
> 物理的に置き、`map→base_link`のTFを読む**（`ros2 run tf2_ros tf2_echo map base_link`
> または同等の手段）。ロボットの自己位置はピンの登録座標と同じmap座標系なので、
> 基準点の変換が一切不要になる。**「いまの姿勢で登録」の登録タイミングそのものをこの
> 実測に使うと同語反復になる**（登録は機体を置いた瞬間のTFをそのまま座標にするため）。
> 必ず登録とは別のタイミングで（一度離れてから戻す、または他方式の登録・実測を挟んでから）
> 独立に置き直して読むこと。

### 2.2 方式特有の評価軸（優劣判断の材料。単独では合否を決めない）

| | いまの姿勢で登録（`ROBOT_POSE`） | 2点指示（`TWO_POINT`） | 地図タップ（`MAP_TAP`） |
| --- | --- | --- | --- |
| 誤差の源 | 操作者が機体（0.55m角）を目標位置・向きへ目視で整列させる精度＋その場のSLAM自己位置精度 | 人物追跡の推定誤差（σ≒0.1m）＋一歩の向き変換の幾何誤差（±8〜11°、Specの理論値） | 画面タップの位置精度＋地図（SLAM）の計量精度。タップ間隔Lを画面のズームで自由に取れるため、L依存の誤差（∝タップ誤差/L）は理論上2点指示より小さくできる（Spec-onsite.md §3.7） |
| 人物追跡への依存 | **無し**（人物追跡が不安定でも登録できる） | **有り**（ロスト中・信頼度低は登録拒否。§3.5） | **無し** |
| 機体の取り回しへの依存 | **有り**（狭所では機体自体を精密に位置決めする必要） | **無し**（人が動くだけでよい） | **無し**（操作者は画面を見るだけで、機体も人も動かす必要が無い） |
| 追加で見る指標 | 狭所での位置決めに要した時間・切り返し回数、操作者の死角・視認性 | 登録拒否率（`two_point_too_close`・ロスト・信頼度低）、複数候補存在下の誤選択有無、ステップ距離Lと向き精度の相関 | ズームレベル（画面上のタップ間隔L）と向き精度の相関、壁上タップの即時拒否・壁近接警告の発生有無、タップやり直し回数 |

**地図タップの壁近接判定・即時拒否自体は実装検証時（2026-09-14、実機）に動作を確認済み。**
今回の試験で見るのは**精度**（Tier1）であって、機能の有無ではない。

## 3. 比較方法（測定手順）

### 3.1 地点の準備（2026-09-15改定: 1地点のみで実施）

**地点2・3（狭所／人混み）を用意できないため、当面は1箇所のみで3方式の登録精度を比較する。**
地点2・3固有の検証（狭所での取り回し、人物追跡の頑健性）は§3.4で保留とし、該当地点が
用意でき次第、別途T-3/T-4として実施する。

1箇所にビニールテープで**目標位置（×印）と目標の向き（矢印線）**を貼る。

**印の真の座標の記録方法**: ロボット本体をその印の位置・向きへ実際に置き、`map→base_link`
のTFを読んで記録する（`ros2 run tf2_ros tf2_echo map base_link`等。メジャー・分度器や
壁からの基準測定は不要。ロボットの自己位置がそのままmap座標系の実測値になる）。

### 3.2 3方式を1セッションで登録し、`panel_1`〜`3`を比較する

1. 上記の印にロボットを置き、`map→base_link`のTFを読んで**真の座標**として記録する
2. ロボットを1〜2m離す
3. 姿勢→2点指示→タップの順（順番は任意。地点が1つだけなので練習効果対策の
   ローテーションは不要）で、**同じ印に対して3方式とも登録する**。**今回はピンを
   削除せず、そのまま登録する**（PANEL種は自動採番なので`panel_1`/`panel_2`/`panel_3`
   として3件残る。`venue/pins.yaml`または「ピン」タブで確認できる。登録に要した時間・
   拒否/やり直し回数も記録。地図タップは登録前のズーム操作の時間も含める）
4. 各`panel_N`の座標と、手順1の真の座標を比較する（位置cm・向き°）
   — **これが3方式それぞれの登録誤差（Tier1本体）**
5. （参考）`panel_1`〜`3`同士も見比べる。3方式が近い値で揃っていれば安心材料、1つだけ
   外れていれば怪しいと分かる。**ただし3方式が一致していても手順1（真の座標との比較）は
   省略しない**（3方式がそろって同じ方向にズレている＝その場のSLAM全体ドリフトの可能性を、
   真の座標との比較でしか検出できないため）
6. （余裕があれば・参考記録）いずれか1つのピンへロボットを1〜2m離してから自律移動させ、
   停止位置・向きを印と比較する（§2.1の「到達誤差」「総合」に使う。Tier0の3/3到達確認も兼ねる）

**計測項目**: 3方式それぞれの登録誤差（位置cm・向き°、手順4） ／ （参考）`panel_1`〜`3`間の
ばらつき ／ 登録に要した時間・拒否/やり直し回数 ／（余裕があれば）到着位置・向きのズレ・
`BLOCKED`の有無

### 3.3 時間が許せば追加する試験

- **登録プロセス自体の再現性**: 同じマークに対して方式ごとにもう一度**登録からやり直し**
  （3.2の手順3から。真の座標との比較は手順1の値をそのまま使い回してよい）を行い、
  1回目の登録座標と結果が大きく変わるか見る（3.2の手順6は同一登録に対する**Nav2の**
  再現性、こちらは**登録プロセス自体の**再現性）
- **2点指示のステップ距離を変える**: 通常の一歩（目安0.7〜1m）と、意識して大きく踏み出した
  場合（目安1.5m以上）で向き精度を比較する。Specの理論（誤差 ∝ σ/L）どおり、歩幅を
  伸ばすと向き精度が改善するなら、UIの案内文を変えるだけで2点指示の精度を上げられる可能性がある
- **地図タップのズーム/タップ間隔を変える**: 「全体表示」のまま（ズーム無し）のタップ間隔と、
  意識して拡大した状態でのタップ間隔で向き精度を比較する。2点指示と同じ理論（誤差 ∝
  タップ誤差/L）どおり、ズームで実効的な点間距離Lを伸ばすと向き精度が改善するなら、
  UIの操作案内（「拡大してからタップしてください」等）を変えるだけで精度を上げられる可能性がある
- **2点指示の頑健性**: 対象選択候補が複数（誤検知含む）ある状態で登録を試み、誤った候補への
  登録が起きないか確認する

### 3.4 地点2・3が用意できたら（保留中。2026-09-15、当面は実施しない）

狭所・人混みでの方式固有の弱点を見るには、引き続き元の2地点が必要。用意でき次第、
§3.2と同じ手順（真の座標をTFで実測→3方式を同じ印に登録→`panel_N`と比較）をそれぞれの
地点で行う。

| 地点 | 狙い |
| --- | --- |
| 地点2: 狭い場所・角 | 「いまの姿勢で登録」に不利な条件（機体の取り回しが難しい）。2点指示・地図タップは機体を動かさないので影響が小さいはず |
| 地点3: 人が近くにいる／視界の端 | 「2点指示」に不利な条件（人物追跡の頑健性）。いまの姿勢で登録・地図タップは人物追跡に依存しないので影響が無いはず |

**地点2・地点3は、いまの姿勢で登録と2点指示それぞれの弱点を突く条件として設計されている。
地図タップはそのどちらの弱点も持たないため、地点2・3でも地点1と同等の精度が出るかどうかが
着眼点になる**（§1「地図タップに固有の着眼点」参照）。地点2では姿勢の位置決め所要時間・
切り返し回数も追加で記録する。地点3では2点指示の拒否理由内訳（ロスト/信頼度低/
`two_point_too_close`）・誤選択の有無も追加で記録する。

#### T-5補足: 登録誤差だけを分離して実測（2026-09-14、地図タップの本項2回目）

T-2〜T-5はすべて「Nav2で自律移動した後の停止位置」と印を比較しており、**登録そのものの誤差**と
**Nav2の到達誤差**（§1の②、`xy_goal_tolerance`＝現行±0.25m）が混ざった数値になっている。
試験後、T-5のタップ2回目終了時点でピンを削除せずに残しておいたところ
（`venue/pins.yaml`の`panel_1`）、**ロボット本体を印の位置へ物理的に置き、`map→base_link`の
TFを読む**ことで、Nav2を介さずに「印の真の座標」を同じmap座標系で直接得られることが分かった
（メジャー・分度器や壁からの基準測定が不要。ロボットの自己位置がそのまま実測値になる）。

| | 値 |
| --- | --- |
| 印の真の座標（ロボット実測、TF） | x=-19.228, y=0.583, yaw=-2.46° |
| 登録された`panel_1`の座標 | x=-19.154, y=0.644, yaw=4.6° |
| **登録誤差（Nav2を介さない）** | **位置 √(7.4²+6.1²)≈9.6cm ／ 向き 7.1°** |

T-2で測った同条件（地図タップ、地点1）の「停止位置と印のズレ」は位置27cm・向き3.7°平均。
**登録誤差(9.6cm)は位置Tier1(10cm)をほぼ達成しているのに対し、停止位置ベースの27cmとの差
(約17cm)はNav2の到達誤差（許容値±25cm）で概ね説明がつく**。n=1（タップ・地点1・1回のみ）の
参考値であり確定的な結論ではないが、**位置Tier1(10cm)を「停止位置」で測る現行の指標は、
登録方式の優劣ではなくNav2側の誤差を主に測ってしまっている可能性が高い**。

**次回への申し送り**: 「ロボットを印に置いてTFを読む」を標準の実測手順にし、3方式×複数地点で
「登録誤差」と「到達誤差（登録誤差との差分）」を分けて記録する。位置Tier1(10cm)は登録誤差側に
適用し、到達誤差側は`xy_goal_tolerance`の妥当性検証として別枠で扱う。

### T-7. 実用ライン判定のまとめ

**位置Tier1の定義を2026-09-15に「停止位置 vs 印」から「登録座標 vs 印」へ改定した**（§2.1参照）。

9.6cmとTier1にほぼ到達することを確認）。**正式なTier1判定はT-2bで行う**（このT-2の表は
「総合」の参考記録として残す）。

**判定の指針**（T-2b実施後に使う）:
- 全方式Tier0未達 → いずれも実用不可。[Spec-onsite.md](plan/spec/Spec-onsite.md) §3.3の

- 1方式のみ全ライン通過 → その方式を採用
- 2方式以上が全ライン通過 → 所要時間・拒否率・方式特有の弱点（狭所／人物追跡／画面操作）で

- 全方式Tier0のみ通過しTier1未達 → 「実用ラインには届かないが、どれがより実用に近いか」を
  数値で記録し、盤面正対の要否判断（`O-a1`/`O-c3`）に反映する。特に地図タップがTier1に届かない
  場合、ズーム操作の案内文を変える（T-6b）だけで改善するかを優先して調べる
