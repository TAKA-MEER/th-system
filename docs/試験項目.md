## 1. この試験のねらい

**3階コース（約170m）で、これまでの修正が通しで効くかを初めて確認する試験。**

第1〜3回はいずれも再生中に自己位置推定が外れて衝突し、その原因は修正済み。第4回は
その効果を確かめるはずだったが、**ESP32 の通信エラーで教示すら完了できずに終わった**
（[教示再生走行試験.md](教示再生走行試験.md) §5）。その後 ESP32 の無線を廃止して
ラズパイ経由のシリアル接続にしたので、**今回はまず「教示が最後まで完了できるか」が
最初の関門**になる。

今回見るのは次の 4 つ。

1. **通信が最後まで保つこと**（シリアル化の効果。第4回の再発が無いこと）★最大の関門
2. **教示が1周完了し、地図が保存されること**
3. **再生（中速）が経路を外れずに完走すること**（第1〜3回の修正の効果確認。
   特に**曲がり角で自己位置推定が外れないか**）
4. **高速再生のふらつきが解消しているか**（lookahead の速度スケール修正 `7b482e9` の
   実走行検証。実測に基づかない見積もり値なので、駄目なら現場で詰める）

## 3. 試験項目

### T-1. 起動と通信の安定性 ★今回の主目的 ①

| | |
| --- | --- |
| やること | `enable_route_slam:=true` で起動し、5 分間放置する |
| 見るもの | `[FAULT]` が出るか。「非常停止中」の窓が出るか。`/esp32/wheel_feedback` の間隔 |
| **合格** | 起動から 2 分以内にすべて `[FAULT CLEARED]` になり、以後 3 分間フォルトが出ない。かつ `wheel_feedback` が**約100ms間隔（標準偏差 0.01s 以下）** |
| 記録 | 「非常停止中」が出た回数: ____ 回 ／ std dev: ____ s |

通信の質（別ターミナル・コンテナ内）:

```bash
docker exec th_robot bash -lc \
  'source /opt/ros/humble/setup.bash && source /root/th_ws/install/setup.bash && \
   timeout 20 ros2 topic hz /esp32/wheel_feedback'
```

> **正常**: `min 0.08 / max 0.12` 付近で標準偏差 0.003〜0.01s。
> **異常**: 2件がほぼ同時（min 0.001）に届いた直後に約200msの空白、が**毎周期**続く。
> この場合は [network.md](network.md)「導入時に実際に踏んだこと」を見る。

CPU の確認:

```bash
docker exec th_robot ps -eo pcpu,args --sort=-pcpu | head -8
```

### T-2. 教示（3階1周・約170m）★今回の主目的 ②・最大の関門

| | |
| --- | --- |
| やること | 始点マークから手動で1周教示し、「保存」する |
| 見るもの | **操作を受け付けなくなる瞬間が無いか**（第4回の症状）。地図が壊れないか |
| **合格** | **1周を通して手が離れず、途中で止まらず、壁に当たらずに始点へ戻り、「保存しました」が出る** |

> **第4回はここで頓挫した。** 「操作を受け付けなくなり壁へ衝突」が1回でも起きたら、
> その時刻を記録して T-3 以降へは進まず、まず [network.md](network.md) の切り分けを行う。

## 4. 中止の条件

次のどれかに当たったら**その場で試験を止めて報告する**。無理に続けない。

- ロボットが人・壁に向かって進み、「停止」で止まらない
- 「非常停止中」が短時間に 3 回以上繰り返し出る
- 教示中に地図が壊れる（壁が四方八方に散る）
- **教示中に操作を受け付けなくなる**（第4回の症状。1回でも起きたら T-2 で止める）
- `ESP32_DISCONNECTED` が消えない
