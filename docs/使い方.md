[← README に戻る](../README.md)

## 1. 起動する

### 1-1. 電源とネットワーク

ロボット（ESP32）とラズパイの電源を入れ、PC をロボット AP に繋ぐ。

```bash
nmcli connection up th-rpi-ap-wlo1     # 自動接続済みなら不要
ping -c3 192.168.5.1                   # ラズパイ（AP 兼 LiDAR）
ping -c3 192.168.5.125                 # ESP32
ip route | head -1                     # default が 5GHz 側（wlx...）であること
```

両方の ping が返らないと先へ進めない → [network.md](network.md)「復旧手順」

> **ロボット回線は PC の内蔵 Wi-Fi カードを使う。** USB ドングルに替えると通信が
> 不安定になり ESP32 が切れ続ける（実測で確認済み）。
> **インターネットは 5GHz の別アダプタに逃がす。** PC が 2.4GHz を 2 枚同時に
> 使うと互いに干渉する。

### 1-2. ROS2（コンテナ内）

```bash
cd ~/code/MIRS-Local/TM/th-system/th_ws
docker start th_robot
docker exec -it th_robot bash
```

コンテナの中で:

```bash
cd /root/th_ws
colcon build --symlink-install      # ソースを更新した直後だけ。数分かかる
source install/setup.bash

ros2 launch th_bringup bringup.launch.py \
  lidar_source:=network use_stub:=false enable_route_slam:=true
```

**このターミナルは開いたままにする。** 閉じるとロボットが止まる。

#### 起動オプション


| 引数                          | 既定    | 意味                                           |
| ------------------------------- | --------- | ------------------------------------------------ |
| `lidar_source:=network`       | `local` | LiDAR をラズパイから受け取る。**実機では必須** |
| `use_stub:=false`             | `false` | 人物トラッカーを偽物にしない                   |
| **`enable_route_slam:=true`** | `false` | **SLAM を起動する。教示・再生では必須**（§4） |
| `imu_enabled:=false`          | `true`  | ジャイロ（vyaw）の自己位置融合を**切る**。既定は融合あり（コーナーの yaw ドリフト対策。WS-9V）。ジャイロ単位未修正ファームの個体でだけ `false` |
| `stage:=N`                    | `1`     | 起動するノードの範囲。実機デモは`1` のまま     |

### 1-3. WebUI（コンテナの外・別ターミナル）

```bash
cd ~/code/MIRS-Local/TM/th-system/th_ws/web_ui
npm run dev
```

- タブレット: **`http://192.168.5.50:5173`**
- PC で見るだけ: `http://localhost:5173`

rosbridge（9090）は bringup が自動で起動する。

## 2. 起動後の健全性確認

別のターミナルをもう1枚開く。

```bash
docker exec -it th_robot bash
source /root/th_ws/install/setup.bash
```


| # | コマンド                               | 期待する結果                | 駄目なとき                                 |
| --- | ---------------------------------------- | ----------------------------- | -------------------------------------------- |
| 1 | `ros2 topic hz /scan_filtered`         | 約 10 Hz                    | [network.md](network.md)                   |
| 2 | `ros2 topic hz /map`                   | 0.5 Hz 程度                 | `enable_route_slam:=true` を付け忘れ       |
| 3 | `ros2 run tf2_ros tf2_echo map odom`   | 数値が出る                  | 同上。**これが SLAM が効いている証拠**     |
| 4 | `ros2 topic hz /route/map_view`        | 数秒に 1 回（0.25〜0.5 Hz） | タブレットに地図を出すための間引き済み地図 |
| 5 | `ros2 topic echo /system/state --once` | `mode: IDLE`                | 起動直後は`INIT`。1〜2分待つ               |

タブレット側は **S-00「疎通確認」画面**で全機器が「疎通」になり、総合が
**「運用に入れます」**に変わること。**「メインメニュー画面へ」**のボタンはそれまで出ない。

起動直後の `[FAULT]` は 1〜2 分で `[FAULT CLEARED]` になるのが正常。

## 3. 画面と操作

画面はモードに追従して自動で切り替わる。**画面を直接選ぶ操作は無い。**

```
S-00 疎通確認 ──(全機器が疎通)──> S-01 メインメニュー
                                      ├─ 手動走行
                                      ├─ 教示（手動）
                                      └─ 教示再生
```

### 3-1. ボタンの場所

**「終了」だけは画面の左上**にある（タブの左）。それ以外は**右列の操作カード**。
操作カードに出るボタンは画面ごとに違う。


| 画面         | 左上 | 操作カード          | 右列               |
| -------------- | ------ | --------------------- | -------------------- |
| 教示（手動） | 終了 | **停止** / **保存** | 手動介入スティック |
| 教示再生     | 終了 | **停止** / **再生** | 手動介入スティック |


| ボタン   | 送るもの    | 意味                                   |
| ---------- | ------------- | ---------------------------------------- |
| **停止** | `ui.stop`   | 走行・記録を止める                     |
| **再生** | `ui.run`    | 走り出す（再生画面のみ）               |
| **保存** | `ui.save`   | 記録した経路を保存する（教示画面のみ） |
| **終了** | `ui.finish` | そのモードを抜けてメインメニューへ     |

**「確認」は操作カードには出ない。** 非常停止の窓の中にだけ現れる（§3-5）。

> **押しても何も起こらないことがある。** いまの状態で受け付けられないボタンを押すと、
> **画面には何も出ずに黙って無視される**（拒否理由は表示されない）。
> 「押したのに反応しない」ときは故障ではなく、**まだその操作をしてよい状態ではない**
> と考えて、画面の状態表示を確認すること。

### 3-2. 手動走行

メインメニュー →「手動走行」。「走行」タブのスティックで動かす。
速度は **低速 / 中速 / 高速** から選ぶ（§5）。

> **その場旋回（スティックを真横に倒す）は速度プリセットの影響を受けない。**
> 低速のまま曲がり角でその場旋回してもキビキビ回る（前進しながら曲がる「斜め倒し」は
> プリセットで絞られる）。旋回の上限は 1.2 rad/s（≈69°/s）。

### 3-3. 教示（手動）— 通り道を記録する

1. メインメニュー →**「教示（手動）」**
2. **「教示」タブ**で経路名を入れる
   - **`/` と `\` は入力すると自動で `_` に置き換えられる**（ファイル名に使えないため）。
     画面の表示名と保存名は一致する
   - 日本語でも半角英数でもよい。空欄なら日時から自動で付く
   - **同じ名前で記録し直すと旧版は `<経路名>.prev` に残る**（新しく録ったほうが
     `<経路名>.json` になる）。区別しやすい名前を付ける
3. **「記録開始」** → 画面が「記録中」になる
4. **「走行」タブ**でスティックを操作して走らせる
   - 記録中は **10 秒ごとに途中経過が自動保存**される。**「保存」を押す前に落ちても
     ここまでの成果は残る**。復旧するには `<経路名>.wip` を `<経路名>.json` へ
     リネームして使う
5. 走り終えたら **「停止」→「保存」** → **「終了」**
   - **「保存しました」の表示を必ず確認してから**「終了」を押すこと。
     **「保存」を押さずに終了・停止すると経路は `.json` にならず一覧に出ない**
     （`.wip` から復旧はできる）。また**保存できなかった場合**は「保存されていません」
     と表示されるので、その場合は「保存」を押し直す
   - 「保存」を押すと**経路（`.json`）と一緒に地図も保存される**（§4-4）。
     地図の書き出しが入るため**保存には数秒かかることがある**。「保存しました」と出る
     まで待つこと

> **⚠ 「保存」のあとにスティックに触れると記録が再開する。**（右列の手動介入
> スティックでも同じ。）保存後は**「終了」を押すまでスティックに触れないこと。**
> 触ってしまった場合は、もう一度「停止」→「保存」を押せば救える
> （旧版は `<経路名>.prev` に退避される）。

記録中に見えるもの:


| 表示     | 意味                                                                          |
| ---------- | ------------------------------------------------------------------------------- |
| 記録距離 | 走った距離                                                                    |
| 点数     | 記録した点の数。10cm におよそ 1 点なので、100m なら 1000 点前後               |
| 経過時間 |                                                                               |
| 地図     | 走るにつれて伸びていく。**伸びないなら SLAM が効いていない**（§2 の #2・#3） |

**走らせ方のコツ**

- **曲がり角では止まらず一定の速度で回る。** 長い直線廊下は LiDAR には
  「どこも同じ景色」に見えて位置がずれやすい。曲がり角と分岐が手がかりになる
- **壁に寄りすぎない。** 壁しか見えないと地図が作れない
- スティックを一気に倒しても急発進はしない（加速度制限が入っている）
- **自動停止がかかるのは「進行方向 ±29 度の範囲」に物があるときだけ**で、
  真横の壁では止まらない（廊下を普通に走るぶんには効かない）。
  止まるのは**機体の前面から約 15cm** まで近づいたとき。
  曲がり角で正面の壁に寄せすぎると止まるので、少し早めに回る

### 3-4. 教示再生 — 記録した通り道を自動で走る

1. **ロボットを教示の開始位置・開始の向きに置く。**
   床に始点マーク（ビニールテープの十字）を貼っておくこと
2. メインメニュー →**「教示再生」**
3. 一覧から経路を選び **「この経路で進む」**
4. 「初期姿勢を推定しています…」→**「推定できました。地図と位置を確認して
   『再生』を押してください」**に変わるのを待つ（数秒）
5. **地図上のロボットの位置が実際と合っているか目で確かめる**
6. **「再生」** を押す

> **経路を選ぶと、教示時に保存した地図が読み直され、そのとき自己位置が経路の
> 始点に合わせられる**（§4-4）。だから**機体を始点マークに置いてから経路を選ぶ**こと。
> 逆に、先に経路を選んでから機体を動かすと、読み直しで合わせた始点から機体が
> ずれたままになり意味がない。

> **「推定できました」より前に「再生」を押しても、黙って無視される**（画面には
> 何も出ない）。表示が変わるまで待つこと。

> **⚠ 押した直後、ロボットはまずその場で旋回する。** 記録した開始の向きに機体を
> 合わせてから走り出す仕様（`rotate_to_start_yaw`）。**故障ではない。**
> 始点マークに置いたときの向きがずれているほど、この旋回は大きくなる。

> **再生速度は右列の「再生速度」（低速 / 中速 / 高速）で選ぶ。走行中に変えてもよい**
> （次の瞬間から効く）。既定は中速（約 0.33 m/s）。速いほど経路を外れやすくなるので、
> 初回は低速〜中速で確かめる。実際の速度は障害物・在席確認の状況で自動的にさらに
> 絞られることがある。

走行中:

- **人はロボットから離れず、いつでも止められる位置にいること**
- 止めるときは **「停止」**。物理の非常停止ボタンは常に有効
- **右列の手動介入スティックに触れると、再生は一時停止して手動操作が優先される**
  （速度指令の優先度が再生より高い）。とっさに避けさせたいときに使える。
  再生を続けるには手を離してから **「再生」** を押し直す
- 前に障害物が出ると自動で減速・停止する。**障害物とみなすには前方に 3 点以上の
  反射が必要**（2026-09-04）。以前は 1 点でも止まったため、何も無いところで止まって
  しばらくして独りでに走り出すことがあった。停止距離では幅 2cm の物でも 5 点以上に
  映るので、実体を見落とすことはない
- 完走すると「一時停止（記録の終端に達しました。終了を押してください）」と出る

**画面を触らなくても止まらない**（2026-09-04 以降）。以前はタブレットを 30 秒
触らないと在席が確認できないとみなされ、黙って止まっていた（画面をスクロールすると
復帰するのはそのため）。いまは**アプリが前面にあって接続が生きていれば在席**とみなす。
画面を消す・別アプリに切り替える・回線が切れた場合は従来どおり止まる。

**途中で止まったときは「再生」で続きから走れる。**フォルト（ESP32 の一時途切れ
など）・スティック介入・「停止」で止まった場合、画面には
**「一時停止中。「再生」を押すと止まったところから続きを走ります。」**と出る。
最初からやり直す必要は無い（2026-09-04 以前は、この場合も「記録の終端に達しました。
終了を押してください」と誤って案内していた）。

> 「記録の終端に達しました」が出るのは**本当に走り切ったときだけ**。
> この 2 つの文言で「もう終わり」か「途中で止まっただけ」かを見分ける。

### 3-5. 「非常停止中」の窓が出たら


| 出方                 | 意味                      | 対処                                                       |
| ---------------------- | --------------------------- | ------------------------------------------------------------ |
| 物理ボタンを押した   | 正常                      | ボタンを戻してから、**画面下端の「非常停止を解除」**を押す |
| 起動直後に勝手に出た | 起動時の CPU 負荷（既知） | 下記の「原因が消えたあと」に従う。走行への影響はない        |
| 走行中に勝手に出た   | 安全監視が働いた          | 下記に従い、**何が出たかログを記録して報告する**             |

**原因が消えたあと、窓のボタンで戻り先を選ぶ。**

| ボタン                 | 戻り先                                              |
| ------------------------ | ----------------------------------------------------- |
| **元のモードに戻る**   | 止まる直前のモードの**一時停止**。教示・再生の準備をやり直さずに済む |
| **メインメニューへ**   | 待機。最初からやり直す                              |
| **確認**               | 待機（戻れる状態でないときはこれだけが出る）        |

> **「元のモードに戻る」を押しても機体は動き出さない。**戻り先は停止した状態なので、
> 走らせるには改めて「再生」（または該当の操作）を押す。
>
> 原因が消えていない間はボタンが出ない。物理ボタンを押したままでも出ない。
> **一瞬だけ出て自然に消えるフォルトでは、そもそも窓が出なくなった**（2026-09-04）。
> 監視が単発の誤検知を無視するようになったため。

## 4. SLAM と地図

### 4-1. SLAM は何をしているか

LiDAR で周囲の壁を見て地図を作り、その地図の中で自分の位置を割り出している。
**車輪の回転数だけだと、滑りや誤差が積み上がって 100m 走ると数 m ずれる。**
SLAM はそれを壁の見え方で常に補正する。

`enable_route_slam:=true` を付けないと SLAM は起動せず、車輪の回転数だけの推測になる。
10m 程度なら走るが長距離では合わない。

### 4-2. 1 周して戻ったとき、地図の継ぎ目（壁の二重）は正常

**一周して元の場所に戻る経路を教示・再生するとき、タブレットの地図で開始地点付近の
壁が二重に（ずれて）描かれていることがある。これは正常であり、操作をやり直す必要は
無い。**

SLAM の「ループ閉じ込み」を**意図的に切っている**ためです。ループ閉じ込みは一周して
戻ったときに地図を過去に遡って作り直して壁を一本に繋ぐ代わりに、**それまでに記録した
経路を補正前のフレームのまま残す**ため、経路と地図がずれて壁に埋まります（2026-09-03
の実機で、1 周 185 m の教示の最中に記録点が 0.1 秒の間に 4.09 m 跳び、経路が壁に
埋まりました）。経路と地図を同じフレームに保つことを優先するため、ループを閉じずに
継ぎ目のままにしています。

| 見た目 | 判定 | 次にやること |
| --- | --- | --- |
| 開始地点の壁が**1本**に重なっている | ループが（偶発的に）繋がった | そのまま再生してよい |
| 開始地点の壁が**二重・ずれて**描かれている | **正常**（ループ閉じ込み OFF） | そのまま再生してよい |

> トレードオフとして、絶対的な終点の誤差にはドリフトぶん（実測 185 m で約 4 m ≒ 2%）
> が残ります。再生は地図と同じフレームの経路をなぞるため、**終点の誤差は数 m 程度
> 見込んで**始点マークを置く・機械と人の間に十分な余裕をとってください。

### 4-3. なぜ再生前に地図を読み直すのか

1 周 185 m の教示を終えたあと、ロボットは**物理的に始点マークの上に居ながら、
地図座標では約 4 m 手前に居ると思っている**ことが実測で分かっている
（ループ閉じ込みが次の再生までに 4.09 m 補正していた差。§4-2 で切った）。

**手で機体を動かしても「自分がどこに居ると思っているか」は変わらない。** 車輪の
累積誤差ぶん、自己位置が地図上の経路始点とズレたまま再生を始めると、経路を外れて
走る。そこで**教示時に地図を保存し、再生時に読み直して自己位置を経路の
始点に合わせる**（§4-4）。

また**教示中と再生中では SLAM の挙動が異なる**:
- **教示中（地図作成）**: 走りながら新しいスキャンを地図に描き足し、地図を広げていく。
- **再生中（自己位置推定 / 地図凍結）**: **再生中は地図作成が止まり、地図は変わらない。ロボットは出来上がった地図の上で自分の居場所だけを推定する**。
  再生中も地図作成が動いていると、自己位置の僅かなズレで新しい壁が描き足されて地図が汚れ、
  推定がさらにズレて発散してしまう（実機で確認された欠陥を防止）。

読み直しで地図が凍結され、自己位置が経路の始点（初期姿勢）に一致するため、教示で作った地図の上を正確に再生できる。

### 4-4. 地図の保存と読み直し（「保存」と経路選択で自動）

- **教示**: 「保存」を押すと、経路（`.json`）と**一緒に地図（`.posegraph` / `.data`）も
  保存され、地図が凍結される**（`th_ws/data/routes/<経路名>.posegraph` など）。地図の書き出しが入るため
  **保存に数秒かかる**（§3-3）。
- **再生**: 経路を選ぶと、教示時に保存した地図が**自動で読み直され、地図を凍結したまま自己位置推定モードに切り替わる**（§4-3）。その際、自己位置が経路の始点に合わせられる。だから**機体を始点マークに置いてから経路を選ぶ**（§3-4）。再生中は地図作成に戻らず、凍結された地図の上で自己位置推定だけを継続する。
  - **経路を選ぶと、SLAM（`slam_toolbox`）が一度自動で再起動される。** そのため
    「この経路で進む」を押してから**「推定できました」に変わるまで数秒〜数十秒
    かかる**（地図が大きいほど長い。校舎 1 周級で 40 秒前後）。画面が
    「初期姿勢を推定しています…」のまま数十秒動かなくても、この間は正常。
    1 分近く経っても進まないときだけ §4-6。

操作者が手でコマンドを叩く必要は無い。

### 4-5. 地図をリセットする（やり直したいとき）

**通常の教示→再生の流れではこのリセットは使わない**（§4-4 のとおり、地図は
「保存」と経路選択で自動保存・自動読み直しされる）。**教示と再生を別々の起動セッションで
やっても問題ない**（経路選択のたびにその経路の地図を読み直すため。2026-09-04 以降）。
ここを使うのは「**地図が壊れたので作り直したい**」といった、**地図を捨てて最初から
やり直したいときだけ**。

**ロボットを始点マークの上に置き、停止している状態で**、スクリプトを 1 回実行する。

```bash
docker exec -it th_robot bash /root/th_ws/scripts/reset_map.sh
```

> **⚠ 走行中に実行しないこと。** スクリプトは走行中でも実行できてしまうが、
> 地図を捨てた瞬間にロボットは自分の位置を見失う。必ず止めてから。

最後に **`=== 完了。教示再生の画面に戻って再生してよい ===`** と出れば成功。
`NG` が出たら**そのまま再生しないこと**（§7 へ）。

<details>
<summary>スクリプトが中で何をしているか（手で叩きたいとき）</summary>

```bash
# ① 地図を捨てて SLAM を作り直す（数秒かかる）
ros2 service call /slam_control/discard_map std_srvs/srv/Trigger

# ② slam_toolbox が戻るのを待つ

# ③ 地図作成を再開する ← 忘れると再生が壊れる
ros2 service call /slam_control/set_mapping std_srvs/srv/SetBool "{data: true}"

# ④ 確認
ros2 topic hz /map                     # 数秒に 1 回出ていること
ros2 run tf2_ros tf2_echo map odom     # 数値が出ていること
```

**③ を忘れないこと。** ① だけだと地図が空のまま止まった状態になり、
自己位置の補正がまったく効かない（車輪の回転数だけの推測に戻る）。
スクリプトを使うのはこの叩き忘れを防ぐため。

</details>

> **なぜ「手で始点に戻す」だけでは駄目なのか**: ロボットを物理的に動かしても
> 「自分がどこに居ると思っているか」は変わらない。地図を捨てると、今いる場所を
> 新しい地図の原点として認識し直すため、記録した経路の1点目（＝原点）と一致する。
>
> ただしこの方法では再生中に参照できる地図が無い（走りながら作り直す）ので、
> 経路の遠い側では誤差が大きくなる。このリセットは「地図が壊れた」ときの復旧手段
> と考える（別セッションで教示した経路の再生には**不要**。§4-6）。

### 4-6. 制約（現状）

- **別の起動セッションで教示した経路も再生できる**（2026-09-04 以降）。経路選択の
  たびに、その経路と一緒に保存した地図（`.posegraph`）を読み直すため。ただし
  **機体は始点マークに置いてから経路を選ぶ**こと（§3-4）。
  - 保存地図が無い経路（教示の「保存」が途中で失敗した、`.posegraph` ファイルが
    消えた 等）は再生できない。経路を選ぶと**「初期姿勢を推定しています…」のまま
    先に進まない**。1 分ほどで画面に「初期姿勢を推定できません。機体を始点マークに
    置き直すか、教示からやり直してください」と出るので、「終了」で抜けて教示から
    やり直す。
- **毎回ほぼ同じ物理位置・向きから始める。** 始点マークからずれた分だけ経路全体がずれる

## 5. 速度と記録の仕様


| 項目                     | 値                                                 | 備考                                              |
| -------------------------- | ---------------------------------------------------- | --------------------------------------------------- |
| 手動走行 低速             | **0.15 m/s**                                       | 教示の精度を優先するならこれ                      |
| 手動走行 中速             | **0.30 m/s**                                       |                                                   |
| 手動走行 高速             | **0.55 m/s**                                       | 駆動系が指令に追従できる上限（約 0.71 m/s）の手前 |
| 手動走行 その場旋回の上限 | **1.2 rad/s（≈69°/s）**                           | 速度プリセットの影響を受けない（2026-09-04 / WS-9T で 0.6→1.2） |
| 再生速度（画面で切替）    | 低速 ≈0.15 / 中速 ≈0.33 / 高速 ≈0.45 m/s          | S-14 右列の「再生速度」。**走行中も変更可**。既定は中速 |
| 記録の間隔               | **10cm 進むごと**または**約 11 度回るごと**に 1 点 | 速いほど点が粗くなる                              |
| ジョグの加速度制限       | 前後 1.0 m/s² / 旋回 4.0 rad/s²                  | スティックを一気に倒しても跳ねない                |

**教示は低速か中速で行うこと。** 速度を上げると記録の点が粗くなり、
再生時に経路を外れやすくなる。

## 6. 保存されるもの・その場所


| もの                               | 場所（PC 側）                     |
| ------------------------------------ | ----------------------------------- |
| 教示した経路                       | `th_ws/data/routes/<経路名>.json` |
| 教示の途中経過（記録中 10 秒ごと） | `th_ws/data/routes/<経路名>.wip`  |
| 同じ名前で保存し直したときの旧版   | `th_ws/data/routes/<経路名>.prev` |
| 生成されたパラメータ               | `th_ws/data/generated/`           |

> コンテナ内では `/root/th_data/` として見える（同じ場所）。
> 記録中は **10 秒ごとに途中経過が `<経路名>.wip` へ自動保存**される（`autosave_period_ms`
> で調整可。0 にすると無効）。**同じ名前で保存し直すと旧版は `<経路名>.prev` に残る**（最新と
> 1 つ前の 2 つだけ）。`.wip` / `.prev` は経路一覧（教示再生の選択肢）には出ない。

## 7. 困ったとき


| 症状                                         | 対処                                                                               |
| ---------------------------------------------- | ------------------------------------------------------------------------------------ |
| 「非常停止中」の窓が出た                     | **「確認」**を押す。物理ボタンを押していたなら先に戻す                             |
| タブレットが「確認中」のまま                 | ブラウザ再読込 → 駄目なら`npm run dev` を再起動                                   |
| 地図が伸びない・出ない                       | `enable_route_slam:=true` の付け忘れ。起動からやり直す                             |
| `/scan_filtered` が無音                      | LiDAR かネットワーク →[network.md](network.md)                                    |
| `ESP32_DISCONNECTED` が消えない              | PC が**内蔵 Wi-Fi** でロボット AP に繋がっているか確認 → [network.md](network.md) |
| 再生を押しても動かない                       | 「推定できました」の表示になっているか。なっていなければ待つ                       |
| 経路の表示がガタつく・地図が重い             | ブラウザを再読込する                                                               |
| 走行中に理由不明で止まる                     | 画面下に**赤い帯**で理由が出る（在席未確認／障害物／死角未校正）。**走行中だけ**出る |
| 「タブレットの在席が確認できない」と出た     | アプリを前面に戻す。別タブ・別アプリになっているか接続が切れている。**画面を見ているだけなら止まらない**（2026-09-04 以降） |
| コマンドがトピックを見つけない・部分的に不通 | `docker restart th_robot` してから §1-2 をやり直す                                |
| 経路を選んでも「推定できました」にならない   | まず**待つ**。経路選択で SLAM が一度再起動されるので、切り替わりに数秒〜数十秒（長距離ほど長い。校舎 1 周級で ~45 秒）かかる（§4-4）。<br>1 分近く経っても進まないなら**地図の読み直しに失敗している**（§4-6）。教示の「保存」が完了しておらず地図ファイル（`th_ws/data/routes/<経路名>.posegraph`）が無い可能性。「終了」で抜けて**教示からやり直す**（別の起動セッションで教示した経路は再生できる） |
| 再生中に地図が汚れていく／経路を選ぶたび地図の形が変わる | 起こらないはず（2026-09-04 修正済み。地図は凍結され、経路選択のたび SLAM を作り直してから 1 回だけ読み直す）。起きたら報告する |

## 8. やってはいけないこと

- **物理の非常停止ボタンを外す・無効にする。** どんな場合も生かしておく
- **人が居る方向へロボットを向けたまま再生を始める**
- **教示と再生で開始位置・向きを変える**（§4-6）
- **`ros2 launch` のターミナルを閉じる**（ロボットが止まる）
- **ノードを `kill -9` で止める。** 通信の仕組みが壊れ、コンテナ再起動が必要になる。
  止めるときは `Ctrl-C`
