## 1. 起動する

起動は **`./start.sh` 1 本**で行う。電源 → PC がロボット AP に繋がっている
→ `cd th_ws && ./start.sh` → タブレットで表示された URL を開く。

### 1-1. 電源とネットワーク

ロボット（ESP32・ラズパイに USB 接続）とラズパイの電源を入れ、PC をロボット AP に繋ぐ。
（2026-09-05 以降、ESP32 は無線を使わない。ラズパイへ USB-UART で直結し、ラズパイ上の
`pi_serial_relay` が代わりに PC と通信する）

**屋内では、PC にロボット専用の USB Wi-Fi ドングル（AIC8800）を挿す。**挿せば数秒で 5GHz の
`th-rpi-5g` に自動でつながる。PC 内蔵の Wi-Fi はインターネット用のまま使ってよい。

```bash
nmcli -t -f DEVICE,CONNECTION dev | grep wlx6c1ff789d5d4   # th-rpi-5g-aic ならつながっている
nmcli connection up th-rpi-5g-aic                         # つながっていなければ
```

> ラズパイを再起動した直後は 5GHz の AP が上がるまで 1 分ほどかかる（上がれば自動でつながる）。
> ドングルが無いときは内蔵 Wi-Fi で `nmcli connection up th-rpi-5g-wlo1`（インターネットは切れる）。
> 2.4GHz の `th-rpi-ap` は UnitV2（カメラ）と昇降機の ESP32 用。
> **屋外では 5GHz を使えない（電波法）。**屋外に出る前に `bash th_ws/scripts/ap_band_switch.sh outdoor`
> （内蔵 Wi-Fi で 2.4GHz につなぐ。PC のインターネットは切れる）、屋内に戻ったら `indoor`
> （[network.md](network.md)「屋外で使うとき」）。屋外で内蔵 Wi-Fi を使っている間にラズパイを再起動したら、
> PC が学校などの別の Wi-Fi に移っていないか確かめる。

### 1-2. 起動（`start.sh` 1 本）

```bash
cd ~/code/MIRS-Local/TM/th-system/th_ws
./start.sh
```

**このターミナルは開いたままにする。** 閉じるとロボットが止まる。
`start.sh` が順にやること: ラズパイへの疎通確認（`ping`。`rpi-serial-relay` は
`ssh` で確認し、失敗は警告のみ）→ コンテナ `th_robot` の起動 →
他で起動していないかの確認（あれば確認のうえ止めて引き継ぐ） → bringup の起動と見張り → WebUI の配信。
終わったらタブレット用と PC 用の URL が表示される。

- タブレット: **`http://192.168.5.50:5173`**（`.50` はこの PC のロボット回線 IP。
  別の PC で制御する場合はその PC のアドレスになる）
- PC で見るだけ: `http://localhost:5173`

rosbridge（9090）は bringup が自動で起動する。

#### よく使う引数と止め方

```bash
./start.sh stage:=1          # 教示再生だけの軽い起動（既定は stage:=4）
./start.sh --build           # ソース更新直後だけ。colcon と WebUI のビルドを行う（数分かかる）
./start.sh --dry-run         # 何も実行せず、何をするかだけ表示する
```

- `stage:=4` などの `key:=value` は bringup にそのまま渡す。
  `start.sh` の既定（`lidar_source:=network use_stub:=false enable_route_slam:=true`）
  と同じキーを渡すと、渡した方が優先される（例: `enable_route_slam:=false`）。
- **止めるときは Ctrl-C。** launch に INT を送って子ノードごと止め、WebUI の
  配信も止めて終わる。

#### `start.sh` の表示が出たら

| 表示 | 意味 | 次にすること |
| --- | --- | --- |
| `制御系を再起動しています（n 回目）` | bringup が落ちたので自動で立て直している | **待つ。** 上限（既定 3 回。初回を含む）に達する前に直ればそのまま使える |
| `bringup が 3 回起動しても直らなかった` | 立て直しをやめた | 機体の電源再投入・AP の確認・ケーブルの確認をしてから、もう一度 `./start.sh` |
| `他で起動している:` ＋ `止めて、こちらで起動しますか？ [y/N]` | 別の `start.sh`、または手作業の bringup が動いている | **誰かが実機作業中の可能性がある。**その人に確認してから `y`。`y` なら相手に停止を送り、止まったのを見届けてこちらで起動する（強制終了はしない）。`y` 以外・止まらなかったときは何も起動せず終わる。確認なしで引き継ぐなら `./start.sh --yes` |
| `別の PC の制御系が動いています（ノード名: ...）。そちらを止めてから起動してください` | 別の PC で制御系（`obstacle_limiter` 等）が動いている状態で bringup を起動しようとした。2 台が同時に動くと速度指令や非常停止が混ざる（Spec-safety §6.4「制御系は同時に 1 つ」）。**2 台目側の bringup は起動しない** | **制御している PC 側を Ctrl-C で止めてから、こちらで起動し直す。**制御を切り替える場合は先に切り替え元を止めること（切り替え先を先に起てることはできない） |
| `bringup (PID ...) がまだ止まっていない` | Ctrl-C で INT を送ったが、子ノードの後始末が上限（30 秒）以内に終わらなかった | **そのまま終わっている（強制終了はしていない）。** 止まってから打ち直すこと。止まらないときは作業者に確認する |
| `web_ui/dist/ が無い` | WebUI の本番ビルドが無い | `./start.sh --build` か `./setup.sh` を実行してから起動する |
| `ポート 5173 が他に取られている` ＋ 持ち主の PID | WebUI 等のポートを別のプロセスが使っている | 持ち主を確かめて `y`（TERM で止めて空ける。強制終了はしない）。`--yes` で確認を省略。持ち主を特定できない・空かないときは終わるので、手で止めてから打ち直す |
| `WebUI の配信が起動しなかった` | ポート 5173 が埋まっている等（ログ `th_ws/log/start-webui.log` の末尾も出る） | ポートを使っているものを止めるか、`WEBUI_PORT` を変えて起動する |
| `ラズパイに届かない` | PC がロボット AP に繋がっていない | §1-1 に戻る。駄目なら [network.md](network.md)「復旧手順」 |

起動オプション（`start.sh` の引数で渡す。§1-4 の手作業でも同じ）:

| 引数                          | 既定    | 意味                                           |
| ------------------------------- | --------- | ------------------------------------------------ |
| `lidar_source:=network`       | `local` | LiDAR をラズパイから受け取る。**実機では必須** |
| `use_stub:=false`             | `false` | 人物トラッカーを偽物にしない                   |
| **`enable_route_slam:=true`** | `false` | **SLAM を起動する。教示・再生では必須**（§4） |
| `imu_enabled:=false`          | `true`  | ジャイロ（vyaw）の自己位置融合を**切る**。既定は融合あり（コーナーの yaw ドリフト対策。WS-9V）。ジャイロ単位未修正ファームの個体でだけ `false` |
| `stage:=N`                    | `4`（`start.sh`。bringup 単体は `1`） | 起動するノードの範囲。**`start.sh` の既定は `4`**（教示再生も試験場内デモもこれで動く）。教示再生だけの軽い起動は `1`。試験場内デモ（PREP／盤前移動／呼び寄せ）は Nav2＝stage3・人物トラッカー＝stage4 が要る |
| `perception_start_delay:=45.0` | `45.0`   | `stage:=4` で DR-SPAAM の起動を遅らせる秒数。Nav2 のライフサイクル起動（約 12 秒）と重ねると一過性の CPU ストールが出る（N-27）うえ、重なった起動では Nav2 の local costmap が止まって配電盤へ動けなくなった（2026-10-10 実機。`stage:=3` では起きない）ため。値を上げても害はない |

### 1-3. WebUI について

WebUI の配信（本番ビルドの `vite preview`。ポート 5173）は `start.sh` が
自動で立ち上げ、Ctrl-C で一緒に止める。`npm run dev` で別途立てる必要は無い。

### 1-4. `start.sh` を使わずに起動する（不具合の切り分け用）

`start.sh` 自体が疑わしいときだけ、下の手作業で切り分ける。ふだんは §1-2 を使うこと。

```bash
ping -c3 192.168.5.1                   # ラズパイ（AP 兼 LiDAR 兼 ESP32中継）
ssh mirs2602@192.168.5.1 'systemctl is-active rpi-serial-relay'   # ESP32中継が動いているか
ip -br addr | grep 192.168.5.50       # ロボット回線（屋内は wlx6c1ff789d5d4）が 1 枚だけ持っていること
nmcli -f SSID,ACTIVE dev wifi list ifname wlo1 | grep -E 'はい|yes'   # th-rpi-5g につながっていること
```

ping が返らない、または `rpi-serial-relay` が `active` でないと先へ進めない
→ [network.md](network.md)「復旧手順」

```bash
cd ~/code/MIRS-Local/TM/th-system/th_ws
docker start th_robot
docker exec -it th_robot bash
```

コンテナの中で:

```bash
cd /root/th_ws
colcon build --symlink-install      # ソースを更新した直後だけ。数分かかる
source install/setup.bash

ros2 launch th_bringup bringup.launch.py \
  lidar_source:=network use_stub:=false enable_route_slam:=true
```

**このターミナルは開いたままにする。** 閉じるとロボットが止まる。

> `ros2 launch` を二重に実行すると、新しい起動が自動で前回の分を止めてから
> 立ち上がる（2026-09-05。`[prelaunch_guard]` の表示はこの後始末の印であり、
> 異常ではない）。**`start.sh` 経由では、既に動いていれば内容を示して確認し、
> `y` のときだけ止めて引き継ぐ**（§1-2 の表）。実機作業中の人の起動を黙って止めないため。

## 2. 起動後の健全性確認

別のターミナルをもう1枚開く。

```bash
docker exec -it th_robot bash
source /root/th_ws/install/setup.bash
```


| # | コマンド                               | 期待する結果                | 駄目なとき                                 |
| --- | ---------------------------------------- | ----------------------------- | -------------------------------------------- |
| 1 | `ros2 topic hz /scan_filtered`         | 約 10 Hz                    | [network.md](network.md)                   |
| 2 | `ros2 topic hz /map`                   | 0.5 Hz 程度                 | `enable_route_slam:=true` を付け忘れ       |
| 3 | `ros2 run tf2_ros tf2_echo map odom`   | 数値が出る                  | 同上。**これが SLAM が効いている証拠**     |
| 4 | `ros2 topic hz /route/map_view`        | 数秒に 1 回（0.25〜0.5 Hz） | タブレットに地図を出すための間引き済み地図 |
| 5 | `ros2 topic echo /system/state --once` | `mode: IDLE`                | 起動直後は`INIT`。1〜2分待つ               |

タブレット側は **S-00「接続確認」画面**で、機器のつながりの図（PC・Wi-Fi AP・タブレット・LiDAR・ESP32・カメラ）の必須の機器がすべて ✓ になること。
**右列の「メインメニューへ」**は必須の機器が揃うまで押せない（押すと理由が出る）。
**機器ごとに独立に判定される**（✓ 疎通 ／ × 未接続。各機器に「応答 12 ms」「0.1 秒ごと」「途絶 12 秒」などの実データ）。
**つながらない機器から先の線は灰の点線**になり、どこで切れているかを位置で読める（Wi-Fi AP は単一障害点）。だめな機器だけ、図の下に対処が 1 行（例「LiDAR の電源とケーブルを確かめる」）と確かめた時刻が出る。必須でないカメラがだめでも図の線は灰にならない。
開発モードで接続確認（`link`）を外していても本当の状態を出し、「開発モードで無視中」と添える。
**「ESP32（速度指令の折り返し）」は ESP32 自身が「速度指令を受け取れている」と返したときだけ疎通になる**（2026-10-04 から）。**2026-10-04 より前のファームはこれを返さないので、ESP32 を書き込み直すまで S-00 から先へ進めない**（行に「ファームの書き込みが必要」と出る。書き込み手順は `docs/esp32.md`。急ぐときは開発モードで `link` を外す）。
メインメニュー（S-01）の「ネットワーク接続確認」にも、繋がっていない機器の名前が出る（「詳細を見る」で S-00 の詳細を開く）。
**物理の非常停止ボタンが押されたまま起動したとき**は、S-00 に
**「起動時に非常停止ボタンが押されたままです。戻してください」**と出て、運用には入れない
（ボタンを戻すと帯が消え、自動で運用に進める）。帯は状態から出すので、画面を開き直した
後・制御系の再起動の後でも出る。押している間は接続確認の時間切れで制御系を再起動せず、ボタンを戻してから接続確認を続ける。閉じるボタンで閉じても、ボタンを一度離して押し直すと出し直す。

S-00 は、項目別の状態が届いているのに必須機器が揃わないとき
図の機器に×を出し、「メインメニューへ」が押せない理由に「LiDAR がつながるまで進めません」などと出す（届いていない間は札が「確認中」のまま）。
bringup が落ちて自動で立て直している間は
ヘッダの札に**「再起動中　n 回目」**と出す（`start.sh` が数えた起動回数。
運用に入れるようになったら消える）。接続確認の時間切れは **起動から 30 秒**
（`link_wait_timeout_ms`。2026-11-19 に 10 秒から延ばした。bringup の起動直後は相手探しの通信が
ラズパイに殺到して LiDAR がつながるまで時間がかかることがあり、10 秒で立て直すと殺到を繰り返して
いつまでもつながらなかった。`docs/network.md`「`/scan` がコンテナに届かない」の 6.）。時間切れになったときの制御系の
再起動は **`start.sh` で起動したときだけ**行う（`ros2 launch` を直接叩いたときは
立て直す者がいないので再起動しない）。再起動の上限は `STARTSH_RESTART_MAX`。
Wi-Fi AP とタブレットの行は、この画面が制御系に繋がっているかで ✓／× を出す
（AP を直接測る手段は無い）。
始業点検の自動判定の項目別の結果は日本語で出す（正常／要確認／異常）。

S-00 の右列には**始業点検の自動判定**の印も出る（起動のたびに自動で判定する
簡易版。非常停止ボタンの今の状態・IMU・LiDAR の 3 項目。モーター確認は自動では
行わない）。自動判定が NG でも**「メインメニューへ」は押せる**
（警告のみで運用は止めない）。メインメニュー（S-01）の「ネットワーク接続確認」
にも同じ警告が出る（「詳細を見る」で S-00 の詳細へ）。

起動直後の `[FAULT]` は 1〜2 分で `[FAULT CLEARED]` になるのが正常。

### `stage:=4`（試験場内デモ）で起動したとき — 非常停止画面が出たら「解除」

`stage:=4` は Nav2 と人物トラッカー（DR-SPAAM）を同時に立てるため、起動 15〜60 秒の間に
PC が一過性に重くなり、`LIMITER_DEAD` / `STATE_INCONSISTENT` が数十 ms だけ発火して
**非常停止（ESTOP）に入ることがある**（N-27。フォルトはすぐ自己解除される）。
**人検出が既定 OFF になった（DR-SPAAM は起動直後 configure のみで推論しない）ため、
この起動時の重さは以前より軽い可能性があるが未検証。** 症状が出たら下記の対処は変わらない。

- **対処**: 起動が落ち着いてから（S-00 で全機器「疎通」になってから）、
  非常停止画面の **「解除」** を 1 回押す。フォルトは既に消えているので `IDLE` に戻る。
- 走行を始める前の 1 手間であり、走行中には起きない。物理の非常停止ボタンと
  ESP32 ウォッチドッグ（600ms）は一切影響を受けていない。
- 根本対策（Nav2 のライフサイクル起動を全ノード安定後にずらす）は別途。

## 3. 画面と操作

画面はモードに追従して自動で切り替わる。**画面を直接選ぶ操作は無い**（メインメニューで選んだモードの画面が開く）。
**端末を開き直すと、機体がいまいるモードの画面が開く**（2026-11-12 以降）。
機体が `INIT` 以外なら接続確認（S-00）には戻らない。接続状態は S-01 の
「ネットワーク接続確認」で要約を見て、「詳細を見る」で S-00 の詳細を開く。

```
S-00 接続確認 ──(必須の機器が疎通)──> S-01 メインメニュー
   試験場 ▸ ……… 試験準備 ／ 試験（当日）
   走行 ▸ ……… 追従走行 ／ 手動走行 ／ 教示再生 ／ 教示（追従）／ 教示（手動）
   点検と校正 ▸ … 始業点検（→ 故障診断）／ 校正
   自律測定 ／ 設定
   制御系を停止する（運用の終了）
```

**ライン誘導と電子リードは廃止した**（2026-11-27）。メニューにも画面にも無い。
**待機場所の宣言も廃止した**（試験（当日）。§3-4b）。

**走行を止める回復フォルトが残っている間は、メインメニューからのモード選択と、試験画面（S-21）での行き先選択が拒否される**（人物追跡の途絶だけの場合は対象外）。窓に表示される残存フォルトを確認し、原因が解消してから選び直す。手押し（物理ボタン）や非常停止から待機に戻れた場合も、この入口の制限は同じ。

### 3-1. 画面の見方（型・ボタンの場所・色・押せない理由・ヘルプ）

**全画面が 3 つの型のどれかで、型が同じ画面は同じ場所に同じ役のボタンがある。タブは無い。**

| 型 | 画面 | 左上 | 主表示 | 操作 |
| --- | --- | --- | --- | --- |
| **走らせる** | 追従走行・手動走行・教示（追従）・教示（手動）・教示再生・試験準備・試験（当日）・自律測定 | **「終了」**（と、画面全体に効く切り替え。人検出・自動ブレーキ） | 左に大きく（地図・レーダー・計器）。機体は緑の三角と機体の大きさの四角 | 右列に上から **① どこへ・あとどれだけ（記録の量）→ ② 停止│走行 → ③ その画面の操作 → ④ 手動（スティック、またはボタン）** |
| **手順を進める** | 始業点検・故障診断・校正 | **「戻る」** | 左に項目の一覧（結果の印つき）、右に選んだ項目の手順 | 手順の下端に **左「やめる」・右＝進むボタン**（位置は固定） |
| **見る・変える** | 接続確認・設定 | 「戻る」（接続確認は無し） | 左に区分、右に中身 | 中身の下端の右に「保存」（いつ効くかの印つき） |

- **「終了」はどの画面でも左上**（右列には無い）。そのモードを抜けてメインメニューへ戻る。
  未保存の記録・地図があれば、確認の窓（保存する／破棄する／やめる。破棄は 2 回押し）が出る。
- **同じ役のボタンは同じ場所**: 停止│走行は右列の ②、保存・終了の語は全画面で同じ意味。**状態によってボタンが入れ替わることは無い**
  （使えないボタンは場所を保ったまま押せない見た目で出る）。
- **入口の選択**（経路を選ぶ・地図を開く・前回の続きか新しく始めるか）は、**主表示の中央のカード**に出る。右列のボタンの位置は変わらない。
- **ヘルプ表示**: ボタンの説明は、求めたときだけ出る。**PC ではボタンにカーソルを重ねてしばらく待つ**（約 0.7 秒）、
  **タブレットでは長押し**（約 0.6 秒。指を離してもボタンは押されない）。閉じるボタンか枠の外を押して閉じる。
  **止める操作（停止・スティック・非常停止・始業点検のモーターの矢印）には出ない**（止める操作を遅らせないため）。**地図にも出ない**（地図の見方は地図の端の「凡例」）。
  設定の「画面」で出す／出さないを端末ごとに切り替えられる（初めは出す）。
- **ボタンの色**（JIS B 9960-1 に合わせた 1 色 1 意味）:

| 見た目 | 意味 |
| --- | --- |
| **赤に黄の地** | **非常停止**だけ（ヘッダの非常停止ボタン・札「非常停止中」） |
| **黒** | **止める操作**（押せるときの「停止する」） |
| **緑** | **機体が動く**（走行する・再開する・再生する・行き先にする・「走らせる」・移動中の札・自律走行中の枠）。**押すと機体が動くボタンだけ**を塗る |
| **薄い緑** | 少しだけ動く（「向く」） |
| **黄** | 注意・異常・中断（「中断」・「自動ブレーキなし」・近い障害物・経路を塞いでいる所・押せない理由の吹き出しの縁） |
| 白・灰・黒 | 中立（入切の切り替え、「一時停止中」「記録中」の札、押しても機体が動かないボタン＝太い縁で強調） |
| 反転 | 選んでいるもの（選んだ人・ピン・区分） |
| 青 | ヘッダの帯だけ（意味は無い） |

  **結果の印は形で分ける**: ✓＝正常（緑）／!＝要確認（黄の縁）／×＝だめ（黄の地）／—＝まだ（灰）。**結果に赤は使わない**。
- **停止│走行のトグル**（`[ 停止する │ 走行する ]`）: **いま押せる側だけが塗られる**（止める＝黒、走る・再開する・再生する＝緑）。
  押せない側は塗りが無い。待機中に塗りが無いのは正常。**次に押す「走行する」「再開する」「再生する」はゆっくり明滅する。**
  いまの状態を言うのはヘッダの札だけ（トグルは言わない）。
- **押せないボタン**は、塗りを外して枠と語だけ残した見た目で出る。**押すと、そのボタンのすぐ上（入らなければ下）に
  「押せません　〈理由〉」が出る**（例: 「押せません　一時停止中は選べません」）。故障ではなく
  「まだその操作をしてよい状態ではない」ので、理由を読んで直す。（旧版の「何も出ずに無視される」は無くなった。）
- **自律走行中は、ヘッダの下の画面の縁が緑の枠で点滅する**（追従・教示再生・移動中・待機場所へ戻る途中など、機体が自分で走る間。一時停止中・手動では出ない）。
- **ヘッダ**（常に最上部。窓に隠れない）: 画面名・**状態の札**（一時停止中・移動中・記録中・非常停止中など。モード名は出さず、出す状態が無いときは札が無い）・
  試験場内の画面では「速度制限」・異常のときだけ**異常の表示**（原因と対処。正常のときは何も出ない）・**自動ブレーキなし**（切れている間だけ黄で点滅）・非常停止ボタン。
  **開発モード中はヘッダの帯の色が変わり、「開発モード」と出る。**
- 物理非常停止を押して機体を手で押して動かしている間（手押し）に、暴走と判定されて非常停止に落ちることはない（離したあとは通常どおり判定する）。

### 3-2. 手動走行

メインメニュー →「走行 ▸」→「手動走行」。**右列のスティックで動かす**（スティックに触れた瞬間に走行が始まる。「走行」ボタンは無い）。
左上は「終了」と**自動ブレーキの切り替え**。右列には「停止する」（走行中は一時停止）と、速度のスライダ・スティック・**速度の段（低速／中速／高速）**が常に出る。
低速・中速・高速は手動ジョグの上限（前進 0.55 m/s）に対する割合
（27% / 55% / 100%）。スライダ（0〜100%）も同じ割合で、100% で上限いっぱいになる（§5）。

主表示は左に**計器**、右に**機体のまわりの図**（縦長でも左右に並ぶ）。
- **計器**: 大きな数＝いまの速さ（後退は −）と回転（弧の矢印＋数）。速さの帯（塗り＝実際・太い縦線＝スティックの指令・点線＝速度の上限・
  **黄＝自動ブレーキで削った分**）。その下に直近 5 秒の線（太い＝実際・細い＝指令）。下段に**左右の車輪**（帯が左右の位置で左右を示す。
  帯の下に実速度・目標・モーター出力 %・エンコーダのパルス/秒）。目標と実際が大きく離れると黄の枠が付く。**この画面（実機）ではモーター出力とエンコーダは機体から届かないので「—」と出る**（届くようになるまで）。
- **機体のまわりの図**: LiDAR の点・機体の外形・**減速が始まる距離の輪**・4 本の柱の死角（灰の扇）。近い障害物の点は黄で、その向きに距離（「前方 12 cm」）が出る。
  **進む向きのガイド線**（機体の前＝後退なら後ろに、機体の幅の 2 本の線が予想の進路に沿って 1.5 m 伸び、0.5 m ごとに横線）。その場で回すときは弧の矢印。止まっている間は出ない。
  自動ブレーキが効いている間は黄になる。後方に死角は無い（4 本の柱だけ）。

**スティックやキーを離すと、機体は通常の加減速で減速して止まります。**最高速からは
停止までに約 0.6 m・約 2.2 秒かかることがあります。すぐに止める必要がある場合は非常停止を押してください。PC では <kbd>W</kbd><kbd>A</kbd><kbd>S</kbd><kbd>D</kbd> か矢印キーでも走れる。

> **その場旋回（スティックを真横に倒す）は速度プリセットの影響を受けない。**
> 低速のまま曲がり角でその場旋回してもキビキビ回る（前進しながら曲がる「斜め倒し」は
> プリセットで絞られる）。旋回の上限は 1.0 rad/s（≈57°/s）。

**自動ブレーキ（障害物に近づいたとき自動で減速・停止する働き）**

- **既定は ON**（場外の手動も ON。2026-11-27 から。以前の「場外は OFF」は改めた）。**S-50「速さとブレーキ」で変えた既定は再起動後も維持される**。
  手動走行に入るたびに既定へ戻る（前回の選択は引き継がない）。
- **切り替えは左上の「自動ブレーキ」**。ON の間は**鍵の印の「入」ボタン**（ロック）になっている。
  **外すには 2 回押す**: 1 回目で黄の **「もう一度押すと外す」** に変わる（約 3 秒で元に戻る）。2 回目でロックが外れて **「切│入」** の切り替えが出る。
  **「切」を押すと OFF**（この 2 回押しが「ON → OFF の確認」を兼ねるので、確認の窓は出ない）。
  ロックがかかり直すのは「入」に戻したとき・状態が変わったとき。OFF のあいだ「入」はすぐ押せる（安全側に戻すのに手間をかけない）。
  表示は押した直後ではなく、**機体が受け付けてから**切り替わる。
- **OFF のあいだ**: **ヘッダの下段に「自動ブレーキなし」が黄で点滅**する。障害物に近づいても減速しない。
  ON なら減速が始まる距離まで近づくと、**近づきの警告**が出る（機体のまわりの図の点が黄になり、「前方 ○ cm」と出る）。
  **機体が止まっているときも出る**: 走っているときは進む向き、**止まっているときは周囲すべて（LiDAR の死角を除く）**で
  最も近い障害物を見る。**スティックを離して指令が途絶えたあとも**同じ判定で出し続ける（離しても消えない）。
  距離は**機体の外形（一番近い面）から**測る。**速度は自動では落ちない**ので、警告を見たら自分で止めること。
  機体のスピーカーの警告音は**走っている間だけ**（止まっているときは画面だけ。§3-6b）。
- **OFF でも変わらないもの**: 非常停止、フォルトによる停止、速度上限、後退速度の制限、
  LiDAR や機体からの通信が途絶したときの停止。**機体からの状態が途絶えると ON に戻って止まる。**
- 切り替えられるのは手動走行・教示（手動）、**試験準備（左上に常設）**、手動操作パネル（W-6）を開いている間（下記）。
  追従・再生などの自律走行では**無効にできない**（切り替えは出ない。通信上で拒否されると理由が出る）。
- 画面を閉じる・別アプリに切り替えるなど、機体が「操作している画面がない」と判断している間は ON になる（戻ると選んだ設定に戻る）。
- **手動操作パネル（「手動」ボタンで出る浮きカード。教示再生・試験（当日）・自律測定）にも同じ切り替えがある**（パネルの上段。同じロックと点滅）。
  **試験（当日）で OFF にできるのは、パネルを開いている間だけ**で、開いている間はスティックに触れていなくても切り替えられる
  （開いている間、タブレットが機体へ「開いている」と知らせ続ける）。
  **パネルを閉じる・モードや状態が変わる（スティックに触れ始めて自律走行が一時停止になった変化は除く）・タブレットとの通信が約 1 秒以上途切れる・画面からの知らせが途絶えると、自動で ON に戻る**
  （安全側。戻ったあとにまた OFF にするには、パネルを開いた状態でもう一度ロックを外す）。**試験準備は、スティックを常設しているので、パネルを開かなくてもいつでも OFF にでき**、状態が変わる・画面を移る・画面からの知らせが途絶えると ON に戻る。
- 開発モードで項目 `auto_brake`（設定の「開発モード」区分の「自律系の自動ブレーキ」）を選ぶと、**自律走行の画面（教示再生・試験（当日））の左上に自動ブレーキの切り替えが出て、自律走行中・試験場内でもこの切替で OFF にできる**
  （選んでいなければ出ない。選んだだけでは OFF にならず、切り替えたときだけ OFF。開発モードを切る・項目を外すとすぐ ON に戻る。始業点検・校正の画面では切れない）。

### 3-2b. 追従走行 — 人について走らせる

メインメニュー →「走行 ▸」→「追従走行」。**対象（試験員）を選んで追従させる。** 人検出は追従走行では自動で動く（左上に人検出の切り替えは無い）。
左上は「終了」だけ。自動ブレーキは自律走行なので切り替えられない（常に ON）。

主表示は**レーダー**（画面いっぱい）。機体は中心の緑の三角。**候補の人は番号つきの灰の丸**、**選んだ人は黒の丸と輪**で、歩いた軌跡が線で付く。
起動直後で候補が 0 人のときは中心に「起動中」と出る。右列は ① **対象までの距離**（選んでいなければ「対象を選んでいません」）／② 停止│走行／③ **「向く」**／④ スティック（常設。触れた瞬間に手動介入になり一時停止）。

1. **対象を選ぶ**: レーダーの人の丸を押す（札「対象選択中」）。**選ぶだけで機体は動かない。**違っていれば別の丸を押して選び直す。
2. **「向く」を押す**: 機体が**対象の方へその場で向くだけ**で、移動はしない。少し動くので薄い緑のボタン。押せるのは対象を選んだあと。
3. **「走行する」を押す**（向いたあとに押せるようになり、ゆっくり明滅する）: 追従が始まる（札「追従中」・画面の縁が緑の枠で点滅）。
4. **止めるとき**: 「停止する」（一時停止。対象は保持され、「再開する」で続きから追従する）。物理の非常停止ボタンは常に有効。
   見失ったときは案内が出る（人検出は自動復帰しない。対象を選び直す）。
5. 終わったら左上の「終了」でメインメニューへ。

### 3-3. 教示（手動）— 通り道を記録する

1. メインメニュー →「走行 ▸」→**「教示（手動）」**
2. 主表示の中央の入口のカードで、**「新しい経路」**（名前を入れる）か**「録り直す」**（既存の経路の一覧から選ぶ）を選ぶ
   （選ぶとすぐに記録が始まる。「記録開始」ボタンは無い。入口のカードは押しても機体が動かないので塗らない）
   - **教示に入ると、機体は地図をまっさらに作り直す**（数秒〜十数秒。画面の地図もいったん消える）。
     前の再生や起動からの蓄積を引きずらないための仕様で、**故障ではない**。作り直しが終わるまで
     記録は始まらない（選んだあと「記録中」になっても、地図が出て点が増え始めるまで少し待つ）。
     記録に入ったあとは作り直さない
   - 新規は経路名を入れて**「新しい経路」**を押す
   - **`/` と `\` は入力すると自動で `_` に置き換えられる**（ファイル名に使えないため）。
     画面の表示名と保存名は一致する
   - 日本語でも半角英数でもよい。空欄なら日時から自動で付く
   - 既存を選ぶ（**「録り直す」**）・同じ名前で始めると**黄の「もう一度押すと上書き」になるので、もう一度押す**
     （2 回押しで確定）。新しく録ったほうが `<経路名>.json` になり、旧版は
     `<経路名>.prev` に残る（世代番号も 1 つ進む）。区別しやすい名前を付ける
3. ヘッダの札が**「記録中」**になる（中立の札に丸の印。赤は使わない）。右列の ① に**記録の量（距離・時間）**が出る
4. **右列のスティック**を操作して走らせる（左上に**自動ブレーキの切替**がある。手動走行と同じ。ロックを外して `OFF` にしたあいだは減速しない）。
   主表示は作成中の地図と経路（機体を中心に追う）。「停止する」で一時停止、スティックに触れ直すと記録を続ける
   - 記録中は **10 秒ごとに途中経過が自動保存**される。**「保存」を押す前に落ちても
     ここまでの成果は残る**。復旧するには `<経路名>.wip` を `<経路名>.json` へ
     リネームして使う
5. 走り終えたら右列の **「保存」**（スティックに触れている間は押せない。→「保存しました」が出る）→ 左上の **「終了」**
   - **「保存」を押さずに「終了」すると、保存確認が出る**（未保存の記録があるとき。「保存する」／「破棄する」／「やめる」）。
     **「保存する」で保存**（「保存」を押したのと同じ）、**「破棄する」で捨てる**
     （2 回押しで確定。同名の既存の経路はそのまま残る）
   - 「保存」を押すと**経路（`.json`）と一緒に地図も保存される**（§4-4）。
     地図の書き出しが入るため**保存には数秒かかることがある**。「保存しました」と出る
     まで待つこと。書き出しに失敗したときは**やり直しを数回行う**（通信が一瞬
     切れたときの取りこぼしを拾うため）
   - やり直しても**地図の画像（`.pgm`／`.yaml`）を保存できなかったとき**は、経路は
     保存されたうえで、**「地図の画像を保存できませんでした。この経路は途中からの
     再開と完全グローバルの位置探しが使えません（始点に置けば再生はできます）」**と出る。
     **黙って「保存しました」にはならない**。その経路は 始点マークに置けば再生できる
     （§3-4）

> **⚠ 「保存」のあとは記録を続けられない。**保存した時点で経路は確定する。
> 続きを録りたいときは「終了」して、新しい経路として教示し直す。
> **保存後にスティックに触れても、受け付けずに「保存しました」の
> まま留まる**（記録は再開しない。記録していないのに「記録中」と出ることはない）。
> 拒否されたときは「保存済みのため記録を続けられません」と出る。

> **記録中に非常停止・手押しが入っても、記録は消えない。**解除して窓の「確認」を押すと一時停止に戻り、
> （手動教示は）スティックに触れると**続きから
> 記録する**。ただし自己位置を見失った・自己位置が一度に 0.5 m 以上飛んだ等で記録の
> 連続性が切れた場合は、メインメニューに戻って保存確認が出る（「保存する」で切れ目までの
> 記録を保存、「破棄する」で捨てる）。
> **機体を手で押して動かしても記録は切れない。**押した動きも車輪の回転で追えているので、
> 押して動いた道筋がそのまま経路に入る（2026-11-13 実機。ユーザー決定でこの作りのまま）。
> 経路に入れたくない動きをしたときは、保存せずに「終了」して録り直す。

| 表示     | 意味                                                                          |
| ---------- | ------------------------------------------------------------------------------- |
| 記録の量（右列 ①） | 走った距離と経過時間（例「12.4 m　1:32」）。記録点数は 10cm におよそ 1 点なので、100m なら 1000 点前後 |
| 地図     | 走るにつれて伸びていく。**伸びないなら SLAM が効いていない**（§2 の #2・#3） |

**走らせ方のコツ**

- **曲がり角では止まらず一定の速度で回る。** 長い直線廊下は LiDAR には
  「どこも同じ景色」に見えて位置がずれやすい。曲がり角と分岐が手がかりになる
- **壁に寄りすぎない。** 壁しか見えないと地図が作れない
- スティックを一気に倒しても急発進・急停止はしない（前進・後退の加減速に制限が
  入っている。ESP32 ファームと obstacle_limiter の二段構え。2026-09-11 実機で
  発進だけでなく停止も急だったことが判明し、両方とも緩めた）。**障害物ブレーキ・
  非常停止はこの制限を経由せず従来どおり鋭く効く**（制動距離は伸びない）。
  その場旋回（真横に倒す）の立ち上がりにはこの制限はかからない（§3-2 参照）
- **自動停止がかかるのは「進行方向 ±29 度の範囲」に物があるときだけ**で、
  真横の壁では止まらない（廊下を普通に走るぶんには効かない）。
  止まるのは**機体の前面から約 15cm** まで近づいたとき。
  曲がり角で正面の壁に寄せすぎると止まるので、少し早めに回る

### 3-3b. 教示（追従）— 人について走って通り道を記録する

メインメニュー →「走行 ▸」→「教示（追従）」。**人について走りながら経路を記録する**（走行の部分は追従走行 §3-2b と同じ画面）。

1. 入口のカード（主表示の中央）で**「新しい経路」**か**「録り直す」**（二段階: もう一度押すと上書き）を選ぶ。選ぶと記録が始まる。
2. 記録の前に、追従走行と同じく**対象を 1 度提示する**（レーダーの丸を押す→「向く」）。違っていれば選び直す。機体は動かさない。
3. 「走行する」で追従しながら記録する（ヘッダの札「記録中」）。右列の先頭は **「記録 12.4 m　1:32」**（距離・時間）。
   主表示はレーダーで、**作成中の地図と経路は左下の小さい枠**に出る（押すと大きくなり、そのとき「入れない所」と「凡例」が出る。もう一度押すと戻る）。
4. 「停止する」は一時停止（続きから記録できる）。右列の **「向く」と「保存」は横に並ぶ**。**「保存」を押すまで記録は確定しない。**
   保存のあとは記録を続けられない（§3-3 の注意と同じ）。「終了」で未保存があれば保存確認が出る。

### 3-4. 教示再生 — 記録した通り道を自動で走る

1. **ロボットを教示の開始位置・開始の向きに置く。**
   床に始点マーク（ビニールテープの十字）を貼っておくこと。
   **経路の途中から走らせたいときは、経路の上（2 m 以内）に置いてもよい**（下の「初期姿勢の確度と、途中からの再開」）
2. メインメニュー →「走行 ▸」→**「教示再生」**
   （**教示済みの経路が 1 本も無いと押せない**。押すと「教示済みの経路がありません」と出る。先に教示（§3-3）で経路を記録する）
3. **主表示の中央の入口のカード**で、一覧から経路を選び（名前・長さ。**地図の画像の無い経路には印**が付く）、
   **「順再生」／「逆再生」**を選んで **「この経路で進む」** を押す（押しても機体は動かないので塗らない）
4. 右列に「位置を探しています」→**位置が決まる**（確度の印）のを待つ（数秒。始点から離れているほど長くかかる）。
   確度の印が出たら下の「初期姿勢の確度と、途中からの再開」を見る
5. **地図上のロボットの位置が実際と合っているか目で確かめる**
6. 右列の **「再生する」**（位置が決まるとゆっくり明滅する）を押す

画面は主表示に地図・経路・始点・終点・機体が出て、右列は ① 位置の確度／経路からのずれ ② 停止│再生 ③ 「完全グローバルで探す」・再生速度の 3 段・「経路を選び直す」 ④ 「手動」の順（タブは無い）。

> **経路を選ぶと、教示時に保存した地図が読み直され、そのときの LiDAR の見え方から
> 地図上の自己位置を探して合わせる**（§4-4。2026-10-03 から。それまでは始点に決め打ち）。
> だから**機体を置いてから経路を選ぶ**こと。先に経路を選んでから機体を動かすと、
> 合わせた位置から機体がずれたままになり意味がない。
> 保存地図（`.pgm`）を持たない古い経路（教示の保存で地図の画像を残せなかった経路も
> 含む）は、これまでどおり始点に決め打ちで合わせる（確度の印は出ない）。
> **このときは「始点の印に置いて再生する（途中からの再開はできない）」と 1 行出て、「完全グローバルで探す」は
> 押せない**（押しても効かないため）。**必ず始点マークに置くこと。**
> （**実機の画面では、一覧の「地図の画像なし」の印は、経路を読み込んだあとにその経路についてだけ出る**。一覧のすべての行には出ない。）

> **経路を選んだあとの読み込みには待ち時間がある**（短い経路で数秒、長い地図で 30〜45 秒。
> 読み込みが終わるまで、**地図の上に「地図を読み込んでいます」**と出る）。
> **位置が決まるまで「再生する」は押せない**（押せない見た目で、押すと「押せません　探しています」などの理由が出る）。
> 慌てて操作しないこと。
> **経路に使える地図が無い／経路ファイルが読めないときは、そう案内が出て先へ進まない**
> （「この経路には使える地図がありません」「経路ファイルが読み込めません」）。
> そのときは別の経路を選ぶか、教示からやり直す。

> **教示再生の「地図の更新」は現在使えない**ので、画面にも出さない（機体側も ON の要求を拒否する）。
> 教示再生（と試験（当日））に「保存」ボタンは無い。
> **走っても画面の地図も経路計画の地図も変わらない**（開いた地図、または最後に保存した地図のまま。
> 走って見えた物は障害物の検知だけが扱い、地図には残らない）。教示の記録中・前日の地図作成（試験準備）は対象外
> （書き足しが正しい）。試験当日（盤前移動・待機場所へ戻る・呼び寄せ）も同じ。
> 地図には、**始点（塗りの丸と名前）・終点（経路の行き先の輪と名前）・経路（緑の線）**が出る。

> **「推定できました」（位置が決まった）より前は「再生する」を押せない**（押せない見た目で、そばに
> 「探しています」「見つかりません」「経路から離れています」のどれかが出る）。
> 表示が変わるまで待つこと。

> **⚠ 押した直後、ロボットはまずその場で旋回する。** 走り始める点で記録した向きに
> 機体を合わせてから走り出す仕様（`rotate_to_start_yaw`）。**故障ではない。**
> 置いたときの向きがずれているほど、この旋回は大きくなる。

#### 初期姿勢の確度と、途中からの再開（2026-10-06 から）

自己位置を探している間と探し終えたとき、S-14 の右列 ① に**確度の印と一言**（✓／!／×）が出る。

| 表示 | 意味 | どうするか |
| --- | --- | --- |
| 探しています（右列 ①。!の印） | 探索中。経路の始点から半径 5 m を探し、一致が弱ければ自動で半径 10 m に広げる | 待つ |
| 位置が決まりました（✓の印） | 位置が決まった | 地図上の位置を目で確かめて「再生する」 |
| 位置が決まりました（似た場所が複数あり、取り違えの可能性がある旨が添う） | 決まったが、似た場所と取り違えているかもしれない（「再生する」は押せる） | **地図上の位置が実際と合っているかを特によく見る**。違っていれば経路を選び直す |
| 見つかりません（完全グローバルで探すか、経路を選び直す） | 見つからない／似た場所が多すぎて決められない（機体は動かない） | 機体を経路の近く（始点マークが確実）へ置き直して経路を選び直すか、**「完全グローバルで探す」**（地図全体を探す。数秒〜十数秒） |
| 経路から離れています（経路の近く 2 m 以内に置き直す） | 自己位置は決まったが、**経路から 2 m 以上離れている**（機体は動かない。推定の失敗とは別） | 機体を経路の近く（2 m 以内。始点マークが確実）へ置き直して経路を選び直すか、**「完全グローバルで探す」**を押す |
| （確度の印は出ない）**始点の印に置いて再生する（途中からの再開はできない）** | 教示の保存で地図の画像（`.pgm`）を残せなかった経路、または画像を持たない古い経路。始点に決め打ちで合わせる | **始点マークに置く**。「完全グローバルで探す」は押せない。途中からの再開はできない |

**経路の途中に置いて始めると、始点へ戻らずその場所から続きを走る。**
決まった位置に最も近い経路の点から再開し、その点で記録した向きへその場で回ってから走り出す。
**機体の向きは問わない**（逆向きに置いてもよい）。行きと帰りが重なる経路で近い点が複数あるときだけ、
機体の向きに合う側を選ぶ。機体が経路から 2 m 以上離れていると途中からは始めず、
**「経路から離れています」**になる（離れた始点へいきなり向かわないため）。
逆再生でも同じ（終点での向きのまま終点に置けば、始点の方へ回ってから逆向きに走る）。

> 始点から 10 m 以上離れた途中に置いたときは、自動の探索では届かないので「見つかりません」になる。
> そのときは「完全グローバルで探す」を押す。

> **再生速度は右列の 3 段（低速 / 中速 / 高速）で選ぶ。走行中に変えてもよい**
> （次の瞬間から効く）。既定は中速（約 0.33 m/s）。速いほど経路を外れやすくなるので、
> 初回は低速〜中速で確かめる。実際の速度は障害物・在席確認の状況で自動的にさらに
> 絞られることがある。

走行中:

- **人はロボットから離れず、いつでも止められる位置にいること**
- 止めるときは右列の **「停止する」**（一時停止）。物理の非常停止ボタンは常に有効
- **「手動」を押して出る手動操作パネル（スティック）に触れると、再生は一時停止して手動操作が優先される**
  （速度指令の優先度が再生より高い）。とっさに避けさせたいときに使える。
  再生を続けるには手を離してから右列の **「再開する」**（ゆっくり明滅）を押す。パネルは右列の「停止する」「再開する」などを押すと閉じる
- 前に障害物が出ると自動で減速・停止する。**障害物とみなすには前方に 3 点以上の
  反射が必要**（2026-09-04）。以前は 1 点でも止まったため、何も無いところで止まって
  しばらくして独りでに走り出すことがあった。停止距離では幅 2cm の物でも 5 点以上に
  映るので、実体を見落とすことはない
- 完走すると、右列 ① に**経路の名前と「終点」**が出て終了を促す（「再開する」は押せなくなる。「経路を選び直す」は押せる）
- 再生中、右列 ① に **「ずれ　いま 0.08 m　最大 0.21 m」** が出る。いま経路から横にどれだけ外れているか [m] と、この再生での最大値が出る（小数 2 桁）。停止しても最大値は残り、次の再生を始めると 0 に戻る

**画面を触らなくても止まらない**（2026-09-04 以降）。以前はタブレットを 30 秒
触らないと在席が確認できないとみなされ、黙って止まっていた（画面をスクロールすると
復帰するのはそのため）。いまは**アプリが前面にあって接続が生きていれば在席**とみなす。
画面を消す・別アプリに切り替える・回線が切れた場合は従来どおり止まる。

**走行中にタブレットを閉じる／切れると一時停止になる**（2026-10-06 以降）。
走行中に使用中の端末がすべて離れると、モードを保ったまま一時停止し、
異常の窓に「操作端末が離れたため一時停止しました」と出る。
端末が戻ってアプリを開き直すと、**機体がいまいるモードの画面**（走行中の方式なら
その走行画面）に戻り、同じ窓が「確認」を押せる状態に変わるが、**「確認」を押しても機体は一時停止のまま走らない**。
**右列の「再開する」を押すまで機体は走らない**（押さずに戻ってきても勝手に走り出さない）。
接続確認（S-00）には戻らない。S-00 の表を見たいときは S-01 の
「ネットワーク接続確認」から「詳細を見る」で開く。
止まっている間（待機・一時停止・準備中など）に離れても一時停止にはならず、
確認も出ない。

**途中で止まったときは「再開する」で続きから走れる。**フォルト（ESP32 の一時途切れ
など）・スティック介入・「停止」で止まった場合、画面には
**「止まったところから続きを走ります」**の案内が出る（札は「一時停止中」。右列の「再開する」が明滅する）。
最初からやり直す必要は無い（2026-09-04 以前は、この場合も「記録の終端に達しました。
終了を押してください」と誤って案内していた）。

> 「終点」と出るのは**本当に走り切ったときだけ**。
> 「終点」か「止まったところから続きを走ります」かで、「もう終わり」か「途中で止まっただけ」かを見分ける。

### 3-4c. 逆再生

記録した経路を**終点から始点へ**逆向きに走らせる。S-14 の「順再生／逆再生」の行で
選ぶ。

1. **機体を経路の終点の印に、終点での向きのまま置く**（逆再生は終点から始まる。
   地図の読み直しでは、終点の周りで自己位置を探す。逆向きの経路の途中に置けば、そこから続きを走る。§3-4「初期姿勢の確度と、途中からの再開」）
2. メインメニュー →「走行 ▸」→**「教示再生」**を開く
3. 入口のカードで一覧から経路を選び、**「逆再生」**を選ぶ（順再生に戻すときは「順再生」。**順再生│逆再生の切り替え**）
4. **「この経路で進む」**を押す。以降は §3-4 の手順 4〜6 と同じ
   （位置が決まるのを待つ → 位置を目で確かめる → **「再生する」**）。

> 画面が使えないときの代替：経路の選択をコマンドで送ることもできる
> （`<経路名>` を置き換える）:
>
> ```bash
> ros2 service call /system/trigger th_system_msgs/srv/UiTrigger \
>   "{trigger: 'ui.route_select', arg_json: '{\"id\": \"<経路名>\", \"reverse\": true}', requester: 'cli'}"
> ```
>
> `accepted: true` が返ればよい。以降は §3-4 の手順 4〜6 と同じ。

### 3-4b. 試験場内デモ（試験準備／試験（当日）、`stage:=4`）

教示再生デモとは別のデモ。前日に **試験準備（S-20）** で待機場所・配電盤のピン登録と
**会場地図の保存**を行い、当日の **試験（S-21）** で配電盤の移動・呼び寄せ・
測定を実演する。入口はメインメニュー →「試験場 ▸」→「試験準備」／「試験」。
**試験場内の 2 画面は、タブの無い 1 画面**（地図・ボタンが 1 画面に出る）で、
**右列のボタンの場所は状態で変わらない**（使えないボタンは押せない見た目で場所を保ち、押すとそのボタンのすぐ上に理由が出る）。

#### 試験準備（S-20）— 前日に地図とピンを作る

**左上の操作バー**: 「終了」／**人検出 切│入**（入のときだけ明るい）／**自動ブレーキの切り替え**（鍵つき。§3-2）／未保存があれば「未保存」の印。

0. **入り口のカード（主表示の中央）**は、機体が地図作成中でないときに出る。**押しても機体は動かないので、どのボタンも塗らない太い縁**で出る。
   - **前回（前の試験日）のピンが残っている場合**: **「続きから再開」**（前回の地図とピンをそのまま使う）と
     **「新しい試験日として開始（前回を消す）」**。会場の配置が前回と大きく変わった、または前回のピンをそのまま使う予定が無いときは後者を押す
     （誤操作防止のため 2 回押しで確定する。1 回目は黄の「もう一度押すと消去します」に変わるだけ）。
     **押すと地図作成をやり直し（`slam_toolbox` の再起動）、ピンも全部消える。元に戻せない。**
     押している間は「地図を初期化しています…」と出るので、消えるまで待つ（数秒〜再起動が絡むと長くて 1 分弱）。
   - **前回が無いとき**: 「地図作成を開始」が 1 つだけ出る。
   - **作成中は入口のカードは出ない**ので、地図作成を止めてやり直したいときは、保存せずに「終了」してから入り直す。
1. **地図作成中**（札「地図作成中」）は、主表示に作成中の地図とピン・機体・いまの LiDAR スキャンが出る。
   **レーダー（候補の人を丸で出す）が地図の右上に重なる**。地図の上の左側に**「順番を決める」**、地図の端に「入れない所」・「凡例」・
   地図の向きを 15° ずつ回す「左へ回す」「右へ回す」（地図作成中だけ。表示だけで座標は変わらない）が出る。
   **機体は右列の手動のスティックで動かして地図を作る**（スティックは常に出ている。場内なので「高速」は出ない）。
2. **人検出（DR-SPAAM）は既定で止まっている。** 人を使う登録・呼び寄せの前に、左上の**「人検出」を「入」**にする
   （入れてから最初の検出まで数秒かかる。その間レーダーの中心に「起動中」と出る）。人検出が止まっている間、「人の位置で」の登録は押せない見た目で、
   押すと理由が出る。**「いまの姿勢で」「地図をタップして」は人検出を使わないので、止まっていても押せる。**
3. **登録は、地図の下の帯で行う。** 先に**方式**（**人の位置で／いまの姿勢で／地図をタップして**。前回の方式が既定）を選び、
   次に **「待機場所を登録」**／**「配電盤を登録」** を押す。登録の手順や警告は、この帯に重ねて出る（地図の大きさは変わらない）。
   - **人の位置で（2 点指示）**: レーダーで試験員の丸を押して対象を選ぶ。①**登録したい場所に立って「この位置を登録」**

> 速度上限は、試験準備（S-20）と同じ `v_slow`（既定 0.30 m/s）。以前は盤前と同じ
> `v_jog_panel`（0.10 m/s）で遅すぎた。**盤前（`AT_PANEL`）は従来どおり `v_jog_panel`**
> （盤に当てないため）。**S-20・S-21 の手動操作には速度プリセットの「高速」が出ず、
> 低速・中速の 2 段**（スライダも 55% まで）。場外の画面（S-11・S-13・S-14）は従来どおり 3 段。

> `stage:=4` でないと、このデモで要る人物トラッカー（DR-SPAAM）のノード自体が
> 起動しない。試験場内ノード（`pin_registrar` / `venue_navigator` / `wait_clear_gate` /
> `home_declarer`）と Nav2 は `stage:=3` から起動するが、2 点指示の登録・呼び寄せに
> 人物トラッカーが要るので **デモは `stage:=4`** で起動する。
> **人検出は既定で停止（OFF）している。** `stage:=4` でノードが立ち上がっても、
> 左上の「人検出」を「入」にするまで DR-SPAAM は推論しない（CPU 負荷を
> 抑えるため）。メインメニューなど「動かさない」画面に戻ると自動で止まる。

### 3-5. 「非常停止」の窓と異常の窓が出たら

**画面の最上部（ヘッダ）は常に一番上に出て、どの窓にも隠れない。** 非常停止ボタンもいつも押せる。
異常・非常停止の窓は**本文の中央**に出て、ヘッダ以外の本文を暗くする。**窓を隠す操作は無い**（異常が続く間は出し続ける）。
窓の中のボタンは **「確認」の 1 つだけ**で、原因が消えて「解消しました」「解除しました」に変わってから押せる。

| 出方 | 札・窓の題 | 対処 |
| --- | --- | --- |
| 画面の非常停止ボタンを押した | ヘッダの札「非常停止中」・窓の題「非常停止中」 | 画面下端の**「非常停止を解除」バー**を押す → 窓が「解除しました」に変わる → **「確認」** |
| **機体の物理ボタンを押した**（手押し） | **画面では「非常停止」として出る**（札「非常停止中」・窓の題「非常停止」。「手押し」の語・紫の帯は出ない） | 機体後部の赤いボタンを右へひねって戻す → 窓が「解除しました」に変わる → **「確認」** |
| 異常が起きた（例: LiDAR 途絶） | ヘッダ下段に異常の名前（黄）・窓の題は何が起きたか（「LiDAR 途絶」など）＋対処 1 行 | 原因を取り除く → 窓が「解消しました」に変わる → **「確認」** |
| 起動直後に勝手に出た | 起動時の CPU 負荷（既知） | 原因が消えたあと「確認」を押す。走行への影響はない |
| 走行中に勝手に出た | 安全監視が働いた | 下記に従い、**何が出たかログを記録して報告する** |

> **画面下端の「非常停止を解除」バーは、画面の非常停止ボタンを押したとき（または他の端末が押したまま）だけ出る。**
> 安全監視（重大フォルト）で入った非常停止には出ない（押しても何も起きないため）。そのときは窓に
> フォルトの名前と対処が出て、原因が消えたあと窓の「確認」で戻る。
> 解除バーは小さめの白地・黒の太い枠で、本文の下端の中央にある（誤って解除しないため）。

**「確認」を押した後の戻り先**（どの場合も**走行は再開しない**）:

| 状況 | 戻り先 |
| --- | --- |
| 走行中・経路が塞がれて待っていた・向き合わせ中だった | 止まる直前のモードの**一時停止**（右列の「走行する」「再開する」で再開）。待機（メインメニュー）には戻らない |
| 止まっていた状態（位置合わせ・確認・選択など） | **止まる直前の状態へ、その入口からやり直す**（確認・向き合わせ・2 点指示を飛ばさない。呼び寄せは 2 点指示から、始業点検・校正は一覧から） |
| 手動走行などで異常の窓だった | 窓が閉じ、モードはそのまま一時停止に残る。走らせるには改めて走行の操作をする |
| 戻れる状態でない（モードごとの復帰可否は Spec-modes §6） | メインメニュー（待機） |

> **「確認」を押しても機体は動き出さない。**戻り先は停止した状態なので、走らせるには改めて「走行する」「再開する」「再生する」
> （または該当の操作）を押す。盤前・待機場所への移動で経路が塞がれて待っていた場合や向き合わせ中だった場合も、一時停止で止まる
> （自動で再開しない）。「走行する」を押すと経路の先を確かめてから走り出す。手押しのあとは位置が変わっているので、
> その後の走行は経路を計画し直す（古い経路の残りは使わない）。
>
> **異常が続いている間は、右列の「走行する」「再開する」「中断」は押せない見た目**になる（ハードの異常の解消を待つ）。
> 原因が消えていない間は「確認」も出ない。物理ボタンを押したままでも出ない。
> **一瞬だけ出て自然に消えるフォルトでは、そもそも窓が出なくなった**（2026-09-04）。監視が単発の誤検知を無視するようになったため。
> 物理非常停止を押して機体を手で押して動かしている間（手押し）に、暴走と判定されて非常停止に落ちることはない（離したあとは通常どおり判定する）。

> **手押しの間（非常停止の窓の間）に ESP32 との通信が切れたとき**は、窓に
> 「ESP32 との通信が切れているため、非常停止ボタンの状態が分かりません。ボタンを戻しても解除できません」
> と出る。フォルトが消えると文言も消える（2026-11-10）。

**窓が出ている間に自然に解消したフォルトは、「何だったか」が窓に残る**（2026-10-12）。原因が消えて
窓が「解消しました」に変わると、窓の本文に **「解消した異常：LiDAR 途絶（0.1 秒・12:34:56）」** のように
種別・継続時間・開始時刻が出る（時刻は時:分:秒）。0.1 秒で解消しても、**「確認」を押すまで残る**。
同じ種別が 60 秒以内に続いたときは **「ほか 2 回」** が添わる。窓が出る前に履歴が届いていなければ、
届いた時点で現れる。**添えるのは、その一時停止（窓が出た時点）以降に起きて解消した異常だけ**で、
端末が離れたことによる一時停止などでは、それより前の古い異常は出ない（2026-11-10）。

**ヘッダの「直近の異常」と履歴の一覧**: 異常が解消すると、ヘッダの下段に
**「直近の異常：LiDAR 途絶 12:34:56」** が残り、**発生から 3 分ほどで消える**。押すと **フォルト履歴の窓**（直近 50 件・新しい順。
時刻・種別・継続時間・発生時のモードと状態・重大／回復・止まったか。継続中は「継続中」と経過）が開き、
「閉じる」で戻る。見るだけで操作は無い。同じ一覧は **設定（§3-6）の「異常の履歴」**でも見られる。
異常が継続している間は、ヘッダには現在のフォルトが出る。

**ヘッダの「自動ブレーキなし」**: 自動ブレーキが切れている間だけ、ヘッダの下段の左に黄で**点滅**して出る（§3-2）。

### 3-6. 設定（メインメニュー →「設定」）

メインメニューの **「設定」** タイルから開く（機体のモードを動かさないので、起動直後で接続確認のあいだでも押せる。
接続確認 S-00 で止まったときは「開発モードの設定」からも入れる）。**左上の「戻る」でメインメニューに戻る。**

画面は**左に区分の一覧、右に選んだ区分の中身**が出る（タブは無い）。変えられる区分では、右の下端に **「保存」** と
**いつ効くかの印**（「すぐ」／「次の起動から」／「次に地図を読み直したときから」）が並ぶ。効き方の違う設定は区分を分けてあるので、
その区分の保存はその印のとおりに効く。

| 区分 | 中身 | 効き方 |
| --- | --- | --- |
| **速さとブレーキ** | **速度プリセットの割合**（低速／中速／高速。低速 0.27・中速 0.55・高速 1.0 が既定。**低速≦中速≦高速でなければ保存できない**。高速の上限は 100%。違反は理由を表示。機体側も同じ規則で弾く。変えた理由の入力が必須）。**自動ブレーキの既定**（場外の手動・場内。**どちらも既定は ON**。変えた既定は再起動後も維持される。変えた理由の入力が必須。自律系の無効化不可・ゾーン不明時の ON は変わらない） | **次の起動から**（「再起動後に反映」。保存済みでまだ効いていない値は「次回から」で示す） |
| **再生の位置合わせ** | 再生の自己位置推定（廊下で地図とずれるときの補正間隔・探索窓・照合の受理下限など） | **次に地図を読み直したときから**（保存後、次に「この経路で進む」を押したとき。§4-4） |
| **知らせる** | タブレットの音声（ON／OFF のみ。**読み上げはまだ実装していないので、ON でも声は出ない**。切替は端末に記憶されるだけ）／**機体のスピーカー**（周囲への報知の ON/OFF・音量・試し鳴らし。§3-6b。**走行中でも変えられる**） | 機体のスピーカーは**すぐ**。音声は端末に記憶 |
| **画面** | 縦横の固定（自動／縦固定／横固定）・文字の大きさ・**ヘルプ表示の出す・出さない**（端末ごと。初めは出す。次の起動へ引き継ぐ） | すぐ（ブラウザに記憶） |
| **つなぎ先** | **カメラ機能の画面の場所**（試験（当日）の「カメラ」が別タブで開く先。既定 `http://192.168.5.129/`。カメラの IP は現場で変わるので、当日現物で確かめてから直すこと。**http:// か https:// で始まるものだけ保存できる**。変えた理由の入力が必須） | **次の起動から** |
| **異常の履歴** | 直近 50 件のフォルトを新しい順に一覧する（見るだけ。§3-5）。何度か異常が出たときに、どの異常だったかをここで読める | 見るだけ（機体が記録を出すたびに更新） |
| **LiDAR 死角** | **今の値の表示だけ**。変えるときはここの **「校正で変更する」** で校正（§3-9）の「LiDAR 死角」へ進む | 見るだけ |
| **開発モード** | 開発モードの ON/OFF と、外す項目の選択 | **開発者が検証に使うもので、試験では使いません。**ON にすると機器が揃っていなくても起動確認を通せてしまいます（警告を無視するため）。ヘッダの帯の色が変わり「開発モード」と出ている間は**通常の運用状態ではありません**。意図せず ON になっていたら OFF にしてください |

**コストマップの表示は設定には無い。**地図の右下の「入れない所」ボタンで入切する（§3-4b）。
地図なし人物追従（軌跡追従）のつまみは、いまの機体の動きに影響しないため画面から外した。教示再生の走り方を変えたいときは、
**S-14 の「再生速度」（低速／中速／高速）**を使う（§5）。

> 変更できるのは **停止中（待機 IDLE・試験準備 PREP の地図作業中）でジョグ中でないとき**だけ。
> それ以外（走行系の各モード・手動走行・一時停止・ジョグ中）では項目が押せない見た目になり、押すと理由が出る
> （サーバ側も同じ条件で弾く。速度プリセットは `params_audit`、
> 自己位置推定は `config_manager`）。**ただし機体のスピーカー（§3-6b）
> だけは走行中でも変えられる。**
>
> 速度プリセット・自動ブレーキの既定・カメラの開く先の欄が「現在値を取得できませんでした」のままのときは、機体側の `params_audit` が起動していません。
> `ros2 service list | grep params`（`/params/get` が出るか）と `ros2 node list --no-daemon | grep params_audit` で確かめ、起動ログに `params_audit` の `process has died` が無いか見てください（2026-11-12 に bringup へ起動を追加。それ以前の版では常にこの表示になる）。

### 3-6b. 機体のスピーカーが鳴る場面（設定 →「知らせる」）

機体（ラズパイ）のスピーカーが、周囲の人に機体の動きを音で知らせる。
タブレットの音声（試験員向け）とは別。**鳴らなくても走行は止まらない**
（安全装置ではない。鳴らないことは画面とログで分かる）。

| 場面 | 音 |
| --- | --- |
| 自律で走っている間（配電盤へ移動・待機場所への移動・呼び寄せ・試験準備の自動帰還・教示再生・校正の自律走行・追従走行・教示（追従）。手動走行・教示（手動）は含めない） | 走行のメロディを繰り返す |
| 塞がれて待っている間 | メロディと聞き分けられる注意音を繰り返す |
| 接近警告が出ている間（自動ブレーキ OFF の手動系。**機体が動いている間だけ**。止まっているときの警告は画面だけで鳴らさない） | 短い警告音を繰り返す |

- 重なったら接近警告 → 塞がれ待ち → 走行のメロディの順（1 つだけ鳴る）。
  一時停止・到着・非常停止・手押しでは止まる。
- **ON/OFF と音量** — 変えた瞬間に効き、機体に残る（再起動後も維持。既定 ON・音量 60）。
- **「試しに鳴らす」** — 走行のメロディを 1 回鳴らす（音量の確認用）。
- 画面の下に **「再生中: drive」のように今鳴っているもの**が出る。
  **「スピーカー応答なし」** と出ていたら、ラズパイの再生が止まっている
  （[network.md](network.md)の「ラズパイ: スピーカー再生の導入」の確認手順で直す）。


### 3-7. 走行データを記録する（試験用の計測）

走行中の**指令と実速度**を CSV に残す計測スクリプト（`th_ws/scripts/meas08_runaway_recorder.py`）。
**購読だけで何も送らない**ので、走行の邪魔にならない。`DRIVE_RUNAWAY` の設定を実データで決めるために使う
（[試験項目.md](試験項目.md)）。

起動済みの `th_robot` に**もう 1 つターミナルを開いて**（§1-2 の起動とは別）:

```bash
docker exec -it th_robot bash
cd /root/th_ws && source install/setup.bash
python3 scripts/meas08_runaway_recorder.py 1800        # 1800 秒（30 分）記録。Ctrl-C で終了
```

- 記録先: コンテナ内 `/root/th_data/runaway/runaway_<日時>.csv` ＝ ホストの `th_ws/data/runaway/`（1 行ごとに書き出す。途中で止めても残る）
- **印**: 動作を始めるとき・終えるときに、**このターミナルへ文字を打って Enter**（例: `前進0.30` / `停止` / `左旋回` / `巻き尺始点`）。
  その時刻から次の印までが 1 区間として集計される。**打つのは印だけ。**
- **記録中は、別の `docker exec` で `ros2 topic echo` などを実行しない**（計測対象の受信が遅れて、測りたい値が悪くなる）
- 解析（ホスト側・ROS 不要）:

```bash
python3 th_ws/scripts/meas08_analyze.py th_ws/data/runaway/runaway_*.csv --tape 3.00   # --tape は巻き尺の実距離[m]（省略可）
```

### 3-7b. 人物追跡を記録する（試験用の計測）

人物トラッカーの出力（途切れる前の生の追跡位置と、画面に出している追跡状態）を `ros2 bag` で残す。
これも**購読だけ**。`stage:=4` で起動し、対象を選んで追跡させてから始める。

ターミナルを **2 枚** 開く（どちらも `docker exec -it th_robot bash` → `source /root/th_ws/install/setup.bash`）。

**1 枚目 — 記録**（Ctrl-C で終了）:

```bash
mkdir -p /root/th_data/person
ros2 bag record -o /root/th_data/person/person_$(date +%Y%m%d_%H%M%S) \
  -e 'following_position|person_candidates|stop_following|/person/status|/person/targets'
```

**2 枚目 — 印**（1 行打つごとに時刻付きで残る。Ctrl-D で終了）:

```bash
while read -r l; do echo "$(date +%s.%N) $l" | tee -a /root/th_data/person/marks.txt; done
```

- 記録先: ホストの `th_ws/data/person/`（bag のフォルダと `marks.txt`）
- 記録を始めたら、1 枚目の出力に `following_position` を含むトピックが購読されたと出ていることを確かめる。
  出ていなければ人物トラッカーが動いていない（`stage:=4` の付け忘れ、対象選択タブで
  「人検出を開始」を押していない、または対象を選んでいない）
- **印を打つ 2 枚目以外で ROS のコマンドを叩かない**（§3-7 と同じ理由）

### 3-7c. いまの機体の位置と、登録したピンの座標を読む

```bash
ros2 run tf2_ros tf2_echo map base_link      # 機体の位置。Translation の x, y と、RPY の yaw（度）を読む。Ctrl-C で終了
```

ピンの座標はホストの `th_ws/data/venue/pins.yaml`（`id`・`kind` ごとに `pose: x / y / yaw`。**yaw はラジアン**）。

### 3-7d. 人検出の CPU 使用率を見る（試験用）

人検出（`dr_spaam_ros`）が動いているかは CPU 使用率で分かる（動いていれば約 300%、止まっていれば数 %）。
ホストのターミナルで:

```bash
docker exec th_robot bash -c 'P=$(pgrep -f "lib/dr_spaam_ros/dr_spaam_ros" | head -1); top -b -n 3 -d 2 -p $P | awk -v p=$P "\$1==p{print \$9}"'
```

`%CPU` の値が 3 回出る（2 秒おき）。最後の値を読む。何も出ないときは人検出のプロセス自体が無い（`stage:=4` で起動していない）。

### 3-8. 始業点検（メインメニュー →「点検と校正 ▸」→「始業点検」）

**`IDLE` か `MANUAL` からしか入れない。** 走行中のモードからは「始業点検」が
押せない（押すと理由が出る）。

画面は左に項目の一覧、右に選んだ項目の手順が出る（タブは無い）。左上は「戻る」。

1. **一覧**に 4 項目（非常停止ボタン／モーター・エンコーダ／IMU／LiDAR）が並ぶ。
   各行に**結果の印**（✓ 正常／! 要確認／× だめ／— まだ）と確かめた時刻が出る（総合の文は出さない。一覧の上に印ごとの数が出る）。
   一覧の下には、選んだ項目の**手順が番号付きの文**で出る（いまの段の番号が太字）。
   **行を押しただけでは始まらない。右下の「確かめる」を押して確認を始める**（押しても機体は動かないので塗らない）。
   **確認中に一覧の別の項目を押すとそちらへ切り替わり、「戻る」を押すと抜けられる**
   （どちらも途中の項目の結果は記録しない＝「—」のまま。**下端左の「やめる」を先に押す必要は無い**。「やめる」は確認中だけ押せる）。
   LiDAR・非常停止ボタンの項目は、データが 3 秒届かなければ NG（データ無し）になる。
   - **IMU のモニター**: 判定の下に校正状態 `sys / gyro / accel / mag`（各 0〜3。3 が校正済み）がリアルタイムで出る。
     合否に使うのは **`gyro` が 3 であることと静止時のバイアスだけ**。`sys / accel / mag` は状態を見せるだけで、点検の合否には入れない。
   - **LiDAR のモニター**: 死角除去前の生スキャンがその場で出て、**いま登録されている死角マスクが灰色の扇で重なる**
     （マスクの内側の点は区別して描く）。実機のアルミパイプの位置と扇がずれていないか目で確かめる。
     ずれていれば「校正へ」から LiDAR 死角を校正する。マスクの値は機体（`lidar_filter`）から読む。
     読めないときは「死角マスクを取得できませんでした」と出て扇は出ない。
   - **判定の結果は消えない**: 判定（✓／!／× とその理由）が出ると、機体は一覧へ戻るが、
     **右側に結果が残り、「戻る」を押すまで消えない**（IMU・LiDAR など一瞬で終わる項目も読める）。
     NG のときは「校正へ」（IMU・LiDAR）または「故障診断へ」（非常停止・モーター）が**結果の表の下**に出る。一覧の別の項目を押しても閉じる。押さずに放置しても機体の動作には影響しない。
   - **判定の根拠（測った値と基準）**: IMU・LiDAR の結果には、**判定に使った測定値と基準が並ぶ**
     （判定の時点の値で、「戻る」まで残る）。**基準を満たさなかった値は黄の地で強調される**ので、NG・要確認の原因がどれかが分かる。
     - LiDAR: 無効帯の最大幅（**基準 20° 未満**）／受信周期（基準 0.3 秒以内。registry の scan_stale_ms）／死角のズレ（基準 5° 以内。死角マスクが未登録なら「測れず」）。
       無効帯は、反射が無く距離が出ないビーム（∞）が連続する幅。**正常でも広い会場の遠方などで 8° ほどの無効帯が常にある**ので、
       基準は 20° とした（2026-10-13）。20° 以上が続くとき（LiDAR の汚れ・遮り・故障）だけ NG になる。
       死角のズレは、**約 1.5 秒ぶん（15 枚）のスキャンをまとめて**、近距離の写り込みが登録した死角の外へ出ている角度で見る。
       1 枚では柱が数本しか写らないことがあり、それだけで NG にしない（2026-11-10 T-14）。
     - IMU: 静止時のバイアス（基準 0.2 rad/s 以内）／最大角速度（基準 10 rad/s 以内）／ジャイロの校正状態（`gyro` が 3）。
       `sys / accel / mag` も値は残るが**表示だけで、合否には使わない**（この機体では 3 にならないため。2026-11-10 T-11）。
       校正状態は判定の数秒後には画面から消えるが、結果にはその時点の値が残る。足りないジャイロ校正が強調される。
     - **同じ内容が機体のログにも 1 行で残る**（解析用）。`opcheck_runner` のログの
       `LIDAR 判定: NG (coverage_gap) period=… basis=[{"key":"coverage_gap_deg","value":25.0,…}]`、
       `IMU 判定: WARN (needs_calibration) … basis=[…]`。古い機体（根拠を出さない版）では表は出ず、判定と理由だけになる。

**起動時の自動判定との関係**: S-00／S-01 に出る自動判定は、起動のたびに機体が
自動で行う簡易版（非常停止ボタンの今の状態・IMU・LiDAR のみ。走行を伴う確認は
しない）。ここの 4 項目（人が押す・離す・動かす）は導入時と定期に行う本式の点検。
自動判定が NG でも運用には入れる（警告のみ）。
開発モードで「起動時の自動点検」を外すと自動判定の警告が出なくなる
（判定自体は続いている。消している旨が画面に出る。何も出ないのを「正常」と
取り違えないこと）。

**項目1: 非常停止ボタン**

手順の文と画面の案内どおりに操作する。

1. 「非常停止ボタンを押してください」→ 実物のボタンを押す
2. 「実物と一致していますか」→ 画面の表示（押されている）が実物と合っていれば
   **「はい」**、合っていなければ**「いいえ」**
3. 「非常停止ボタンを解除してください」→ 実物を解除する
4. 「一致していますか」→ 同様に はい／いいえ

**この項目を確かめている間は、非常停止の窓は出ない**（機体も手押しの状態に落ちない）。
**押す・離すの両方を試すのは配線の断線と短絡を区別するため。** 途中で
判定が出て一覧へ自動で戻ることがある（押す・離すの両方が検出できた時点で
自動判定が先に終わることがあるため。「はい」を押しそびれても問題ない）。
**押したまま 30 秒離さないと NG（固着・短絡の疑い）で故障診断へ進む。**
押す気配が無いまま待っていても NG にはならない（別の項目か「戻る」で抜けられる）。

**項目2: モーター・エンコーダ**

「前」「後」「左」「右」の 4 つの矢印が並ぶ（前＝前に進む／後＝後ろに進む／左・右＝その場で回る）。**押している間だけ
低速で動き、離すと止まる。** 矢印の右に、**左右の車輪の指令（細い線）と実測（太い線）のグラフ**
（直近 15 秒。左の車輪のグラフが左）が出るので、左右輪がちゃんと追従しているか目で見て確認する。
各矢印の角にはその方向の結果の印が付く。

**4 方向すべて実施してはじめて OK になる。** 1 方向だけでは確定しない（前進だけでは左右の
入れ替わりが見えないため）。逆に、どれか 1 方向で合わなければその場で NG
（故障診断へ進む）になる。

> **指を離した・画面が裏に回った・タブレットを閉じた、どの場合でも機体は止まる。**
> 何もしなくても 0.5 秒で自動的に止まる安全装置（デッドマン）も入っている。

> **LiDAR（`/scan`）が届いていないと、矢印を押しても動かない**（障害物が見えない間は
> 止める安全装置が効くため）。LiDAR を外して配線だけ確かめたいときは、開発モードで
> 「LiDAR 途絶のフォルト」と「LiDAR 無しの手動停止」の 2 つを外す
> （`dev_ignore:=lidar_fault,scan_stop`）。このとき**障害物では止まらない**ので、
> 車輪を浮かせるか周りに何も無い状態で行う。

**項目3: IMU／項目4: LiDAR**

自動確認のみ。「確かめる」を押すと判定（✓／!／×）と理由が出る。
**要確認・NG のとき「校正へ」が結果の表の下に出る。** 押すと校正画面（§3-9）へ進む。

**故障診断（非常停止ボタン・モーターが NG のとき）**

結果の表の下の「故障診断へ」から、故障診断画面に入る。左に症状（どの点検がだめで、測った値は何か）、
右に NG の内容に応じた**チェック手順**（配線・極性・電源・バイパスの確認など。図と 1 行の並び）が出る。
**項目を押すと ✓ が付く**（画面の中だけの控えで、記録しない）。
下端は左が「やめる」（一覧へ戻る）、右が **「始業点検へ戻る」**（直ったか見る）。
この画面は診断結果を示すだけで、修理は人が行う。直ったら「始業点検へ戻る」で始業点検をやり直す。
（手順の正本は `th_ws/src/th_maintenance/config/repair_hints.yaml`。直したら
`python3 th_ws/web_ui/scripts/gen_repair_hints.py .` で画面用の json を作り直す。）

### 3-9. 校正（メインメニュー →「点検と校正 ▸」→「校正」。始業点検の「校正へ」、設定の「校正で変更する」からも入れる）

**`IDLE` か `MANUAL` からしか入れない**（始業点検と同じ）。**校正は始業点検と違い、機体が自律で走る・回る。**
押している間だけ動くのではなく、**止めたいときは下端左の「やめる」か非常停止**。
**周囲 2 m 以上を空け、すぐ止められる位置に立つ。** メジャー（直進）か分度器（旋回）を用意する。

画面は左に項目の一覧、右に選んだ項目の手順が出る（タブは無い）。左上は「戻る」。手順の下端は
**左が「やめる」、右が進むボタン**で、位置は段が進んでも変わらない。

> **必ず直進 → 旋回の順にやる**（車輪半径と車輪間距離は互いに影響する）。旋回の行に
> 「先に直進校正を実施してください」が出る。直進が未実施・旋回より古いときは案内にも警告が出る。

**途中で別の操作をしてよい。**校正の途中でも、**一覧の別の項目・「履歴」・「戻る」は押せる**。
押すと実行中の校正をやめ（補正値は確定しない）、押したものへ移る。**「やめる」を先に押す必要は無い。**
途中で押せないのは、機体が自律で走っている間の「走らせる」だけ。

**一覧（左）**: 直進／旋回／IMU／LiDAR 死角の各行に前回の校正日・**前回検証誤差**が出る。
**「要校正」の印は出さない**（いつ再校正するかは使用者が決める。判断の材料として前回校正日と
検証誤差の履歴を見る）。行を押すとその項目の手順が右に出る。**履歴**は右上の「履歴」ボタンで開く。

**直進・旋回（段の印は 案内／実行／確認／検証）**。進むボタンの語は段で変わる（同じ場所）。

1. **案内**: 走る距離（直進は 1 m）・回る角度（旋回は 180°）を読み、右下の**「走らせる」**（機体が動くので緑）を押す。
2. **実行**: ロボットが自律で走る・回る。止まったら次の段へ自動で進む。
3. **確認**: **実際に進んだ距離（m）／回った角度（°）をメジャー・分度器で測って入力**し「確定する」。
   補正前後の値が出る。**プレビューが出てはじめて進める。**
   「補正が大きすぎます」と出たら測り直す（直進は ±10% まで。それ以上のずれは校正ではなく
   機械の異常）。
4. **検証**: 補正を適用してもう一度同じだけ走る・回る。終わったら**また実測値を入力**して
   結果を送る。許容範囲内なら確定して一覧に戻る（右下は「完了」）。

- **検証で許容範囲を超えたら、補正は適用前に戻り、「実行」の段に戻る。** 理由が出る。もう一度走らせる。
- **許容範囲（`calib_linear_tolerance_ratio`・`calib_rotation_tolerance_deg`）は未確定**（registry の placeholder）。
  **値が入っていないと検証は必ず NG になる**（理由に「許容範囲が未確定」と出る）。試すときは起動後に
  `ros2 param set /calib_runner calib_linear_tolerance_ratio 0.05` のように入れる。
- 「やめる」・非常停止・フォルト・モードが変わったとき: 機体はその場で止まり、適用していた補正は元に戻り、**確定しない**。
- **旋回の速さは毎回 0.45 rad/s 一定**（`calib_rotation_w_rps`）。車輪間距離の校正値では変わらない。
  終わりぎわも 0.40 rad/s（`turn_in_place_w_min_rps`。モーターの不感帯の上）を下回らない。
  前方に障害物があると安全装置が旋回を絞るので、**絞られた回は使わず**「旋回が安全装置に絞られたため、
  この測定は使いません」と出る。周囲を空けて測り直す。

**IMU（段の印は 案内／測る／確定。右下は「始める」→「確定する」）**: IMU を機体から外して手に持ち、いろいろな向きに傾けて数秒ずつ静止させる（画面の図が傾ける角度を 0°・90°・180°・270°・45°・315° の順に示す。加速度）。
**地磁気は 8 の字に動かす**（機体は自走しない）。システム・ジャイロ・加速度・地磁気が
全部 3/3 になると自動で完了し、「確定する」を押す。

**LiDAR 死角（ロボットは動かない。段の印は 選ぶ／確かめる／確定）**

死角マスクは「その角度の点を**障害物として見ない**」設定。**広げすぎると本物の障害物が見えなくなる**ので、
次の上限を超える選択は機体が適用しない: **1 区間 30°・総幅 90°・8 区間まで**（出荷時の実機は 4 区間・約 68°）。

1. **選ぶ**: 右下の「スキャンを表示する」。画面に**ライブスキャン（死角除去前の生スキャン。上が前方）**が出る。支柱など
   写り込んでいる帯を**指かマウスでなぞって**選ぶ（灰色＝登録済み、選択中は別の濃さ）。最初から登録済みの区間が
   選択に入っている。区間ごとの「削除」・「全部外す」・「登録済みに戻す」で編集できる。上限を超えると文言が出て
   「確認（プレビュー）」が押せない。**生のスキャンがまだ届いていないと進めない**（登録済みの死角を消さないため。届くまで待つ）。
2. **確かめる**: 「消える点: N 点」と総幅が出る（スキャン上の点が、選ぶと消える点）。
   選び直したいときは同じ画面でなぞり直して確認し直す。よければ右下の「確定する」で適用して検証へ進む。
3. **確定**: 3 つのノード（`lidar_filter`＝地図用スキャン、`obstacle_limiter`＝安全判定、`opcheck_runner`＝始業点検）へ
   **同時に**適用し、数秒スキャンを集めて確かめる。**選んだ範囲の点が `/scan_filtered` から消えていること**と、
   **恒常的に写り込む帯が選んだ範囲の外に 5° を超えて残っていないこと**が合格条件。合格すると確定して一覧に戻る
   （実機の操作は不要。実測値の入力は無い）。

- **検証で不合格なら、3 つとも適用前に戻り、「選ぶ」の段に戻る。** 理由が出る（「選んだ範囲の外に写り込みが残っています」など）。
  選び直して確認からやり直す。
- **どれか 1 つのノードにでも届かない・拒否されたら、全部が適用前に戻る**（地図用と安全判定で食い違わせない）。
- 空（全部外す）も選べる。ただし写り込みがあると検証で不合格になる。
- **`obstacle_limiter` は自分でも上限を検査する**（画面・校正を通さずに `ros2 param set` で上限違反の値を入れても拒否して古い値のまま）。
  死角に向かう方向へは速度が `v_reverse` に絞られる（死角方向の安全マージン）。
- 確定値は `/root/th_data/calib/current.yaml` の `BLIND`。**次回の bringup 起動時に、registry の出荷値より優先して
  上記 3 ノードの `blind_angle_ranges` に入る**（上限違反の値が入っていたら使わず出荷値に戻る。ログに警告が出る）。

**履歴（右上の「履歴」）**: 項目ごとに過去 3 世代の補正値と日時。「この値に戻す」で 1 つ前などへ戻せる
（**二段階**: 1 回押すと「本当に戻す？」に変わり、10 秒以内にもう一度押すと戻る。一覧の状態のときだけ押せる。直進で ±10% を超える値、死角で上限を超える値には戻せない。死角は 3 ノードへ同時に戻る）。右下の「閉じる」で一覧へ戻る。

**完了後**: 結果の下の **「始業点検へ」** で直ったか確認する。確定した値は `/root/th_data/calib/current.yaml`
（履歴は項目ごとに `history/<項目>/`）。次回の bringup 起動時に自動で `esp32_bridge` へ反映される。

### 3-10. 運用の終了（メインメニュー右の「運用の終了」→「制御系を停止する」）

1 日の運用を終えるときは、走行をやめてメインメニューに戻してから、
「運用の終了」カードの **「制御系を停止する」** を押す（「終了」という語は
方式を抜ける操作に使っているので、ここではこの名前にしている）。
未保存のデータがあれば件数が出る。いま機体側で検出できるのは
**試験場内地図**（画面から地図作成を始めて、まだ保存も破棄もしていない）と
**教示経路**（記録したまま保存も破棄もしていない）。ボタンを押すと一覧が出て、項目ごとに
**「保存」／「破棄」**（破棄は 2 度押し）を選ぶ。「保存」「破棄」は本当に保存・破棄し、
機体側の一覧から消えたのを確かめてから「処理済み」にする（消えなければ項目の下に
理由が出る）。**未保存が残っている間は「停止する」を押せない**（理由も出る）。
校正の補正値・教示再生中の地図の書き足しは、まだ機体側で未保存を検出できない
（検出できるようになるまで一覧に出ない）。

未保存が無くなると「停止する」を押せる。押すと（約 0.5 秒後に）制御系（bringup）が止まり、
画面に「停止しています…」→ **「停止が完了しました。電源を切って構いません」**
が出る。**完了が出てから機体の電源を切る。** そのあと PC 側は Ctrl-C で
`start.sh` を終わらせる（停止要求で bringup が止まっているので立て直さない）。

> `ros2 launch` で直接起動した場合は、停止要求の印ファイル
> （`th_ws/data/.control_stop`）が残る。次に `./start.sh` を起動するときに
> 自動で消すので、そのままでよい。

## 4. SLAM と地図

### 4-1. SLAM は何をしているか

LiDAR で周囲の壁を見て地図を作り、その地図の中で自分の位置を割り出している。
**車輪の回転数だけだと、滑りや誤差が積み上がって 100m 走ると数 m ずれる。**
SLAM はそれを壁の見え方で常に補正する。

`enable_route_slam:=true` を付けないと SLAM は起動せず、車輪の回転数だけの推測になる。
10m 程度なら走るが長距離では合わない。

### 4-2. 1 周して戻ったとき、地図の継ぎ目（壁の二重）は正常

**一周して元の場所に戻る経路を教示・再生するとき、タブレットの地図で開始地点付近の
壁が二重に（ずれて）描かれていることがある。これは正常であり、操作をやり直す必要は
無い。**

SLAM の「ループ閉じ込み」を**意図的に切っている**ためです。ループ閉じ込みは一周して
戻ったときに地図を過去に遡って作り直して壁を一本に繋ぐ代わりに、**それまでに記録した
経路を補正前のフレームのまま残す**ため、経路と地図がずれて壁に埋まります（2026-09-03
の実機で、1 周 185 m の教示の最中に記録点が 0.1 秒の間に 4.09 m 跳び、経路が壁に
埋まりました）。経路と地図を同じフレームに保つことを優先するため、ループを閉じずに
継ぎ目のままにしています。

| 見た目 | 判定 | 次にやること |
| --- | --- | --- |
| 開始地点の壁が**1本**に重なっている | ループが（偶発的に）繋がった | そのまま再生してよい |
| 開始地点の壁が**二重・ずれて**描かれている | **正常**（ループ閉じ込み OFF） | そのまま再生してよい |

> トレードオフとして、絶対的な終点の誤差にはドリフトぶん（実測 185 m で約 4 m ≒ 2%）
> が残ります。再生は地図と同じフレームの経路をなぞるため、**終点の誤差は数 m 程度
> 見込んで**始点マークを置く・機械と人の間に十分な余裕をとってください。

### 4-3. なぜ再生前に地図を読み直すのか

1 周 185 m の教示を終えたあと、ロボットは**物理的に始点マークの上に居ながら、
地図座標では約 4 m 手前に居ると思っている**ことが実測で分かっている
（ループ閉じ込みが次の再生までに 4.09 m 補正していた差。§4-2 で切った）。

**手で機体を動かしても「自分がどこに居ると思っているか」は変わらない。** 車輪の
累積誤差ぶん、自己位置が地図上の経路始点とズレたまま再生を始めると、経路を外れて
走る。そこで**教示時に地図を保存し、再生時に読み直して自己位置を経路の
始点に合わせる**（§4-4）。

また**教示中と再生中では SLAM の挙動が異なる**:
- **教示中（地図作成）**: 走りながら新しいスキャンを地図に描き足し、地図を広げていく。
- **再生中（自己位置推定 / 地図凍結）**: **再生中は地図作成が止まり、地図は変わらない。ロボットは出来上がった地図の上で自分の居場所だけを推定する**。
  再生中も地図作成が動いていると、自己位置の僅かなズレで新しい壁が描き足されて地図が汚れ、
  推定がさらにズレて発散してしまう（実機で確認された欠陥を防止）。

読み直しで地図が凍結され、自己位置が経路の始点（初期姿勢）に一致するため、教示で作った地図の上を正確に再生できる。

### 4-4. 地図の保存と読み直し（「保存」と経路選択で自動）

- **教示の開始**: 教示に入る（経路選択）と地図を**まっさらに作り直して**から記録する（§3-3）。
  起動からの地図・前の再生の地図は引き継がない。
- **教示**: 「保存」を押すと、経路（`.json`）と**一緒に地図（`.posegraph` / `.data`）も
  保存され、地図が凍結される**（`th_ws/data/routes/<経路名>.posegraph` など）。地図の書き出しが入るため
  **保存に数秒かかる**（§3-3）。
  - **同じ名前で保存し直すと、経路と地図の両方が旧版 1 世代残る**
    （`<経路名>.prev` と `<経路名>.prev.posegraph` / `.prev.data` /
    `.prev.pgm` / `.prev.yaml`）。新版がおかしいときは、ファイルを戻して旧版に戻せる
    （下の手順。経路と地図は名前が対になっているので、必ず対で戻すこと）
  - 戻し方（コンテナの中。`<経路名>` を置き換える。**再生を止めた状態で**行うこと）:

    ```bash
    cd /root/th_data/routes
    mv '<経路名>.json' '<経路名>.json.bad'
    mv '<経路名>.prev' '<経路名>.json'
    for e in posegraph data pgm yaml; do
      mv "<経路名>.$e" "<経路名>.$e.bad"
      mv "<経路名>.prev.$e" "<経路名>.$e"
    done
    ```

    戻したら教示再生の画面で経路を選び直す（地図の読み直しが走る）。
- **再生**: 経路を選ぶと、教示時に保存した地図が**自動で読み直され、地図を凍結したまま自己位置推定モードに切り替わる**（§4-3）。その際、自己位置が経路の始点に合わせられる。だから**機体を始点マークに置いてから経路を選ぶ**（§3-4）。再生中は地図作成に戻らず、凍結された地図の上で自己位置推定だけを継続する。
  - **経路を選ぶと、SLAM（`slam_toolbox`）が一度自動で再起動される。** そのため
    「この経路で進む」を押してから**「推定できました」に変わるまで数秒〜数十秒
    かかる**（地図が大きいほど長い。校舎 1 周級で 40 秒前後）。画面が
    「初期姿勢を推定しています…」のまま数十秒動かなくても、この間は正常。
    1 分近く経っても進まないときだけ §4-6。

操作者が手でコマンドを叩く必要は無い。

### 4-5. 地図をリセットする（やり直したいとき）

**通常の教示→再生の流れではこのリセットは使わない**（§4-4 のとおり、地図は
「保存」と経路選択で自動保存・自動読み直しされる）。**教示と再生を別々の起動セッションで
やっても問題ない**（経路選択のたびにその経路の地図を読み直すため。2026-09-04 以降）。
ここを使うのは「**地図が壊れたので作り直したい**」といった、**地図を捨てて最初から
やり直したいときだけ**。

**ロボットを始点マークの上に置き、停止している状態で**、スクリプトを 1 回実行する。

```bash
docker exec -it th_robot bash /root/th_ws/scripts/reset_map.sh
```

> **⚠ 停止中（IDLE・PREP の地図作業中）に実行すること。** 走行中・手動走行中・
> ジョグ中に実行すると機体側が拒否する（応答に「停止中（IDLE・PREP の地図作業中）
> のみ操作できます」と出る）。地図を捨てた瞬間にロボットは自分の位置を見失う
> ため、必ず止めてから。

最後に **`=== 完了。教示再生の画面に戻って再生してよい ===`** と出れば成功。
`NG` が出たら**そのまま再生しないこと**（§7 へ）。

<details>
<summary>スクリプトが中で何をしているか（手で叩きたいとき）</summary>

```bash
# ① 地図を捨てて SLAM を作り直す（数秒かかる）
ros2 service call /slam_control/discard_map std_srvs/srv/Trigger

# ② slam_toolbox が戻るのを待つ

# ③ 地図作成を再開する ← 忘れると再生が壊れる
ros2 service call /slam_control/set_mapping std_srvs/srv/SetBool "{data: true}"

# ④ 確認
ros2 topic hz /map                     # 数秒に 1 回出ていること
ros2 run tf2_ros tf2_echo map odom     # 数値が出ていること
```

**③ を忘れないこと。** ① だけだと地図が空のまま止まった状態になり、
自己位置の補正がまったく効かない（車輪の回転数だけの推測に戻る）。
スクリプトを使うのはこの叩き忘れを防ぐため。

</details>

> **なぜ「手で始点に戻す」だけでは駄目なのか**: ロボットを物理的に動かしても
> 「自分がどこに居ると思っているか」は変わらない。地図を捨てると、今いる場所を
> 新しい地図の原点として認識し直すため、記録した経路の1点目（＝原点）と一致する。
>
> ただしこの方法では再生中に参照できる地図が無い（走りながら作り直す）ので、
> 経路の遠い側では誤差が大きくなる。このリセットは「地図が壊れた」ときの復旧手段
> と考える（別セッションで教示した経路の再生には**不要**。§4-6）。

### 4-6. 制約（現状）

- **別の起動セッションで教示した経路も再生できる**（2026-09-04 以降）。経路選択の
  たびに、その経路と一緒に保存した地図（`.posegraph`）を読み直すため。ただし
  **機体は始点マークに置いてから経路を選ぶ**こと（§3-4）。
  - 保存地図が無い経路（教示の「保存」が途中で失敗した、`.posegraph` ファイルが
    消えた 等）は再生できない。経路を選ぶと**「初期姿勢を推定しています…」のまま
    先に進まない**。1 分ほどで画面に「初期姿勢を推定できません。機体を始点マークに
    置き直すか、教示からやり直してください」と出るので、「終了」で抜けて教示から
    やり直す。
- **毎回ほぼ同じ物理位置・向きから始める。** 始点マークからずれた分だけ経路全体がずれる

## 6. 保存されるもの・その場所


| もの                               | 場所（PC 側）                     |
| ------------------------------------ | ----------------------------------- |
| 教示した経路                       | `th_ws/data/routes/<経路名>.json` |
| 教示の途中経過（記録中 10 秒ごと） | `th_ws/data/routes/<経路名>.wip`  |
| 同じ名前で保存し直したときの旧版   | `th_ws/data/routes/<経路名>.prev`（経路）＋ `<経路名>.prev.posegraph` / `.prev.data` / `.prev.pgm` / `.prev.yaml`（地図） |
| 生成されたパラメータ               | `th_ws/data/generated/`           |

> コンテナ内では `/root/th_data/` として見える（同じ場所）。
> 記録中は **10 秒ごとに途中経過が `<経路名>.wip` へ自動保存**される（`autosave_period_ms`
> で調整可。0 にすると無効）。**同じ名前で保存し直すと旧版は経路・地図ともに 1 世代残る**（最新と
> 1 つ前の 2 つだけ。世代番号も 1 つ進む）。`.wip` / `.prev` は経路一覧（教示再生の選択肢）には出ない。
> 旧版に戻す手順は §4-4。

**フォルトの履歴（機体のログファイル）**: 機体は異常が起きるたびに `th_ws/data/fault_log/fault_log.jsonl`
（コンテナ内では `/root/th_data/fault_log/fault_log.jsonl`）へ追記する。**1 件につき 2 行**で、
開始時に `ongoing`（継続中）、解消してしばらく後に確定行（`final`）が付く。同じ種別・開始時刻の行は
後のものが正。一定の大きさを超えると古い分は `fault_log.jsonl.1` へ退避する。時刻は機体の時計の epoch 秒で、
他のログと時刻を突き合わせて原因を調べるのに使う。画面で読めるのは直近 50 件（§3-5）。

| 配電盤を押すと「経路が見つかりません」の帯と移動を 10 秒ほどで繰り返し、その場で旋回し続ける（`ros2 topic hz /local_costmap/costmap` が 0 件） | Nav2 の controller が TF 停滞で経路を進めない（打ち切り→再送の繰り返し）。打ち切りが 3 回続いて機体が 20 cm も動かず `/tf` は新しいとき、機体が `evt.nav_tf_stall`（記録だけ。`controller_server` のログが届くかどうかは条件でない）と警告ログ `Nav2 TF stall を検知` を出す（止める・再起動は自動ではしない）。起動し直す。直らなければ `./start.sh stage:=3` で切り分ける |
| 再開（「走行する」「再開する」）を押したのに走り出さず経路待ち（`BLOCKED`）になった | 経路の先 1.5 m に障害物がある（または障害物マップが届いていない・古い）ため、走り出す前の確認で止めた（Spec-onsite §6.3）。障害物をどけると自動で走り出す。下の行も参照 |
| 障害物をどけたのに `BLOCKED` のまま走り出さない | 経路の先 1.5 m が空いたと確認できるまで待つ仕様（Spec-onsite §6.3）。コストマップ上に障害物が残っているか（WebUI のコストマップ）、`ros2 topic hz /global_costmap/costmap` が約 1 Hz で届いているか確認する。残っていれば下の幽霊マークの手動クリアか「再検索」。届いていなければ Nav2 の状態を確認する。機体のログに `障害物マップ未受信` / `更新されない` が出ていれば後者 |
| コストマップに何も無い場所が赤く残る         | 地図作成中に一時的に写り込んだ障害物（人など）が消えずに残る「幽霊マーク」（WS-9AC）。盤前移動の開始・再探索のたびに自動でクリアするようにした（2026-09-11）ので通常は自然に消える。WebUI 表示だけ気になる場合は `ros2 service call /global_costmap/clear_entirely_global_costmap nav2_msgs/srv/ClearEntireCostmap "{}"` で手動クリアできる |
| 当日地図を開くと配電盤・待機場所・自機の位置が地図とズレる | bringup を再起動するたびに地図の座標系はまっさらに始まり直すが、ピンはファイルに残って次回起動でそのまま使われる。**地図を保存し直さないまま再起動を挟むとピンと地図の座標系が食い違う**（WS-9AL・2026-09-11）。「会場地図を開く」時にこの食い違いを検知するようにしたので、注意書きが出たら前日の `PREP` に戻ってピンを登録し直し、必ず「保存」を押す。予防策: `PREP` の作業中に bringup を再起動したら、続きの作業の前に一度ピンを登録し直して保存し直す |
| `/scan_filtered` が無音                      | LiDAR かネットワーク →[network.md](network.md)                                    |
| LiDAR の USB を抜き差ししたあと `LIDAR_LOST` が戻らない | ラズパイの見張りが自動で立て直す（約 10 秒以内）。30 秒たっても戻らなければ `journalctl -u rplidar.service` を見て、ラズパイで `sudo systemctl restart rplidar.service`（未導入の機体は [network.md](network.md)「rplidar の自動復帰の導入」） |
| `ESP32_DISCONNECTED` が消えない              | PC が**内蔵 Wi-Fi** でロボット AP に繋がっているか、ラズパイの `rpi-serial-relay` が動いているか確認 → [network.md](network.md) |
| 行き先（ピン・次の配電盤・待機場所・呼び寄せ）と「再開する」が押せず「会場地図を開いてから選べます」と出る（自己位置推定が落ちて立ち上がり直したあと） | 会場地図を持たないため自律移動を止めている（Spec-onsite §4.0.3）。「中断」→ 手動操作で待機場所へ戻す →「会場地図を開く」→「待機場所にいる」を宣言し直す（§3-4b S-21） |
| 再生を押しても動かない                       | 右列の確度が「位置が決まりました」になっているか。なっていなければ待つ（押すと理由が出る） |
| 経路の表示がガタつく・地図が重い             | ブラウザを再読込する                                                               |
| 走行中に理由不明で止まる                     | 止まっている理由の帯が出る（在席未確認／障害物／死角未校正）。異常の窓が出ているときは窓が理由を言う |
| 「タブレットの在席が確認できない」と出た     | アプリを前面に戻す。別タブ・別アプリになっているか接続が切れている。**画面を見ているだけなら止まらない**（2026-09-04 以降） |
| コマンドがトピックを見つけない・部分的に不通 | `docker restart th_robot` してから §1-2 の `./start.sh` をやり直す                |
| 起動直後から `esp32_bridge` / `obstacle_limiter` がすぐ落ちる、`slam_toolbox` が再起動を繰り返す | 前回の起動が生きたまま新しく起動した二重起動。手作業の `ros2 launch` なら次の起動が自動で前回分を止めるので、もう一度やり直す。**`start.sh` は確認のうえ止めて引き継ぐ**（§1-2 の表）ので、`他で起動している` と出たら内容を確かめて `y` を答える。それでも直らなければ報告する |
| 経路を選んでも「推定できました」にならない   | まず**待つ**。経路選択で SLAM が一度再起動されるので、切り替わりに数秒〜数十秒（長距離ほど長い。校舎 1 周級で ~45 秒）かかる（§4-4）。<br>1 分近く経っても進まないなら**地図の読み直しに失敗している**（§4-6）。教示の「保存」が完了しておらず地図ファイル（`th_ws/data/routes/<経路名>.posegraph`）が無い可能性。「終了」で抜けて**教示からやり直す**（別の起動セッションで教示した経路は再生できる） |
| 再生中に地図が汚れていく／経路を選ぶたび地図の形が変わる | 起こらないはず（2026-09-04 修正済み。地図は凍結され、経路選択のたび SLAM を作り直してから 1 回だけ読み直す）。起きたら報告する |
| 特徴の少ない長い廊下で機体位置が地図とずれる | まず `imu_enabled` が既定 true で効いていることを確認（§1-2）。低速で試す。<br>それでも残るなら、**メインメニュー →「設定」→「再生の位置合わせ」区分（再生の自己位置推定）**で **補正間隔を小さく／探索窓を広く** → 「YAML に保存」→ **もう一度「この経路で進む」**（保存しただけでは効かない。§3-6）。原理的に廊下は苦手なので、経路を短い区間に分ける・特徴のある側を通すのも有効 |

## 8. やってはいけないこと

- **物理の非常停止ボタンを外す・無効にする。** どんな場合も生かしておく
- **人が居る方向へロボットを向けたまま再生を始める**
- **教示と再生で開始位置・向きを変える**（§4-6）
- **`ros2 launch` のターミナルを閉じる**（ロボットが止まる）
- **ノードを `kill -9` で止める。** 通信の仕組みが壊れ、コンテナ再起動が必要になる。
  止めるときは `Ctrl-C`
