# WebUI の作り直し — 前提（現状の問題・数・動かせない制約）

起票 2026-11-12。[ui-redesign.md](ui-redesign.md) の詳細。**未確定の検討メモ**であり [spec/](spec/README.md) を上書きしない。

## 1. ユーザーの評価（2026-11-12）

* **1 画面の情報量が多く、使いにくい。**
* **機能が多いのでボタンが多く、複数のタブに分かれていて、目的のボタンがどこにあるか分からない。**
* メインメニューは多階層にして 1 画面のボタンを減らし、ボタンを大きくした分アイコンを入れて分かりやすくしたい。
* 試験場内の画面（試験準備・試験）もボタンの数を減らしたい。

## 2. ボタンとタブの数（実測）

## 4. 制約 — 動かせないもの／spec を改めれば動かせるもの

### 4.1 動かせない（安全要件・運用の前提）

| 制約 | 出典 |
| --- | --- |
| ヘッダは常に最上位。非常停止が隠れない | Spec-webui.md §0 原則 4・§1.1 |
| ページ全体はスクロールしない。非常停止の解除は下端に固定 | Spec-webui.md §1.5（**装飾ではなく安全要件**） |
| ブラウザ標準の確認ダイアログを使わない | Spec-webui.md §0 原則 5 |
| **画面がモードを決める**（ゾーンと速度上限が画面から決まる） | Spec-webui.md §0 原則 6・§2 |
| 走行方式どうしは直接移らない。必ずメインメニューを経由する | Spec-webui.md §2.1 |
| 「終了」を操作カードに入れない（一時停止のつもりで抜ける誤操作） | Spec-webui.md §3.3 |
| 運用を終える導線の語は「制御系を停止する」。**未保存に気づく唯一の機会**なのでメインメニューの一番上に置く | Spec-webui.md §3.2.1（F-23） |
| **呼び寄せと「人の位置で登録」は、対象が見えないまま実行させない** | Spec-webui.md §3.10・§3.11 |
| 「人の位置で」という語をラベルに入れる（2026-10-12 ユーザー決定） | Spec-webui.md §3.10 |
| 「会場地図を開いた」は機体が持つ。画面の中だけで持たない | Spec-webui.md §3.11（2026-10-13） |
| 外部から何も読み込まない（アイコンはインラインの SVG） | DetailedDesign-webui.md §9-5（U-3） |
| PC とタブレット、縦長と横長の両方で使える | Spec-webui.md §0 原則 2・3 |
| ジョグは「触れたら始まる」が唯一の入口。継続の合図を送り続ける | Spec-webui.md §3.3（U-16・F-29） |
