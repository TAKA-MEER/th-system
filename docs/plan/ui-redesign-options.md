### 1.1 R2 の細目（案）

* **(a) 同じ場所に、状態によって別の操作を出さない。**その場所のボタンは状態によらず同じ操作で、変わるのは押せるか押せないかだけ。
* **(b) 似た配置で中身が違う、を作らない。**画面どうし・階層どうしでも、同じ位置・同じ形のボタンが違う意味を持たないようにする。
* **(c) 状態で使えないボタンは、場所を保ったまま薄く表示する。**隠してよいのは、隠しても他のボタンが動かず、その場所に別のものが出ないときだけ。隠すかどうかは個別に決める。

**R2 に照らして見直すもの**:
* S-20 の右上の「次にやること」ボタン（いまは同じ場所で「地図作成開始」「対象を選ぶ」「待機場所を登録」…と語が変わる）。**(a) に反する**。無くすか、語を固定する。
* 「中断」（いまは一時停止と `BLOCKED` のときだけ現れる）。場所を固定して、それ以外は薄く表示する。
* メインメニューの階層（§2.3）。

### 1.3 ヘルプ表示 — **入れることに決定**（2026-11-15 ユーザー案。D19）

ボタンの説明を、求めたときだけ出す。原則 7（UI に説明文を置かない）は保ったまま、初めての人が語の意味を確かめられる。

| 項目 | 決めたこと |
| --- | --- |
| 出す・出さない | 設定（S-50）で切り替える。**初めは出す。切り替えた設定は次の起動へ引き継ぐ** |
| マウス | ボタンに重ねてしばらく（案の画面では 0.7 秒）で出る。外すと消える |
| タップ | 長押し（同 0.6 秒）で出る。その指を離してもボタンは押されない。閉じるボタンか、枠の外を押して閉じる |
| 中身 | ボタンの名前＋押すと何が起きるか 1〜2 文 |
| 長押しの対象外 | 停止・ジョグのスティック・非常停止。止める操作を遅らせない。ジョグは「触れたら始まる」（[premises §4.1](ui-redesign-premises.md)） |
| 枠の外を押して閉じる | その 1 回はボタンの操作に数えない（閉じるだけ）。**ヘッダ（非常停止を含む）と、赤く表示される停止ボタンは対象外**で、ヘルプが出ていても 1 回で効く |
| 出す場所 | **ヘッダには絶対に重ねない。**停止ボタンはなるべく避ける（案の画面では、右列のボタンのヘルプを左の地図の上に出す） |

**まだ決めていないこと**: 説明文の置き場所（`使い方.md` と二重に持たない）。設定をどこに持つか（端末ごとか機体か）。

## 2. メインメニュー（S-01）の多階層化 — **M2（種類の順）に決定**（2026-11-13）

**前提**: 下の階層も **S-01 の中**に置く（モードは `IDLE`・場外・速度上限は停止のまま）。新しい画面 ID は作らない。
階層は **2 段まで**。下の階層の左上に「戻る」（一番上へ）。走行方式を抜けたら、入った階層へ戻す（例: 手動走行を「終了」→「走行」の階層）。

| **試験場 ▸** | 試験準備 ／ 試験（当日） |
| **走行 ▸** | 追従走行 ／ 手動走行 ／ 教示（追従） ／ 教示（手動） ／ 教示再生（**ライン誘導・電子リードは開発中止で削除**。2026-11-13） |

### 2.2 タイルの形

* アイコン（インライン SVG）＋ 語 ＋（押せないときだけ）理由 1 行。**語を主、アイコンを従**にする（初見では語で選び、慣れたらアイコンで選べる。2026-11-13 ユーザー所見）。
* **区画ごとに色分けする**（試験場・走行・点検と校正。一番上のタイルの線とアイコン、下の階層の帯にそろえる）。どこにいるか分かりやすい（2026-11-13 ユーザー）。
* **下の階層のボタンがすべて押せないときは、一番上のタイルにもそれを出す**（例: 人検出が止まっていて追従系が全部押せない →「走行」のタイルに「追従は人検出が止まっています」）。入ってから気づかせない。
* アイコンの候補（たたき台）: 試験場＝地図 ／ 走行＝ハンドル ／ 点検と校正＝チェックリスト ／ 自律測定＝計測器 ／ 設定＝歯車 ／ 試験準備＝地図とペン ／ 試験（当日）＝旗 ／ 追従＝人と矢印 ／ 手動＝スティック ／ 教示＝人またはスティックと記録の丸 ／ 再生＝三角と軌跡。

### 2.3 R2 (b) との関係

一番上と下の階層はどちらもタイルの並びなので、「似た配置で中身が違う」に当たりうる。次で見分けを付ける（案の画面で確かめる）。

* 下の階層は、上端に**いまの階層の名前とアイコン**（「走行 ▸」）を大きく出す
* 「戻る」の位置は全階層で固定（左上の操作バー。§4.1 の「終了」と同じ場所）
* 区画ごとに色の帯を変える（試験場・走行・点検と校正）— **採用**（2026-11-13）

## 3. 試験場内（S-20・S-21）のボタンを減らす

### 3.1 S-21 試験 — **F2（地図のピンを押して行き先を決める）に決定**（2026-11-13）

F1（状態ごとに右列を入れ替える）は R2 に反するので採らない。

| 場所 | 置くもの（状態によらず位置は固定） |
| --- | --- |
| 左上の操作バー | 終了 ／ **人検出 [止める │ 動かす] のトグル**（試験準備と同じ場所） |

| 右列の先頭 | いまの状態の文字（「待機中」「移動中: 盤 A-1 へ」「一時停止中」）＋操作カード: **[停止 │ 走行] のトグル**（一時停止中は「再開する」と書いて点滅。待機中は押せない）・手動・**中断（走行中も効く）** |

| 右列の下 | 盤の前: **測定機能へ ／ カメラ**（spec 2026-11-01 の版。いまの仮の「作業中 ON/OFF」を置き換える） |

| | いま | F2 |
| --- | --- | --- |
| タブ | 5（左右 2 列） | **0** |
| 見えるボタン（地図のピンを除く） | 待機 16〜17 ／ 一時停止 17〜18 | **どの状態でも同じ 9 個**（終了・停止│走行・手動・中断・待機場所・次の配電盤・呼び寄せ・測定機能へ・カメラ） |
| 一時停止中に押せないもの | 11 | 5（待機場所・次の配電盤・呼び寄せ・測定機能へ・カメラ） |

* **中断**（2026-11-13 ユーザー決定）: 移動中・一時停止中・呼び寄せの位置指定中に効く。止めて行き先の選び直しへ戻る（待機場所へは走らない）。**行き先を押したら即出発するので、誤選択からすぐ止める出口として要る。**いまの spec は「走行中（`NAV`・`ALIGN`）は出さない。停止してから中断」なので改める（Spec-webui.md §3.11・Spec-modes.md `SM-3.1.2-110`〜`-112`）。
* **「中断」の語**（D15）: 変えない。「停止」と語が近いので「行き先を取り消す」「選び直す」も比べたが、語が長いと認識しにくい。ほかの人には違って見える可能性があるので、別の語は案として残す（案の画面で切り替えられる）。
* **薄いボタンを押したとき**（D16）: そのボタンの押せない理由を出す。区切りは空白（「—」は「一時停止」の「一」と紛れる）。**画面の文言の区切りに「—」を使わない。**
* **停止│走行のトグルは大きくする**（D17）。幅と位置は変えない。案の画面では高さを出すために「操作」の見出しを外した。
* **近いピンの押し分けは作らない**（D18）。地図を拡大できる。
* **機体の印の下に、機体の大きさの四角形を描く**（D26）。地図の縮尺に合わせた実寸で、機体の向きに合わせて回る。案の画面の四角形は縮尺を仮に置いたもの。試験準備の地図にも同じ印を使う。
* **消すもの**: ピンの行ごとの「移動」×N（地図のピンで選ぶ）・3 か所の「会場地図を開く」・「地図の更新 OFF」（使えるようになるまで出さない。R2 (c) で隠してよい条件を満たす）・タブごとに出ていた「人検出を停止」（左上のトグル 1 つにまとめる）。
* **呼び寄せ**: 押すと主表示に対象のレーダーを重ねて 2 点指示へ。**対象が見えないまま実行させない**（§4.1 の安全要件）。
* **一日の始めの 2 手**（会場地図を開く・待機場所にいると宣言）: 地図がまだ出せない間は、**主表示の中央に**その 1 手だけを出す。右列のボタンの位置は変えない。R2 に当たらないかは案の画面で確かめる。
* **前提**: 地図が読めること・タブレットでピンが押せる大きさであること（[venue-map-readability.md](venue-map-readability.md)）。ピンの一覧が要るなら、地図の上に小さく重ねる。

| 項目 | 状態 | 案の画面 |

**どちらでも守っていること**: 印の名前と吹き出しは回さず正立のまま／機体の四角形（D26）・経路・壁は地図と一緒に回る／回しても地図が枠からはみ出さないよう縮尺を合わせる（全角度で機械検査した）／右列のボタンは動かない。

**擬似 3D の作り**（2026-11-16 にユーザーの指摘で作り直した）: 概念図をやめ、**実機が作った地図**（経路地図「試験ブロックC2」。287 × 199 マス・1 マス 0.05 m）を案の画面に埋め込んだ。占有のマスを高さ 0.5 m（仮）の箱に起こす。見下ろす角度は控えめにした（縦のつぶしを 0.56 → 0.80。真上が 1）。平面の表示も同じ地図を使う。ピン・経路・機体の位置は、この地図の空いている場所に仮で置いたもの。

**擬似 3D を試して分かったこと**（実物の地図で）:

* **高さの情報は地図に無い。**2D の LiDAR の地図は「そこに何かある」しか持たないので、高さは一律の仮になる。低い台と天井までの壁の区別は付かない。
* **実物の地図は壁がつながっていない。**点の集まりや途切れた線が多く、そのまま箱に起こすと細かい柱が散らばって見える。
* **壁を付けた**（2026-11-16 ユーザー指示）。占有のマスを次の順で加工してから、高さ 0.8 m（仮）の壁に起こす: ① 約 30 cm までのすき間をつなぐ（ただし空いていると分かっているマスは埋めない） ② 10 マス未満の点の集まりを捨てる。面は向きで明るさを分け、奥を向いた面は描かない。案の画面の切り替え「擬似 3D の壁」で、加工なし（地図のマスのまま）と比べられる。
  * **壁にしなかった小さい点は、壁より低い箱（0.25 m・仮）で出す**（2026-11-16 ユーザー指示）。消さないので、実在する細い脚などを見落とさせない。色も壁より沈めてある。
  * **表示のための加工で、走行に使う地図は変えない。**壁か小さい点かの区別は見た目だけのもので、障害物としての扱いは同じ。
  * **地図の色の選択肢**（同日ユーザー指示。床・壁の横・壁の上を大きく違う色に）: 切り替え「地図の色」で、いまの色／紺の床・橙の壁・明るい壁上／明るい床・灰の壁・水色の壁上 を比べられる。平面の表示にも効く（床と壁の色）。明るい床でも読めるよう、経路の線と印の柱に暗い縁を付けた。色そのものは仮（自分が選んだ）。
  * 最初に試した「空いているマスも含めてつなぐ」は、壁が太い塊になり通路をふさいで見えたのでやめた。
  * 壁の線は地図のマスの向きに沿うので、地図を回すと階段状に見える。なめらかにするには線の当てはめが要る（未検討）。
* 角度を控えめにしたので、手前の壁が奥を隠すことは少ない。そのぶん**向きを変えないと平面との差が小さい**。
* ピンを押す位置が地面から浮く（印を柱で持ち上げている）。地図をタップして登録する方式は、斜めの見え方では位置がずれやすいので、**登録のときは平面に戻す**のが安全（自分の考え）。
* 回すと、地図の四隅が枠に収まるよう全体が小さくなる（平面でも同じ）。実装では拡大・移動と合わせて考える。
* 実装の負担: いまの地図は平面の画像の上に印を重ねている。占有のマスを箱に起こす処理と重ね順の処理が新しく要る。案の画面では箱が約 1,300 個。描画の速さは測っていない（タブレットでも未確認）。

### 5.1 追加の要望（2026-11-16 ユーザー）と案の画面の切り替え

| 要望 | 案の画面 |
| --- | --- |
| 非常停止をよりボタンらしく（D29） | 角丸・明るい縁・下の影で立体にし、押すと沈む。ヘッダの中に余白を取った分、高さが少し減る。**実装では「画面で一番高いボタン」の寸法の決まり（Spec-webui.md §1.1）を保つ**（ヘッダの 2 段目を広げる） |
| フォントを比べたい | 切り替え「フォント」: 端末の標準／Noto Sans JP／BIZ UDPゴシック／IBM Plex Sans JP／M PLUS 1p／Zen 角ゴシック New。候補は自分が選んだもの（どれも SIL OFL で同梱できる） |
| ボタンの形のバリエーション | **「役割で変える」に決定**（D32。出発するボタンは丸、道具のボタンは角、「終了」は片側だけ丸）。案の画面の既定にした。ほかの形（角丸／角ばった／丸い）は切り替えに残してある。アイコンだけのボタンは、どれに使うかが決まってから |

* どの切り替えでも、右列のボタンの位置と大きさが全状態で変わらないことを機械検査した（フォント 6 種 × 全状態 × 横長・縦長、形 4 種）。
* **フォントは実装で同梱が要る。**機体のネットワークはインターネットに出られない。日本語フォントは 1 つの太さで数 MB あるので、使う太さを絞る。BIZ UDPゴシックは太さが 2 段階だけ。
* 検査の途中で、状態の行が長いと折り返してボタンが下へずれることが分かった（字幅の広いフォント）。**状態の行は高さを固定し、折り返さない**ことを R2 の細目に足す。
