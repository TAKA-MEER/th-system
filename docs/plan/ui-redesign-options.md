## 1. 全画面に効く規則（案）

| # | 規則 | ねらい | 改める spec |
| --- | --- | --- | --- |
| R1 | **1 画面 1 目的。**その状態で「次にやること」を 1 つ大きく出し、ほかの操作は 2〜3 個まで | 目的のボタンを探させない | U-14・§3.10・§3.11 |
| R2 | **隠すか薄くするかを 1 つの規則にする。**状態の上で意味の無い操作は**隠す**（移動中の行き先・何もしていないときの停止など）。前提が足りないだけの操作は**薄く出して理由を添える**（人検出が止まっている・経路が 0 本など） | 薄いボタンの列を無くす（S-21 一時停止で 11 個） | `SM-3.1.2-118`・U-15「格子は固定」 |
| R3 | **平常のときは何も出さない。**注意の色（黄・赤）は異常のときだけ。「障害物情報なし」「確認中」「再生中」は出さないか、灰色の小さな文字にする | 本当の注意を埋もれさせない（C11） | §3.3.1 に「注意の色」の行を足す |
| R4 | **いまの状態は操作カードの上に大きな文字で 1 回だけ出す**（「一時停止中」「移動中: 盤 A-1 へ」）。ボタンの色で状態を読ませない | 青＝いまの状態の決まりが読めない問題（C12・A-9 の 6）。重複（C3）と浮いた表示（C13）もまとめて消える | U-17 |
| R5 | **縦長は 1 列。**主表示（地図・レーダー）を上、操作を下 | 折り返しと余白（C15） | 原則 3 の具体化 |
| R6 | 見出しとモードの札が同じなら札を出さない | C10 | §1.3 |

R2 と R4 を入れると、操作カードの固定格子（U-15）は「置く位置は固定、出すかどうかは状態で決める」に読み替える。
「終了」を操作カードに入れない決まりは残す。

## 2. メインメニュー（S-01）の多階層化

**前提**: 下の階層も **S-01 の中**に置く（モードは `IDLE`・場外・速度上限は停止のまま）。新しい画面 ID は作らない。
階層は **2 段まで**。下の階層の左上に「戻る」（一番上へ）。走行方式を抜けたら、入った階層へ戻す（例: 手動走行を「終了」→「走行」の階層）。

### 2.1 一番上の階層 — 分け方の 2 案

| | 案 M1: 使う順 | 案 M2: 種類の順 |
| --- | --- | --- |
| 大タイル | **試験（当日）**・試験準備・**走行 ▸**・**点検と校正 ▸**・自律測定 | **試験場 ▸**・**走行 ▸**・**点検と校正 ▸**・自律測定・設定 |
| 一番上のボタンの数 | 5〜6 | 5 |
| よく使うものまでの押す回数 | 試験（当日）は 1 回 | 試験（当日）は 2 回 |
| 下の階層 | 走行（7）・点検と校正（始業点検・校正） | 試験場（準備・当日）・走行（7）・点検と校正（2） |
| 設定 | 右上の小さなボタン | タイル |
| 向き | 試験の日に毎日使う | 機能の数が増えても形が崩れない |

**どちらの案でも一番上に残すもの**: 接続確認の要約（緑・黄・赤の点と 1 行）・バッテリー・**運用の終了（未保存の件数と「制御系を停止する」）**。
運用の終了は F-23 の唯一の機会なので、下の階層へ入れない。

### 2.2 タイルの形

* アイコン（インライン SVG）＋ 語 ＋（押せないときだけ）理由 1 行。横長で 3 列、縦長で 2 列。
* **下の階層のボタンがすべて押せないときは、一番上のタイルにもそれを出す**（例: 人検出が止まっていて追従系が全部押せない →「走行」のタイルに「追従は人検出が止まっています」）。入ってから気づかせない。
* 自律測定（S-60。spec は 2026-11-01 に追加、実装はまだ）の置き場所を最初から取っておく。
* アイコンの候補（たたき台）: 試験（当日）＝旗 ／ 試験準備＝地図とピン ／ 走行＝ハンドル ／ 点検と校正＝チェックリストとスパナ ／ 自律測定＝計測器 ／ 設定＝歯車 ／ 走行の下: 追従＝人と矢印・手動＝スティック・教示＝丸と軌跡・再生＝再生の三角と軌跡・ライン＝線・電子リード＝ひも。

## 3. 試験場内（S-20・S-21）のボタンを減らす

### 3.1 S-21 試験 — 2 案

| | 案 F1: 状態ごとに中身を入れ替える | 案 F2: 地図を主にして、ピンを押して行き先を決める |
| --- | --- | --- |
| 骨格 | 右列を「いまの状態の 1 枚」にする。地図未読込 →「会場地図を開く」だけ／宣言前 →「待機場所にいる」だけ／待機 → 行き先の一覧＋呼び寄せ／移動中 → 行き先と停止だけ／一時停止 → 走行・中断・手動／盤前 → 測定機能へ・カメラ・次の行き先 | 左の地図を大きくし、**ピンを押すと吹き出しに「ここへ移動」**。右列は操作カードと状態だけ |
| 行き先の選び方 | 一覧の行（ピン名）を押す →「走行」で出発。行の「移動」ボタンは無くす。「待機場所」は一覧の先頭の行（「次の行き先」の区画と統合） | ピンを押す →「ここへ移動」。「次の配電盤」「待機場所」は地図の上の小さなボタン |
| タブ | **なし**。対象選択（レーダー）は呼び寄せの流れの中で自動で出す。配電盤前の中身は盤前の状態で自動で出す | 同左 |
| 待機中に見えるボタン（今 16〜17） | 終了・手動・行き先 7 行・呼び寄せ ＝ **約 10**（行はボタンより目立たない） | 終了・手動・次の配電盤・待機場所・呼び寄せ ＋ 地図のピン ＝ **約 5** |
| 一時停止中（今 17〜18、うち押せない 11） | 終了・走行・中断・手動 ＝ **4** | 同左 |
| 長所 | 状態とボタンが 1 対 1 で、迷いにくい。いまの部品を流用しやすい | ボタンが一番少ない。「地図で場所を選ぶ」が直感的 |
| 短所 | 状態が変わるたびに右列が入れ替わる | 地図が読めることが前提（[venue-map-readability.md](venue-map-readability.md)）。ピンが小さいとタブレットで押しにくい |
| 改める spec | U-14・§3.11・`SM-3.1.2-118` | 同左（地図のピンを押して選ぶこと自体は §3.11 の「(a) ピンを選ぶ」に既にある） |

**どちらの案でも消すもの**: 「地図の更新 OFF」（使えるようになるまで出さない）・3 か所の「会場地図を開く」（地図未読込のときの 1 か所だけ）・「人検出を停止」の常時表示（呼び寄せの流れの中だけ）。
**どちらの案でも残すもの**: 呼び寄せでは対象のレーダーが見えてから 2 点指示を進める（§4.1 の安全要件）。

## 4. 作り直しを待たずに直すもの

次は作り直しの後も残る不具合なので、大きな変更を待たずに直してよい（[premises §3.2](ui-redesign-premises.md)）。

* C1 状態名が英語のまま（`i18n/states.js` に足す）
* C2 「Step 3/4」・ISO の日時
* C7 「(a)」の記号
* A-9 の 1（IMU の開始ボタンの語）・4（地図の保存をジョグ中に薄く）・7・8（窓の空行と見切れ）
* A-9 の 3（後方の死角の表記）— spec が先
