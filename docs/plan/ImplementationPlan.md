## 2. 進め方の原則

| # | 原則 | 補足 |
| --- | --- | --- |
| 1 | **実装は Sonnet 5-high が行う** | 1 つの作業単位＝1 セッションで完結する形に分けてある |
| 2 | **実装 → 単体試験 → Gazebo シミュレーション → 実機試験 → 次の段階** | 段階を飛ばさない |
| 3 | **人が関与するのは「管理者権限が要る操作」と「通電した実機での確認」だけ** | それ以外は自動 |
| 4 | **実機はモータの電源だけ切って PC に繋ぐ**（ESP32 も USB 接続） | 疎通確認・モード遷移・UI 操作・フォルト検知の時間測定まで**人の関与なしで**できる |
| 5 | **完成の判定は実行できるコマンドで行う** | 「できたと思う」で先に進まない |

**通電（モータを回す）が要るのは走行を伴う確認だけ**——制動距離の測定、物理非常停止の動作確認、直進・旋回の校正。

## 3. 全体像 —— 9 段階

**「終わりに何ができるようになるか」で読む。**

> **「段階」と `stage:=N` は別物。**ここでいう段階 0〜8 は作業の順番であり、
> `bringup.launch.py` の起動引数 `stage:=1`〜`4`（どのノード群まで起動するか）とは
> 一致しない。例: 試験場内動作（段階 6）は `stage:=4` で起動する。

## 7. 用語

| 語 | 意味 |
| --- | --- |
| **作業単位（`WP-…`）** | 1 セッションで完結する作業のまとまり。48 個ある |
| **状態遷移表** | 「どのモードで・何を操作したら・何が起きるか」を並べた表。**表にない動きは起きない** |
| **故障注入** | わざと壊して、ちゃんと止まるかを確かめる試験 |
| **教示** | 人が一度走らせて、その道を機体に覚えさせること |
| **通電 / 電源断** | 通電＝モータを回せる状態。電源断＝モータの電源だけ切って PC と繋いだ状態 |
| **Gazebo** | ロボットのシミュレータ。実機を使わずに動作を確かめる |
