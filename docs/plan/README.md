## 運用ルール: 本体は一目で読める分量に保ち、詳細は別ファイルに分ける

検討が進むと本体ドキュメントは必ず肥大化する。読み返す人（と AI）が全体像を
掴めなくなるのを防ぐため、以下の構成を守る。

### 本体（`<テーマ>.md`）に置くもの

* **結論**（数行）
* **比較表**（判断に使う軸と数値。表そのものが要約になっているもの）
* **次にやること**のリスト
* 詳細ファイルへのリンク一覧

**根拠・計算・各案の詳細な長所短所・却下理由は本体に書かない。**
「一目で読める」＝スクロールせずに何が結論かが分かる状態を維持する。

### 詳細ファイル（`<テーマ>-<側面>.md`）に置くもの

テーマ名を接頭辞にして分割する。1 ファイル 1 側面。

| 側面 | 典型的な中身 |
| --- | --- |
| `-premises` | 前提・制約・実測値・測定が必要な項目・評価軸 |
| `-options` | 候補の詳細と比較 |
| `-recommendation` | 推奨・意思決定・関係者に確認する項目 |
| `-ideas` | 定石から外れた案・アイデア置き場 |

実例: `NewVISION.md` ＋ `transit-premises.md` / `transit-options.md` /
`transit-recommendation.md` / `transit-ideas.md`。

### 相互参照の書き方

* **同じファイル内**の節は `§0.1` のようにそのまま書く。
* **別ファイル**の節は Markdown リンクにする — `[§0.1](transit-premises.md)`。
  番号だけ書くとどのファイルの節か分からなくなる。
* `VISION.md` / `docs/architecture.md` の節を指すときは
  **必ずファイル名を付ける**（`VISION.md §8`）。plan 側の節番号と衝突するため。

### 分割のタイミング

* 本体が **200 行を超えたら**分割を検討する。
* 1 つの節が **本体の他の節より明らかに長くなったら**、その節を切り出す。
* 分割時は**文章を書き換えず、そのまま移す**。参照の書式だけ直す。
  移動と加筆を同時にやると、どこが変わったのか diff から追えなくなる。
