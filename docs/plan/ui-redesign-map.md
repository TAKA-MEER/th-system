# WebUI の作り直し — 地図の見え方（地図・点群・コストマップの色）

起票 2026-11-23。[ui-redesign.md](ui-redesign.md) の詳細。**未確定の検討メモ**であり [spec/](spec/README.md) を上書きしない。
地図が SLAM を知らない人に読めるかの検討は [venue-map-readability.md](venue-map-readability.md)（2026-10-07）。ここはその「A 配色」「B コストマップ」を、作り直しの色の決まり（D37・JIS 案・ISA-101 のグレー基調）に合わせて具体にしたもの。

## 結論（案）

* **地図は色相を使わず、濃淡だけで描く。**色（緑・黄・赤）は、地図の上でも機体の状態と操作の意味にだけ使う（D37）。
* **白い床＝機体の中心が通れる所、と読めるようにする。**未探索は画面の地と同じ色にして消し、壁は黒から中間の灰へ下げる。
* **点群（いま LiDAR に見えている点）は壁より濃い灰。**点が壁に乗っているかで、地図と位置がずれていないかを読める。**減速が始まる距離より近い点だけ注意の黄**にする。
* **コストマップは「入れない帯」（機体の中心が入ると壁に当たる帯）だけを薄い灰で描く。**避けたい帯（膨張半径 0.80 m まで）まで描くと床のほとんどが覆われて読めない（いまの実装の赤も同じ）。
* **経路が塞がれたとき（`BLOCKED`）は、塞いでいる所を注意の黄で示す**（コストマップの表示の切り替えによらず出す）。
* 案の画面の切り替え「地図の配色」「コストマップ」「点群の色」で、いまの実装と並べて比べられる。

## 層ごとの色

| 層 | いまの実装（`OnsiteMap.jsx`・`costmapPixels.js`） | 案 | 理由 |
| --- | --- | --- | --- |
| 地（未探索） | 灰 128（地図の外側は濃紺 `#20242c`） | **画面の地と同じ薄い灰**（明るい地で `#dde2e8`）。地図の外側も同じ色 | 灰の広い領域が「壁の外」に見える（venue-map-readability §1.2 の 1）。未探索は「まだ何も無い」として消す |
| 床（空き） | 白 | 白 | いちばん明るい＝自由に動ける所 |
| 壁（占有） | 黒 | **中間の灰**（`#7f8896`） | 黒だと点群と見分けられない。点群を一番濃くするため一段下げる |
| 点群 | 水色 `#00e5ff`（半径 1.2） | **濃い灰**（`#1f2733`）。**減速が始まる距離より近い点は注意の黄** | 水色は意味を持たない色（G2）。濃い点が中間の灰の壁に乗っていれば位置が合っている。近い点だけ色を変えると、色が状態に結び付く |
| コストマップ | 赤〜橙のヒートマップ（膨張の帯まで。既定で出す。S-50 で消せる） | **入れない帯だけ薄い灰**（Nav2 の値 99・100＝内接・致死のセル）。避けたい帯は描かない | 赤は止める操作と非常停止の色（D37・JIS 案）。危険やノイズに見える（同 §1.2 の 4）。入れない帯だけなら「白い所なら通れる」と読め、機体の大きさの感覚にもなる（同 §1.2 の 5・D26） |
| 経路が塞がれた所 | 無い（ヒートマップの中で見分ける） | **注意の黄の円（点線の縁）** | 「なぜ止まったか」を地図で一目に。`BLOCKED` の間だけ |
| 経路 | 水色 `#4fc3f7` | 進むの色（JIS 案は緑） | D37（作り直しの案の画面は既にこの色） |
| 機体 | 緑の丸（直径 9 px） | 進むの色の三角＋機体の大きさの四角（D26） | 既に決定 |
| ピン | 待機場所＝青・配電盤＝黄 | 中立の濃い灰、形で区別（D63） | 既に決定。黄は注意なので配電盤に使わない |
| 追跡中の人 | 橙の人型 | **選んでいるもの＝反転**（濃い人型）。案の画面には未作成 | 橙は注意の色（D37）。人はいつも注意すべきものではない |
| 地図をタップしたときの位置と向き | 紫の点線 | **選んでいるもの＝反転**（濃い灰の丸と矢印） | 紫は AI っぽさの代表の色（D42）。案の画面は「進む」の色で描いていたので直した（登録する位置は機体が進む先ではない） |

**数値の出どころ**: 機体は 0.55 m 角（内接半径 0.275 m）、グローバルのコストマップの膨張半径 0.80 m（`th_bringup/config/nav2_params.yaml`）。案の画面の帯は、埋め込みの地図の壁からこの値で計算した。実装では `/global_costmap/costmap` の値 99（内接）・100（致死）のセルを塗ればよく、機体側の変更は要らない。

## まだ決めていないこと

1. **コストマップをふだん出すか。**案の画面の既定は「入れない帯だけ」を出す。venue-map-readability の案 B は「既定で消し、スイッチで出す」。出しておくと「ここを通れるか」が分かる、消すと地図が軽くなる
2. 点群を黄にする距離。案の画面は機体から約 0.6 m（Spec-safety.md §2.1 の「減速が始まる距離」に合わせる想定）
3. 凡例を置くか。R8（説明の文を置かない）に合わせ、**ヘルプ表示（D19）で出す**案
4. 暗い地の配色（いまは明るい地だけを作った）。擬似 3D の地図はこの配色に合わせていない（「案の画面のこれまで」で描く）
5. 教示経路のプレビュー（S-13・S-14）も同じ配色にするか。いまの実装は `occupancyGridToPixels()` を試験場の地図と共用している
