# 新設計

この設計書は配電盤上部確認用ロボットの移動機構について、簡易的な追従走行試験の結果に基づき再設計する。

この設計書は内容の追記は人の手で行い、ClaudeCodeは提案と指示による整形のみ行う。詳細はAI(基本的にOpus5)が別ファイルに作成する。

## 目標

1. 人・物への接触 0 件、意図しない挙動 0 件
2. カメラ昇降が要求する許容差内に、手動微調整なしで停止できる
3. 地図作成＋盤登録が試験員1人で完結し、地図の手修正が不要
4. 保管場所⇔試験場を、試験員が付き添う以上の負担なく移動できる

### 走行方式KPI

全方式共通

| KPI                      | 数値     | 合否の目安                       |
| ------------------------ | -------- | -------------------------------- |
| 完走率                   | %        | 区間を介入なしで走り切れた割合   |
| 人の介入回数             | 回/100 m | 手動介入・E-Stop・リカバリの合計 |
| 経路逸脱（最大横ずれ）   | m        | 通路幅に対して                   |
| 実効平均速度             | m/s      | 記録項目（合否に使わない）       |
| 使い始めるまでの準備時間 | min      | 教示・線の確認・リード接続など   |
| 許可の要否               | 可否     | 足切り                           |

方式固有

| 方式              | 固有 KPI                                                                         |
| ----------------- | -------------------------------------------------------------------------------- |
| 1. 追従走行       | ロスト回数/100 m、ロスト→復帰時間、誤追従（別人・別物）回数、追従距離のばらつき |
| 2. 手動走行       | 操作者が画面を見ている時間の割合、WiFi 途絶起因の停止回数                        |
| 3-4. 教示（記録） | 記録の完走率、記録に要する時間、やり直し回数                                     |
| 5. 教示再生       | 終点位置誤差 [m]（＝ドリフト）、経路逸脱最大値、障害物遭遇時の挙動               |
| 6. 教示逆再生     | 同上（往路との差分で対称性を見る）                                               |
| 7. 区画線走行     | 線のロスト率、線が無い／途切れる区間の割合、分岐での判断成功率                   |
| 8. 電子リード走行 | 距離追従誤差、意図しない停止回数、リードの取り回しの実用性（定性）               |

盤前の向きの3方式も同じ枠で比較：平面検出成功率 / 法線誤差 [deg]（2点指示との差分で相対評価できる）/ 押下回数 / 盤が壁と面一のときの挙動。

MVP で残すか切るかの判断順：① 許可 → ② 完走率・介入回数 → ③ 安全（接触0・意図しない発進0）→ ④ MVP 期間内に作れるか。

## 制作の仕方

PoC後のMVP作成期間が短いためPoCで本ソフトウェアは候補の案全部乗せで開発し試験し、MVP開発段階で採用されなかったものを削って行く。方式ごとにKPIを設定する。

## 完成形の使い方

### 起動

1. 保管場所で機体の電源を入れる
2. 機体のWi-FiにPCを接続
3. PCのソフトウェアを起動(start.sh)
4. 各ネットワークデバイスがリンクする。トピックを送り合うなどで正常に通信できていることを自動で確かめる。webUIでそれを確認できるようにする。必須はESP32とRaspberryPI(LiDAR),PC、それ以外も接続されていれば正常か、起動しているか確認できる。
5. 一定時間接続できない場合は制御系を再起動する。(細かくはマニュアルを参照する)

### 保管場所から試験場への移動

1. PCのソフトウェアのwebUIから複数の走行方法から選択する。
   1. 追従走行　速度改善済み
   2. 手動走行  現行のまま
   3. 教示　追従走行
   4. 教示　手動走行
   5. 教示再生走行
   6. 区画線走行
   7. 電子リード走行
2. 試験場まで走行

保管場所以外からは教示はしない。教示再生走行は基本的に保管場所からのみ。できれば経路付近なら復帰できるようにしたい。

教示は何度も使う新規経路ができたとき、物の配置が大きく変わったときにする。

[各走行方法の詳細](NewDesign-transit.md)

### 試験場内の移動(前日)

1. 地図作成を開始する(教示再生用とは別の地図にする)
2. 待機場所に立って登録
3. 地図に待機場所ピンが立つ。この待機場所、姿勢を地図初期位置とする。
4. 追従で連れ回しながら地図を生成
5. 各盤の前で「ロボットに立ってほしい位置少し手前」に立って登録開始
6. 「ロボットに立ってほしい位置」に立って登録。同じ位置のボタンを2回おして位置と向きを登録する。
7. もしくはLiDAR平面認識による1ボタン登録
8. 地図に配電盤ピンが立つ
9. 地図を作り終わったら1ボタンで待機場所に戻す。
10. 必要に応じて地図を修正
11. 地図を保存

### 試験場内の移動(当日)

1. 必要なときにピンを選択する。
2. 登録済み座標へ Nav2
3. 到着後超信地旋回で向きを合わせる。
4. 作業が完了したら待機場所を選択する。
5. 待機場所へ Nav2
6. 必要なところに立ち呼び寄せを押す。
7. 試験員が退き次第、居た位置へ Nav2
8. 作業が完了したら待機場所を選択する。
9. 待機場所へ Nav2

### 配電盤前

ピッチ,ヨー,高さは別担当

低速での並進を担当する可能性があるがまだ含めない

### 試験場から保管場所への移動

保管場所から試験場への移動と同様。UIも分けない。

### その他仕様

## ハードウェア構成

### Wi-Fi AP

全ての機器の通信を中継する

### PC

ほとんどの処理を担う。機体に乗せる必要はなく、有線での接続はしない。

### ESP32

CuGoV3(モーターx2、エンコーダx2)、IMUと接続。

### RaspberryPi4

LiDARを接続。/scanをパブリッシュする
