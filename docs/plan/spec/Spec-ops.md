# 運用シーケンス（導入・起動・終了）

[Spec.md](Spec.md) の詳細。**1 日の始めから終わりまでに何が起きるか。**

---

## 1. 導入（1 台につき 1 回）

| 順 | やること | 詳細 |
| --- | --- | --- |
| 1 | PC で `setup.sh` を実行する | — |
| 2 | 起動し、**動作確認画面**から動作確認を行う | [Spec-checks.md](Spec-checks.md) §動作確認 |
| 3 | **キャリブレーション画面**を開き、較正を行う | [Spec-checks.md](Spec-checks.md) §キャリブレーション |

**操作系は WebUI のみ。**専用アプリやコマンドライン操作を運用手順に含めない。
`setup.sh` / `start.sh` は導入と起動の 2 か所だけで、それ以外に端末を触る場面を作らない。

---

## 2. 毎回の起動

| 順 | やること | 主体 |
| --- | --- | --- |
| 1 | 保管場所で機体の電源を入れる | 人 |
| 2 | 機体が張る Wi-Fi に PC を接続する | 人 |
| 3 | PC のソフトウェアを起動する（`start.sh`） | 人 |
| 4 | 各ネットワークデバイスがリンクする | 自動 |
| 5 | **トピックを送り合うなどして、正常に通信できていることを自動で確かめる** | **自動** |
| 6 | 結果を WebUI（起動・接続確認画面）で確認する | 人 |
| 7 | 一定時間つながらない場合は**制御系を再起動する** | 自動（§2.4） |

この間、モードは `INIT`。**必須通信系統がすべて疎通するまで `IDLE` へ進めない。**

### 2.1 疎通確認の対象

| 機器 | 扱い | 確認できること |
| --- | --- | --- |
| **ESP32** | **必須** | 通信可否、ホイールフィードバック、IMU データ、物理緊急停止ボタンの状態 |
| **RaspberryPi4（LiDAR）** | **必須** | 通信可否、スキャンが届いているか |
| **PC** | **必須** | 疎通を確かめる主体。自身のノードが起動しているか |
| Wi-Fi AP | **単一障害点として表示**（必須通信系統には数えない） | リンク状態・電波強度 |
| カメラ（区画線用） | 任意 | 接続されていれば正常か・起動しているか |
| リードデバイス | 任意 | 接続されていれば正常か・起動しているか |
| タブレット | 任意 | 接続台数・使用中かどうか |

**「必須通信系統」は ESP32・RaspberryPi4・PC の 3 者**と定義する。
Wi-Fi AP を数に入れない理由は [Spec-open.md](Spec-open.md) C-01 を参照
（AP は通信路であり、その障害は 3 者全滅として検出できる）。

### 2.2 疎通の合否条件

「リンクしている」だけでは足りない。**実際にデータが行き来していることを確かめる。**

| 対象 | 合格条件 |
| --- | --- |
| ESP32 | ホイールフィードバックが `esp32_alive_timeout_ms` 以内に届き続けている |
| ESP32 | PC が送った速度指令が折り返し確認できる（キープアライブが成立している） |
| RaspberryPi4 | スキャンが規定の周期・規定の点数で届いている |
| PC | 必要なノードがすべて起動している |

### 2.3 必須機器が繋がらないとき

| 状況 | 挙動 |
| --- | --- |
| 必須 3 者のいずれかが未疎通 | **運用に入れない。**`INIT` に留まり、主選択画面へ進めない。どれが繋がっていないかを画面に出す |
| 任意機器が未接続 | **運用に入れる。**該当機能のボタンだけ非活性にし、理由を出す（例：リードデバイス未接続 → 電子リード走行が選べない） |
| 動作確認の総合ステータスが NG | **運用に入れる（警告のみ）。**`C-r4` の解決。ただし必須通信系統の不通だけは別扱いで運用に入れない |
| **物理緊急停止ボタンが押されたまま** | **運用に入れない。**「解除してください」と案内する（`CL-B-6`） |

**開発モードでは**、機器未接続の警告を無視して先へ進める（[Spec-safety.md](Spec-safety.md) §10）。

### 2.4 再起動（`CL-B-2` / `E-4`）

| 項目 | 決めたこと |
| --- | --- |
| 何を再起動するか | **「制御系」＝ PC 側の ROS2 ノード群**。機体の電源は落とさない |
| 誰がやるか | **自動。**一定時間つながらなければソフトウェアが再起動を試みる |
| 進捗の提示 | 画面に「制御系を再起動しています（n 回目）」と出す |
| **一定時間の値・再試行の回数** | **未確定。**「実装をもとに作成するマニュアル」側に書くと原典が明言している（[Spec-open.md](Spec-open.md) O-d4） |
| 再起動しても直らない場合 | 手順を示して人の判断に委ねる（機体の電源再投入、AP の確認、ケーブルの確認） |

### 2.5 起動完了の提示（`CL-B-8`）

原典では起動完了の提示が **WebUI のみ**になっており、旧案の「起動ランプ」が消えている。
**現場で PC を見るとは限らない**ため、次の 2 つを両方持つ。

| 手段 | 内容 |
| --- | --- |
| WebUI | 起動・接続確認画面に機器ごとの状態と総合判定を出す |
| **機体側の表示** | 起動完了が機体を見ただけで分かる表示（LED 等）。手段の選定は詳細設計 |

### 2.6 毎回の起動で動作確認をやるか（`C-r5`）

| 項目 | 決めたこと |
| --- | --- |
| 導入時 | **4 項目すべてを人が実施する** |
| 毎回の起動時 | **自動で判定できる項目だけを自動実行する**（データ受信・値の範囲・死角マスクのズレ・物理ボタンの状態） |
| 走行を伴う確認 | 自動実行しない。人が動作確認画面から明示的に始める |
| 結果 | 起動・接続確認画面に総合ステータスとして出す。NG でも運用には入れる（§2.3） |

## 3. 1 日の流れ

```
[保管場所]
  電源 ON → Wi-Fi 接続 → start.sh → 疎通確認 → 主選択画面（IDLE）
     │
     │ バッテリー残量を確認する
     ▼
  走行方式を 1 つ選ぶ（7 つから） ────────────> [試験場] へ移動
     │
     ▼
  ＜前日の場合＞ 試験準備画面 → 地図作成・待機場所登録・盤登録 → 保存
  ＜当日の場合＞ 試験画面 → 待機場所を宣言
                    │
                    ├─ (a) ピンを選ぶ → 盤へ → 作業 → 次の行き先
                    └─ (b) その場で呼ぶ → 退く → 盤へ → 作業 → 次の行き先
                    │
                    ▼
                  待機場所へ戻る
     │
     ▼
  走行方式を 1 つ選ぶ（往路と同じ手順・同じ UI） ──> [保管場所] へ移動
     │
     ▼
  終了手順（§4）
```

**往路と復路を区別しない。**行きも帰りも同じ手順・同じ UI を使う。

移動の前に必ず**駆動用バッテリー残量を確認する**。
警告が出ていないことは長時間の動作を保証しない（[Spec-safety.md](Spec-safety.md) §8）。

## 4. 終了手順（`CL-B-3`）

原典に記述が無かったので新たに定める。**順序が重要**（保存前に電源を切ると作業が消える）。

| 順 | やること | 理由 |
| --- | --- | --- |
| 1 | 走行方式・試験モードを**終了**して主選択画面（`IDLE`）に戻す | 走行中に落とさない |
| 2 | **未保存のデータがあれば保存する**（試験場内地図・教示経路・較正値） | UI が未保存を検出して警告する |
| 3 | 主選択画面の「終了」を押す | 制御系を安全に停止させる |
| 4 | 停止が完了したことを画面で確認する | — |
| 5 | 機体の電源を切る | — |
| 6 | PC のソフトウェアを終了する | — |

### 4.1 未保存の検出

| 対象 | 未保存になりうる場面 |
| --- | --- |
| 試験場内地図 | 前日の作成中に終了しようとした |
| 教示経路 | 記録の途中、または保存可否を問われて答えていない |
| 較正の補正値 | ウィザードを検証まで終えずに離れた |
| 地図の書き足し（教示再生中） | 「地図の更新」を ON にしたまま走った |

いずれも**手順 3 の時点で検出し、保存するか破棄するかを問う**。
破棄は二段階（一度押してから確認）にする。

## 5. 目標との対応

| 目標 | この節との関係 |
| --- | --- |
| **G3** 地図作成＋盤登録が試験員 1 人で完結し、地図の手修正が不要 | §3 の前日フローが 1 人で回ること。**現状の所要時間が未取得**（[Spec-open.md](Spec-open.md) O-a3）でベースラインが無い |
| **G5** 往復＋準備＋試験を再起動なしで完走 | §3 の全体を通して `INIT` に戻らないこと。§2.4 の再起動が走らないこと。**n=1 で足りる** |

**G5 の測り方**: 1 日の運用（往復＋ N 盤）を通し、バッテリー交換・再起動なしで完走できるか。
途中で §2.4 の自動再起動が走ったら未達とする。
