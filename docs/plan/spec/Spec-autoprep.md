# 自動前日準備

[Spec.md](Spec.md) の詳細。**機体が自分で会場を回って地図を作り、盤のピンの候補を立てる機能。**

2026-11-10 起票。**実装はまだ先で、いまは骨子だけを書いた段階である。**未定の項目は §9（[Spec-open.md](Spec-open.md) §5 に同じ ID で載せた）。
手で行う前日準備の正は [Spec-onsite.md](Spec-onsite.md) §2。**ここには自動化で変わるところだけを書く。**

## 0. 骨子

**判断は準備機能、実行は移動機能、確定は人。**

| 項目 | 方針 | 出どころ |
| --- | --- | --- |
| 何か | 前日準備のうち、**地図作成と盤のピンの登録を機械に任せる** | ユーザー決定 |
| 狙い | 先方の要望「前日準備が大変」（目標 G3）。**どれだけ減るかは測るまで言わない**（現状の所要時間が未取得。`O-a3`） | [prep-burden.md](../prep-burden.md) |
| 人がやること | **待機場所の登録・盤の名前付け・結果の確認・保存** | ユーザー決定 |

### 0.2 自律測定との違い

判断と実行を分ける形は自律測定（[Spec-measure.md](Spec-measure.md)）と同じ。違いは次のとおり。

| 項目 | 自律測定（`AUTO_MEASURE`） | 自動前日準備 |
| --- | --- | --- |
| 指示を出すもの | 測定機能（fk-system。別リポジトリ） | 準備機能（本システムのリポジトリの中） |
| 目的 | その場で測ること | **当日に使う地図とピンを残すこと** |
| 作った地図 | 保存しない | **人が確かめて保存する** |
| 人 | 画面を前面に出した端末がある | **画面を開いた端末はあるが、人は別の作業をしている**（§5） |

## 2. 準備機能の権限

**このモードの間に限り、準備機能の次の指示を試験員の操作と同等に扱う。**モードを抜けると解ける（2026-11-10 ユーザー決定）。

| 同等に扱う指示 | 試験員の操作に当たるもの |
| --- | --- |
| 目的地 | 行き先を選ぶ |
| 経路の再計算 | 「再検索」 |
| 発進（一時停止からの再開を含む） | 「走行」 |
| 停止 | 「停止」 |
| 中止 | 「中断」 |

**同等に扱わないもの（人が行う）:**

| 操作 | 理由 |
| --- | --- |
| 非常停止・手押しの解除、異常ウィンドウへの応答 | [Spec-measure.md](Spec-measure.md) §2 と同じ。異常が解消したことは人が確かめる |
| 設定値の変更 | SD-9 |
| **待機場所の登録・盤の名前付け・候補の採否・保存** | 自動化の範囲に入れない（§0）。**誤った座標は当日まで気づけない**（[Spec-onsite.md](Spec-onsite.md) §3.5 と同じ考え） |

同じリポジトリの中にあっても、**準備機能は移動機能の内部を直接触らず、この指示の出し入れだけで動かす。**自律測定と同じ境界を保つことで、安全の決まりの適用が 2 通りに分かれないようにする。

## 3. 地図

| 項目 | 振る舞い | 出どころ |
| --- | --- | --- |
| 作り方 | **地図を作りながら走る。**地図のない所の扱いと経路の検査は自律測定と同じ（[Spec-measure.md](Spec-measure.md) §4.2） | 本システム側の設計 |
| 発進前の確認 | 自律測定と同じ（同 §4.4） | 本システム側の設計 |
| 既存の会場地図 | **人が保存するまで上書きしない。**会場地図は 1 枚のみ保持なので（[Spec-onsite.md](Spec-onsite.md) §1）、保存した時点で置き換わる | 本システム側の設計 |
| 自己位置を見失ったとき | **検知と閾値は試験場内と同じ**（[Spec-safety.md](Spec-safety.md) §3.5.0）。飛びの大きさは実測（`O-c8`）。見失ったあとの地図の扱いは未定（`O-d17`） | 本システム側の設計 |
| どこまで回るか | **運用で決める。起動前に、通ってほしくない所へ LiDAR に写るようにカラーコーンを置く**（§3.1）。範囲を画面で与える機能は作らない | ユーザー決定 2026-11-10 |

### 3.1 カラーコーンによる範囲の指定

**機体はコーンを「ただの障害物」として避けるだけで、範囲を知っているわけではない。**コーンの置き忘れ・倒れたコーンは機械では検知できない。

| 項目 | 振る舞い | 出どころ |
| --- | --- | --- |
| 置く人・時期 | 試験員が、**許可を押す前に**置く | ユーザー決定 2026-11-10 |
| 写る条件 | **LiDAR の走査面（床から 32 cm）の高さに届くコーン**を使う。コーンの間に渡したバーやロープは、走査面の高さに無ければ写らない | 本システム側の設計 |
| 置く間隔 | **機体の幅（0.55 m）より狭い間隔**で置く。通れる隙間が残ると機体はそこを通る | 本システム側の設計 |
| 許可のダイアログ | 「自律動作を許可しますか」に、**通ってほしくない所へコーンを置いたかの確認を含める** | 本システム側の設計 |
| コーンの向こうが見えたとき | コーンの隙間から奥が見えても、**通れない所は「行けなかった場所」として扱い、回り終える判定を止めない**（§7・`O-d16`） | 本システム側の設計 |
| コーンの写り込み | **コーンは地図に障害物として残る。**当日にコーンを片付けても、地図の上ではその場所を通らない（当日の地図は凍結。[Spec-onsite.md](Spec-onsite.md) §4.0.2）。通ってほしくない所なので差し支えない。通路をふさいだコーンを消したいときは地図の修正で行う（同 §2.2） | 本システム側の設計 |

## 4. 盤の検出とピンの候補

ss-system の受け取るもの・返すものの正は ss-system の [Spec.md](../../../../ss-system/docs/plan/spec/Spec.md) §1。ここには本システムに効くことだけを書く。

| 項目 | 振る舞い | 出どころ |
| --- | --- | --- |
| 候補とピンの違い | **準備機能が立てるのは候補まで。**人が採用して初めて盤のピンになる。**当日の盤前移動は採用済みのピンしか使わない** | ユーザー決定からの帰結 |
| 座標の変換 | ss-system の結果は**依頼した時点の機体を基準にしたローカル座標**なので、**依頼した時点の自己位置で地図の座標に直す**のは準備機能の役目 | ss-system の決まりからの帰結 |
| 撮っている間 | **走らない。**ss-system の後片付けの完了を受けるまで機体を動かさない（座標の基準がこれを前提にしている） | ss-system の決まりからの帰結 |
| 壁からの距離 | **盤のピンと同じ基準で検査し**（[Spec-onsite.md](Spec-onsite.md) §3.5 の 0.51 m）、**満たさない候補は落とす** | ユーザー決定 2026-11-10 |
| 検査する時点 | **回り終えたあとの地図で検査する。**撮った時点の地図にはまだ周りの壁が写っていないことがある。地図のできていない所の候補も落とす | 本システム側の設計 |
| 人物追跡の条件 | 候補には適用しない（人を使わないので。地図タップと同じ扱い。[Spec-onsite.md](Spec-onsite.md) §3.7） | 本システム側の設計 |
| 走る前の昇降機 | **本システムは昇降機の高さを知らない**（[Spec-measure.md](Spec-measure.md) §5.1）。下がっていることを確かめるのは準備機能の役目。**人が撮影に割り込むと ss-system は昇降機を戻さず手を離す**ので、確かめずに走り出してはいけない（`O-d19`） | ss-system の決まりからの帰結 |
| 正面が分かる盤 | ss-system が「正面が分かっている」印を付けた盤は、**その正面に候補を 1 つ立てる**（吊り金具が前側 2 個だけの盤。ss-system によると多い） | ユーザー決定からの帰結 |
| 正面が分からない盤 | **正面の候補を複数立てて、人に選ばせる。**採用するのは盤ごとに 1 つ | ユーザー決定 2026-11-10 |
| どの辺に候補を立てるか | **4 辺すべてに立て、壁からの距離の検査で落とす。**吊り金具 3〜4 個の盤は矩形までしか分からず、4 辺のどれが正面かは結果から決まらない。**長辺が正面とは仮定できない**。盤が並んでいれば隣の盤に面した辺は検査で落ちる | ユーザー決定 2026-11-10 |
| 候補が残らない盤・向きが分からない盤 | **盤の位置だけを地図に出し、人がピンを追加できるようにする**（対角の吊り金具 2 個の盤は向きが立てられない）。候補が無いことと盤が無いことを取り違えさせない | 本システム側の設計 |
| 盤からの距離 | **未定**（`O-d15`） | — |

## 5. 人が別の作業をしていること

**ここが自律測定との最大の違いである。**

| 現在の決まり | 別の作業をしているときに起きること | 扱い |
| --- | --- | --- |
| 画面が前面にある端末が無いと止まる（[Spec-safety.md](Spec-safety.md) §6.2。判定の基準は「見ているか」） | 端末を置いて作業しても、**画面が開いていれば走れる。**画面を消す・別のアプリへ切り替える・端末のスリープで、走行中なら `PAUSE` に落ち、戻ったら再開を問う（同 §6.2.2） | **決まりは変えない。画面を開いたままにする運用とする**（2026-11-10 ユーザー決定。**不便なら後で見直す**）。端末は自動でスリープしない設定にしておく |
| 異常のあとは人が応答するまで走らない（[Spec-safety.md](Spec-safety.md) §5） | **変えない。**ただし人が気づかないと止まったままになる | 呼び方は未定（`O-d12`）。機体のスピーカーは周囲の人に動きを知らせるもので、試験員を呼ぶ用途ではない（[Spec-safety.md](Spec-safety.md) §11） |
| LiDAR が見ているのは床から 32 cm の 1 枚の水平面だけ（[Spec-measure.md](Spec-measure.md) §5.2） | 机の天板・開いた扉・段差など、**人が見ていれば止められた物を誰も見ていない** | **未定**（`O-d18`） |
| 無人走行の許可は教示再生とライン誘導走行についてだけ確認項目がある（`O-a5`） | **機体を見ていない自律走行の許可は、確認項目すら無い** | 先方に確認（`O-a10`） |

**本システム側の設計**: 自律で走っている間は走行のメロディを鳴らす（[Spec-safety.md](Spec-safety.md) §11 の「自律系」に含める）。止まった理由は画面に必ず出す（同 §6.2.1）。

## 6. 速度・異常・通信断

| 状況 | 振る舞い |
| --- | --- |
| ゾーン・速度・自動ブレーキ | 自律測定と同じ（`IN`・`v_slow`・ON。[Spec-measure.md](Spec-measure.md) §6） |
| 回復フォルト・重大フォルト・非常停止・手押し・人のジョグ | 自律測定と同じ（同 §7）。**戻っただけでは動かない** |
| 準備機能が止まった・応答しない | **止まって `PAUSE` に落ちる**（同 §7 の測定機能の途絶と同じ）。戻っても発進の指示があるまで走らない |

いずれも本システム側の設計（既存の決まりの引き継ぎ）。
