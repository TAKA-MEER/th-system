# モード定義と遷移

[Spec.md](Spec.md) の詳細。**本システムの状態モデルを定義する。**

原典（`NewDesign.md` / `restate/NewDesign-restated.md`）にはモードの定義も遷移表も無い。
にもかかわらず本文は「異常発生前のモードに戻る」「停止モードで戻る」「手押しモード」
「モード選択で人物追跡が不要なモードが選ばれた場合」を前提にしている。
**本ファイルはその欠落を埋めるもので、設計書の中で最も新規性が高い。**

現行実装 `mode_manager.cpp` の FSM（`FOLLOWING` / `MOVING_TO_PANEL` / `SUMMONING` …）は
7 走行方式より前の設計である。本ファイルは**あるべき姿**を書く。現行コードとの差分は詳細設計で扱う。

## 1. 二層構造：モードと状態

**モード（mode）** は「いま何の機能を使っているか」。
**状態（state）** は「そのモードの中で今どの段階にいるか」。

モードと画面は**1 対 1 ではない**（18 モード / 15 画面）。対応は次の 3 種類になる。

| 対応 | 例 |
| --- | --- |
| 画面 1 : モード 1 | 追従走行画面 ⇔ `FOLLOW` |
| 画面 1 : モード多 | 試験画面 ⇔ `IDLE` / `PANEL_NAV` / `AT_PANEL` / `SUMMON` / `HOME_NAV` |
| 画面多 : モード 1 | 始業点検画面・故障診断画面 ⇔ `OPCHECK` ／ メインメニュー画面・設定画面 ⇔ `IDLE` |

**ゾーンは画面が決める**（§7）ので、この多対多でもゾーン判定は一意に決まる。

この分け方により、「停止」「保存」「終了」の 3 語（[Spec-open.md](Spec-open.md) F-01）が素直に表せる。

```
「停止」 = 状態が RUN → PAUSE に変わる。モードは変わらない。選択・指定・記録は保持される
「保存」 = 記録・地図を確定して保存する。状態が SAVED になる。モードは変わらない
「終了」 = モードが IDLE に戻る。未保存があれば保存可否を問う
```

**`PAUSE` は「一時停止」であって「走行の終わり」ではない。**続きから再開できる。
走行の終わりを宣言するのは「保存」（記録がある場合）か「終了」（記録がない場合）である。

もう 1 つ、モードと直交する**フラグ**を持つ。フラグはモードを変えない。

| フラグ | 意味 |
| --- | --- |
| `jog_active` | 手動ジョグ介入中（[Spec-open.md](Spec-open.md) U-4） |
| `estop_ui` | WebUI の非常停止ボタンが押されている |
| `estop_hw` | 物理非常停止ボタンが押されている |
| `tracker_enabled` | 人物追跡が動いている |
| `auto_brake` | 自動ブレーキが有効 |
| `working` | 盤前の「作業中」ボタンが ON（暫定仕様） |

## 3. 各モードの状態（サブステート）

| モード | 状態の遷移 | 備考 |
| --- | --- | --- |
| `FOLLOW` | `SELECT`（対象選択）→ `CONFIRM`（確認・**向くだけで移動しない**）→ `RUN`（走行）⇄ `PAUSE`（一時停止） | 原典の手順 3〜10 |
| `MANUAL` | `PAUSE` ⇄ `RUN` | 操作している間だけ `RUN` |
| `TEACH_FOLLOW` | `ROUTE_SEL`（新規／既存の選択）→ `REC`（記録＋走行）⇄ `PAUSE`（**一時停止。終点は確定しない**）→ **`SAVED`（「保存」で終点確定）** | 「確認」は省略。ただし記録開始前に対象を 1 度提示する（`DF-D-6`）。**`SAVED` から `REC` へ戻れる**（次の保存は新版） |
| `TEACH_MANUAL` | `ROUTE_SEL` → `REC` ⇄ `PAUSE` → **`SAVED`** | 同上（対象提示は無い）。**`REC` への出入りはスティック操作**（§3.1.2） |
| `REPLAY` | `ROUTE_SEL`（経路＋順/逆）→ `LOCALIZE`（初期姿勢推定）→ `READY`（試験員が地図で確認）→ `RUN` ⇄ `PAUSE`。地図更新 ON なら `SAVED` あり | `LOCALIZE` は確度が低ければ範囲拡大→完全グローバル。**記録の終端に達したら `PAUSE`**（自動で終了はしない） |
| `LINE` | `SETUP`（現在地→向き→目的地の 3 指定）→ `PLANNED`（経路表示）→ `RUN` ⇄ `PAUSE` → `ARRIVED`（自動停止） | 唯一、自分で終点を判定する |
| `LEASH` | `DEV_CHECK`（デバイス接続確認）→ `READY` → `RUN`（張力あり）⇄ `HOLD`（張力なし＝停止）⇄ `PAUSE` | 一定速。張力喪失で停止 |
| `PREP` | `MAPPING`（地図生成中）⇄ `REGISTER`（登録操作中）→ `RETURN`（1 ボタンで待機場所へ）→ `EDIT`（地図修正）→ **`SAVED`（「保存」で地図を確定）**。いずれの状態からも **`PAUSE`（一時停止。地図・登録内容は保持し、方式は抜けない）** | 登録は待機場所・盤の両方。**`EDIT` は `MAPPING` からも入れる**／**`SAVED` からも `MAPPING` に戻れる**（§3.1.2） |
| `PANEL_NAV` | `NAV`（Nav2 走行）⇄ **`PAUSE`** → `ALIGN`（超信地旋回で向き合わせ）→ `ARRIVED` | 経路が塞がれたら `BLOCKED`（待ち・タイムアウトしない） |
| `AT_PANEL` | `IDLE_P` ⇄ `WORKING`（作業中ボタン ON）。`IDLE_P` ⇄ **`PAUSE`**（ジョグ介入中） | `WORKING` 中は他の行き先を選べない |
| `SUMMON` | `POINT`（2 点指示）→ `WAIT_CLEAR`（退避待ち）→ `NAV` ⇄ **`PAUSE`** → `ALIGN` → `ARRIVED` | `WAIT_CLEAR` は**タイムアウトで中止**。**`WAIT_CLEAR` に `PAUSE` は無い**（§3.1.1） |
| `HOME_NAV` | `NAV` ⇄ **`PAUSE`** → `ARRIVED` | 同じく `BLOCKED` あり |
| `OPCHECK` | `LIST`（一覧）→ `RUNNING_CHECK`（項目実行中）→ `REPAIR`（故障診断画面） | 走行を伴うのはモーター確認のみ。`REPAIR` は校正で直らない NG の受け皿 |
| `CALIB` | `LIST` → `S1 案内` → `S2 実行・実測` → `S3 確認` → `S4 検証` | 全ステップから中断可 |

## 3.1 状態遷移の一覧表（**状態モデルの正本**）

**モード内の状態遷移は、この表が唯一の正である。**
[Spec-transit.md](Spec-transit.md) の手順表と [Spec-webui.md](Spec-webui.md) §3.3 の操作カードは
**この表の見せ方**であって、定義ではない。食い違ったらこの表に合わせる。

> **なぜ作ったか**（[Spec-open.md](Spec-open.md) F-19〜F-28）: 状態の定義が §3・手順表・操作カードの
> 3 か所に散っており、**未定義の状態名（`STOP`）が手順表に混入する**、
> **同じジョグ介入に 2 通りの規則が書かれる**といったずれが起きていた。
> 遷移を 1 か所に集めると、この種のずれは書いた時点で見つかる。

### 3.1.1 すべてのモードに共通する遷移

| 遷移元 | 契機 | 遷移先 | 副作用 |
| --- | --- | --- | --- |
| 任意の状態（**下記の除外を除く**） | **手動 UI に触れている**（リースが有効な間） | **同モードの `PAUSE`** | `jog_active = true`。元の方式の速度指令を抑止（§8） |
| `PAUSE`（`jog_active`） | **リースが切れた**（手を離した／通信が途絶えた） | `PAUSE` のまま。**`AT_PANEL` だけ `IDLE_P` へ戻る** | `jog_active = false`。**勝手に走り出さない** |
| 任意の状態 | **回復フォルト**（[Spec-safety.md](Spec-safety.md) §3.5） | **同モードの `PAUSE`** | 異常ウィンドウ W-1。駆動は安全チェーンが即時ゼロに |
| `PAUSE`（フォルト解決後） | 「はい」 | **同モードの走行状態**（`RUN` / `REC` / `NAV` …） | 走行状態は §6 の属性表で引く。§6.1 |
| `PAUSE`（フォルト解決後） | 「いいえ」／「確認」 | `PAUSE` のまま | §6.1 |
| 任意の状態 | **重大フォルト** ／ UI 非常停止 | `ESTOP`（モードごと） | 解除後は `IDLE` のみ |
| 任意の状態 | 物理非常停止ボタン | `CARRY`（モードごと） | 解除＋再開で**押下前のモードと状態**へ |
| 任意の状態 | **「終了」** | `IDLE`（モードごと） | 未保存があれば保存可否を問う（W-4） |

**リース満了後の戻り先が `PAUSE` のままでないのは `AT_PANEL` の 1 つだけである**
（`IDLE_P` へ戻る。§3.1.2）。「到着ずれを手で詰める」用途なので、詰め終わったら盤前の待機に戻るのが自然だから。
**例外はこの 1 つに限る**（[Spec-open.md](Spec-open.md) F-30）。

**フォルトの解消そのものは遷移ではない。**W-1 が「再開しますか」に変わるだけで、
遷移が起きるのは試験員が「はい」「いいえ」「確認」を押したときである。
**どの選択肢を出すかは §6 の属性表から導き、画面ごとにハードコードしない**（F-34）。

**`PAUSE` は全モード共通の「一時停止」である。**`STOP` という状態名は使わない
（「停止」は操作の名前であって、状態の名前ではない）。
ジョグ介入を受ける以上、**`PAUSE` を持たないモードは無い**（§3 の状態欄もそれに合わせてある）。

#### ジョグ介入の除外（安全上の例外）

| 除外する状態 | 理由 |
| --- | --- |
| `SUMMON` / **`WAIT_CLEAR`** | **退避待ちゲートは「人がゴール地点にいる間は動かさない」ための仕組み**（[Spec-onsite.md](Spec-onsite.md) §5 ／ F-10）。ここでジョグを許すと、**ゲートが止めているはずの状況で機体が動く**。動かしたければ**中止して `POINT` からやり直す**（タイムアウトと同じ経路） |
| `INIT` / `ESTOP` / `CARRY` / `OPCHECK` / `CALIB` | §8 のとおり。駆動が切れている、または確認・校正の手順そのものが動きを規定している |
| **`MANUAL` / `TEACH_MANUAL`** | **スティックそのものが走行操作である。**この 2 モードはジョグ介入という概念を持たず、触れると `PAUSE` ではなく `RUN` / `REC` へ**入る**（§3.1.2）。除外していないと、**触れた瞬間に `PAUSE` へ落ちて走れなくなる**（[Spec-open.md](Spec-open.md) F-31） |

**`WAIT_CLEAR` 中は手動 UI を非活性にし、「退避待ちの中止」ボタンを代わりに出す。**
触れても何も起きないだけでは、なぜ動かないのかが分からない。

#### ジョグは押下／解放ではなくリースで表す（[Spec-open.md](Spec-open.md) F-29）

| 項目 | 仕様 |
| --- | --- |
| UI | 触れている間、**ジョグ継続の合図を繰り返し送る** |
| 判定 | 最後の受信から **`jog_lease_ms`** を超えたら `jog_active = false`（＝上表 2 行目の「リースが切れた」） |
| 制約 | **`jog_lease_ms ≥ 手動系の速度指令が多重化から落ちるまでの時間`。**逆にすると「多重化はまだ手動を流しているのに、状態管理は解除済み」という窓ができる |

**「触れた」「手を離した」の 2 イベントで表してはいけない。**
WiFi の受信ギャップ（実測 0.5〜1.2 s・[Spec-params.md](Spec-params.md) §1）で解放が落ちると、
`jog_active` が**永久にラッチ**して元の方式に戻れなくなる。
リースなら、合図が途切れた時点で必ず解除される。

## 4. 遷移表

### 4.1 共通規則（すべてのモードに優先する）

| 契機 | 遷移 |
| --- | --- |
| WebUI 非常停止ボタン押下 | **どのモードからでも** → `ESTOP`（ただし `CARRY` 中は受け付けない。下記） |
| 物理非常停止ボタン押下 | **どのモードからでも** → `CARRY`（**ただし例外が 1 つある。下記**） |
| 物理非常停止ボタン解除 | `CARRY` → 再開ボタンで**押下前のモードへ**／押さなければ `IDLE` |
| `ESTOP` 解除 | `ESTOP` → `IDLE` **のみ** |
| **重大フォルト**発生（[Spec-safety.md](Spec-safety.md) §3.5） | **どのモードからでも** → `ESTOP` |
| **回復フォルト**発生（動作系モード） | **モードは変わらない。**状態が `PAUSE` に落ちる（§5） |

**例外：始業点検の「非常停止ボタン確認」中の物理ボタン押下は `CARRY` へ遷移させない。**
この確認は押す・離すを試すことが目的であり（[Spec-checks.md](Spec-checks.md) §2.4）、
押下のたびに手押しモードへ落ちると確認そのものが実行できない。
`OPCHECK` の状態が「非常停止ボタン確認を実行中」のときに限り、押下は
**確認対象の入力として扱い、モードを変えない**。この間も駆動は物理的に切れている。

**`CARRY` 中は UI 非常停止ボタンを受け付けない。** すでに駆動が物理的に切れており、
受け付けると「押下前のモード」が `CARRY` になって復帰先が壊れるため。

#### `ESTOP` / `CARRY` の入れ子（[Spec-open.md](Spec-open.md) F-33）

**押下前のモードと状態は 1 段だけラッチする。入れ子にしない。**
`ESTOP` 中に物理ボタンを押す、`CARRY` 中に重大フォルトが起きる、といった組み合わせは実際に起こるので、
**4 通りすべてを決めておく**。

| 状況 | 挙動 |
| --- | --- |
| 動作系 → `ESTOP` | 押下前のモードと状態を記録。**解除後は `IDLE` のみ**で、記録は捨てる |
| 動作系 → `CARRY` | 同じく記録。**「再開」で押下前のモードと状態へ戻す** |
| **`CARRY` 中に UI 非常停止** | **受け付けない**（F-26）。ボタンは隠さず、効かない理由を手押しウィンドウ W-2 に出す |
| **`CARRY` 中に重大フォルト** | `ESTOP` へ移る。**記録は上書きしない**（`CARRY` を復帰先にしない） |
| **`ESTOP` 中に物理ボタン押下** | `CARRY` へ移る。**記録は上書きしない**（`ESTOP` を復帰先にしない） |
| **`ESTOP` / `CARRY` 中の「終了」** | `IDLE` へ。記録は捨てる |

**上書きしないのが要点である。**上書きすると、解除したときの戻り先が
「非常停止していた状態」になり、元の作業に戻れなくなる。

`ESTOP` と `CARRY` の違い：

| | `ESTOP` | `CARRY` |
| --- | --- | --- |
| 契機 | UI ボタン／重大フォルト | 物理ボタン押下 |
| 意味 | 「止めたい」 | 「人が押して運ぶ」 |
| センサ系統 | 動かし続ける | **動かし続ける**（原典明記） |
| 解除後 | `IDLE` のみ | **押下前のモードへ戻れる** |

### 4.2 モード遷移許可表

`IDLE` を中心とするハブ＆スポーク構造。**走行方式どうしの直接遷移は無い**
（＝走行中の方式切替はしない。`CL-T-1`）。

| 遷移元 | 遷移先 |
| --- | --- |
| `INIT` | `IDLE` のみ（必須通信系統がすべて疎通したとき） |
| `IDLE` | `FOLLOW` / `MANUAL` / `TEACH_FOLLOW` / `TEACH_MANUAL` / `REPLAY` / `LINE` / `LEASH` / `PREP` / `PANEL_NAV` / `SUMMON` / `HOME_NAV` / `OPCHECK` / `CALIB` |
| `MANUAL` | `IDLE`（「終了」）／ **`OPCHECK` / `CALIB`**（保守は `IDLE` と `MANUAL` から始められる。[Spec-checks.md](Spec-checks.md) §1） |
| `FOLLOW` / `TEACH_*` / `REPLAY` / `LINE` / `LEASH` | `IDLE` のみ（「終了」） |
| `PREP` | `IDLE` のみ |
| `PANEL_NAV` | `AT_PANEL`（到着）／ `IDLE`（終了） |
| `AT_PANEL` | `PANEL_NAV`（次の盤）／ `SUMMON`（その場で呼ぶ）／ `HOME_NAV`（待機場所へ）／ `IDLE` |
| `SUMMON` | `AT_PANEL`（到着）／ `IDLE` |
| `HOME_NAV` | `IDLE`（到着または終了） |
| `OPCHECK` | `CALIB`（「校正へ」導線）／ `IDLE` |
| `CALIB` | `OPCHECK`（校正後に直ったか見る）／ `IDLE` |

**試験画面を開いた直後は `IDLE` のまま**である。行き先（ピン／呼び寄せ／待機場所）を選んだ時点で
`PANEL_NAV` / `SUMMON` / `HOME_NAV` に入る。
[Spec-onsite.md](Spec-onsite.md) §4.0 の「待機場所にいることの宣言」と自己位置の照合は
この `IDLE` の間に行う。

**`AT_PANEL` の遷移は `working` フラグでゲートされる。**
`working == true` の間、`PANEL_NAV` / `SUMMON` / `HOME_NAV` への遷移はすべて拒否される
（原典「作業中ボタンがオンのときは待機場所や別の配電盤を選択しても拒否される」）。

## 5. フォルト発生時の挙動

**フォルトは 2 階級ある**（[Spec-safety.md](Spec-safety.md) §3.5）。
下表の 4 つはすべて**回復フォルト**なので、**モードは落とさず、状態を `PAUSE` に落とす。**
重大フォルトだけが `ESTOP` へ落ち、解除は `IDLE` のみになる。

| フォルト | 影響するモード | 挙動 |
| --- | --- | --- |
| `LIDAR_LOST` / `ESP32_DISCONNECTED`（必須通信系統の断） | すべての動作系モード | **モードは保持し、状態を `PAUSE` へ。**安全チェーンが `/cmd_vel` を先にゼロにする。復帰は §6 の表 |
| `PERSON_TRACKER_LOST` | **人物追跡を要するモードのみ**（`FOLLOW` / `TEACH_FOLLOW` / `SUMMON`） | 同じく**モードは保持し `PAUSE` へ。**それ以外のモードは人物データを使わないので継続 |
| `PERSON_TRACKER_LOST`（`PREP` のみ） | `PREP` | **`PAUSE` にもしない。**登録操作を受け付けなくなるだけで、地図作成は続行する（[Spec-open.md](Spec-open.md) C-15） |
| バッテリー低下 | なし | 警告のみ。停止させない（原典「最終的に試験員が判断する」） |

`IDLE` 中のフォルトはモード変化なし（表示のみ）。

**`IDLE` へ落とすのは 1 つの場合だけ**: **そのモードを続けられない**とき
（教示の記録の連続性が切れた等）。このとき**未保存の記録は破棄せず、保存するかを問う**（§6.1）。

> **なぜ「`IDLE` へ強制遷移」をやめたか**（[Spec-open.md](Spec-open.md) F-20）:
> `IDLE` に落とすと、画面はそのまま（例: 追従走行画面）でヘッダのモード表示だけ「待機」になり、
> §1 の「画面 1 : モード 1」対応が崩れる。
> 駆動を止めるのは安全チェーンの層 3（[Spec-safety.md](Spec-safety.md) §1）であってモード管理ではないので、
> **モードを畳んでも安全は 1 ミリも増えない。**畳まないほうが復帰が素直になる。

**`PREP` だけ扱いが違う理由**: 前日の地図作成は数十分続き、その大半は人物追跡を必要としない。
ロストのたびに `IDLE` へ落とすと、作りかけの地図を毎回失う。
**人物追跡が要るのは 2 点指示の瞬間だけ**なので、その瞬間だけ拒否すれば安全は保てる。

### 5.1 意図的な人検知 OFF とフォルトの区別（`CL-X-1` の解決）

原典は「人物追跡は任意のタイミングで停止できる」と書くが、
現行実装は追跡の途絶を `PERSON_TRACKER_LOST` として扱い強制遷移させる。
**このままでは、試験員が意図して止めた瞬間にフォルト扱いになる。**

決定：

1. 試験員が明示的に停止した場合は `tracker_enabled = false` とし、**フォルトとして扱わない**。
   強制遷移も異常ウィンドウも起こさない。
2. **人物追跡を要するモードでは、そもそも OFF にできない。** OFF ボタンを非活性にする。
   **OFF ボタンは設定画面（S-50 一般）に置く**（[Spec-webui.md](Spec-webui.md) §3.15）。
   走行方式の画面からは切り替えられない。
3. `tracker_enabled == false` のとき、人物追跡を要するモードは**開始できない**
   （メインメニュー画面で該当ボタンを非活性にし、理由を表示する）。
4. `tracker_enabled == true` なのにデータが途絶えた場合のみ `PERSON_TRACKER_LOST` とする。

この区別が無いと、原典の「異常発生前のモードに戻る」が壊れる
（意図的な OFF で `IDLE` に落ちた場合、戻り先が意味をなさない）。

### 6.1 「異常解決後の復帰」の読み方（[Spec-open.md](Spec-open.md) C-13 / U-8）

**どの選択肢を選んでも待機（`IDLE`）には戻さない。**モードは必ず異常発生前のものに戻る。
違うのは**走り出すかどうか**だけである。

| 表記 | 出す選択肢 | 結果 |
| --- | --- | --- |
| **はい／いいえ** | 2 択 | **はい**＝元モードで**走行を再開**（そのモードの走行状態。`FOLLOW`→`RUN` / `TEACH_*`→`REC` / `PANEL_NAV`・`HOME_NAV`→`NAV` …）／**いいえ**＝元モードの**一時停止のまま**（`PAUSE`） |
| **「確認」1 択 → 元モードの `X`** | 1 択 | 走行の自動再開はしないが、モードは戻す。状態は `X` から再開する |

**「はい」の戻り先を `RUN` 固定にしてはいけない**（[Spec-open.md](Spec-open.md) F-37）。
`RUN` を持たないモード（`TEACH_*` は `REC`、Nav2 系は `NAV`）で成り立たなくなる。
**この表の右列がモードごとの走行状態の定義であり、UI はここから引く。**

**例外**: 異常によってモード自体を続けられない場合（教示の記録が途切れた等）だけ `IDLE` へ戻す。
このとき**未保存の記録は破棄せず、保存するかを問う**。

「いいえ」で `IDLE` に戻さないのは、対象選択・経路指定・記録内容を選び直させないためである。
方式をやめたいときは「終了」を押す（[Spec-transit.md](Spec-transit.md) §0.1）。

## 7. ゾーン（試験場内／場外）の判定

**決定（[Spec-open.md](Spec-open.md) U-1）: 画面で自動判定する。**

**ゾーンは「いま開いている画面」だけで決まる。モードでは決めない**
（[Spec-open.md](Spec-open.md) F-19）。

| ゾーン | 該当画面 | 効果 |
| --- | --- | --- |
| **場内** | **S-20 試験準備 ／ S-21 試験** | 速度上限 `v_slow`、自動ブレーキ既定 ON |
| **場外** | **S-01 メインメニュー ／ S-10〜S-16（走行方式 7）／ S-50 設定** | 速度上限 `v_max`、手動系のみ自動ブレーキ既定 OFF |
| **非該当** | **S-00 接続確認 ／ S-30 始業点検 ／ S-31 故障診断 ／ S-40 校正** | ゾーンの概念を持たない（それぞれ固有の速度規定） |

理由: 試験場内で使うのは試験準備画面と試験画面だけであり、**画面がそのまま場所を表している**。
試験員が切り忘れる余地が無く、追加操作もゼロになる。

**モードで定義してはいけない理由**: モードで定義すると、**場内にいるのに場外の速度上限が
適用される経路が 3 つできる**。いずれも「機体は試験場内にあるまま、モードだけが変わる」場合である。

| 経路 | モードで定義した場合に起きること |
| --- | --- |
| 試験画面を開いた直後（§4.2 により `IDLE`） | `IDLE` は場外なので `v_max` になる |
| 場内でフォルトが起きたとき（§5） | 落ちた先のモードが場外扱いなら `v_max` に戻る |
| 場内で `ESTOP` / `CARRY` に入り、解除したとき | この 2 つは「ゾーン非該当」なので判定が抜ける |

**画面で定義すればいずれも起きない。**`ESTOP` / `CARRY` は画面を変えずウィンドウを乗せるだけなので
（[Spec-webui.md](Spec-webui.md) §2.1）、**下の画面のゾーンがそのまま保たれる。**

**ヘッダのゾーン表示も画面から出す。**モックアップ `mockup/index.html` の
`SCREENS[].zone`（画面ごとの真偽値）がこの定義の実装であり、本表と一致していなければならない。

**ヘッダにゾーンを常時表示する**（場内のときだけ「試験場内・低速・自動ブレーキ ON」を出す）。
場内で走行方式を使う場合は場外扱いになるため、その運用は行わない旨を運用手順に記す。

## 8. ジョグ介入（`jog_active`）

**決定（[Spec-open.md](Spec-open.md) U-4）: モードを変えない一時介入として扱う。**

原典 `NewDesign-transit.md`「他の走行方式操作画面でも同様の手動操作をできるようにする（UI も配置する）」
の実現方法。

| 項目 | 仕様 |
| --- | --- |
| 発動 | 走行方式画面・試験画面の手動 UI（仮想スティック等）に触れた瞬間 |
| **走行中に触れた場合** | **まず元の方式が `PAUSE` に落ち、そのままジョグが効く**（`RUN` 中は効かない、という規則にはしない） |
| 効果 | `jog_active = true`。**元の方式の速度指令を抑止**し、ジョグ指令のみを通す |
| 元の方式 | 同時に状態が `PAUSE` に遷移する（勝手に走り出さないため） |
| **継続** | **リースで表す。**触れている間は継続の合図を送り続け、`jog_lease_ms` 更新されなければ解除する（§3.1.1） |
| 解除 | **リース満了**（手を離した／通信が途絶えた）。`jog_active = false`。**モードは元のまま、状態は `PAUSE`（一時停止）。**`AT_PANEL` だけ `IDLE_P` へ戻る |
| 再開 | 試験員が改めて「走行」「再生」などを押す |
| **障害物・自動ブレーキ** | **ジョグ中は、元のモードが自律系でも手動系として扱う。**警告のみで、自動ブレーキはゾーン既定に従う（場外 OFF・場内 ON）。[Spec-safety.md](Spec-safety.md) §2.1 の「手動系」にジョグ介入が挙がっているのがこれ |
| 速度上限 | ゾーンに従う。ただし `AT_PANEL` だけは `v_jog_panel`（§6） |
| 不可なモード | `INIT` / `ESTOP` / `CARRY` / `OPCHECK` / `CALIB` |
| **不可な状態** | **`SUMMON` の `WAIT_CLEAR`（退避待ち）。**ゲートが止めている状況で動かさない（§3.1.1 の除外）。手動 UI を非活性にし「退避待ちの中止」を代わりに出す |
| **概念を持たないモード** | **`MANUAL` / `TEACH_MANUAL`。**「不可」とは別である。**この 2 モードではスティックが走行操作そのもの**で、触れると `PAUSE` ではなく `RUN` / `REC` へ入る（§3.1.1 の除外 ／ F-31） |

**§6 の属性表の「自動ブレーキ既定 ON（無効化不可）」は、その方式が自分で走っているときの規定である。**
ジョグ中は人が操作しているので、上表が優先する。
「無効化不可」が外れることを試験員に隠さないよう、**ジョグ中は画面に自動ブレーキの状態を出す**。

**なぜモードを変えないか**: モードを `MANUAL` に切り替えてしまうと、
介入中に異常が起きたときの「異常発生前のモード」が `MANUAL` になり、
原典の「異常発生前のモードに戻る」が意味を失う。フラグにすることで戻り先が保たれる。

## 9. 人物追跡の要否（`E-9` の解決）

原典「人物追跡は任意のタイミングで停止できる／必要な画面に入った場合は自動で起動する」
「モード選択で不要なモードが選ばれた場合はウィンドウを自動で閉じる」の根拠表。
**「不要なモード」＝下表で「不要」の行**と定義する。

| 人物追跡 | モード |
| --- | --- |
| **要**（画面に入ると自動起動、OFF 不可） | `FOLLOW` / `TEACH_FOLLOW` / `SUMMON` / `PREP`（登録操作中のみ） |
| 不要（OFF のままでも使える） | `MANUAL` / `TEACH_MANUAL` / `REPLAY` / `LINE` / `LEASH` / `PANEL_NAV` / `AT_PANEL` / `HOME_NAV` / `OPCHECK` / `CALIB` |
| 任意 | `IDLE` / `INIT` |
| **直前の状態を継続**（勝手に止めない） | `ESTOP` / `CARRY` |

`ESTOP` と `CARRY` でセンサ系統を止めないのは原典の明記事項であり、
止めないからこそ解除後にそのまま再開できる（[Spec-safety.md](Spec-safety.md) §4.1）。

**`tracker_enabled == false` のときに使えない機能**（`CL-X-5`）: 追従走行・教示（追従）・呼び寄せ・
盤登録・待機場所登録。メインメニュー画面と試験画面で該当ボタンを非活性にし、
「人物追跡が停止しています」と理由を出す。

ロストの猶予は用途で違う（[Spec-open.md](Spec-open.md) C-05）:

| 用途 | 猶予 |
| --- | --- |
| 追従・呼び寄せ・位置指定（走る用途） | `tracker_lost_grace_ms`（暫定 500 ms） |
| 登録（座標を確定する用途） | **猶予なし**。ロスト後は即拒否 |

### 9.1 「対象選択」をどの画面に置くか（[Spec-open.md](Spec-open.md) U-14）

**人物追跡を「要」とするモードの画面には、必ず対象選択の UI を置く。**
どの人を対象にしているか確かめられないまま、その人の位置を使って
登録したり走らせたりしてはいけない。

| 画面 | 対象選択 | 置き方 |
| --- | --- | --- |
| S-10 追従走行 ／ S-12 教示（追従） | あり | 走行タブそのもの |
| **S-20 試験準備** | **あり** | **「対象選択」タブ**（地図タブと切り替え） |
| **S-21 試験** | **あり** | **「対象選択」タブ**（地図タブと切り替え） |
| その他 | なし | 人物データを使わない |

**部品は 1 つに統一する**（[Spec-webui.md](Spec-webui.md) §3.4）。
画面ごとにレーダーの見た目や候補の選び方が違うと、対象の取り違えを誘発する。

## 10. 現行実装との差分（詳細設計への申し送り）

| 現行 `mode_manager.cpp` | 本設計 |
| --- | --- |
| `FOLLOWING` / `FOLLOWING_MAPLESS` | `FOLLOW` に統合（地図の有無は内部事情でモードではない） |

| `SUMMONING` | `SUMMON` |

| （無い） | `TEACH_FOLLOW` / `TEACH_MANUAL` / `REPLAY` / `LINE` / `LEASH` / `PREP` / `HOME_NAV` / `OPCHECK` / `CALIB` / `CARRY` を新設 |

| ゾーンの概念が無い | **画面でゾーンを判定する**（§7）。モードからは引かない |
