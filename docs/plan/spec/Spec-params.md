# パラメータと保存先

[Spec.md](Spec.md) の詳細。**設計上の数値を 1 か所に集める。**

**実装のパラメータファイル名・ノード名は書かない**（詳細設計の担当）。
ここに書くのは「どういう値が要るか」「いくつか」「なぜその値か」だけである。

---

## 0. 数値の 3 分類

| 分類 | 意味 | 扱い |
| --- | --- | --- |
| **(a)** | 外部から与えられる（先方・他担当に聞く） | 聞かないと決まらない。仮置きしない |
| **(b)** | 物理・仕様から逆算できる | いま計算して置ける |
| **(c)** | 測らないと分からない | **事前の目標値を置いてはいけない** |

**(c) に目標値を置くと、測定が「目標の確認」になってしまい、実態が見えなくなる。**

## 2. 速度の階層

| 記号 | 用途 | 値 | 根拠 |
| --- | --- | --- | --- |
| `v_max` | 場外の走行方式すべて | **0.7 m/s**（計画値） | §1 |
| `v_slow` | **試験場内**（`PREP` / `PANEL_NAV` / `AT_PANEL` / `SUMMON` / `HOME_NAV`） | **未確定** (b) | 納品物への接触を避ける。制動距離から逆算する |

| `v_jog_panel` | **配電盤前（`AT_PANEL`）のジョグ介入**。到着ずれを手で詰めるとき | **未確定** (b) | 盤と接触させないため `v_reverse` 相当まで落とす（[Spec-modes.md](Spec-modes.md) §6 ／ [Spec-onsite.md](Spec-onsite.md) §7.3） |
| `v_check` | 始業点検のモーター確認 | **未確定** (b) | 極低速。押している間だけ |

## 3. 逆算の連鎖

**1 つの実測値が多数のパラメータを従属させている。**依存関係を明示しておく。

### 【A】停止精度の連鎖

```
カメラ昇降の許容差 [±m, ±deg]  ← (a) 未取得
   ↓
到着精度の要求
   ↓
盤前の合成誤差と比べる  ← 誤差源は 2 つ。片方だけで判定しない
   │
   ├─ ① 2 点指示が与える目標の向きの誤差  ±8〜11°（L = 1 m・σ = 0.1 m）
   └─ ② Nav2 の到達許容                    ±0.25 m / ±14°
        合成 ≒ √(①² + ②²) ≒ ±16〜18°（最悪の重なりで ±22〜25°）
   ↓
   ├─ 要求 > 合成 → 2 点指示だけで終わり
   └─ 要求 < 合成 → 到着後の LiDAR 盤面正対を作る
   ↓
2 点指示の点間距離 L を詰めて ① を下げる余地があるか（L を詰めると手数は減るが精度は落ちる）
```

**合成のとり方（独立か、系統誤差として同方向に乗るか）は実測で確かめる**（O-c3）。
上の式は見積もりであり、**②だけを敷居にすると「足りる」と誤判定する**
（[Spec-onsite.md](Spec-onsite.md) §3.3 ／ [Spec-open.md](Spec-open.md) F-22）。

### 【B】制動の連鎖（最も広く効く）

```
実測の制動加速度 a  ← (c) 未測定・最優先
   ↓
制動距離 = v² / (2a) + v × t_遅延
   ↓
├─ obstacle_check_distance_m
├─ lidar_timeout_ms / esp32_timeout_ms
├─ v_max / v_slow / v_reverse
├─ 追従走行の停止距離 follow_stop_distance_m
└─ 停止・再開のヒステリシス帯の幅
```

### 【C】経路長の連鎖

```
通路幅 W  ← (a) 未取得       機体幅 B
   ↓
許容逸脱 = (W − B) / 2 − マージン
   ↓
教示再生のドリフト上限
   ↓
1 経路の長さの上限
```

## 8. 先に潰す 4 つ

| 順 | 項目 | 分類 | なぜ先か |
| --- | --- | --- | --- |
| **1** | **実測の制動加速度 a** | (c) | 最も安く、**最も多くのパラメータを従属させる**（【B】）。安全距離の成否を決める |
| **2** | **カメラ昇降の許容差** | (a) | 聞くより先に「**どこまで緩められるか**」を交渉する。盤面正対を作るかが決まる |
| **3** | **人が歩いている部屋で地図を作ってみる** | (c) | **最も安いテスト。**人物マスク実装の要否が決まる |
| **4** | **前日準備の現状ベースライン** | (a) | 無いと目標 G3 を検証できない |

これと並行して、速度は**3 点セットで上げる**（どれか 1 つでは効かない）:

1. 出力上限と `v_max` を上げる
2. 停止・再開のヒステリシス帯を広げる
3. 安全距離・タイムアウトを引き直す（【B】）

さらに **WiFi リンクの改善**（平常時 0.5〜1.2 s の受信ギャップ）は、
速度を上げるすべての案の前提条件である。
