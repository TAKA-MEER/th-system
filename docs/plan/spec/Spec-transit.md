# 走行方式（保管場所⇔試験場）

[Spec.md](Spec.md) の詳細。**7 つの走行方式それぞれの完全仕様。**

往路と復路を区別しない。行きも帰りも同じ手順・同じ UI を使う。
方式の選択は**メインメニュー画面で 1 度だけ**行い、走行中に方式を切り替えることはしない
（手動が要るときはジョグ介入を使う → [Spec-modes.md](Spec-modes.md) §8）。

---

## 0. 全方式に共通する規則

### 0.1 「停止」「保存」「終了」（[Spec-open.md](Spec-open.md) F-01 / U-6）

**この 3 語は全画面で同じ意味に固定する。**

| 操作 | 効果 | 置く画面 |
| --- | --- | --- |
| **停止** | **一時停止。**走行をやめるだけ。モード・対象選択・経路指定・記録内容は**すべて保持**し、そのまま続きから再開できる | **全方式＋試験準備＋試験** |
| **保存** | **記録・地図を確定して保存する。**ここで初めて経路の終点が確定する | **記録を伴う画面のみ**（教示 2 種／試験準備／教示再生で地図更新 ON のとき） |
| **終了** | 方式を抜けてメインメニュー画面（`IDLE`）へ戻る。**未保存があれば保存可否を問う** | **全画面** |

**「停止」で終わってはいけない。**「停止」はいつでも押せる一時停止であり、
走行の終わりを宣言するものではない。走行の終わりは「保存」（記録がある場合）か
「終了」（記録がない場合）で宣言する。

> **原典との差異**: 原典では手動走行だけ「終了」しか書かれておらず、また「停止」が
> 一時停止と走行終了の両方を兼ねていた。これを 3 語に分けて全画面で統一した。

### 0.2 到着の判定（F-02）

**全方式で試験員が「停止」を押す。**システムは到着を判定しない。
唯一の例外がライン誘導走行で、目的地ノードに達したときに**自動停止**する
（自動停止しても「終了」はしない。試験員が終了を押すまで方式に留まる）。

### 0.3 障害物への反応（[Spec-open.md](Spec-open.md) C-11 / U-2）

| 方式 | 障害物を検知したとき |
| --- | --- |
| 追従走行・教示（追従）・教示再生・区画線・電子リード | **停止する。**自動回避はしない。無効化できない |
| 手動走行・教示（手動）・ジョグ介入 | **警告する。**自動ブレーキは任意 ON（場外の既定は OFF、試験場内の既定は ON） |

停止したあとの復帰は、人が手動操作で避けるか、障害物をどける。
**走行開始時に決定した経路を逸脱しない**（＝迂回して回り込むことはしない）。

後退方向は LiDAR の死角になるため、後退速度をさらに落とす（`CL-X-4` → [Spec-safety.md](Spec-safety.md)）。

### 0.4 手動 UI の常設（U-4）

**7 方式すべての画面に、手動操作 UI（仮想スティック＋速度プリセット）を配置する。**
触れている間だけジョグ介入になり、離すと元の方式の**一時停止**に戻る。モードは変わらない。

### 0.5 教示は「教示なしの画面＋教示タブ」で作る（U-5）

**教示（追従）は追従走行と、教示（手動）は手動走行と、同じ画面構成にする。**
違いは**「教示」タブが 1 枚増えることだけ**である。

| 画面 | タブ構成 |
| --- | --- |
| 追従走行 | 「追従」 |
| **教示（追従）** | 「追従」＋**「教示」** |
| 手動走行 | 「走行」 |
| **教示（手動）** | 「走行」＋**「教示」** |

走行部分（レーダー／地図／操作カード／手動 UI／速度プリセット）は**4 画面で完全に共通**にする。
教示タブに入るのは、経路の選択（新規／既存の再設定）と記録の状況（距離・時間・記録点数・開始時の向き）だけ。

**理由**: 教示は「走らせ方」を変えるものではなく「走った軌跡を記録するかどうか」の違いしかない。
画面を作り分けると、試験員は同じ走行操作を 2 通り覚えることになる。

詳細は [Spec-webui.md](Spec-webui.md) §3.4〜§3.6。

**操作の置き場所は 4 画面に限らず全画面で固定する**（[Spec-webui.md](Spec-webui.md) §3.3）。
「終了」は画面左上の操作バー、「停止・確認・走行・保存・手動」は右列先頭の操作カードに、
常に同じ格子位置で置く。

### 0.5 前提条件の確認（`CL-T-2`）

| 前提 | 誰が確認するか |
| --- | --- |
| 教示済みの経路があるか | **UI が判定する。**経路が 1 つも無ければ教示再生のボタンを非活性にする |
| リードデバイスが繋がっているか | **UI が判定する。**電子リード走行の開始時に自動で接続確認する |
| 人物追跡が動いているか | **UI が判定する。**追従系のボタンを非活性にする（[Spec-modes.md](Spec-modes.md) §9） |
| 区画線があるか | **人の責任。**画面に「区画線を認識できる位置に機体を置いてください」と案内を出す |
| リードを持っているか | **人の責任** |

## 1. 追従走行（`FOLLOW`）

LiDAR で足を検知し、**その位置の軌跡を追従する**。
試験員が歩いた場所をなぞって移動し、直角に曲がった場合などに**ショートカットしない**。

### 1.1 手順

| 順 | 操作 | 状態 |
| --- | --- | --- |
| 1 | メインメニュー画面で「追従走行」を選ぶ | `IDLE` → `FOLLOW` |
| 2 | 追従対象を選ぶ（候補が 1 人だけの状態が数秒続けば自動選択） | `SELECT` |
| 3 | **「確認」**を押す。機体が対象の方を向く。**移動はしない** | `CONFIRM` |
| 4 | 試験員が左右に動き、向きが追従することを目で確かめる | `CONFIRM` |
| 5 | **「追従開始」**を押す | `RUN` |
| 6 | ゆっくり目的地まで歩く。機体は軌跡をなぞる | `RUN` |
| 7 | 到着したら**「停止」**を押す | `STOP` |
| 8 | **「終了」**を押す | → `IDLE` |

### 1.2 挙動の詳細

| 項目 | 仕様 |
| --- | --- |
| 追従の方式 | **軌跡追従**。対象の現在位置へ直行しない |
| 対象に近づいたとき | **停止する。**しきい値は `follow_stop_distance_m`（制動距離から逆算。[Spec-params.md](Spec-params.md) §3【B】） |
| 「近くにいる」対象の範囲 | **追従対象のみ**（F-07）。周囲の人は障害物として扱う |
| ロスト | `tracker_lost_grace_ms`（暫定 500 ms）以内は停止しない。超えたら**選択を解除して停止**し、案内ウィンドウを出す |
| 障害物 | 停止（§0.3） |

### 1.3 KPI

ロスト回数/100 m ／ ロスト→復帰時間 ／ **誤追従（別人・別物）回数** ／ 追従距離のばらつき

## 2. 手動走行（`MANUAL`）

基本的に現行のまま。**他の方式が使えないときのフォールバックでもある。**

### 2.1 手順

| 順 | 操作 | 状態 |
| --- | --- | --- |
| 1 | メインメニュー画面で「手動走行」を選ぶ | `IDLE` → `MANUAL` |
| 2 | 仮想スティックと速度プリセット（低速／中速／高速）で走らせる | `RUN` ⇄ `STOP` |
| 3 | 到着したら「停止」→「終了」 | → `IDLE` |

### 2.2 挙動の詳細

| 項目 | 仕様 |
| --- | --- |
| 障害物 | **警告のみ。**自動ブレーキは任意 ON。場外の既定 OFF、試験場内の既定 ON |
| 通信断 | 操作に使っている端末との通信が切れたら停止（[Spec-safety.md](Spec-safety.md)） |
| 後退 | LiDAR 死角のため速度をさらに落とす |
| 復帰 | 異常解決後の再開は**「確認」1 択**。手動操作は人が改めて始めるもので、自動復帰の対象にしない |

### 2.3 KPI

操作者が画面を見ている時間の割合 ／ 通信途絶起因の停止回数
（他方式を比較するときの**基準線**として使う）

## 3. 教示（`TEACH_FOLLOW` / `TEACH_MANUAL`）

**経路を一度人が走らせて記録すること。記録そのもので移動も達成される。**
教示中は LiDAR で地図を作りつつ、IMU とエンコーダで経路を作る。

### 3.1 教示するかは方式選択時に決める

**途中から教示に切り替えることはしない。**メインメニュー画面で「教示（追従）」「教示（手動）」を
選んだ時点で教示が始まる。

### 3.2 手順（追従・手動で共通）

| 順 | 操作 | 状態 |
| --- | --- | --- |
| 1 | メインメニュー画面で「教示（追従）」または「教示（手動）」を選ぶ | `IDLE` → `TEACH_*` |
| 2 | **教示タブ**で、**既存経路の再設定**か**新規経路の設定**かを選ぶ | `ROUTE_SEL` |
| 3 | （追従のみ）追従対象が提示される。違っていれば選び直す | `ROUTE_SEL` |
| 4 | **選択直後から記録が始まる。**「記録開始」ボタンは無い | `REC` |
| 5 | 目的地まで走らせる（追従なら歩く／手動なら操作する） | `REC` |
| 6 | 途中で休みたければ**「停止」**。**一時停止するだけで終点は確定しない。**「走行」で続きから記録を再開できる | `PAUSE` ⇄ `REC` |
| 7 | 到着したら**「保存」**。ここで**経路の終点が確定し、保存される**（F-03） | `SAVED` |
| 8 | **「終了」**で方式を抜ける。保存していなければ保存可否を問う | → `IDLE` |

### 3.3 通常の追従走行との違い

| 項目 | 追従走行 | 教示（追従） |
| --- | --- | --- |
| 「確認」の動き | 押すと対象の方を向く。左右に動いて確かめる | **省略する。**代わりに**走行開始時の向きを記録**する |
| 対象の取り違え対策 | 「確認」で目視できる | **記録開始前に対象を 1 度画面に提示する**（`DF-D-6` への対処） |
| 一時停止 | 自由にできる | **記録には残さない。**再生時はスムーズに走らせる |

原典は「確認」を省くとだけ書いているが、そのままでは**別人を掴んだまま記録が始まりうる**。
「機体は動かさないが対象は提示する」ことで、省略の意図を保ったまま取り違えを防ぐ。

### 3.4 記録されるもの

| 種類 | 情報源 |
| --- | --- |
| 地図 | LiDAR |
| 経路 | IMU ＋ エンコーダ |
| 走行開始時の向き | IMU（再生時に最初この角度まで超信地旋回する） |

### 3.5 保存

| 項目 | 仕様 |
| --- | --- |
| 保存先 | docker ワークスペース内（経路地図の領域。試験場内地図とは別の位置）→ [Spec-params.md](Spec-params.md) |
| 既存経路の再設定 | **上書きしない。新版として保存し、旧版を 1 世代残す**（F-04）。記録が途中で失敗しても旧版が残る |
| エクスポート／インポート | **可能。**別の機体・別の PC へ経路を持ち出せる |
| 教示する契機 | 何度も使う新規経路ができたとき／物の配置が大きく変わったとき |
| 起点の制約 | **保管場所以外を起点にした教示はしない** |

### 3.6 KPI

記録の完走率（回数で記す） ／ 記録に要する時間 ／ やり直し回数

## 4. 教示再生走行（`REPLAY`）

教示で記録した**地図と経路**を使い、教示時の経路を辿る。

### 4.1 手順

| 順 | 操作 | 状態 |
| --- | --- | --- |
| 1 | メインメニュー画面で「教示再生走行」を選ぶ | `IDLE` → `REPLAY` |
| 2 | 経路を指定する。**逆再生も選択肢に含む。角度の指定は不要** | `ROUTE_SEL` |
| 3 | LiDAR で正確な初期姿勢を推定する。確度が低ければ**探索範囲を広げ**、場合により**完全グローバルローカライゼーション**を行う | `LOCALIZE` |
| 4 | 経路途中からの復帰用に、**最初から完全グローバルローカライゼーションさせることも選べる** | `LOCALIZE` |
| 5 | 表示される地図と位置を見て、推定が正確であることを試験員が確かめる | `READY` |
| 6 | **「再生」**を押す | `RUN` |
| 7 | 到着したら**「停止」**→**「終了」** | `STOP` → `IDLE` |

### 4.2 挙動の詳細

| 項目 | 仕様 |
| --- | --- |
| 開始時の向き | 記録した「走行開始時の向き」まで**超信地旋回**してから走り出す |
| 一時停止の再現 | しない。記録時の一時停止は再生に反映せず、スムーズに走らせる |
| 障害物 | **停止する。自動回避はしない。**人が手動操作で避けるか障害物をどける |
| 地図の更新 | **いつでもオンオフできる。**対象は「自己位置推定に使う地図への書き足し」（F-05）。既定では保存せず、終了時に保存可否を問う |
| 途中からの復帰 | 経路の付近にいれば、完全グローバルローカライゼーションで復帰できる（[Spec-open.md](Spec-open.md) C-10）。ただし本命は保管場所起点 |
| 起点の制約 | **基本的に保管場所から**。途中復帰は付随機能 |

### 4.3 逆再生

**独立した走行方式ではなく、この画面の中の選択肢**（[Spec-open.md](Spec-open.md) C-03）。
UI 上は「順再生／逆再生」のトグル。ただし **KPI では別々に計測する**
（往路と復路の差分で対称性を見るため）。

### 4.4 KPI

**終点位置誤差 [m]（＝ドリフト）** ／ 経路逸脱の最大値 ／ 障害物遭遇時の挙動
（順再生・逆再生を分けて計測）

### 4.5 未解決の課題

**走行中のドリフト補正手段が無い**（`CL-T-4`）。手順 3〜4 の LiDAR 推定は
**開始時の位置合わせ**であって走行中の補正ではない。ホイールオドメトリ＋ジャイロだけの EKF で
200 m を再生すると流れる。1 経路の長さの上限は実測で決める（[Spec-open.md](Spec-open.md) O-c4）。

## 5. ライン誘導走行（`LINE`）

**カメラ**で区画線と分岐を認識して走る。**LiDAR は障害物検知にのみ使う。**

### 5.1 事前準備（マップ登録）

工場内の全ライン経路を「**ノード（分岐点）**」と「**エッジ（ライン区間）**」からなるマップとして登録する。

> **マップ編集画面の設計は行わない。**原典が「[以降設計はあとにまわす]」と
> 明示的に後回しを宣言しているため（[Spec-open.md](Spec-open.md) O-d1）。
> 本設計書ではマップが既にある前提で走行手順だけを定義する。

### 5.2 手順

| 順 | 操作 | 状態 |
| --- | --- | --- |
| 1 | メインメニュー画面で「ライン誘導走行」を選ぶ | `IDLE` → `LINE` |
| 2 | 機体を区画線が見える位置に置く（人の責任） | `SETUP` |
| 3 | マップ上をクリックして**現在地**を指定 | `SETUP` |
| 4 | マップ上をクリックして**向き方向の位置**を指定（方向ベクトルが決まる） | `SETUP` |
| 5 | マップから**目的地**を選ぶ | `SETUP` |
| 6 | 経路が自動計算されマップに反映される | `PLANNED` |
| 7 | **「走行開始」**を押す | `RUN` |
| 8 | 目的地に着くと**自動で停止する** | `ARRIVED` |
| 9 | **「終了」**を押す | → `IDLE` |

### 5.3 挙動の詳細

| 項目 | 仕様 |
| --- | --- |
| 障害物 | **停止する**（§0.3） |
| 線をロストしたとき | **停止し、案内ウィンドウで復帰方法を示す**（`T-r13`）。自動で探し回らない |
| 終点判定 | **7 方式で唯一、自分で判定する**。目的地ノード到達で自動停止 |
| 手順 3〜4 の幾何 | 盤登録の「2 点指示」と**同じ幾何**。UI 部品を共通化する（`T-r18` → [Spec-webui.md](Spec-webui.md)） |

### 5.4 KPI

線のロスト率 ／ 線が無い・途切れる区間の割合 ／ 分岐での判断成功率

## 6. 電子リード走行（`LEASH`）

試験員が**リード（紐・ケーブル状のもの）**を持って歩く。
**引っ張ると進み、張力がかからなくなると止まる。**引っ張られることと向きで操る。

### 6.1 リードデバイス

| 項目 | 仕様 |
| --- | --- |
| 構成 | RaspberryPi4 に **USB 接続する Arduino のデバイス** |
| 得られるもの | ①リードに**張力がかかっていること** ②リードの**向き** |
| 注意 | RaspberryPi4 は LiDAR も USB で繋いでいる。**ポートと帯域を共有する**（[Spec.md](Spec.md) §ハードウェア構成） |

### 6.2 手順

| 順 | 操作 | 状態 |
| --- | --- | --- |
| 1 | メインメニュー画面で「電子リード走行」を選ぶ | `IDLE` → `LEASH` |
| 2 | **自動でリードデバイスの接続を確認する** | `DEV_CHECK` → `READY` |
| 3 | **「走行開始」**を押す | `READY` |
| 4 | リードを引いて目的地まで歩く | `RUN` ⇄ `HOLD` |
| 5 | 到着したら**「停止」** | `STOP` |
| 6 | **「終了」** | → `IDLE` |

### 6.3 挙動の詳細（[Spec-open.md](Spec-open.md) C-06）

| 項目 | 仕様 |
| --- | --- |
| 速度 | **一定**（`v_leash`）。張力の大きさでは変えない。ゆっくり加減速する処理は入れる |
| 向き | リードの向きに追従する |
| 張力が無くなったとき | **止まる**（状態 `HOLD`）。再び張力がかかれば `RUN` に戻る |
| 意図して離したか落としたか | **区別しない。**どちらも止まる（落としたときに走り続ける方が危険なため） |
| 障害物 | **停止する**（§0.3） |
| 軌跡 | **なぞらない。**追従走行の「ショートカットしない」に当たる規定は電子リードには無い |

### 6.4 KPI

距離追従誤差 ／ 意図しない停止回数 ／ リードの取り回しの実用性（定性）

## 7. 方式の比較（PoC で全部作り、MVP で削る）

| 方式 | 事前に必要なもの | 試験員は | 経路の決まり方 | 主センサ | 障害物 | 終わり方 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 追従走行 | なし | **先を歩く** | 歩いた軌跡 | LiDAR（人＋障害物） | 停止 | 人が停止 |

### 7.1 採否の判断順（上から見て落ちた時点で切る）

1. **許可** — その方式を試験場で使う許可が下りるか（足切り）
2. **完走率・人の介入回数** — 実用に足る自律度があるか
3. **安全** — 接触 0 件、意図しない発進 0 件
4. **MVP 期間内に作れるか** — 工数

### 7.2 無人走行の許可について

**教示再生走行（順再生・逆再生）とライン誘導走行**は、試験員が同行しない形で使うなら
**無人走行の許可**が要る（`CL-G-2`）。先方には移動方式を追従走行と説明済みで、まだ聞いていない。

→ **教示再生走行は「試験員が先導・同行する形」を既定として測る**
（`NewVISION.md` 案 4-B「教示再生・先導」。許可不要・現場改変不要）。
許可が取れれば同じコードで無人版に切り替える。

→ **ライン誘導走行も同じく先導・同行を既定とする。**ただしこれは本設計書での判断であり、
`NewVISION.md` 案 4-B は教示再生についてのものである（ライン誘導走行を含んでいない）。
ライン誘導走行はカメラで線を追うため先導者が線を隠す懸念があり、**先導が成立するかは実測で確かめる**。

> **採番に注意**: ここで挙げた方式は **UI 採番**（5＝教示再生、6＝区画線）ではなく
> **名前**で書いている。KPI 採番では 5＝教示再生（順）、6＝教示逆再生、7＝区画線となり
> ずれるため（[Spec-open.md](Spec-open.md) C-03）、この節では番号を使わない。

### 7.3 KPI の測り方

**率ではなく回数で書く**（[Spec-open.md](Spec-open.md) C-08）。「10 回中 10 回」「介入 0 回 / 200 m × 10 往復」。

| 段階 | 場所 | n | 目的 |
| --- | --- | --- | --- |
| **社内試験（PoC 期）** | 社内 | 1 方式あたり **10〜30** | **方式の比較と取捨選択はここでしかできない** |
| **実証実験（MVP）** | 先方の教育用施設 | 1 方式あたり **1〜2** | 選び抜いた方式のデータ取得 |

10 回中 10 回成功しても失敗率の 95% 信頼上限は約 26%。30 回中 30 回でようやく約 10%。
**実証実験の n では 8 方式の比較はできない**ので、選抜は社内試験で終わらせる（`CL-G-7`）。
