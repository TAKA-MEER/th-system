# 始業点検と校正

[Spec.md](Spec.md) の詳細。**「気づく」ための始業点検と、「直す」ための校正。**

この 2 つは**対になっている**。行き止まりを作らないことが設計の要点である。

```
始業点検（気づく） ──ズレを検知──> 校正（直す） ──> 始業点検（直ったか見る）
        ▲                                                              │
        └──────────────────────────────────────────────────────────────┘
```

現状はどちらも独立した CLI スクリプトで、手順書はコードのコメントにしかなく、
実測値はターミナルへの手入力、適用は補正値をコピーして別コマンドを叩く形になっている。
**理想はこれを一つの体験にまとめること。**

---

## 1. 共通の安全規則

| 規則 | 始業点検 | 校正 |
| --- | --- | --- |
| **開始できるモード** | `IDLE` / `MANUAL` 以外では開始できない | **同じ制限を課す**（`Z-1` / F-15） |
| 非常停止・フォルト | 即座に反映され停止する | 同左 |
| 機体が動く項目 | **モーター・エンコーダ確認のみ** | **直進・旋回の 2 つ**（自律で一定距離・角度を動く） |
| 動かし方 | **押している間だけ動き、離せば止まる** | **自律で動く。**だから常に見える位置に**中断ボタン**を置く |
| 中断後 | いつでもやり直せる | **補正値を確定せずに終われる** |
| 非常停止・フォルトで止まった後 | やり直す | **やり直す。途中再開はしない**（`K-r5`） |

**校正のほうが危険である。**始業点検は人がボタンを押している間だけ動くが、
校正は自律で走る・回る。したがってモード制限は校正にも必ず課す。

原典は始業点検にだけモード制限を書いていたが、これは書き漏れとみなす。

## 2. 始業点検（`OPCHECK`）

**項目を選ぶだけでモニターが立ち上がり、その場で見える。**
別ツールの起動やトピック名の暗記を要らなくする。

### 2.1 対象は 4 項目（[Spec-open.md](Spec-open.md) C-09）

| # | 項目 | 何を確認するか | 機体が動くか |
| --- | --- | --- | --- |
| 1 | **物理非常停止ボタン** | ボタンの状態をシステムが把握しているか | 動かない |
| 2 | **モーター・エンコーダ** | 低速で指令どおりに動くこと、エンコーダが回転を検出できること | **動く** |
| 3 | **IMU** | データが届くこと、校正状態 | 動かない |
| 4 | **LiDAR** | スキャンが正しい範囲・周期で届くこと、死角マスクが実機と合っていること | 動かない |

> 原典は対象を 4 項目としながら本文と画面図が 3 項目のままだった（`N-14` / `C-r1`）。
> **4 項目で統一し、欠けていた非常停止ボタン確認の手順・画面・NG 時の行き先を新たに定める。**

### 2.2 共通の機能

| 機能 | 内容 |
| --- | --- |
| **選ぶだけで見える** | 項目を選択した瞬間にモニターが立ち上がる |
| **合否をできる範囲で自動判定** | 「データが届いているか」「値が想定範囲内か」は自動で OK/NG。目視でしか判断できないものは**どこを見ればいいかを画面が指し示す** |
| **総合ステータス** | **4 項目**すべての結果を一覧に集約し、「このまま使い始めてよいか」を一目で判断できる |
| **すぐ再実行できる** | いつでも同じ確認をやり直せる |
| **異常時は校正へ誘導する** | ズレを検知したら、直すための画面へその場で遷移できる |

### 2.3 何が自動で分かり、何は人が見るしかないか

| # | 自動で OK/NG が出る | 目視するしかない | NG のときの行き先 |
| --- | --- | --- | --- |
| 1 非常停止 | ボタン状態を受信できているか、状態が変化を検出できるか | ボタンの実物の状態と画面表示が一致しているか | **故障診断**（§2.5） |
| 2 モーター | 指令と実測（エンコーダ）の**符号・追従** | 機体が実際に動いたか | **故障診断**（§2.5） |
| 3 IMU | データ受信、静止時バイアスが小さいこと、校正状態 | — | **IMU 校正** |
| 4 LiDAR | 死活、受信周期、全周の有効性、死角マスクのズレ | マスクが実機のアルミパイプ位置と合っているか | **LiDAR 死角マスク校正** |

### 2.4 項目ごとの流れ

#### 1. 物理非常停止ボタン（新規に定めた項目）

原典は「ボタンの状態と画面の表示が一致していることを確認」の **1 行だけ**だった（`C-r3`）。
押す／離すの手順も、画面表示も、NG 時の行き先も無かったので次のように定める。

| 順 | 画面の案内 | 判定 |
| --- | --- | --- |
| 1 | 「非常停止ボタンを**押してください**」 | 押下を検出したら自動で OK |
| 2 | 「押されていることが画面に出ています。実物と一致していますか」 | 人が目視で答える |
| 3 | 「ボタンを**解除してください**」 | 解除を検出したら自動で OK |
| 4 | 「解除されたことが画面に出ています。一致していますか」 | 人が目視で答える |

**押す・離すの両方**を試す。片方だけでは配線の断線・短絡を区別できないため。

#### 2. モーター・エンコーダ

| 順 | 内容 |
| --- | --- |
| 1 | **前進・後退・右超信地旋回・左超信地旋回**の 4 方向ボタンを、**押している間だけ低速で動く** |
| 2 | 目視で機体が動くことを確認しつつ、画面で**指令と実測（エンコーダ）の追従をリアルタイムに見る** |
| 3 | ボタンを離すと自動で停止する |
| 4 | 指令と実測の**符号・追従**が合っているかを自動で OK/NG 表示する |

左右輪それぞれについて「指令 −0.10 m/s ／ 実測 −0.09 m/s ／ ✓」の形で並べる。

#### 3. IMU

| 順 | 内容 |
| --- | --- |
| 1 | 画面を開くと IMU データの生死とジャイロ値がすぐ表示される |
| 2 | **静止状態でバイアスが小さいことを自動確認**する |
| 3 | 校正状態（sys / gyro / accel / mag）をリアルタイムに表示する |
| 4 | 未校正・劣化していれば「校正してください」と**IMU 校正へ誘導**する |

**「校正済みで今は正常」なのか「劣化していて校正が必要」なのかを画面が判断し、
後者のときだけ人に校正を促す。**毎回同じ確認・同じ案内をなぞらせない。

#### 4. LiDAR

| 順 | 内容 |
| --- | --- |
| 1 | 画面を開くと生のスキャンがその場にライブ表示される |
| 2 | 死活・受信周期・全周の有効性を自動確認する |
| 3 | **死角マスクを重ねて表示**し、実機のアルミパイプの位置とズレていないかを目視で確認する |
| 4 | ズレを自動検知したら「校正してください」と**LiDAR 死角校正へ直接誘導**する |
| 5 | 既知距離の障害物との比較も、**カーソルを合わせるだけで数値が読み取れる** |

### 2.5 故障診断への誘導（新規・`C-r6` / `Z-2`）

**非常停止ボタンとモーター・エンコーダの NG は校正では直らない。**
IMU と LiDAR には校正への導線があるが、この 2 つには受け皿が無かった。

→ **「故障診断」画面**を設け、NG の内容に応じたチェック手順を出す。

| NG の内容 | 出すチェック手順 |
| --- | --- |
| 非常停止ボタンの状態が届かない | GPIO 配線・プルアップ・ボタン自体の導通 |
| 押しても状態が変わらない | 同上 |
| 指令を出しても実測が 0 | モーター配線・ドライバ・電源 |
| 指令と実測の**符号が逆** | 左右の入れ替わり、エンコーダ極性 |
| 片輪だけ追従しない | その側の配線・エンコーダ |

この画面は診断結果を示すだけで、修理そのものは人が行う。

### 2.6 いつやるか

| タイミング | 範囲 |
| --- | --- |
| 導入時 | **4 項目すべてを人が実施する** |
| 毎回の起動時 | **自動で判定できる項目だけ自動実行する**（→ [Spec-ops.md](Spec-ops.md) §2.6） |
| 気になったとき | いつでも始業点検画面から再実行できる |

**総合ステータスが NG でも運用には入れる（警告のみ）。**
必須通信系統の不通だけは別扱いで運用に入れない（`C-r4` → [Spec-ops.md](Spec-ops.md) §2.3）。

## 3. 校正（`CALIB`）

### 3.1 対象は 4 項目

| # | 項目 | 何を補正するか | 適用の重さ |
| --- | --- | --- | --- |
| 1 | **直進校正** | 車輪半径（走行距離の誤差） | 即時反映・永続化（**PC 側のスケール係数で補正する。**§3.6） |
| 2 | **旋回校正** | 実効車輪間距離（旋回角度の誤差） | 即時反映・永続化 |
| 3 | **IMU 校正** | センサ内部オフセット（ジャイロ・加速度・地磁気） | 完了状態を保存し、次回起動時に自動復元 |
| 4 | **LiDAR 死角マスク校正** | 機体アルミパイプが写り込む角度範囲 | 即時反映・永続化 |

### 3.2 共通の機能

| 機能 | 内容 |
| --- | --- |
| **ガイド付きウィザード** | 「何をどう準備するか」「どう動かすか」「どこを測るか」をその場で案内する。事前に文書やコードのコメントを読みに行かせない |
| **測定値の入力も画面内で完結** | ターミナルへの手入力を経由しない |
| **即時反映・永続化** | 補正値は求まった瞬間に反映され、電源を入れ直しても消えない。**再ビルド・再書き込みを必要とする補正は理想ではない** |
| **適用前のプレビュー** | 「現在値 → 補正後の値」を確定前に見せ、明らかにおかしい値（ゼロ割れ・桁違い）を弾く |
| **履歴とロールバック** | 過去の補正値を残し、いつでも 1 つ前に戻せる。校正して悪化したときに戻す手段がないと安心して校正できない |
| **適用後の検証** | 補正して終わりにせず、同じ動作をもう一度行い、誤差が許容範囲に収まったことを確認してから完了とする |
| **中断・安全** | 常に見える位置に中断ボタン。非常停止・フォルトで即座に停止。中断後は補正値を確定せずに終われる |
| **始業点検との連携** | 校正が終わったら**始業点検へ戻る導線**を出し、直ったかを見せる |

### 3.3 ウィザードの骨格

```
Step 1 案内 ──> Step 2 実行・実測 ──> Step 3 確認（プレビュー）──> Step 4 検証
   │                 │                      │                        │
   └─────────────────┴──────────────────────┴────────────────────────┘
                    どのステップからでも [ 中断 ]（補正値を確定せず終了）
```

**この骨格が完全に当てはまるのは直進・旋回の 2 項目だけ**である（`K-r4`）。

| 項目 | 骨格との差 |
| --- | --- |
| 1 直進 | 完全に当てはまる |
| 2 旋回 | 完全に当てはまる |
| 3 IMU | **実測値の入力もプレビューも無い。**センサ自身が校正するため、進捗を見て待つだけ |
| 4 LiDAR 死角 | **実測値の入力の代わりに、画面上でなぞって範囲を指定する** |

### 3.4 項目ごとの流れ

| # | 流れ |
| --- | --- |
| **1 直進** | 指定距離を自律走行 → 実際に進んだ距離を画面へ入力 → 補正後の値をプレビュー → 適用 → **検証走行で再確認** |
| **2 旋回** | 指定角度を自律旋回 → 実際の回転角を（分度器で測って）入力 → プレビュー → 適用（即時反映・永続化）→ **検証旋回で再確認** |
| **3 IMU** | 案内に従って機体を**8 の字**に動かす → sys / gyro / accel / mag のリアルタイム表示を見ながら全て「完全」になるまで続ける → **自動で完了**。オフセットを保存し次回起動時に自動復元 |
| **4 LiDAR 死角** | 生のスキャンをライブ表示 → 死角として写り込んでいる角度帯を**画面上でなぞって選択** → プレビューで死角マスクが正しくかかることを確認 → 適用（即時反映・永続化） |

### 3.5 死角マスクの編集・削除（`K-r6`）

原典は「追加」しか書いていない。**登録済みの角度帯を選んで、編集・削除できる**ようにする。
実機の構造が変わったときや、誤って広く取ったときに直せないと使えないため。

### 3.6 直進校正のギャップ（`K-r7`）— **解決済み**

**車輪半径は ESP32 ファームウェアのコンパイル時定数であり、そのままでは適用に書き換えと再書き込みが要る。**
他の 3 項目と同様に即時反映・再起動不要であるべきで、**是正すべきギャップとして扱っていた**（`O-d10`）。

**決定: PC 側のスケール係数で補正する。ファームウェアは触らない。**

| 項目 | 内容 |
| --- | --- |
| 方法 | ファームの車輪半径を**公称値として固定**し、**PC 側に補正係数（真値 ÷ 公称値）を持つ** |
| かけ方 | **指令と実測の両方向にかける**（片方だけだと指令と報告がずれ、閉ループが崩れる） |
| 適用 | **即時反映・再起動不要・再書き込み不要。**他の 3 項目と同じ扱いになる |
| 保存先 | 補正値の保存先（§3.8）。ファームには何も残さない |
| **安全上の制約** | **係数が 1 から 10% を超えて外れたら起動を拒否する。**それは校正ではなく**機械的な異常**（摩耗・別部品）であり、数値で押し切らせない。故障診断（§2.5）へ誘導する |
| 当面の扱い（**撤回**） | ~~ウィザードで「再書き込みが必要」と案内する~~ → **不要になった** |

**係数を PC 側に持つことの副作用**: 機体を入れ替えたとき、値が**前の機体のまま付いてくる**。
複数機体になったときの扱いは詳細設計で保留になっている（当面は機体 ID を持たせて警告する）。

### 3.7 許容範囲と要再校正の判定（`K-r1` / `K-r2` / F-13）

原典は「誤差が許容範囲に収まったことを確認」「要再校正」「ドリフト増加を検知」と書くが、
**その許容範囲も判定基準も定義していない。**枠と式だけ定め、数値は実測後に確定する。

#### 検証の合否

```
Step 4 の検証で測った誤差 ≦ 許容範囲  → 完了
Step 4 の検証で測った誤差 >  許容範囲  → 適用前に戻し、やり直しを促す
```

| 項目 | 許容範囲の定義 | 値 |
| --- | --- | --- |
| 1 直進 | 指定距離に対する相対誤差 | **未確定**（[Spec-open.md](Spec-open.md) O-c5） |
| 2 旋回 | 指定角度に対する絶対誤差 [deg] | **未確定** |
| 3 IMU | sys / gyro / accel / mag が全て最大値であること | 定義済み（3/3） |
| 4 LiDAR 死角 | マスクと実際の写り込みの角度差 [deg] | **未確定** |

**許容範囲は目標 G2（カメラ昇降が要求する許容差）から逆算できる**ので、
[Spec-open.md](Spec-open.md) O-a1 が決まると連鎖して決まる。

#### 要再校正の判定

次の**2 条件のいずれか**を満たしたら「要再校正」と表示する。

| 条件 | 内容 |
| --- | --- |
| **経過** | 前回校正から `calib_interval_days` を超えた |
| **悪化** | 始業点検で測った誤差が、前回の検証時より一定以上悪化した |

「ドリフト増加を検知」は後者にあたる。

### 3.8 補正値と履歴の保存（`K-r3` / F-14）

原典は教示データ・地図の保存先を書いているのに、**校正の補正値と履歴の置き場所を書いていない。**
「永続化」「履歴とロールバック」を求めている以上、置き場所が要る。

| 項目 | 決めたこと |
| --- | --- |
| 保存先 | docker ワークスペース内。**地図・経路とは別の位置**（[Spec-params.md](Spec-params.md)） |
| 世代 | **3 世代残す。**1 つ前に戻せることが原典の要求だが、余裕を持たせる |
| 内容 | 補正値・校正日時・検証結果・誰が実施したか（開発モードでは記録項目を選べる） |
| 直進校正 | **他の 3 項目と同じ扱い。**補正値（スケール係数）をここに残し、そのまま適用する（§3.6） |

### 3.9 いつやるか

| タイミング | 範囲 |
| --- | --- |
| 導入時 | **4 項目すべて** |
| 始業点検から誘導されたとき | 該当項目のみ |
| 定期 | §3.7 の「経過」条件で促す |

**未確定**: 定期校正の間隔 `calib_interval_days`（[Spec-open.md](Spec-open.md) O-c5）。

## 4. 2 つの画面の対応関係（`Z-2`）

始業点検の 4 項目と校正の 4 項目は **1 対 1 で対応していない。**

| 始業点検 | 対応する校正 | 備考 |
| --- | --- | --- |
| 1 物理非常停止ボタン | **なし** | 校正で直る種類のものではない → **故障診断**（§2.5） |
| 2 モーター・エンコーダ | **なし**（直進・旋回は「校正」であって「故障の検知」ではない） | 同上 → **故障診断** |
| 3 IMU | 3 IMU 校正 | 1 対 1 |
| 4 LiDAR | 4 LiDAR 死角マスク校正 | 1 対 1 |
| （始業点検に対応項目なし） | 1 直進校正 | 走行距離の精度は始業点検では測れない |
| （始業点検に対応項目なし） | 2 旋回校正 | 旋回角度の精度は同上 |

**この非対称が「故障診断」画面を新設する理由**である。
校正へ誘導できない NG が 2 つあり、それらが行き止まりにならないようにする。
