# WebUI 仕様

[Spec.md](Spec.md) の詳細。**画面・遷移・ウィンドウ・共通部品の定義。**

見た目のモックアップは [mockup/index.html](mockup/index.html)（ブラウザで開ける単一ファイル）。
**本ファイルとモックアップは同じ画面一覧・同じウィンドウ種別を持つ。**

## 0. 大前提

| # | 原則 | 理由 |
| --- | --- | --- |
| **1** | **操作系は WebUI のみ。** 専用アプリ・コマンドライン操作を運用手順に含めない | 試験員 1 人で完結させるため |
| **2** | **PC とタブレットの両方で操作できる** | 現地で登録操作をするのはタブレット。地図を見るのは PC |
| **3** | **縦長・横長の両方に対応する** | タブレットを縦でも横でも持つ |
| **4** | **ヘッダは常に最上位。何も被さらない** | 非常停止が隠れないため |
| **5** | **ブラウザ標準の確認ダイアログを使わない** | ヘッダより上に出てしまうため |
| **6** | **画面がモードを決める** | ゾーン（試験場内／場外）が画面から自動で決まる（[Spec-modes.md](Spec-modes.md) §7） |
| **7** | **UI には説明文を置かない**（[Spec-open.md](Spec-open.md) U-11） | 下表 |
| **8** | **同じ操作は同じ場所に置く**（[Spec-open.md](Spec-open.md) U-15） | §3.3 |

### 0.1 原則 7「UI には説明文を置かない」の切り分け

| 種類 | 例 | 置き場所 |
| --- | --- | --- |
| **状態** | 「一時停止中（記録は保持・終点は未確定）」「前方 0.6 m に障害物」 | **UI に置く** |
| **次にできる操作** | 「立ってほしい位置に立って押してください」 | **UI に置く**（短く 1 行） |
| **拒否された理由** | 「カメラが接続されていません」 | **UI に置く**（ウィンドウ。押されて初めて出す） |
| 設計の根拠 | 「面積ではなく高さを基準にする理由は…」 | **設計書へ** |
| 仕様の宣言 | 「自動でルートを変えません」「ショートカットしません」 | **設計書へ** |
| 手順の解説 | 「①→② が方向ベクトルになります」 | **マニュアルへ** |

**判定のしかた**: その文を消したとき、**試験員が次に何を押すか分からなくなる**なら UI に残す。
「そういう仕様だと分かる」だけなら設計書へ移す。「◯◯しません」で始まる文はほぼ後者である。

## 1. 常設ヘッダ

**画面の最上部に固定。スクロールしない。何にも覆われない。**

| 要素 | 内容 |
| --- | --- |
| ロゴ | 高見舎ロゴ |
| プロジェクト名 | **MIRS2602-高見舎プロジェクト** |
| 画面名称 | いま開いている画面の名前。**ヘッダで最も大きい文字**（§1.3） |
| 現在のモード | [Spec-modes.md](Spec-modes.md) の 18 モード。モードごとに色を変える。**2 番目に大きい文字**（§1.3） |
| **ゾーン表示** | 試験場内のときだけ「試験場内・低速・自動ブレーキ ON」を出す |
| フォルト表示枠 | 正常／フォルト名。非表示中の異常ウィンドウがあればバッジ |
| **非常停止ボタン** | 常時表示・常時動作 |

### 1.1 重なり順（z 順）

**通常のモーダルとは逆で、ヘッダがすべての上に来る。**

```
┌─────────────────────────────────────────┐ ← ヘッダ（最上位・常に押せる）
│ ロゴ  プロジェクト名  画面名  モード     │
│ フォルト枠            [ 非 常 停 止 ]     │
├─────────────────────────────────────────┤
│                                          │
│   ┌───────────────────────────────┐     │ ← ウィンドウ（本文の上・ヘッダの下）
│   │  異常ウィンドウ               │     │
│   │             [非表示] [確認]   │     │
│   └───────────────────────────────┘     │
│                                          │
│   本文（この領域だけスクロールする）      │
│                                          │
└─────────────────────────────────────────┘
```

| 層 | 内容 |
| --- | --- |
| 最上位 | ヘッダ（非常停止を含む） |
| 中間 | ウィンドウ類（異常・案内・確認・手押し） |
| 最下位 | 本文（唯一スクロールする領域） |

**検証方法**: 異常ウィンドウを開いた状態で非常停止ボタンが押せること。
これが押せなければ設計違反である。

### 1.2 非常停止ボタンの大きさ（[Spec-open.md](Spec-open.md) U-9）

**タップで確実に押せる大きさにする。画面内で最も大きい操作要素とする。**

| 項目 | 要件 |
| --- | --- |
| **高さ** | **72 px 以上、かつ基準文字サイズの 4.2 倍以上**（§1.4 で基準が大きくなれば連動して大きくなる）。かつ**画面内のどのボタンよりも高い**こと |
| **幅** | **160 px 以上**。かつ**画面幅の 25% 以上** |
| 縦長のとき | ヘッダ 2 段目の**幅 45% 以上**を占める |
| 文字 | **基準文字サイズの 1.25 倍以上・太字**。省略せず「非常停止」と表示する |
| 余白 | 他の操作要素と隣接させない（誤タップ防止） |

**「面積で最大」ではなく「高さで最大」を要件にする理由**: メインメニュー画面のように
横長のリストボタンが並ぶ画面では、面積では一覧ボタンが上回ってしまう。
タップの成否を決めるのは**指の当たる方向の余裕＝高さ**なので、そちらを基準にする。

**解除ボタンにはこの要件を適用しない。**誤って解除しないよう、
むしろ小さめにし、画面の反対側（下端）に置く。

### 1.3 画面名称と現在のモードの大きさ（[Spec-open.md](Spec-open.md) U-10）

**この 2 つは「いま何をしている画面か」を示す唯一の手掛かりなので、ヘッダで最も大きくする。**

| 要素 | 大きさ | 備考 |
| --- | --- | --- |
| **画面名称** | 本文の基準文字サイズの **1.45 倍以上・太字** | ヘッダで最大 |
| **現在のモード** | 基準の **1.05 倍以上・太字**。モード色の枠と背景を付ける | 2 番目 |
| プロジェクト名 | 基準の 0.8 倍以下 | 常時同じ文字列なので情報量が無い |
| ゾーン表示・開発モード | 基準の 0.72 倍 | 出ているかどうかが分かればよい |

**場所が足りないときに畳む順序**（縦長で必ず起きる）:

1. **プロジェクト名を消す**（ロゴは残す。ロゴだけで所属は分かる）
2. **ゾーン表示を短縮する**（「試験場内・低速・自動ブレーキ ON」→「場内・低速」）
3. 画面名称を末尾省略（`…`）にする

**画面名称・モード・非常停止は、どれだけ狭くても縮めない。**
また**ヘッダが 2 行を超えて折り返してはいけない。**ヘッダが伸びた分だけ本文が痩せ、
§1.4 の「スクロールさせない」が崩れる。

### 1.4 文字と図の大きさは画面幅に追随させる（[Spec-open.md](Spec-open.md) U-12・U-13）

**同じ文字サイズのまま画面を広げると、広い画面ほど文字が小さく見える。**
基準文字サイズを画面（アプリの表示領域）の幅の関数にする。

| 画面幅 | 基準文字サイズ |
| --- | --- |
| 〜1130 px（スマートフォン・タブレット縦・小さめの窓） | **16 px**（据え置き） |
| 1130〜1670 px | 幅に比例して増やす |
| 1670 px 〜 | **22 px**（頭打ち） |

**ビューポート幅ではなくアプリの表示領域幅で決める。**
ウィンドウを小さくして使うことがあるため、ビューポート基準だと合わない。

**スクロールの要件**:

| 端末 | 要件 |
| --- | --- |
| **短辺 768 px 以上**（タブレット・PC） | **どの画面もスクロールさせない。**本文が縦に溢れたら設計不良とみなす |
| 短辺 768 px 未満（スマートフォン） | スクロールしてよい。ただしヘッダと画面左上の操作バーは固定して常に見せる |

**溢れたときに使う手段**（この順に検討する）:

1. **図の高さを頭打ちにする** — レーダー・地図・仮想スティックは幅なりに縦へ伸びる。
   縦長では上限を決めて中央に収める（縦横比は保つ）
2. **右列の詳細をタブに畳む** — 操作カードは常に見せ、それ以外をタブで切り替える
3. **広い画面では右列を 2 列に割る** — 幅 1300 px 以上。操作カードは必ず左上に置く

**手動操作パネル（§4.0 W-6）はこの判定に影響しない。**浮くカードなので本文の高さを変えない。

### 1.5 レイアウトの骨格（安全上の要件）

| 項目 | 仕様 |
| --- | --- |
| 高さ | 画面高いっぱいの固定高。ページ全体はスクロールしない |
| ヘッダ | 上端に固定 |
| 非常停止の解除 | **下端に固定。**「押す」と離して配置し、色も形も変える |
| スクロール | **本文領域だけ** |

**理由**: 過去にスクロールで非常停止ボタンが画面外に出た事例が、安全上の欠陥として記録されている。
この骨格は装飾ではなく安全要件である。

### 3.2 S-01 メインメニュー

| 区画 | 内容 |
| --- | --- |
| **移動** | 7 つの走行方式ボタン。前提を満たさないものは**非活性＋理由表示** |
| **試験場** | 試験準備 ／ 試験 |

| **その他** | 設定 |

| **運用の終了** | **1 日の運用を終える導線**（下記）。[Spec-ops.md](Spec-ops.md) §4 の手順 3〜4 が押す先 |

#### 3.2.1 「運用の終了」区画（[Spec-open.md](Spec-open.md) F-23）

**この区画が無いと、[Spec-ops.md](Spec-ops.md) §4 の終了手順が実行できない。**
同 §4 は「**順序が重要**（保存前に電源を切ると作業が消える）」と明示しており、
**未保存の検出はここが唯一の機会**である。

**区画はカード 1 枚に畳み、詳細は確認ウィンドウ（W-4）に出す。**
一覧をカードに常時展開すると、**メインメニュー画面がスクロールを要求してしまう**（§1.4 違反）。

| 順 | どこ | 中身 |
| --- | --- | --- |
| 1 | **カード** | **未保存の件数**（「2 件」／「なし」）と、**「制御系を停止する」**ボタン 1 つだけ |
| 2 | **W-4** | ボタンを押すと開く。**未保存の一覧**（試験場内地図／教示経路／校正の補正値／教示再生中の地図の書き足し）を出す |
| 3 | **W-4** | 項目ごとに**「保存」／「破棄」**を選ばせる。**破棄は二段階アーム式ボタン**（§6） |
| 4 | **W-4** | **「停止する」**。未保存が残っている間は押せない（押すと理由を表示） |
| 5 | 画面 | 停止の進捗と、**停止が完了したことを出す**（ここまで確認してから機体の電源を切る） |

**カードのボタン自体は未保存があっても押せる。**押せないボタンを置くより、
押したら一覧と理由が出るほうが「何をすれば終われるか」が分かる。
**押せなくするのはウィンドウの中の「停止する」だけ**にする。

**「終了」という語を使わない。**この設計書では「終了」＝**方式を抜けてメインメニュー画面へ戻る**に
固定してある（[Spec-transit.md](Spec-transit.md) §0.1）。同じ語で運用そのものを終わらせると、
**方式を抜けるつもりで制御系を止める誤操作**を招く。**画面には「制御系を停止する」と書く。**

> **原典との差異**: [Spec-ops.md](Spec-ops.md) §4 手順 3 は「メインメニュー画面の**「終了」**を押す」と
> 書いているが、上記の理由で**表示上の語だけ「制御系を停止する」に改める**。手順そのものは変えない。

### 3.3 操作の置き場所（**全画面共通の規則**・[Spec-open.md](Spec-open.md) U-15）

**この規則は 7 走行方式だけでなく、試験準備・試験・始業点検・校正にも等しく適用する。**
画面ごとに置き場所が違うと、試験員は画面の数だけ「どこを押すか」を覚えることになる。

| 置き場所 | 何を置くか |
| --- | --- |
| **画面左上の操作バー**（固定・スクロールしない） | **「終了」**（または「戻る」）／画面内のタブ／状態を表すピル |
| **右列の先頭の「操作カード」** | **停止・確認・走行・保存・手動** |

**操作カードの格子は固定する。使わないボタンは置かないが、置くボタンの位置は動かさない。**

**どの状態でどのボタンが押せるかは [Spec-modes.md](Spec-modes.md) §3.1 が正。**
この節は置き場所を決めるだけで、遷移の定義はしない。

|  | 左 | 中 | 右 |
| --- | --- | --- | --- |
| **上段** | **停止** | **確認** | **走行**（教示再生では「再生」） |
| **下段** | **保存** | — | **手動** |

| ボタン | 置く画面 | 意味 |
| --- | --- | --- |
| **停止** | **全画面** | 一時停止。モード・選択・記録はすべて保持する |
| **確認** | 追従系（S-10 / S-12） | 向くだけで移動しない |
| **走行 / 再生** | 自律で動く方式（S-10 / S-12 / S-14 / S-15 / S-16） | 走り出す |
| **保存** | 記録・地図を持つ画面（S-12 / S-13 / S-14※ / S-20） | 記録・地図を確定する。※ S-14 は地図更新 ON のときだけ |
| **手動** | **仮想スティックを常設できない画面だけ**（S-14 / S-15 / S-16 / S-20 / S-21） | 押すと**手動操作パネル**（§4 W-6）が出る |

**「終了」を操作カードに入れてはいけない。**一時停止のつもりで方式を抜ける誤操作を招く。

**「手動」ボタンを置くかどうかは、スティックを常設できるかだけで決まる**（[Spec-open.md](Spec-open.md) U-16）:

| 画面 | スティック | 「手動」ボタン |
| --- | --- | --- |
| S-10 / S-12（追従系） | **常設する** | **置かない。**スティックに触れた瞬間にジョグ介入が始まる |
| S-11 / S-13（手動系） | **常設する** | **置かない。**スティックそのものが走行操作 |
| S-14 / S-15 / S-16 / S-20 / S-21 | 置けない（主表示が地図・図で埋まる） | **置く。**押すとパネルが出る |

ボタンが 2 つあると「スティックを触る前に手動を押すのか」が分からなくなる。
**触れば始まる、が唯一の入り口**である。

**始まりは「触れた瞬間」だが、続いていることは合図を送り続けて示す。**
触れている間、UI はジョグ継続の合図を繰り返し送る（[Spec-modes.md](Spec-modes.md) §3.1.1 のリース）。
**「離した」という 1 回きりのイベントに頼らない** — 通信が途切れて届かなかったとき、
機体側が介入中のまま固まるため（[Spec-open.md](Spec-open.md) F-29）。

### 3.3.1 色の使い分け（[Spec-open.md](Spec-open.md) U-17）

| 見た目 | 意味 | 使う場所 |
| --- | --- | --- |
| **青（塗り）** | **いまの状態** | 停止／確認／走行のうち、**いま該当している 1 つだけ** |
| **緑（塗り）** | 押すと確定する動作 | 保存 |
| 枠のみ | 押せるが、いまの状態ではない | それ以外 |

**同じ操作カードの中で青を 2 つ以上にしてはいけない。**
「停止が青くて再生も青い」状態は、いま止まっているのか走っているのかを読めなくする。
**強調のために青を使わない。**青は状態表示専用である。

### 3.4 S-10／S-12（追従系）と S-11／S-13（手動系）は同じ画面（[Spec-open.md](Spec-open.md) U-5）

**教示は「教示なしの画面＋教示タブ」で作る。**走行部分は完全に共通にする。

| 画面 | 走行タブ | 教示タブ | 操作カード（§3.3 の格子） |
| --- | --- | --- | --- |
| **S-10** 追従走行 | 「追従」 | — | 停止／確認／走行 |
| **S-12** 教示（追従） | 「追従」**（S-10 と同一）** | **「教示」** | 停止／確認／走行／**保存** |
| **S-11** 手動走行 | 「走行」 | — | 停止 |
| **S-13** 教示（手動） | 「走行」**（S-11 と同一）** | **「教示」** | 停止／**保存** |

**この 4 画面の操作カードに「手動」ボタンは無い。**仮想スティックを常設するので、
**触れた瞬間にジョグ介入が始まる**（§3.3 の判定基準）。

**ただし S-11 / S-13（手動系）はジョグ介入ではない。**スティックそのものが走行操作なので、
触れると一時停止ではなく**走行（教示中なら記録）に入る**（[Spec-open.md](Spec-open.md) F-31）。
**S-13 に「走行」ボタンが無いのはこのため**で、一時停止・保存のあとに記録を再開する契機も
**スティック操作**である（[Spec-modes.md](Spec-modes.md) §3.1.2 ／ F-38）。

**共通にするもの**: レーダー（追従系）／仮想スティック／速度スライダ／速度プリセット／
障害物の警告表示／自動ブレーキのトグル（手動系）／「終了」ボタンの位置。

**レーダーと仮想スティックは 1 つの部品として定義し、置く画面が増えても中身を作り分けない。**
モックアップではテンプレートから差し込んで、4 画面で同一であることを構造的に保証している。

**教示画面だけが増やすもの**: 「教示」タブ 1 枚と、操作カードの「**保存**」ボタン 1 つ。

**理由**: 教示は「走らせ方」を変えるものではなく「走った軌跡を記録するかどうか」の違いしかない。
画面を作り分けると、試験員は同じ走行操作を 2 通り覚えることになる。

### 4.0 帯で出すもの（W-3）と、浮かせるもの（W-6）

| | W-3 案内 | W-6 手動操作パネル |
| --- | --- | --- |
| 出し方 | **本文の下に帯として差し込む** | **浮くカード**（他のウィンドウと同じ見た目） |
| 高さ | 1 行 | スティックが入る高さ |
| 理由 | 1 行しか無いので差し込んでも本文をほとんど圧迫しない | 帯にすると本文を大きく圧迫し、**スティックを小さくせざるを得ない／地図が縮んで見え方が変わる** |

下端に積む順序（上から）: **本文 → 案内（帯）→ 非常停止解除バー**。
解除バーは常に最下段から動かさない。**手動操作パネルはこれらの上に浮く。**

#### W-6 手動操作パネルの要件（[Spec-open.md](Spec-open.md) U-16・2026-08-15 改訂）

| 項目 | 要件 |
| --- | --- |
| **レイアウト** | **開いても本文のレイアウトを一切動かさない。**カードの位置も、地図・レーダーの大きさも変えない |
| **大きさ** | 仮想スティックは**画面内に常設するものと同じ大きさ**にする。パネルのために小さくしない |
| 置き場所 | **左下**。横長では操作カードが右カラムにあるので構造的に被らない。縦長では開くときに操作カードを本文の上端へ送り、その下に浮かせる |
| モード | **変わらない。**パネル上部に「モードは『◯◯』のまま変わりません」と出す |
| 覆ってはいけないもの | **ヘッダ（非常停止）** と **操作カードの「停止」** |
| **自動で閉じる** | 下表 |

**自動で閉じる条件**:

| きっかけ | 閉じる | 理由 |
| --- | --- | --- |
| 操作カードの**停止・確認・走行・再生・保存**を押した | **閉じる** | 手動介入をやめて別の操作に移った |
| 画面を離れた／異常が発生した／非常停止（UI・物理） | **閉じる** | そのモードが続いていない |
| **スティックを離した**（＝**リース満了**。[Spec-modes.md](Spec-modes.md) §3.1.1） | **閉じない** | 離すたびに閉じると、少しずつ寄せる操作が毎回押し直しになる。状態だけ「一時停止」に戻す（`AT_PANEL` だけ `IDLE_P`） |

閉じたときは、その方式の**一時停止**に戻す（勝手に走り出さない）。
ただし**別の操作が原因で閉じた場合は、その操作が決めた状態表示を上書きしない**
（「走行」で閉じたのに「一時停止中」と出てはいけない）。

### 4.1 W-1 異常ウィンドウのライフサイクル

```
異常発生
   ▼
[ W-1 表示 ]───「非表示」───> [ ヘッダにバッジ ]
   │  ▲                              │
   │  └────────「再表示」────────────┘
   │
   │ 異常が解決
   ▼
[ 同じウィンドウが「再開しますか」に変わる ]
   ├─ [ はい ]   → 異常発生前のモードへ戻り、そのモードの走行状態から再開する
   │               （FOLLOW→RUN / TEACH_*→REC / Nav2 系→NAV）
   ├─ [ いいえ ] → 異常発生前のモードへ戻るが、一時停止のまま
   └─ [ 確認 ]   → 1 択。走行は再開せずモードだけ戻す
                   （モード自体を続けられない異常のときだけ IDLE へ）
```

| 規則 | 内容 |
| --- | --- |
| 位置 | 本文の上・**ヘッダの下** |
| 非表示 | **解決していなくても非表示にできる。**ヘッダのバッジから戻せる |
| 解決時 | **同じウィンドウが再開確認に変わる**（別ウィンドウを出し直さない・`E-5`）。**異常が解決したこと自体では何も遷移しない**（[Spec-open.md](Spec-open.md) F-34） |
| 選択肢 | 走行を自動再開できる → **はい／いいえ**。できない → **確認 1 択**（`E-6`） |
| **選択肢の決め方** | **[Spec-modes.md](Spec-modes.md) §6 の属性表から導く。画面ごとにハードコードしない**（F-34） |
| **「はい」の戻り先** | **モードごとの走行状態。`RUN` 固定にしない**（`TEACH_*` は `REC`、Nav2 系は `NAV`。F-37） |
| **復帰先** | **どの選択肢でも待機（`IDLE`）には戻さない**（[Spec-open.md](Spec-open.md) U-8） |

モードごとの復帰可否は [Spec-modes.md](Spec-modes.md) §6 の表が正。

| **警告の無視** | 「機器が接続されていない」「バッテリー電圧が低い」など、**選択した特定の警告**を無視して動作させられる |
| **ログの選択記録** | **選択した特定のログのみ**を、タイムスタンプ付きで記録する設定ができる |

**暴走する危険を承知の上で開くモード。**

| 無視できる | **無視できない** |
| --- | --- |
| 機器未接続の警告 | **物理非常停止ボタン** |
| バッテリー電圧低下の警告 | **ESP32 のウォッチドッグ** |
| 始業点検の総合ステータス NG | **UI 非常停止ボタン** |
| 手動系の自動ブレーキ（場内でも OFF 可） | **自律系の障害物停止** |

開発モード中は**ヘッダの色を変え**、常に「開発モード」と表示する。

**未確定**（[Spec-open.md](Spec-open.md) O-d6）: 誰が有効化できるか（権限）、
通常運用中に誤って有効化されないための対策。

## 7. 縦長・横長の対応

| 向き | 配置 |
| --- | --- |
| **縦長**（タブレット縦・スマホ） | 1 カラム。上から「操作バー（終了・タブ）→ 主表示（レーダー／地図）→ **操作カード** → 手動 UI」。**図の高さは頭打ちにする**（§1.4） |

参考画面例は縦長のみなので、**横長は新規に設計する。**

## 8. 表示に関する規則

| 項目 | 規則 |
| --- | --- |
| モードの表示 | **日本語で表示する**（表示名は §8.1 が正）。内部の記号（`FOLLOW` 等）をそのまま出さない |
| 状態の表示 | 同じく日本語。「対象選択中」「確認中」「走行中」「一時停止中」 |
| フォルトの表示 | 日本語。原因と対処を 1 行で添える |
| 数値 | 単位を必ず付ける。桁が揃うフォントで表示する |
| 色 | 状態の意味と色を全画面で統一する（正常＝緑、要注意＝橙、異常＝赤、非常停止＝赤／解除待ち＝紫） |
| **オフライン** | **外部のフォント・アイコン・スクリプトを読み込まない。**機体の AP 配下にインターネットは無い |

### 8.1 モードの表示名（**この表が正**）

**18 モードそれぞれを画面に何と出すかを、ここで一意に決める。**
[Spec-modes.md](Spec-modes.md) の記号と 1 対 1 で対応する。
以前はこの表が無く「日本語で表示する」としか書いていなかったため、
設計書とモックアップで語がずれていた（[Spec-open.md](Spec-open.md) U-18）。

| 記号 | 表示名 | 記号 | 表示名 |
| --- | --- | --- | --- |
| `INIT` | 起動中 | `LEASH` | 電子リード |
| `IDLE` | 待機 | `PREP` | 試験準備 |
| `ESTOP` | **非常停止** | `PANEL_NAV` | **配電盤へ移動** |
| `CARRY` | **手押し** | `AT_PANEL` | **配電盤前** |
| `FOLLOW` | 追従走行 | `SUMMON` | 呼び寄せ |
| `MANUAL` | 手動走行 | `HOME_NAV` | **待機場所へ移動** |
| `TEACH_FOLLOW` | 教示（追従） | `OPCHECK` | **始業点検** |
| `TEACH_MANUAL` | 教示（手動） | `CALIB` | **校正** |
| `REPLAY` | 教示再生 | | |
| `LINE` | **ライン誘導** | | |

**表記の決めごと**:

- 移動を伴うモードは**「〜へ移動」で語尾を揃える**（`PANEL_NAV` / `HOME_NAV`）
- **名前の長い走行方式は、モード名から「走行」を落とす**
  （`LINE`＝ライン誘導、`LEASH`＝電子リード、`REPLAY`＝教示再生）。
  画面名（ライン誘導走行）と並べてヘッダに出るため、両方が長いと画面名が末尾省略になる。
  **短い `FOLLOW`＝追従走行 / `MANUAL`＝手動走行は落とさない**（落とすと「追従」「手動」だけになり、
  ジョグ介入中の「手動介入中」表示と紛らわしくなる）
- **UI では「盤」と略さず「配電盤」と書く。**本文・現場語としての「盤」は許容するが、
  画面に出す語は略さない
- 「待機」（`IDLE`＝何も選んでいない）と「待機場所」（機体を置く場所）は**別物**。
  混同しやすいので、モード名の「待機」は単独で使い、場所を指すときは必ず「待機場所」と書く
