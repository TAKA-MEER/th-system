[Spec.md](Spec.md) の詳細。**画面・遷移・ウィンドウ・共通部品の定義。**

見た目のモックアップは [mockup/index.html](mockup/index.html)（ブラウザで開ける単一ファイル）。
**本ファイルとモックアップは同じ画面一覧・同じウィンドウ種別を持つ。**

**2026-11-27 改定（画面の作り直し）。**1 画面の情報量が多くタブに分かれていて目的のボタンが見つからない、という評価（2026-11-12）から、
画面の組み立てを作り直した。決めた経緯と根拠は検討メモ [ui-redesign.md](../ui-redesign.md)・[ui-redesign-decisions.md](../ui-redesign-decisions.md)（D1〜D104）にある。
**モックアップもこの版に置き換えた。**モックアップの右の欄の切り替え（比べるための別案）は参考で、既定の表示が本ファイルの内容に当たる。

| 目標 | 中身 |
| --- | --- |
| G1 | **文章を読まずに、画面を見るだけで「何ができて、どうすればいいか」が分かる** |
| G2 | **不快な「AI っぽさ」を無くす**（色・動き・装飾は機体の状態か操作の意味に対応させる） |
| G3 | 使いやすい UI の障害になっている機体の仕様を見つけ、直すかを 1 件ずつ決める |

## 0. 大前提

| # | 原則 | 理由 |
| --- | --- | --- |
| **1** | **操作系は WebUI のみ。** 専用アプリ・コマンドライン操作を運用手順に含めない | 試験員 1 人で完結させるため |
| **2** | **PC とタブレットの両方で操作できる** | 現地で登録操作をするのはタブレット。地図を見るのは PC |
| **3** | **縦長・横長の両方に対応する**（横長＝PC の 16:9、縦長＝タブレット。§7） | タブレットを縦でも横でも持つ |
| **4** | **非常停止は最優先で最上位に描く。**画面の中身と切り離して最初に描き、ほかのどの表示（ヘルプ・吹き出し・窓・幕）よりも上に重ねる。ヘッダは常に最上位で、何も被さらない | 非常停止が隠れないため。表示の不具合で中身が描けなくても押せる可能性を上げる（2026-11-17 D39） |
| **5** | **ブラウザ標準の確認ダイアログを使わない** | ヘッダより上に出てしまうため |
| **6** | **画面がモードを決める** | ゾーン（試験場内／場外）が画面から自動で決まる（[Spec-modes.md](Spec-modes.md) §7） |
| **7** | **使い方や仕様を説明する文は画面に置かない。使用者に特定の操作を求めるときは指示文を出す（場所が無ければ省いてよい）**（[Spec-open.md](Spec-open.md) U-11。2026-11-26 D85） | 下表。説明はヘルプ表示（§3.3.6）が担う |
| **8** | **同じ操作は同じ場所に置く。配置は状態で変えない**（[Spec-open.md](Spec-open.md) U-15） | §3.3。状態の変化で同じ場所のボタンの意味が変わると誤操作を招く |
| **9** | **1 画面 1 目的。**ボタンを減らすのは「似た機能をまとめる」「重複を消す」「常に使えないものを出さない」で行い、**状態による入れ替えでは行わない** | 目的のボタンを探させない（2026-11-27 D88） |
| **10** | **平常のときは何も出さない。**注意の色・点滅は異常と注意のときだけ。「正常」「障害物情報なし」などは出さない | 本当の注意を埋もれさせない（D45・D88） |

### 0.1 原則 7 の切り分け

| 種類 | 例 | 置き場所 |
| --- | --- | --- |
| **状態** | 「一時停止中」「前方 12 cm」 | **UI に置く**（語より印・図・数で） |
| **使用者に求める操作** | 「機体に来てほしい位置に立って「記録」」「非常停止ボタンを押す」 | **UI に置く**（短く。場所が無ければ省いてよい） |
| **拒否された理由** | 「カメラが接続されていません」 | **UI に置く**（押せないボタンを押したとき、そのボタンのそば。§3.3.3） |
| ボタンの意味・使い方 | 「停止する: 移動をその場で止めます。行き先は残り…」 | **ヘルプ表示**（§3.3.6） |
| 設計の根拠・仕様の宣言 | 「自動でルートを変えません」 | **設計書へ** |
| 手順の解説 | 「①→② が方向ベクトルになります」 | **マニュアルへ**。ただし始業点検は手順の文を画面に出す（§3.12） |

**文言の区切りに「—」を使わない。**空白にする（「待機中　待機場所」）。「一時停止」の「一」と紛れる（2026-11-15 D20）。

## 1. 常設ヘッダ

**画面の最上部に固定。スクロールしない。何にも覆われない。**上段と下段の 2 段。

| 段 | 要素 | 内容 |
| --- | --- | --- |
| 上段（青の帯） | ロゴ・プロジェクト名 | 高見舎ロゴ、**MIRS2602-高見舎プロジェクト**（小さく。狭いときは消す） |
| 上段 | **画面名称** | いま開いている画面の名前。**ヘッダで最も大きい文字**。ロゴ・プロジェクト名の真後ろに置き、位置をほぼ固定する（D24） |
| 上段の右 | **ゾーン表示** | **試験場内のときだけ「速度制限」とだけ出す**。場外・対象外では出さない（D22） |
| 上段の右端 | **状態の札** | **モードではなく状態を出す**（「一時停止中」「移動中」「記録中」「非常停止中」など）。画面名称と同じ語が並ぶのをやめる。**出す状態が無いときは札を出さない**（D21）。色は §3.3.1 |
| 下段の左 | **異常の表示** | **異常のときだけ出す。「正常」は出さない**（D45）。継続中のフォルトは消さない。解消した直近の異常は「直近の異常：LiDAR 途絶 12:34:56」と種別と時刻を残し、**発生から 3 分ほどで消える**（押すと履歴の一覧を開く。[Spec-safety.md](Spec-safety.md) §3.5.5。D23） |
| 下段の左 | **「自動ブレーキなし」** | **自動ブレーキが切れている間だけ、注意の黄で点滅させる**（2026-11-23 D74。[Spec-safety.md](Spec-safety.md) §2.1） |
| 下段の右 | **非常停止ボタン** | 常時表示・常時動作。§1.2 |

**人検出の状態はヘッダに入れない**（D25。人検出の切り替えは画面の左上の操作バーに置く）。バッテリーはヘッダに出すかを、検知の機能を作るときに決める。
**開発モード中はヘッダの帯の色を変え、常に「開発モード」と出す**（§5。D44）。帯の青は意味を持たないメインカラーで、操作・状態の色には使わない（D40）。

### 1.1 重なり順（z 順）

**通常のモーダルとは逆で、ヘッダがすべての上に来る。**

```
┌─────────────────────────────────────────┐ ← ヘッダ（最上位・常に押せる。非常停止は最初に描く）
│ ロゴ  画面名                  速度制限  [札] │
│ 異常の表示／自動ブレーキなし   [ 非 常 停 止 ] │
├─────────────────────────────────────────┤
│░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░│ ← 幕（本文の全体を暗くする）
│░░░░░┌──────────────────────┐░░░░░░░░░│
│░░░░░│ LiDAR 途絶             │░░░░░░░░░│ ← 窓（本文の中央）
│░░░░░│ 対処を 1 行            │░░░░░░░░░│
│░░░░░└──────────────────────┘░░░░░░░░░│
│░░░░░░░░░░░░░[ 解除 ]░░░░░░░░░░░░░░░░░░│ ← 非常停止の解除の帯（本文の下端の中央）
└─────────────────────────────────────────┘
```

| 層 | 内容 |
| --- | --- |
| 最上位 | ヘッダ（非常停止を含む） |
| その下 | 非常停止の解除の帯（本文の下端の中央。窓にも幕にも覆われない） |
| 中間 | 窓（異常・確認・案内）とその幕、ヘルプ表示、手動操作パネル（W-6） |
| 最下位 | 本文 |

**検証方法**: 異常の窓（W-1）を開いた状態で、非常停止ボタンと解除の帯の両方が押せること。どちらかが押せなければ設計違反である。

### 1.2 大きさ（[Spec-open.md](Spec-open.md) U-9。2026-11-17 D36）

**大きさはタブレットで 0.8 倍に縮む前提で、論理 px（§7 の固定論理キャンバス上の px）で決める。**

| 項目 | 要件 |
| --- | --- |
| **非常停止の高さ** | **76 以上で、画面内のどのボタンよりも高い**。**例外: メインメニューのタイル**（機体が走らない画面のため。2026-11-27 D92） |
| 非常停止の幅 | **160 以上**。かつ**画面幅の 25% 以上**。縦長ではヘッダ 2 段目の**幅 45% 以上** |
| 非常停止の文字 | 基準文字の 1.25 倍以上・太字。省略せず「非常停止」と表示する |
| 非常停止の見た目 | **押せるボタンらしく**（角丸・縁・立体の影・押すと沈む。D29）。赤に黄の地（§3.3.1） |
| **押す的** | **すべて 56 以上**（地図の上の小さな道具を除く）。停止│走行のトグルは **68**、「行き先にする」は 60、地図のピンの当たり判定は 60 以上 |
| **小さい文字** | **15 以上** |
| 余白 | 非常停止は他の操作要素と隣接させない（誤タップ防止） |

**「面積で最大」ではなく「高さで最大」を要件にする理由**: タップの成否を決めるのは指の当たる方向の余裕＝高さだから。

**解除の帯にはこの要件を適用しない。**誤って解除しないよう、**小さめの白地・黒の太い枠・角なし**にし、本文の下端の中央に置く（D51）。

### 1.3 画面名称と状態の札の大きさ（[Spec-open.md](Spec-open.md) U-10）

| 要素 | 大きさ | 備考 |
| --- | --- | --- |
| **画面名称** | 基準文字の **1.45 倍以上・太字** | ヘッダで最大 |
| **状態の札** | 基準の **1.05 倍以上・太字**。札の枠と地は §3.3.1 の状態の色 | 2 番目 |
| プロジェクト名 | 基準の 0.8 倍以下 | 常時同じ文字列なので情報量が無い |
| ゾーン表示・開発モード | 基準の 0.72 倍以上（かつ §1.2 の 15 以上） | 出ているかどうかが分かればよい |

**場所が足りないときに畳む順序**: ① プロジェクト名を消す（ロゴは残す）② 画面名称を末尾省略（`…`）にする。
**画面名称・状態の札・非常停止は、どれだけ狭くても縮めない。**ヘッダが 2 段を超えて折り返してはいけない。

**見出しとモードの札が同じ語なら札を出さない**（D88）。

### 1.4 文字と図の大きさ（[Spec-open.md](Spec-open.md) U-12・U-13）

**画面は決め打ちの論理サイズ（横長 1280 幅／縦長 960 幅）で描き、画面いっぱいまで等倍で拡大する**（§7。`SG-D7`）。
基準文字サイズは論理 px で向きごとに一定にし、実際の大きさは端末に合わせた拡大で決まる。試験員が S-50 で倍率を変えたときもこの基準に掛ける。

**スクロールの要件**:

| 端末 | 要件 |
| --- | --- |
| **短辺 768 px 以上**（タブレット・PC） | **どの画面もスクロールさせない。**本文が縦に溢れたら設計不良とみなす |
| 短辺 768 px 未満（スマートフォン） | スクロールしてよい。ただしヘッダと画面左上の操作バーは固定して常に見せる |

**溢れたときの手段**: 図（地図・レーダー・スティック）の高さを頭打ちにして中央に収める（縦横比は保つ）。**タブで畳まない**（タブは目的のボタンを隠す。2026-11-27 の作り直しで全画面のタブを無くした）。
**手動操作パネル（§4.0 W-6）はこの判定に影響しない。**浮くカードなので本文の高さを変えない。

### 1.5 レイアウトの骨格（安全上の要件）

| 項目 | 仕様 |
| --- | --- |
| 高さ | 画面高いっぱいの固定高。ページ全体はスクロールしない |
| ヘッダ | 上端に固定 |
| 非常停止の解除 | **本文の下端の中央に固定。**「押す」と離して配置し、色も形も変える（§1.2） |
| スクロール | 本文の中だけ（§1.4 の端末だけ） |

**理由**: 過去にスクロールで非常停止ボタンが画面外に出た事例が、安全上の欠陥として記録されている。
この骨格は装飾ではなく安全要件である。

## 3. 画面ごとの構成

### 3.1 S-00 接続確認（型: 見る・変える）

| 要素 | 内容 |
| --- | --- |
| 主表示 | **機器のつながりの図**（タブレット → PC → Wi-Fi AP → ラズパイ → LiDAR・ESP32、AP の先にカメラ）。各機器に結果の印（§3.3.1 の P1）と実データ（受信の間隔・応答の時間）。**つながらない機器から先の線を灰の点線にする**（どこで切れているかを位置で読む）。**Wi-Fi AP は単一障害点**であることが図の形で分かる。必須と任意は印の大きさで分け、任意はだめでも図の線を灰にしない（2026-11-27 D101） |
| 対処 | 図の下に、だめな機器だけ対処を 1 行（例「LiDAR の電源とケーブルを確かめる」）と、確かめた時刻 |
| 右列 | 上＝**「メインメニューへ」**（必須 3 者が揃うまで押せない。押すと理由）。下＝始業点検の自動判定の 4 つの印。最下段に小さく「開発モードの設定」（§5） |
| 状態の札 | 「確認中」／「再起動中　2 回目」（制御系の再起動） |
| 開き直したとき | **機体が `INIT` 以外のモードにいるなら S-00 を出さず、そのモードの画面を開く**（2026-11-12 ユーザー決定。A-13。[Spec-safety.md](Spec-safety.md) §6.2.2）。S-00 は速度上限 0 の画面で、ここで走行を再開すると機体は動かない |

### 3.2 S-01 メインメニュー

#### 3.2.1 「運用の終了」区画（[Spec-open.md](Spec-open.md) F-23）

**この区画が無いと、[Spec-ops.md](Spec-ops.md) §4 の終了手順が実行できない。**
同 §4 は「**順序が重要**（保存前に電源を切ると作業が消える）」と明示しており、
**未保存の検出はここが唯一の機会**である。

**区画はカード 1 枚に畳み、詳細は確認ウィンドウ（W-4）に出す。**
一覧をカードに常時展開すると、**メインメニュー画面がスクロールを要求してしまう**（§1.4 違反）。

| 順 | どこ | 中身 |
| --- | --- | --- |
| 1 | **カード** | **未保存の件数**（「2 件」／「なし」）と、**「制御系を停止する」**ボタン 1 つだけ |
| 2 | **W-4** | ボタンを押すと開く。**未保存の一覧**（試験場内地図／教示経路／校正の補正値／教示再生中の地図の書き足し）を出す |
| 3 | **W-4** | 項目ごとに**「保存」／「破棄」**を選ばせる。**破棄は二段階アーム式ボタン**（§6） |
| 4 | **W-4** | **「停止する」**。未保存が残っている間は押せない（押すと理由を表示） |
| 5 | 画面 | 停止の進捗と、**停止が完了したことを出す**（ここまで確認してから機体の電源を切る） |

**カードのボタン自体は未保存があっても押せる。**押せないボタンを置くより、
押したら一覧と理由が出るほうが「何をすれば終われるか」が分かる。
**押せなくするのはウィンドウの中の「停止する」だけ**にする。

**「終了」という語を使わない。**この設計書では「終了」＝**方式を抜けてメインメニュー画面へ戻る**に
固定してある（[Spec-transit.md](Spec-transit.md) §0.1）。同じ語で運用そのものを終わらせると、
**方式を抜けるつもりで制御系を止める誤操作**を招く。**画面には「制御系を停止する」と書く。**

> **原典との差異**: [Spec-ops.md](Spec-ops.md) §4 手順 3 は「メインメニュー画面の**「終了」**を押す」と
> 書いているが、上記の理由で**表示上の語だけ「制御系を停止する」に改める**。手順そのものは変えない。

### 3.3 画面の型と操作の置き場所（**全画面共通の規則**・[Spec-open.md](Spec-open.md) U-15。2026-11-27 改定）

**画面ごとに場当たりで並べない。全画面を次の 3 つの型のどれかに当てはめ、型が同じ画面は同じ場所に同じ役のものを置く。**
一度覚えた場所が、ほかの画面でも通じる。**タブは使わない。**

| 型 | 画面 | 左上の操作バー | 主表示 | 操作 | 「次に押すもの」 |
| --- | --- | --- | --- | --- | --- |
| **走らせる** | S-10〜S-14・S-20・S-21・S-60 | 「終了」／画面全体に効く切り替え（人検出・自動ブレーキ） | 左に大きく。機体のまわり（地図・レーダー・まわりの図）。**機体の印（位置と向きの三角）と機体の大きさの四角はどの画面でも同じ形**（D26） | 右列に上から **① どこへ・あとどれだけ（記録の量）→ ② 停止│走行のトグル → ③ その画面の操作 → ④ 手動** | 停止│走行のうち押せる側（§3.3.2） |
| **手順を進める** | S-30・S-31・S-40 | 「戻る」 | 左＝**項目の一覧**（各行に結果の印）。右＝**選んだ項目の手順**（段の印・図・測った値と基準） | 手順の下端に **左＝「やめる」／右＝進む**（位置は全段で固定） | 右下の進むボタン |
| **見る・変える** | S-00・S-50 | 「戻る」（S-00 は無し） | 左＝区分の一覧。右＝中身 | 中身の下端の右に「保存」（いつ効くかの印つき） | 「メインメニューへ」／変えたときの「保存」 |

**配置は状態で変えない**（原則 8。2026-11-13 決定・D87 で細目を確定）:

| # | 規則 |
| --- | --- |
| (a) | **同じ場所に、状態によって別の操作を出さない。**語が段の中身に合わせて変わるだけ（同じ「次へ進む」操作）は許す |
| (b) | **画面をまたいで、同じ役のものは同じ場所に置く**（「終了」は全画面で左上、停止│走行は右列の ②） |
| (c) | **状態で使えないボタンは、場所を保ったまま押せない見た目で出す**（§3.3.3）。**隠してよいのは、隠しても他のボタンが動かず、その場所に別のものが出ないときだけ**（例: 使えるようになるまで「地図の更新」を出さない）。隠すかは個別に決める |

**「終了」を右列に入れてはいけない。**一時停止のつもりで方式を抜ける誤操作を招く。

**入口の選択（経路を選ぶ・地図を開く・前回の続きか新しく始めるか）は、主表示の中央のカードで出す**（P7）。右列のボタンの位置は変えない。

**どの状態でどのボタンが押せるかは [Spec-modes.md](Spec-modes.md) §3.1 が正。**この節は置き場所を決めるだけで、遷移の定義はしない。

| ボタン | 置く画面 | 意味 |
| --- | --- | --- |
| **停止する** | **走らせる型の全画面**（S-60 を含む。D91） | 一時停止。モード・選択・記録はすべて保持する |
| **向く** | 追従系（S-10 / S-12） | 対象の方へその場で向くだけで移動しない。**停止│走行のトグルとは別のボタン**で ③ に置く。少し動くので、色は進むの色を薄くした緑（D90） |
| **走行する／再開する／再生する** | 自律で動く方式（S-10 / S-12 / S-14 / S-20 の予約 / S-21） | 走り出す。一時停止からは「再開する」 |
| **保存** | 記録・地図を持つ画面（S-12 / S-13 / S-20 / S-14※ / S-21※） | 記録・地図を確定する。**※ S-14 / S-21 は地図更新 ON のときだけ**（いまは地図更新が使えないので出さない）。**ハードコードせず、その画面が記録を持つかで出す** |

| 画面 | スティック | 「手動」ボタン |
| --- | --- | --- |
| S-10 / S-12（追従系） | **常設する** | **置かない。**スティックに触れた瞬間にジョグ介入が始まる |
| S-11 / S-13（手動系） | **常設する** | **置かない。**スティックそのものが走行操作 |

ボタンが 2 つあると「スティックを触る前に手動を押すのか」が分からなくなる。**触れば始まる、が唯一の入り口**である。

**始まりは「触れた瞬間」だが、続いていることは合図を送り続けて示す。**
触れている間、UI はジョグ継続の合図を繰り返し送る（[Spec-modes.md](Spec-modes.md) §3.1.1 のリース）。
**「離した」という 1 回きりのイベントに頼らない** — 通信が途切れて届かなかったとき、
機体側が介入中のまま固まるため（[Spec-open.md](Spec-open.md) F-29）。

### 3.3.1 色の使い分け（[Spec-open.md](Spec-open.md) U-17。**2026-11-27 改定: JIS B 9960-1:2019 に合わせる。D98**）

**1 色 1 意味。**色は機体の状態と操作の意味にだけ使い、強調や飾りに使わない。**割り当ては JIS B 9960-1:2019（IEC 60204-1）10.2.1・10.3 による。**

| 色 | 意味 | 使う場所 |
| --- | --- | --- |
| **赤に黄の地** | **非常停止**（この組は非常停止だけ） | 非常停止ボタン・「非常停止中」の札 |
| **黒** | **止める操作** | 「停止する」（押せるとき）。赤は非常停止の近くで使わない |
| **緑** | **進む（機体が動く）・正常** | 走行・再開・出発・「行き先にする」・機体の印・経路・行き先の輪・「移動中」の札・自律走行中の枠。**押すと機体が動くボタンだけを塗る**（P8。D103） |
| **薄い緑** | 少しだけ動く | 「向く」（D90） |
| **黄** | **注意・異常・中断** | 「中断」・「自動ブレーキなし」・近い障害物・経路を塞いでいる所・異常の印・押した理由の吹き出しの縁 |
| **白・灰・黒** | 中立 | 入切の切り替え・「一時停止中」「記録中」の札（記録中は中立の札＋丸の印。D70）・押すと動かないボタン（太い縁で強める）・地図 |
| **反転** | 選んでいるもの | 選んだ人・選んだピン・選んだ区分・入っている切り替えの側 |
| 青 | **意味を持たないメインカラー**（D40） | ヘッダの帯だけ。操作・状態には使わない |

**結果の印は語ではなく形で分ける**（P1）: ✓＝正常（緑）／!＝要確認（黄の縁）／×＝だめ（黄の地）／—＝まだ（灰）。**結果に赤は使わない**（赤は非常停止だけ）。
**押すと機体が動かない「進む」ボタン**（「確かめる」「確定する」「この経路で進む」「会場地図を開く」「続きから再開」など）は**塗らず、太い縁で強める**（P8。D103）。

### 3.3.2 停止│走行のトグル（[Spec-open.md](Spec-open.md) U-17。D2・D33）

**対になる操作は 1 つのトグルの見た目にする**（`[ 停止する │ 走行する ]`）。

| 規則 | 内容 |
| --- | --- |
| 塗るのは | **いま押せる側だけ**（止める＝黒・走る／再開＝緑）。押せない側は塗りを外す。待機中に塗りが無くなるのは問題ない |
| 語 | **動詞で固定**（「停止する」「走行する」）。一時停止からは「再開する」、教示再生は「再生する」（D13） |
| 状態 | **いまの状態を言うのはヘッダの札だけ**（トグルは言わない。D33） |
| 次に押す走行 | 押せる「走行する／再開する／再生する」は**ゆっくり明滅させる**（§3.3.4。D11） |
| 大きさ | 高さ 68（§1.2） |
| 予約 | 試験準備の停止│走行は、追従走行を足すときの**予約**（押しても何も起きない）。**予約の間は押せない見た目にする**。待機場所へ戻る途中だけ「停止する」が押せる（D6・D89） |

### 3.3.3 押せないボタン（D16・D28・D97）

| 規則 | 内容 |

閉じたときは、その方式の**一時停止**に戻す（勝手に走り出さない）。
ただし**別の操作が原因で閉じた場合は、その操作が決めた状態表示を上書きしない**
（「走行」で閉じたのに「一時停止中」と出てはいけない）。

### 4.1 異常と非常停止の窓のライフサイクル（2026-11-21 D47・D48 で改定）

```
異常発生／非常停止
   ▼
[ 窓を表示（本文の中央・幕で暗くする。隠せない）]   ← 機体はその方式の一時停止
   │                                                  （右列の「再開する」「中断」も押せない）
   │ 異常が解消した／非常停止を解除した
   ▼
[ 同じ窓が「解消した」「解除した」に変わる ]
   └─ [ 確認 ] → 窓を閉じる。走行は再開しない（その方式の一時停止に戻る）
                 再開は、閉じたあとの右列の「再開する」で行う
```

| 規則 | 内容 |
| --- | --- |
| 位置 | **本文の中央。ヘッダ以外を幕で暗くする**（D47・D53） |
| 隠す | **隠せない**（隠すボタンを持たせない。旧版の「非表示」は廃止。D47） |
| 異常の間 | **機体は必ず一時停止し、中断・再開もさせない。ハードの異常の解消を待たせる**（D47）。右列の「再開する」「中断」は押せない見た目 |
| 解決時 | **同じ窓が「解消した」に変わる**（別の窓を出し直さない・`E-5`）。**異常が解決したこと自体では何も遷移しない**（[Spec-open.md](Spec-open.md) F-34） |
| 選択肢 | **「確認」の 1 つだけ**（2026-11-21 D48。旧版の「はい／いいえ」は廃止）。**解消・解除の窓は「あったこと」を知らせるだけで、走行の再開を持たせない** |
| 「確認」で何が起きるか | 異常（W-1）: その方式の一時停止のまま（[Spec-modes.md](Spec-modes.md) `SM-3.1.1-05`）。非常停止（W-2）: 押下前が復帰可能なら**押下前のモードの復帰先**（一時停止）へ、そうでなければメインメニュー（`SM-3.1.1-11`・`-14`）。**モードごとの復帰可否は [Spec-modes.md](Spec-modes.md) §6 の表が正。画面ごとにハードコードしない** |
| **復帰先** | **どの場合でも、復帰可能なら待機（`IDLE`）には戻さない**（[Spec-open.md](Spec-open.md) U-8） |
| **解消した異常の表示**（2026-10-12） | **解消後の窓には、解消した異常の種別・開始時刻・継続時間を添える**（例：「LiDAR 途絶（0.1 秒・12:34:56）」）。**一瞬で解消しても、確認を押すまで何が起きたかを読める**。短時間に同じ種別が続いた場合は、**最新の 1 件と、その前の件数**（「ほか 2 回」）を添える。**添えるのは、その一時停止（窓を開いた時点）以降に起きて解消した異常だけ**（2026-11-10） |
| 非常停止の解除の帯 | 非常停止の窓の間、本文の下端の中央に出す（§1.2。白地・黒の太い枠・小さめ） |

#### 物理 E-Stop の扱い —— 1 点だけ緩む（2026-09-20 実装時に判明）

**押されていると分かっている間は、開発モードでも運用開始を止める**（境界は守られている）。
ただし**状態がまだ分からない間**（一度も受信していない）は、開発モードでは**通してしまう**。

| 物理 E-Stop の状態 | 通常 | 開発モード |
| --- | --- | --- |
| 押されている | 止める | **止める**（境界どおり） |
| 押されていない | 通す | 通す |
| **まだ分からない**（未受信） | **止める** | **通す** ← ここだけ緩む |

**理由**: 物理 E-Stop の状態を配信しているのは ESP32 だけで、**ESP32 が居ない環境では
一度も届かない**。受信を要求すると「機器ゼロから `IDLE` へ到達する」という開発モードの
目的そのものが達成できない。

**受け入れた理由と範囲**: 入る先は `IDLE`（停止状態）で機体は動かない。ESP32 が居るなら
最初のフレームで状態が判明し、押されていればそこで止まる。**押されたまま走り出すことはない。**
通したときは**ログに残す**（「未受信のまま通した」と明示する）。
**通常運用では ESP32 が必ず居るので、この緩みは開発モード専用である。**

**この決定は開発段階限定である。**`O-d6`（誰が有効化できるか・通常運用中に誤って有効化されない対策）は
**通常運用に入る直前に決める**（ユーザー決定 2026-09-20。それまでは未確定のまま置く）。
[Spec-open.md](Spec-open.md) `O-d6` の期限をそこに置くこと。

### 6.1 地図の見え方（**すべての地図で共通**。2026-11-26 D78〜D80）

**地図は色相を使わず、濃淡だけで描く。**色（緑・黄）は、地図の上でも機体の状態と操作の意味にだけ使う（§3.3.1）。
試験準備・試験（当日）・教示（手動・追従）・教示再生・自律測定、教示経路のプレビューのすべてに当てはめる。

| 層 | 見え方 | 理由 |
| --- | --- | --- |
| 未探索 | **画面の地と同じ色にして見えなくする**（地図の外側も） | 灰の広い領域が「壁の外」に見えた |
| 床（空き） | 白 | いちばん明るい＝自由に動ける所 |
| 壁（占有） | **中間の灰** | 点群を壁より濃くするため |
| 点群（いま LiDAR に見えている点） | **壁より濃い灰**。**減速が始まる距離より近い点は注意の黄** | 点が壁に乗っているかで、地図と位置がずれていないかを読める |
| **コストマップ** | **「入れない所」（機体の中心が入ると壁に当たる帯＝Nav2 の内接・致死のセル）だけを薄い灰で描く**。避けたい帯（膨張の帯）は描かない | 膨張の帯まで描くと床のほとんどが覆われて読めない。白い床＝機体の中心が通れる所と読める |
| 経路が塞がれた所 | **注意の黄の円（点線の縁）**。`BLOCKED` の間だけ、コストマップの入切によらず出す | なぜ止まったかを地図で一目に |
| 経路・行き先の輪 | 進むの色（緑） | |
| 機体 | **位置と向きの三角＋機体の大きさの四角**（実寸・向きに合わせて回る。D26） | 大きさの感覚 |
| ピン | 中立の色。**向きが分かる形**（配電盤＝四角に向きの三角、待機場所＝家形。D63）。配電盤は**順番の番号を印の中に**（D67） | 黄は注意なので配電盤に使わない |
| 追跡中の人・タップの印 | 選んでいるもの＝反転 | 人はいつも注意すべきものではない |

**地図の端の道具**（右下。レーダー・スティックが右にある画面はその左、下に帯がある画面はその上。D78・D79）:

| 道具 | 中身 |
| --- | --- |
| **「入れない所」**（アイコンだけ。D95） | **コストマップの入切。地図のある画面すべてに置く**。入っている間は反転。**ふだん出しておくか（既定）は、実際の地図で見て決める**（未決。それまでは出す） |

## 7. 縦長・横長の対応

**横長は PC の 16:9、縦長はタブレットの 3:4 とみなす**（2026-11-17 D38。制御本体の PC の画面を使うことが多い）。横長 4:3 は作らない。
論理キャンバスは横長 1280 幅・縦長 960 幅の**定数**で、画面いっぱいまで等倍で拡大する（§1.4）。

| 型 | 横長 | 縦長 |
| --- | --- | --- |
| 走らせる | 主表示を左に大きく、右列（①〜④）を右 | **主表示を上、右列を下**（2 列に並べる。D88 の R5）。**例外: 手動走行（S-11）は計器と機体のまわりの図を主表示の中で左右に並べる**（図がほぼ正方形で、上下に積むと左右が大きく空くため） |
| 手順を進める | 左に一覧、右に手順 | **一覧を上に 2×2、手順を下**（D102）。始業点検の手順の文は一覧の下に全幅で |
| 見る・変える | 左に区分、右に中身 | 区分を上、中身を下 |
| メインメニュー | タイルの格子 | タイルの格子（列を減らす） |

いずれも**ヘッダは上端固定、非常停止の解除は本文の下端の中央**という骨格は変えない。**図の高さは頭打ちにする**（§1.4）のは向きに関係ない共通ルール。

### 8.1 モードの表示名（**この表が正**）

**18 モードそれぞれを画面に何と出すかを、ここで一意に決める。**
[Spec-modes.md](Spec-modes.md) の記号と 1 対 1 で対応する。

| 記号 | 表示名 | 記号 | 表示名 |
| --- | --- | --- | --- |
| `INIT` | 起動中 | `PREP` | 試験準備 |
| `IDLE` | 待機 | `PANEL_NAV` | **配電盤へ移動** |
| `ESTOP` | **非常停止** | `AT_PANEL` | **配電盤前** |
| `CARRY` | **非常停止**（画面では非常停止として出す。D46） | `SUMMON` | 呼び寄せ |
| `FOLLOW` | 追従走行 | `HOME_NAV` | **待機場所へ移動** |
| `MANUAL` | 手動走行 | `OPCHECK` | **始業点検** |
| `TEACH_FOLLOW` | 教示（追従） | `CALIB` | **校正** |
| `TEACH_MANUAL` | 教示（手動） | **`AT_HOME`** | **試験（当日）** |
| `REPLAY` | 教示再生 | **`AUTO_MEASURE`** | **自律測定** |

**表記の決めごと**:

- 移動を伴うモードは**「〜へ移動」で語尾を揃える**（`PANEL_NAV` / `HOME_NAV`）
- **短い `FOLLOW`＝追従走行 / `MANUAL`＝手動走行は「走行」を落とさない**（落とすと「追従」「手動」だけになり、ジョグ介入中の「手動介入中」表示と紛らわしくなる）。`REPLAY` は「教示再生」
- **UI では「盤」と略さず「配電盤」と書く。**本文・現場語としての「盤」は許容するが、画面に出す語は略さない
- 「待機」（`IDLE`＝何も選んでいない）と「待機場所」（機体を置く場所）は**別物**。
  混同しやすいので、モード名の「待機」は単独で使い、場所を指すときは必ず「待機場所」と書く
- **「手押し」の語を画面に出さない**（機体の非常停止ボタンも「非常停止」。D46）
