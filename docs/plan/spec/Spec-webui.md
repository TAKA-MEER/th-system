# WebUI 仕様

[Spec.md](Spec.md) の詳細。**画面・遷移・ウィンドウ・共通部品の定義。**

見た目のモックアップは [mockup/index.html](mockup/index.html)（ブラウザで開ける単一ファイル）。
**本ファイルとモックアップは同じ画面一覧・同じウィンドウ種別を持つ。**

## 0. 大前提

| # | 原則 | 理由 |
| --- | --- | --- |
| **1** | **操作系は WebUI のみ。** 専用アプリ・コマンドライン操作を運用手順に含めない | 試験員 1 人で完結させるため |
| **2** | **PC とタブレットの両方で操作できる** | 現地で登録操作をするのはタブレット。地図を見るのは PC |
| **3** | **縦長・横長の両方に対応する** | タブレットを縦でも横でも持つ |
| **4** | **ヘッダは常に最上位。何も被さらない** | 緊急停止が隠れないため |
| **5** | **ブラウザ標準の確認ダイアログを使わない** | ヘッダより上に出てしまうため |
| **6** | **画面がモードを決める** | ゾーン（試験場内／場外）が画面から自動で決まる（[Spec-modes.md](Spec-modes.md) §7） |

## 1. 常設ヘッダ

**画面の最上部に固定。スクロールしない。何にも覆われない。**

| 要素 | 内容 |
| --- | --- |
| ロゴ | 高見舎ロゴ |
| プロジェクト名 | **MIRS2602-高見舎プロジェクト** |
| 画面名称 | いま開いている画面の名前 |
| 現在のモード | [Spec-modes.md](Spec-modes.md) の 18 モード。モードごとに色を変える |
| **ゾーン表示** | 試験場内のときだけ「試験場内・低速・自動ブレーキ ON」を出す |
| フォルト表示枠 | 正常／フォルト名。非表示中の異常ウィンドウがあればバッジ |
| **緊急停止ボタン** | 常時表示・常時動作 |

### 1.1 重なり順（z 順）

**通常のモーダルとは逆で、ヘッダがすべての上に来る。**

```
┌─────────────────────────────────────────┐ ← ヘッダ（最上位・常に押せる）
│ ロゴ  プロジェクト名  画面名  モード     │
│ フォルト枠            [ 緊 急 停 止 ]     │
├─────────────────────────────────────────┤
│                                          │
│   ┌───────────────────────────────┐     │ ← ウィンドウ（本文の上・ヘッダの下）
│   │  異常ウィンドウ               │     │
│   │             [非表示] [確認]   │     │
│   └───────────────────────────────┘     │
│                                          │
│   本文（この領域だけスクロールする）      │
│                                          │
└─────────────────────────────────────────┘
```

| 層 | 内容 |
| --- | --- |
| 最上位 | ヘッダ（緊急停止を含む） |
| 中間 | ウィンドウ類（異常・案内・確認・人力搬送） |
| 最下位 | 本文（唯一スクロールする領域） |

**検証方法**: 異常ウィンドウを開いた状態で緊急停止ボタンが押せること。
これが押せなければ設計違反である。

### 1.2 緊急停止ボタンの大きさ（[Spec-open.md](Spec-open.md) U-9）

**タップで確実に押せる大きさにする。画面内で最も大きい操作要素とする。**

| 項目 | 要件 |
| --- | --- |
| **高さ** | **56 px 以上**。かつ**画面内のどのボタンよりも高い**こと | 
| **幅** | **160 px 以上**。かつ**画面幅の 25% 以上** |
| 縦長のとき | ヘッダ 2 段目の**幅 45% 以上**を占める |
| 文字 | **1.2 rem 以上・太字**。省略せず「緊急停止」と表示する |
| 余白 | 他の操作要素と隣接させない（誤タップ防止） |

**「面積で最大」ではなく「高さで最大」を要件にする理由**: 主選択画面のように
横長のリストボタンが並ぶ画面では、面積では一覧ボタンが上回ってしまう。
タップの成否を決めるのは**指の当たる方向の余裕＝高さ**なので、そちらを基準にする。

**解除ボタンにはこの要件を適用しない。**誤って解除しないよう、
むしろ小さめにし、画面の反対側（下端）に置く。

### 1.3 レイアウトの骨格（安全上の要件）

| 項目 | 仕様 |
| --- | --- |
| 高さ | 画面高いっぱいの固定高。ページ全体はスクロールしない |
| ヘッダ | 上端に固定 |
| 緊急停止の解除 | **下端に固定。**「押す」と離して配置し、色も形も変える |
| スクロール | **本文領域だけ** |

**理由**: 過去にスクロールで緊急停止ボタンが画面外に出た事例が、安全上の欠陥として記録されている。
この骨格は装飾ではなく安全要件である。

| --- | --- |

### 3.3 S-10／S-12（追従系）と S-11／S-13（手動系）は同じ画面（[Spec-open.md](Spec-open.md) U-5）

**教示は「教示なしの画面＋教示タブ」で作る。**走行部分は完全に共通にする。

| 画面 | 走行タブ | 教示タブ | 操作列 |
| --- | --- | --- | --- |
| **S-10** 追従走行 | 「追従」 | — | 停止／確認／走行／手動 |
| **S-12** 教示（追従） | 「追従」**（S-10 と同一）** | **「教示」** | 停止／確認／走行／**保存**／手動 |
| **S-11** 手動走行 | 「走行」 | — | 停止 |
| **S-13** 教示（手動） | 「走行」**（S-11 と同一）** | **「教示」** | 停止／**保存** |

**「終了」は 4 画面すべて左上に置く**（操作列には入れない）。
手動系の操作列に「走行」「手動」が無いのは、**仮想スティックそのものが走行操作**だからである。

**共通にするもの**: レーダー（追従系）／仮想スティック／速度スライダ／速度プリセット／
障害物の警告表示／自動ブレーキのトグル（手動系）／「終了」ボタンの位置。

**教示画面だけが増やすもの**: 「教示」タブ 1 枚と、操作列の「**保存**」ボタン 1 つ。

**理由**: 教示は「走らせ方」を変えるものではなく「走った軌跡を記録するかどうか」の違いしかない。
画面を作り分けると、試験員は同じ走行操作を 2 通り覚えることになる。

### 3.4 走行タブの中身

| 系統 | 中身 |
| --- | --- |
| **追従系**（S-10 / S-12） | **対象選択エリア**（レーダー表示。機体を中心に候補を丸で表示、選択中は強調、歩いた軌跡を線で描く） |
| **手動系**（S-11 / S-13） | 障害物の警告表示 ＋ **自動ブレーキのトグル**（場外の既定 OFF、場内の既定 ON） ＋ 後退時の死角注意 |

**「起動中」表示**（追従系のみ・`E-10` の解決）:

| 状況 | 表示 |
| --- | --- |
| 人物追跡が起動中で**候補が 0 人** | **対象選択エリアの中心に「起動中」** |
| 候補が 1 人以上出た | **中心から隅へ退き、小さく「追跡中」**と出す |

原典は「対象選択画面の中心に『起動中』」とだけ書くが、中心表示は対象選択を妨げうる。
**候補が出たら退く**ことで、両方の要求を満たす。

### 3.5 教示タブの中身（S-12 / S-13 のみ）

## 4. ウィンドウ

**すべてページ内のコンポーネント。ブラウザ標準ダイアログは使わない。**

| ID | 種別 | 出る条件 | 閉じ方 |
| --- | --- | --- | --- |
| **W-1** | **異常ウィンドウ** | フォルト発生 | 非表示にできる／解決で自動クローズ |
| **W-2** | **人力搬送ウィンドウ** | 物理緊急停止ボタン押下 | 解除するまで閉じない |
| **W-3** | **案内ウィンドウ** | 人物追跡ロスト、登録拒否、線ロストなど | 閉じられる／条件解消で自動クローズ |
| **W-4** | **確認ウィンドウ** | 破棄・保存・上書きなど | はい／いいえ |
| **W-5** | **経路ブロックウィンドウ** | Nav2 の経路が塞がれた | 「再検索する」を押すまで出続ける（タイムアウトしない） |

### 4.1 W-1 異常ウィンドウのライフサイクル

```
異常発生
   ▼
[ W-1 表示 ]───「非表示」───> [ ヘッダにバッジ ]
   │  ▲                              │
   │  └────────「再表示」────────────┘
   │
   │ 異常が解決
   ▼
[ 同じウィンドウが「再開しますか」に変わる ]
   ├─ [ はい ]   → 異常発生前のモードへ戻り、走行を再開する
   ├─ [ いいえ ] → 異常発生前のモードへ戻るが、一時停止のまま
   └─ [ 確認 ]   → 1 択。走行は再開せずモードだけ戻す
                   （モード自体を続けられない異常のときだけ IDLE へ）
```

| 規則 | 内容 |
| --- | --- |
| 位置 | 本文の上・**ヘッダの下** |
| 非表示 | **解決していなくても非表示にできる。**ヘッダのバッジから戻せる |
| 解決時 | **同じウィンドウが再開確認に変わる**（別ウィンドウを出し直さない・`E-5`） |
| 選択肢 | 走行を自動再開できる → **はい／いいえ**。できない → **確認 1 択**（`E-6`） |
| **復帰先** | **どの選択肢でも待機（`IDLE`）には戻さない**（[Spec-open.md](Spec-open.md) U-8） |

モードごとの復帰可否は [Spec-modes.md](Spec-modes.md) §6 の表が正。

### 4.2 W-3 案内ウィンドウの位置（`E-10`）

**対象選択とモード選択の操作に被らない位置に出す。**

| 画面 | 案内ウィンドウの位置 |
| --- | --- |
| 追従走行（S-10） | レーダー（対象選択）と操作列を避け、**画面下部の帯**に出す |
| 試験準備（S-20） | 地図と登録ボタンを避け、**地図の上端に細く**出す |
| 試験（S-21） | 同上 |

**モード選択で人物追跡が不要なモードが選ばれたら自動で閉じる。**
「不要なモード」の定義は [Spec-modes.md](Spec-modes.md) §9 の表による。

## 5. 開発モード

**通常モードとの違いは以下だけ。それ以外は同じ画面・同じ挙動。**

| 機能 | 内容 |
| --- | --- |
| **警告の無視** | 「機器が接続されていない」「バッテリー電圧が低い」など、**選択した特定の警告**を無視して動作させられる |
| **ログの選択記録** | **選択した特定のログのみ**を、タイムスタンプ付きで記録する設定ができる |

**暴走する危険を承知の上で開くモード。**

| 無視できる | **無視できない** |
| --- | --- |
| 機器未接続の警告 | **物理緊急停止ボタン** |
| バッテリー電圧低下の警告 | **ESP32 のウォッチドッグ** |
| 動作確認の総合ステータス NG | **UI 緊急停止ボタン** |
| 手動系の自動ブレーキ（場内でも OFF 可） | **自律系の障害物停止** |

開発モード中は**ヘッダの色を変え**、常に「開発モード」と表示する。

**未確定**（[Spec-open.md](Spec-open.md) O-d6）: 誰が有効化できるか（権限）、
通常運用中に誤って有効化されないための対策。

## 6. 共通部品

| 部品 | 使う画面 | 仕様 |
| --- | --- | --- |
| **操作列** | 全走行方式・試験準備・試験 | **「停止」「保存」「終了」の 3 語を全画面で同じ意味に固定する**（[Spec-transit.md](Spec-transit.md) §0.1）。「保存」は記録を伴う画面にだけ出す |

| **レーダー表示** | S-10 / S-12 / S-20 / S-21 | 機体中心。候補の人を丸で、選択中を強調。軌跡を線で |
| **地図表示** | S-12〜S-15 / S-20 / S-21 | 占有格子＋経路＋ピン＋現在位置。ピンチズーム・パン |

## 7. 縦長・横長の対応

| 向き | 配置 |
| --- | --- |
| **縦長**（タブレット縦・スマホ） | 1 カラム。上から「タブ → 主表示（レーダー／地図）→ 操作列 → 手動 UI」 |
| **横長**（PC・タブレット横） | 2 カラム。左に主表示（レーダー／地図）、右に「操作列 ＋ 手動 UI ＋ 状態」 |

いずれも**ヘッダは上端固定、緊急停止解除は下端固定、本文だけスクロール**という骨格は変えない。

参考画面例は縦長のみなので、**横長は新規に設計する。**

## 8. 表示に関する規則

| 項目 | 規則 |
| --- | --- |
| モードの表示 | **日本語で表示する。**内部の記号（`FOLLOW` 等）をそのまま出さない |
| 状態の表示 | 同じく日本語。「対象選択中」「確認中」「走行中」「停止中」 |
| フォルトの表示 | 日本語。原因と対処を 1 行で添える |
| 数値 | 単位を必ず付ける。桁が揃うフォントで表示する |
| 色 | 状態の意味と色を全画面で統一する（正常＝緑、要注意＝橙、異常＝赤、緊急停止＝赤／解除待ち＝紫） |
| **オフライン** | **外部のフォント・アイコン・スクリプトを読み込まない。**機体の AP 配下にインターネットは無い |
