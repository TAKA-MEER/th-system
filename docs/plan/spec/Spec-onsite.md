# 試験場内の移動と配電盤前

[Spec.md](Spec.md) の詳細。**前日の地図作成・登録と、当日の盤前移動・呼び寄せ。**

先方の要望「立ち会い試験で配電盤上部を安全に確認したい」「前日準備が大変」に
**直接あたるのがこの区間**であり、保管場所⇔試験場の移動はその前後の付随作業である。

ここでは**速度は評価軸にならない**（1 回の移動は数 m）。効くのは
**盤前に何 cm・何度で着けるか**と、**1 盤あたり何操作かかるか**（盤の数だけ掛かる）。

---

## 0. 設計の骨子

盤の位置は「**試験員がそこに立つ**」ことで与える。
これにより「地図原点が毎回変わる」「地図からどこが盤か読めない」の 2 つが同時に消える。

```
【前日】試験場に到着 → 追従で連れ回しながら地図を作る
        各盤の前で「ロボットに立ってほしい位置」に立って【登録】→ 地図にピンが立つ

【当日】(a) ピンを選ぶ   → 登録済み座標へ Nav2（歩かなくてよい／地図品質に依存）
        (b) その場で呼ぶ → 今いる位置へ Nav2（盤まで歩く／地図品質への依存が小さい）
             ↓ 試験員が退いたのを確認して発進 → 到着 → 向き合わせ → 撮影
```

**(a) と (b) は同じ幾何の「あとで行く」版と「今行く」版**である。
手順は同じで、**保存するかどうかだけが違う**。

|  | 位置の指定精度 | 向きの指定精度 | 手数 | 地図品質 |
| --- | --- | --- | --- | --- |
| **(b) その場で呼ぶ** | 人物位置の推定誤差 σ ≒ 0.1 m | 2 点指示 ±8〜11° | 押下 2 回 ＋ 退く | 依存が小さい |
| **(a) ピンを選ぶ** | 同上 | 同上 | 登録 2 回 → 選択 1 回 | 依存する |

**この表は「試験員が与えられる指定の精度」であって、機体が実際に停まる精度ではない。**
到着時の誤差は、これに **Nav2 の到達許容（±0.25 m / ±14°）が合成される**（§3.3）。

> **注意**: 「(b) は地図品質にほぼ非依存」という旧記述は**誤り**（`CL-R-1`）。
> 呼び寄せも Nav2 を使い、グローバルコストマップは静的レイヤを含む。**地図は必須**である。
> 正しくは「**依存が小さい**」。

## 2. 前日：地図作成と登録（モード `PREP`）

| 順 | 操作 | 状態 |
| --- | --- | --- |
| 1 | メインメニュー画面から**試験準備画面**を開く | `IDLE` → `PREP` |
| 2 | 地図作成を開始する（**教示再生用とは別の地図**） | `MAPPING` |
| 3 | **待機場所に立って登録する**（§3 の 2 点指示） | `REGISTER` |
| 4 | 地図に**待機場所ピン**が立つ。**この待機場所と姿勢を地図の初期位置とする** | `MAPPING` |
| 5 | **追従で連れ回しながら**地図を生成する | `MAPPING` |
| 6 | 各盤の前で登録する（§3） | `REGISTER` |
| 7 | 地図に**配電盤ピン**が立つ | `MAPPING` |
| 8 | ピンをタップして**名前を設定**する | `MAPPING` |
| 9 | 作り終わったら**1 ボタンで待機場所に戻す** | `RETURN` |
| 10 | 必要に応じて地図を修正する（**人の映り込みをその場で選択して消せる**） | `EDIT` |
| 11 | **「保存」**を押して地図を確定する | `SAVED` |
| 12 | **「終了」**を押して方式を抜ける | → `IDLE` |

**「停止」は一時停止**である（[Spec-open.md](Spec-open.md) U-7）。押しても方式は抜けず、
作成中の地図・登録済みピン・修正内容はすべて保持される。「走行」で続きから再開できる
（**一時停止する直前の状態に戻る**。[Spec-modes.md](Spec-modes.md) §3.1.2 ／ F-35）。
方式を抜けるのは「終了」だけで、未保存があれば保存可否を問う。

**手順どおりの順番でなくてもよい。**地図の修正（手順 10）は**手順 9 を経由せず地図作成中にも入れる**し、
**保存（手順 11）のあとも「走行」で地図作成に戻れる**（登録や修正を続けられる。F-32）。
上表は典型的な流れであって、この順にしか進めないという意味ではない。

> **手順番号について**: 上表は**本設計書の採番**（11 手順）。原典 `NewDesign-onsite.md` は
> 13 手順で採番しており対応しない。[Spec-open.md](Spec-open.md) が原典の手順を指すときは
> 「原典 手順 n」と明記している。

### 2.1 手順 9 の時点で地図はまだ保存されていない（`O-r8`）

保存は手順 11 なので、**手順 9 は作りかけの地図で自己位置推定して戻る**ことになる。
これは想定どおりとする。理由：待機場所ピンは手順 3 で既に地図上に立っており、
連れ回しで作った地図もその時点で自己位置推定には十分だから。
**保存を戻る前に持ってこない**のは、手順 10 の地図修正を保存前に済ませたいため。

### 2.2 地図の修正（`CL-M-3`）

| 項目 | 仕様 |
| --- | --- |
| 誰がやるか | **試験員**（WebUI の操作者）。2 人目の補助を要しない（目標 G3） |
| 何ができるか | 地図上で範囲を選び、**人の映り込みを消す**。消した結果は元に戻せる |
| いつやるか | 手順 10。保存前 |

**人の映り込みが実際に問題になるかは未検証**（[Spec-open.md](Spec-open.md) O-c2）。
「作業者が写り込んで特殊なツールで整形が必要」は伝聞であり、この構成で再現するか未確認。
**人物マスク実装の要否はこのテストで決まる**（最も安いテスト）。

### 2.3 ピンの編集・削除（`CL-M-6`）

ピンをタップすると、**名前の変更・削除・位置と向きの再登録**ができる。
再登録は §3 と同じ 2 点指示をやり直す。

## 3. 登録の仕方（待機場所・配電盤に共通）

### 3.1 方式 A：2 点指示（本命）

**決定（[Spec-open.md](Spec-open.md) U-3）: 押す順は次のとおり。**

| 順 | 試験員がすること | 意味 |
| --- | --- | --- |
| **①** | **ロボットに立ってほしい位置**に立って押す | **＝ゴール地点** |
| **②** | そこから**盤へ一歩寄った点**で押す | **向きを与えるためだけ**（保存されない） |

①→② のベクトルが盤の法線方向になる。**①がゴール**である。

> **原典との差異**: `NewDesign-onsite.md` 手順 6〜7 は「①少し手前で登録開始 → ②立ってほしい位置で登録」
> （＝ゴールが②）と書いており、本決定で**上書きされる**。向きベクトルの向きはどちらも同じだが、
> **ロボットが実際に停まる位置が入れ替わる**。①をゴールにすると、試験員が最初に立った場所が
> そのままゴールになるため直感的である。

| 項目 | 仕様 |
| --- | --- |
| 押すもの | **同じボタンを、異なる 2 か所で押す**（`DF-D-2` の解決） |
| 精度 | 点間距離 L と人物位置の推定誤差 σ で決まる。L = 1 m・σ = 0.1 m で **±8〜11°**（計算値・未実測） |
| 待機場所への適用 | **同じ方式を使う**（F-08）。②は「機体に向いてほしい方向へ一歩」 |
| 呼び寄せへの適用 | **同じ方式を使う**（F-09）。保存しないだけ |
| ライン誘導走行との共通性 | ライン誘導走行の初期姿勢指定（現在地→向き方向）と**同じ幾何**。UI 部品を共通化する |

**なぜ「2 点登録」ではなく「2 点指示」と呼ぶか**: 登録（保存する）にも
呼び寄せ（保存しない）にも同じ操作を使うため。

### 3.2 方式 B：LiDAR 平面認識による 1 ボタン登録

| 順 | 動作 |
| --- | --- |
| 1 | 試験員が「登録」を押す。**押した時点の立ち位置が暫定ゴールとして記録される**（F-12） |
| 2 | 試験員が**その場を退く** |
| 3 | 機体が**暫定ゴールまで移動する** |
| 4 | 機体が**盤面の平面を認識して向きを決める** |
| 5 | ピンが立つ |

**手順 1 の暫定ゴール記録が要る理由**（`O-r6`）: 原典は「試験員が退いたあと配電盤前まで移動し認識する」
とだけ書くが、**その時点で盤の位置はまだ登録されていない**ので、機体は「配電盤前」がどこか知らない。
押した時点の立ち位置を暫定ゴールとすることで、この穴が埋まる。

**遮蔽の問題**（`CL-M-2`）: 登録の瞬間、試験員はロボットと盤の間に立っており盤面が隠れる。
手順 2 の退避で解消するが、**退避完了の判定は §5 の退避待ちゲートと同じ仕組みを使う**。

### 3.3 到着後の盤面正対（オプション・許容差次第）

到着後に LiDAR で盤面へ正対する処理を**別途足せる**。
これは登録の方式ではなく**到着後の追い込み**であり、層が違う（[Spec-open.md](Spec-open.md) C-02）。

**作るかどうかは、カメラ昇降が要求する位置決め許容差で決まる**（[Spec-open.md](Spec-open.md) O-a1）。

**判定は Nav2 の到達許容だけで行ってはいけない**（[Spec-open.md](Spec-open.md) F-22）。
盤前で実際に出る向き誤差は、**独立した 2 つの誤差源の合成**である。

```
① 2 点指示が与える「目標の向き」自体の誤差 = ±8〜11°（計算値・未実測）
② Nav2 がその目標にどれだけ着けるか        = ±0.25 m / ±0.25 rad (±14°)（現行設定値）

盤前で出る向き誤差 ≒ √(①² + ②²)   … ①②は独立なので二乗和平方根で見積もる
                     ≒ ±16〜18°     （最悪の重なりを取れば ±22〜25°）

→ 要求許容差 > 合成誤差 : 2 点指示だけで足りる。正対は作らない
→ 要求許容差 < 合成誤差 : ①をどれだけ正確に指令しても②が残るため、
                          到着後に別ループで詰める正対が必要
```

**±14°（②だけ）を敷居にすると、「足りる」と誤判定する帯域ができる。**
①と②の重なり方（独立なのか、系統誤差として同方向に乗るのか）は実測で確かめる
（[Spec-open.md](Spec-open.md) O-c3）。**上の式は見積もりであって、確定値ではない。**

### 3.4 採らない方式と、その残し方（[Spec-open.md](Spec-open.md) C-02）

向きを与える手段は他に 2 つ検討されたが、いずれも**単独では採らない**。

| 方式 | 精度 | 扱い |
| --- | --- | --- |
| ⓪ 何もしない（接近方向のまま） | **不定**（最悪 90° 以上ずれる） | **却下。**盤の正面に向く保証がない |
| ① 退いた方向の逆を法線とみなす | **当てにならない** | **単独の根拠にはしない。サニティチェックとしてのみ残す**（下記） |

**① を本命にできない理由**: 試験員は盤とロボットの間から**横に退く**のが自然であり、
ロボットが正面から来るほど退避は横向きになる。退避ベクトルは法線に対しておよそ 90° ずれる。

**① の残し方**: 退避待ちゲート（§5）で退避方向は自動的に観測できるので、
**観測した退避がほぼ放射方向だった場合に限り、方式 A で得た向きが妥当かを確かめる**
安価なサニティチェックとして使う。食い違ったら試験員に再指示を促す。実装は任意。

### 3.5 登録の受付条件（`CL-M-10`）

| 条件 | 挙動 |
| --- | --- |
| 人物追跡が確実に対象を認識している | **登録できる** |
| ロスト中、またはロスト直後 | **登録を拒否する。**猶予は無い（[Spec-open.md](Spec-open.md) C-05） |
| 信頼度が低い | 拒否する |

**走行時の 500 ms 猶予は登録には効かない。**誤った座標が地図に永続化されると
当日まで気づけないため、走行より厳しくする。

拒否したときは、**対象選択の操作に被らない位置**に案内ウィンドウを出し、
「確実に認識されてから押してください」と示す（[Spec-webui.md](Spec-webui.md)）。

### 3.6 誰を登録しているのかを画面で確かめられること（[Spec-open.md](Spec-open.md) U-14）

2 点指示は**いま試験員が立っている位置**をそのまま座標にする。
したがって「どの候補を対象にしているか」が画面で見えていなければ、
**別人の位置を盤の座標として保存してしまっても気づけない。**

| 要件 | 内容 |
| --- | --- |
| 対象選択 UI | **試験準備・試験の両画面に「対象選択」タブを置く**（[Spec-webui.md](Spec-webui.md) §3.10・§3.11） |
| 部品 | 追従走行画面と**同一のレーダー部品**。見た目も選び方も変えない |
| 複数人いるとき | 候補が 2 人以上なら、対象を選ぶまで登録ボタンを非活性にする |

**ロスト時の扱いは他モードと違う**: `PREP` では人物追跡ロストで**方式を抜けない**。
登録を拒否するだけで、地図作成そのものは続ける
（[Spec-open.md](Spec-open.md) C-15 ／ [Spec-modes.md](Spec-modes.md) §5）。

## 4. 当日：盤前移動と呼び寄せ

**当日の操作は「順にやること」ではなく「2 つの行き方」である**（[Spec-open.md](Spec-open.md) C-12）。
どちらを使ってもよく、盤ごとに使い分けてよい。

### 4.0 準備：いま待機場所にいることの宣言（`CL-D-2`）

| 順 | 操作 |
| --- | --- |
| 1 | メインメニュー画面から**試験画面**を開く |
| 2 | 機体を待機場所に置き、**「待機場所にいる」を試験員が宣言する** |
| 3 | システムは LiDAR で照合し、**登録済みの待機場所と大きくずれていれば警告する** |

原典は「待機場所・姿勢を地図初期位置とする」と定義するだけで、
**当日に誰がそれを宣言するかを書いていない**。試験員の宣言＋システムの照合で埋める。
ずれが検知されたときは、機体を置き直すか、待機場所を登録し直す。

**UI 上の置き場所**: 試験画面の「行き先」タブの先頭に、状態（未宣言／宣言済み）と
宣言ボタンを置く（[Spec-webui.md](Spec-webui.md) §3.11）。ずれの検知は警告ウィンドウで出し、
「置き直す」か「このまま宣言する」を選ばせる。

### 4.1 行き方 (a)：ピンを選ぶ

| 順 | 操作 | モード |
| --- | --- | --- |
| 1 | 地図のピン、またはリストの名前を選ぶ | `PANEL_NAV` |
| 2 | 登録済み座標へ Nav2 で移動する | `NAV` |
| 3 | 到着後、**超信地旋回で向きを合わせる** | `ALIGN` |
| 4 | 撮影・確認の作業をする（「作業中」ボタン ON） | `AT_PANEL` / `WORKING` |
| 5 | 作業が完了したら、**待機場所／次の配電盤／その場で呼ぶ**のいずれかを選ぶ | → 各モード |

### 4.2 行き方 (b)：その場で呼ぶ

| 順 | 操作 | モード |
| --- | --- | --- |
| 1 | 必要なところに立ち、**2 点指示**をする（§3.1。保存はしない） | `SUMMON` / `POINT` |
| 2 | **試験員が退く** | `WAIT_CLEAR` |
| 3 | 退避を確認してから発進し、指示された位置へ Nav2 | `NAV` |
| 4 | 到着後、2 点指示で与えた向きに合わせる | `ALIGN` |
| 5 | 作業をする | `AT_PANEL` / `WORKING` |
| 6 | 完了したら、**待機場所／次の配電盤／その場で呼ぶ**のいずれかを選ぶ | → 各モード |

> **原典との差異**: 原典は (a) のあとの選択肢を「待機場所もしくは次の配電盤」、
> (b) のあとを「待機場所」だけと書き分けているが、これは**書き分けの不足**とみなし、
> **どちらのあとでも同じ 3 つを選べる**ように統一した（`O-r7`）。

### 4.3 呼び寄せの向き（`DF-D-4`）

原典の当日手順には**呼び寄せ時の向きの決め方が書かれていない**。
(a) は登録済みの向きがあるので「超信地旋回で合わせる」で済むが、(b) には登録済みの向きが無い。

→ **(b) でも 2 点指示を使う**（F-09）。(a)（登録）と (b)（その場で呼ぶ）は
手順が同じで、**保存するかどうかだけが違う**。

## 5. 退避待ちゲート（安全上必須・`CL-D-6`）

**試験員が退く前に機体が発進してはいけない。**原典の「試験員が退き次第」を実現する仕組み。

| 項目 | 仕様 |
| --- | --- |
| 条件 | 追従対象が**ゴール地点から `clear_distance_m` 以上離れ**、その状態が `clear_hold_ms` 続いたら発進 |
| 満たされない間 | **発進しない。**画面に「退いてください」と表示し、現在の距離を出す |
| 追跡が切れたら | 発進しない（永久に待つのを防ぐため下記タイムアウト） |
| **タイムアウト** | `clear_timeout_ms` を超えたら**中止する**。`POINT` に戻ってやり直す |
| 適用先 | 呼び寄せ (b) ／ 平面認識 1 ボタン登録（§3.2 手順 2〜3） |

**タイムアウトする理由**: 待ちには 2 種類あり、扱いが違う（[Spec-open.md](Spec-open.md) F-11）。

| 待ちの種類 | 扱い |
| --- | --- |
| **人が退くのを待つ** | **タイムアウトする。**人が戻ってこられる状況なので、中止して操作をやり直せばよい |
| **経路が通れるようになるのを待つ** | **タイムアウトしない**（§6） |

---

## 6. 試験場内の Nav2 方針

| 項目 | 仕様 |
| --- | --- |
| 経路 | **最初に決めたルートが通れるようになるのを待つ。自動でルートを変えない** |
| 塞がれたとき | WebUI にウィンドウを表示する。**試験員の指示があったときのみ**ルートを再検索する |
| タイムアウト | **しない** |
| 速度 | 場内なので `v_slow`（[Spec-modes.md](Spec-modes.md) §7） |
| 障害物 | 停止する。自動回避はしない |

これは `NewDesign.md` §異常時の「走行開始時に決定した経路を逸脱しない」を
試験場内の Nav2 に具体化したものである。

## 7. 配電盤前

### 7.1 範囲外

| 項目 | 扱い |
| --- | --- |
| **ピッチ・ヨー・高さ**（カメラ昇降） | **別担当。**本設計書では扱わない |
| 盤前での**低速並進** | 「担当する可能性があるがまだ含めない」。本設計書に含めない |

### 7.2 暫定インターフェース：作業中ボタン

結合設計がまだなので、**仮で「作業中」ボタンを置く**。

| `working` | 挙動 |
| --- | --- |
| ON | **待機場所・別の配電盤・呼び寄せのいずれを選んでも拒否される。**画面に理由を出す |
| OFF | 通常どおり次の行き先を選べる |

**未確定**（[Spec-open.md](Spec-open.md) O-a6）: 誰がいつ押すか、OFF ＝作業完了とみなしてよいか、
そして正式なインターフェース（到着通知／昇降完了／撮影完了／中断通知）。
昇降・撮影側との結合設計が決まり次第、このボタンを正式な信号に置き換える。

### 7.3 到着が許容差を外れたときのリカバリ

**未確定**（[Spec-open.md](Spec-open.md) O-d3）。低速並進を含めないため、
外れたときに詰め直す手段が無い。当面の代替は次のいずれか：

1. 試験員がジョグ介入で手動で詰める（[Spec-modes.md](Spec-modes.md) §8）
2. 呼び寄せ (b) でやり直す
3. 到着後の LiDAR 盤面正対（§3.3）を作る

どれを採るかは、カメラ昇降の許容差（O-a1）が決まってから判断する。
