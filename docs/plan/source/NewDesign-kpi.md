# 目標と KPI — 数値の決め方

[NewDesign.md](NewDesign.md) §目標 / §制作の仕方 の詳細。
**前提**: PoC → MVP → 実証実験でデータを取得した時点で開発終了（2026-08-11 確定）。

---

## 1. 目標（実証実験で何を示せたら終わりか）

| # | 目標 | 判定の形 |
| --- | --- | --- |
| G1 | **安全** — 人・物への接触なし、意図しない発進なし | カウントではなく**故障注入で検証**する（§4.3） |
| G2 | **盤前** — カメラ昇降が要求する許容差内に、手動微調整なしで停止できる | 全盤・全試行での成功回数（分母を明記） |
| G3 | **前日準備** — 地図作成＋盤登録が試験員1人で完結し、地図の手修正が不要 | 所要時間と手修正の回数。**現状のベースラインが未取得**（§5） |
| G4 | **移動** — 保管場所⇔試験場を、試験員が付き添う以上の負担なく移動できる | 介入回数と完走回数。**所要時間は記録項目に留め、合否に使わない** |
| G5 | **継続性** — 1日の運用（往復＋N 盤）をバッテリー交換・再起動なしで完走 | 完走したかどうか（n=1 で足りる） |

G4 で時間を合否に使わないのは、開発が日々の運用最適化ではなくなったため
（[NewVISION.md](NewVISION.md) の前提訂正）。相対比較の物差しとしては残す。

## 2. 数値の出どころは 3 つしかない

| 出どころ | 決まり方 | 該当する数値 |
| --- | --- | --- |
| **(a) 外部から与えられる** | 先方への確認・交渉 | カメラ昇降の許容差、通路幅・扉・段差、盤の数と間隔、前日準備の現状所要時間、無人走行の許可 |
| **(b) 物理・仕様から逆算** | 計算（測定不要） | 安全距離、`v_max`、許容逸脱、2点指示の点間距離、タイムアウト |
| **(c) 測らないと分からない** | ベースライン測定 | 実測制動加速度、教示再生のドリフト、ロスト率、WiFi 受信ギャップ、実効速度 |

> **(c) に事前の目標値を置いてはいけない。** 先に現状値を測り、その分布から閾値を置く。
> 順序を逆にすると、達成不能な数値か、無意味に緩い数値のどちらかにしかならない。

## 3. 逆算の連鎖 — 上流が決まると下流は自動で決まる

```
【A】カメラ昇降の許容差 [±m, ±deg]   ← (a) 先方/別担当に聞く
      ↓
    到着精度の要求  →  Nav2 の到達許容 (±0.25 m / ±14°) で足りるか
      ↓ 足りない
    LiDAR 盤面正対を作る   /   足りる → 2点指示だけで終わり
      ↓
    2点指示の点間距離 L（L=1 m・人物位置誤差 σ=0.1 m で ±8〜11°）

【B】実測制動加速度 a [m/s²]   ← (c) 最も安く、最も多くの下流を決める
      ↓
    制動距離 = v²/(2a) + v × t_遅延
      ↓
    安全距離（`obstacle_check_distance_m`）/ `lidar_timeout_ms` / `v_max`
      ↓
    停止・再開ヒステリシス帯の幅

【C】通路幅 W・機体幅 B   ← (a) 現地確認
      ↓
    許容逸脱 = (W − B)/2 − マージン
      ↓
    教示再生のドリフト上限  →  1 経路の長さの上限
```

**A・B・C はどれも「1 つの数値を決めると 3〜4 個の KPI が自動で決まる」形をしている。**
KPI を 1 つずつ決めようとせず、上流の 3 つを先に潰す。

## 4. n（試行回数）が KPI の書き方を決める

### 4.1 実験は 2 段階あり、n が桁違い

| | 場所 | n | できること |
| --- | --- | --- | --- |
| **社内試験（PoC 期）** | 社内・通路 | 1 方式あたり 10〜30 | **8 方式の比較と取捨選択はここでしかできない** |
| **実証実験（MVP・先方施設）** | 先方の教育用施設 | 1 方式あたり **1〜2** | **選び抜いた 1 構成が成立することの提示** |

**この 2 つを混ぜると KPI が検証不能になる。** 実証実験で 8 方式を並べて順位は付かない。

### 4.2 率（%）で書くと n が足りない

10 回中 10 回成功しても、失敗率の 95% 信頼上限は約 26%（＝成功率の下限は約 74%）。
つまり **n=10 では「完走率 95%」も「99%」も検証できない**。30 回中 30 回でようやく
失敗率の上限が約 10% に下がる。

→ **KPI は率ではなく回数で書く。**「10 回中 10 回」「介入 0 回 / 200 m × 10 往復」。
率で書きたい場合は、その率を主張するために必要な n を先に決めてから実験計画を組む。

### 4.3 安全は KPI ではなく検証手順

「接触 0 回」は要求だが、0/n は発生率をほとんど保証しない。**故障注入で確認する。**

| 検証 | 方法 | 合格条件 |
| --- | --- | --- |
| 障害物リミッタ（X-3） | 意図的に障害物へ向けて走らせる | 停止する。**後退方向も試す**（LiDAR 死角・X-4） |
| E-Stop | 走行中に押す | 停止 |
| フォルト → 停止 | LiDAR / ESP32 の通信を切る | **100 ms 以内**に `/cmd_vel` が 0 |
| 呼び寄せの退避待ち（D-6） | 退かずに待つ | 発進しない → タイムアウトで中止（D-7） |
| ESP32 ウォッチドッグ | ROS2 側を落とす | 600 ms 以内に停止 |

n=1 で検証でき、安全チェーンが実際に主張しているのはこの形である。

## 5. 共有部分は 1 回だけ測る（方式ごとに測らない）

[NewVISION.md](NewVISION.md) の「速度は案を区別する評価軸にならない（全案が同じ
ドライブトレインを使う）」を KPI 表にも適用する。

| 層 | 測る回数 | 項目 |
| --- | --- | --- |
| **共有層（1 回）** | 1 | 制動加速度、実効速度、WiFi 受信ギャップ、遅延バジェット、タイムアウト、障害物リミッタ |
| **方式ごと** | 方式数 × n | **ゴール生成の頑健性**だけ（下表） |

200 m × 8 方式 × n を全項目で回すのは時間的に不可能。**違うところだけ測る。**

### 方式ごとの KPI（社内試験・選抜用）

絶対値の閾値は不要。**同条件で走らせて順位が付けばよい。**

| 方式 | 測る指標 | 備考 |
| --- | --- | --- |
| 1. 追従走行 | ロスト回数/100 m、復帰時間、**誤追従（別人・別物）回数** | |
| 2. 手動走行 | 操作者が画面を見ている時間の割合、通信起因の停止回数 | 比較の基準線 |
| 3-4. 教示（記録） | 記録の完走率、記録所要時間、やり直し回数 | |
| 5. 教示再生 | **終点位置誤差 [m]（ドリフト）**、経路逸脱の最大値 | §3【C】で上限が決まる |
| 6. 教示逆再生 | 同上（往路との差分で対称性を見る） | |
| 7. 区画線走行 | 線のロスト率、線が無い／途切れる区間の割合、分岐での判断成功率 | |
| 8. 電子リード走行 | 距離追従誤差、意図しない停止回数、取り回しの実用性（定性） | |
| 全方式共通 | **介入回数/100 m**、完走回数、経路逸脱の最大値 | 選抜はほぼこの 3 つで付く |

### 盤前の向き 3 方式（同じ枠で比較できる）

平面検出の成功率 ／ 法線誤差 [deg]（**2点指示との差分で相対評価できる**）／ 押下回数 ／
盤が壁と面一のときの挙動。

### 無人走行の許可について

**方式 5・6 は「試験員が先導・同行する形」を既定として測る**
（[NewVISION.md](NewVISION.md) の案 4-B。許可不要・現場改変不要）。
これで**許可の回答を待たずに KPI が取れる**。許可が取れた場合は同じコードのまま
人が付かない運用に切り替わるだけで、測り直しは要らない。

## 7. 先に潰す 4 つ

1. **実測制動加速度**（(c)・社内で今日から可能）
   → `v_max` / 安全距離 / `obstacle_check_distance_m` / `lidar_timeout_ms` が**全部これに従属する**。
   [transit-premises.md](transit-premises.md) 自身が「まずこれを測るべき」としている項目。
2. **カメラ昇降の許容差**（(a)・確認するだけ）
   → LiDAR 盤面正対を作るかどうかが決まる（チェックリスト P-2）。1 と並列に進む。
3. **人が歩いている部屋で地図を作ってみる**（(c)・最も安い）
   → 人物マスク実装の要否が決まる（M-4）。
4. **前日準備の現状ベースライン**（(a)）
   → G3 は現状値がないと検証不能。盤の設問と同じ束で聞ける（[questions-venue.md](questions-venue.md)・R-3）。
