# キャリブレーションシステム詳細

キャリブレーションの開始とサポート、詳しい手順の確認ができる。

実装方式（画面構成・トピック設計など）はまだ検討しない。ここでは「理想的にはどう振る舞ってほしいか」だけを書く。

## 対象（現状キャリブレーションが必要なもの）

| # | 項目 | 何を補正するか |
| --- | --- | --- |
| 1 | 直進キャリブレーション | 車輪半径（走行距離の誤差） |
| 2 | 旋回キャリブレーション | 実効車輪間距離（旋回角度の誤差） |
| 3 | IMUキャリブレーション | BNO055 のセンサ内部オフセット（ジャイロ・加速度・地磁気） |
| 4 | LiDAR死角マスク較正 | 機体アルミパイプが写り込む角度範囲 |

## 理想的な機能（4項目共通）

現状は各項目が独立したCLIスクリプトで、手順書はスクリプトのコメントにしかなく、実測値もターミナルへの手入力、適用は補正値をコピーして別コマンドを叩く、という分断された流れになっている。理想はこれを一つの体験にまとめる。

* **ガイド付きウィザード**: 「何をどう準備するか」「どう動かすか」「どこを測るか」を、その場で・その手順のときに画面に案内する。事前にドキュメントやコード中のコメントを読みに行く必要がない
* **測定値の入力も画面内で完結**: ターミナルへの手入力を経由しない
* **即時反映・永続化**: 補正値は求まった瞬間にシステムへ反映され、電源を入れ直しても消えない。**再ビルド・再書き込みを必要とする補正は理想ではない**（現状これに反しているのは §1 のみ。ギャップとして明記する）
* **適用前のプレビュー**: 「現在値 → 補正後の値」を確定前に見せ、明らかにおかしい値（ゼロ割れ・桁違い）を弾く
* **履歴とロールバック**: 過去の補正値を残し、いつでも1つ前に戻せる。较正して悪化した場合に元に戻す手段がないと安心して較正できない
* **適用後の検証**: 補正して終わりにせず、同じ動作をもう一度行い、誤差が許容範囲に収まったことを確認してから完了とする。現状は「1回測って係数をかけて終わり」で、補正が効いたかどうかを誰も確認していない
* **中断・安全**: 較正動作は人がボタンを押し続ける操作ではなく自律的に一定距離・角度を動くため、常に見える位置に中断ボタンを置き、E-Stop/フォルトで即座に停止する。中断後は補正値を確定せずに終われる
* **[動作確認](NewDesign-operationalCheck.md)との連携**: 動作確認でズレ（例: LiDAR死角の不一致）を検知したら、そのままこの較正画面の該当項目へ導線を出す。「異常に気づく」動作確認と「直す」較正が別画面で完結しないようにする

## 1. 直進キャリブレーション（車輪半径）

流れ: 指定距離を自律走行 → 実際に進んだ距離を画面へ入力 → 補正後の値をプレビュー → 適用 → 検証走行で再確認。

現状とのギャップ: 車輪半径は ESP32 ファームウェアのコンパイル時定数で、適用には書き換え・再書き込みが要る。理想としては他の3項目と同様に即時反映・再起動不要であるべきで、これは是正すべきギャップとして扱う。

## 2. 旋回キャリブレーション（実効車輪間距離）

流れ: 指定角度を自律旋回 → 実際の回転角を入力 → 補正後の値をプレビュー → 適用（即時反映・永続化） → 検証旋回で再確認。

## 3. IMUキャリブレーション（BNO055）

流れ: 案内に従って機体を8の字に動かす → sys/gyro/accel/mag のリアルタイム表示を見ながら全て「完全」になるまで続ける → 完了。

較正が完了した状態（オフセット）を保存し、次回起動時に自動で復元する。

## 4. LiDAR死角マスク較正

流れ: 生のスキャンをその場でライブ表示し、死角として写り込んでいる角度帯を画面上で直接選択（描画上で範囲を指定する操作）→ プレビューで死角マスクが正しくかかることを確認 → 適用（即時反映・永続化）。

現状とのギャップ: 現状は rviz2 で角度を目視で読み取り、設定ファイルへ手入力する運用になっている。数値を人が読み取って転記する工程自体をなくすのが理想。
