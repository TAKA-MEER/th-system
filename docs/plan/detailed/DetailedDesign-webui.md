# WebUI の実装

[DetailedDesign.md](DetailedDesign.md) の詳細。**15 画面を既存 React の上に作り直す。**

| 決定 | 内容 |
| --- | --- |
| 基盤 | **既存 `th_ws/web_ui/`（React 18 + Vite 4 + roslibjs）を土台にする**（ユーザー決定） |
| 捨てるもの | `App.jsx` の 3 タブ構成（運用／準備／診断）と `App.css`（890 行の作り込み） |
| 見た目の正本 | `docs/plan/spec/mockup/index.html`。**CSS とレイアウト規則はここから移す** |
| 残すもの | rosbridge の足回り・地図描画・仮想スティック・レーダー・音声（§3） |

**モックアップは「実装ではない」と宣言されているが、`Spec-webui.md` §1.4 のような
「実際に測らないと分からない要件」を既に満たしている**（`F-23` の改訂はモックアップで実測して出た）。
**CSS を書き直すと、その検証結果を失う。**

## 2. シェル（安全要件）

### 2.1 重なり順（**`SD-3`**）

**通常のモーダルとは逆で、ヘッダがすべての上に来る。**
`Spec.md` §5 `SD-3`「ヘッダは常に最上位。非常停止はどんなときでも動作し、何にも覆われない」の実装。

| 層 | z-index | 内容 |
| --- | --- | --- |
| 最上位 | 100 | **ヘッダ（非常停止を含む）** |
| 下端固定 | 70 | **非常停止の解除バー**（ウィンドウの上。何にも覆われない） |
| 中間 | 60 | **W-6 手動操作パネル**（他ウィンドウの上に浮く） |
| 中間 | 50 | ウィンドウ W-1〜W-5 |
| 最下位 | 0 | 本文（**唯一スクロールする領域**） |

**検証方法**: 異常ウィンドウ（W-1）を開いた状態で、ヘッダの非常停止ボタンも
画面下端の解除バーも押せること。**どちらかが押せなければ設計違反。**自動テストにする
（§9-1。`e2e/estop-clickable.spec.js` / `e2e/estop-release-clickable.spec.js`）。
解除バーが 40（ウィンドウ 50 の下）だった頃は W-1 の `.backdrop` が解除バーを覆い、
非常停止をかけると解除できなくなっていた。

### 2.2 非常停止ボタンの寸法（`U-9`）

| 項目 | 要件 |
| --- | --- |
| 高さ | **72 px 以上、かつ基準文字サイズの 4.2 倍以上。**かつ**画面内のどのボタンよりも高い** |
| 幅 | **160 px 以上。**かつ**画面幅の 25% 以上** |
| 縦長 | ヘッダ 2 段目の**幅 45% 以上** |
| 文字 | 基準の 1.25 倍以上・太字。省略せず「非常停止」 |
| 余白 | 他の操作要素と隣接させない |

**「面積で最大」ではなく「高さで最大」**。メインメニューのような横長リストが並ぶ画面では
面積では一覧ボタンが上回る。タップの成否を決めるのは**指の当たる方向の余裕＝高さ**。

**解除ボタンにはこの要件を適用しない。**むしろ小さめにし、**画面の下端**に置き、色と形も変える。

### 2.3 文字サイズは画面幅に追随する（`U-12` ／ **`SD-2`**）

| 画面幅 | 基準文字サイズ |
| --- | --- |
| 〜1130 px | **16 px**（据え置き） |
| 1130〜1670 px | 幅に比例 |
| 1670 px 〜 | **22 px**（頭打ち） |

**ビューポート幅ではなくアプリの表示領域幅で決める。**
モックアップは `container-type: size` ＋ `clamp(16px, calc(1.1cqi + 3.6px), 22px)` で実装済み。
**この式をそのまま移す。**

### 2.4 スクロールさせない（`U-13`）

| 端末 | 要件 |
| --- | --- |
| **短辺 768 px 以上** | **どの画面もスクロールさせない。**本文が縦に溢れたら**設計不良** |
| 短辺 768 px 未満 | スクロールしてよい。ヘッダと操作バーは固定 |

溢れたときの手段（この順）:

1. **図の高さを頭打ちにする**（レーダー・地図・スティック。縦横比は保つ）
2. **右列の詳細をタブに畳む**（操作カードは常に見せる）
3. **広い画面では右列を 2 列に割る**（幅 1300 px 以上）

**W-6 はこの判定に影響しない**（浮くカードなので本文の高さを変えない）。

### 2.5 ヘッダの畳み順（`U-10`）

場所が足りないとき: ① プロジェクト名を消す（ロゴは残す）→ ② ゾーン表示を短縮 → ③ 画面名称を末尾省略。
**画面名称・モード・非常停止は、どれだけ狭くても縮めない。ヘッダは 2 行を超えて折り返さない。**

| 要素 | 大きさ |
| --- | --- |
| 画面名称 | 基準の **1.45 倍以上・太字**（ヘッダで最大） |
| 現在のモード | 基準の **1.05 倍以上・太字**。モード色の枠と背景 |
| プロジェクト名 | 基準の 0.8 倍以下 |
| ゾーン表示・開発モード・**暫定値バッジ** | 基準の 0.72 倍 |

## 4. 操作の置き場所（**全画面共通**・`U-15`）

| 置き場所 | 何を置くか |
| --- | --- |
| **画面左上の操作バー**（固定） | **「終了」**／画面内のタブ／状態を表すピル |
| **右列の先頭の「操作カード」** | **停止・確認・走行・保存・手動** |

**格子は固定する。使わないボタンは置かないが、置くボタンの位置は動かさない。**

|  | 左 | 中 | 右 |
| --- | --- | --- | --- |
| **上段** | **停止** | **確認** | **走行**（教示再生では「再生」） |
| **下段** | **保存** | — | **手動** |

**「終了」を操作カードに入れてはいけない。**一時停止のつもりで方式を抜ける誤操作を招く。

### 4.1 ボタン → トリガ

**ラベルは状態で変わるが、トリガは 1 つ。**

| ボタン | トリガ | ラベルの例 |
| --- | --- | --- |
| 停止 | `ui.stop` | 停止 |
| 確認 | `ui.confirm` | 確認 |
| 走行 | `ui.run` | 追従開始（`FOLLOW/CONFIRM`）／走行（`PAUSE`）／再生（`REPLAY/READY`）／走行開始（`LINE`/`LEASH`） |
| 保存 | `ui.save` | 保存 |
| 手動 | — | **トリガを送らない。**W-6 を開くだけ |
| 終了 | `ui.finish` | 終了 |

**どの状態でどのボタンが押せるかは `transitions.yaml` が正。**
UI は `/system/trigger` を投げ、`accepted=false` なら `reject_reason_key` を日本語にして出す。

> **押せるかどうかを UI で先読みして非活性にしてよいが、それは表示上の親切であって権威ではない。**
> **必ずサーバー側（`th_state`）が拒否する**（現行 `config_manager` と同じ二重の守り）。

### 4.2 「手動」ボタンを置く画面（`U-16`）

**スティックを常設できるかだけで決まる。**

| 画面 | スティック | 「手動」ボタン |
| --- | --- | --- |
| S-10 / S-12（追従系） | **常設** | **置かない。**触れた瞬間にジョグ介入が始まる |
| S-11 / S-13（手動系） | **常設** | **置かない。**スティックそのものが走行操作 |
| S-14 / S-15 / S-16 / S-20 / S-21 | 置けない（主表示が地図で埋まる） | **置く。**押すと W-6 |

**触れば始まる、が唯一の入り口。**ボタンが 2 つあると「スティックを触る前に手動を押すのか」が分からなくなる。

### 4.3 色（`U-17`）

| 見た目 | 意味 | 使う場所 |
| --- | --- | --- |
| **青（塗り）** | **いまの状態** | 停止／確認／走行のうち、**いま該当している 1 つだけ** |
| **緑（塗り）** | 押すと確定する動作 | 保存 |
| 枠のみ | 押せるが、いまの状態ではない | それ以外 |

**同じ操作カードの中で青を 2 つ以上にしてはいけない。**
**強調のために青を使わない。**青は状態表示専用。

実装: `OperationCard` は `/system/state` の `state` を受け取り、
`stateToBlueButton[state]` で青にするボタンを 1 つだけ決める。**画面側で色を指定させない。**

## 5. ジョグの送出（`F-29` のリース）

```js
// VirtualStick が押されている間
useEffect(() => {
  if (!held) return;
  const id = setInterval(() => {
    publishJogLease();                                   // トピック /ui/jog_lease（応答を待たない）
    publishCmdVelManualRaw(stickToCmd(dx, dy, speedPct)); // 10 Hz は別タイマ
  }, 1000 / JOG_LEASE_HZ);
  return () => clearInterval(id);
}, [held, dx, dy]);
```

| 項目 | 仕様 |
| --- | --- |
| **経路** | **トピック `/ui/jog_lease`。サービス `/system/trigger` を使わない** |
| 頻度 | **5 Hz 以上。**`jog_lease_ms` より十分短く |
| 離したとき | **`ui.jog.release` を送らない。**送信を止めるだけ。リース満了で FSM が解除する |
| 速度指令 | **`/cmd_vel_manual_raw`** へ 10 Hz（`jog_gate` の手前）。**離したらゼロを 1 回送る** |

> **サービスにしてはいけない。**rosbridge 越しの同期呼び出しを毎秒 5 回、
> WiFi 受信ギャップ 0.5〜1.2 s の環境で行うと**応答待ちが詰まってリースが切れる**。
> しかも毎回 `accepted` と `reject_reason_key` が返るので、拒否のたびに UI が異常表示する。
> **リースは「届けばよい」性質**なので best_effort のトピックが正しい。

**`?view=audience` では送らない**（`readOnly: true`）。既存の構造を維持する。

## 6. ウィンドウ

| ID | 種別 | 出る条件 | 閉じ方 |
| --- | --- | --- | --- |
| **W-1** | 異常ウィンドウ | フォルト発生 | 非表示にできる／解決で再開確認に変わる |
| **W-2** | 手押しウィンドウ | 物理非常停止押下 | 解除するまで閉じない |
| **W-3** | 案内ウィンドウ | ロスト・登録拒否・線ロスト・退避待ちなど | 閉じられる／条件解消で自動 |
| **W-4** | 確認ウィンドウ | 破棄・保存・上書き・**運用の終了** | はい／いいえ |
| **W-5** | 経路ブロック | Nav2 の経路が塞がれた | 「再検索する」を押すまで（**タイムアウトしない**） |
| **W-6** | 手動操作パネル | スティックを常設できない画面で「手動」 | §6.3 |

**ブラウザ標準ダイアログ（`alert` / `confirm`）を使わない。**ヘッダより上に出てしまう。

### 6.1 W-3 は帯、W-6 は浮くカード

| | W-3 | W-6 |
| --- | --- | --- |
| 出し方 | **本文の下に帯として差し込む**（1 行） | **浮くカード。レイアウトを一切動かさない** |
| 理由 | 1 行なので本文をほとんど圧迫しない | 帯にすると本文を圧迫し、スティックを小さくせざるを得ない |

下端に積む順（flex order、上から）: **本文 → 案内（帯）→ 非常停止解除バー**。W-6 は
その上に浮く（ただし解除バーの実高さ分だけ上にずらして配置し、解除バーには重ねない。
z-index も解除バー 70 > W-6 60）。

### 6.2 W-1 のライフサイクル

```
異常発生 → [ W-1 ] ──「非表示」──> [ ヘッダにバッジ ] ──「再表示」──> [ W-1 ]
                │
                │ 異常が解決（これ自体では何も遷移しない。F-34）
                ▼
        [ 同じウィンドウが「再開しますか」に変わる ]
                ├─ [ はい ]   → ui.resume_yes  → 元モードの走行状態（F-37）
                ├─ [ いいえ ] → ui.resume_no   → 元モードの PAUSE
                └─ [ 確認 ]   → ui.resume_ack  → 同上
```

| 規則 | 内容 |
| --- | --- |
| 位置 | 本文の上・**ヘッダの下** |
| 非表示 | **解決していなくても非表示にできる** |
| 解決時 | **同じウィンドウが再開確認に変わる**（別ウィンドウを出し直さない・`E-5`） |
| **選択肢の決め方** | **`/system/state` と属性表から導く。画面ごとにハードコードしない**（`F-34`） |
| **復帰先** | **どの選択肢でも待機（`IDLE`）には戻さない**（`U-8`） |

属性表（`attributes.yaml` の `resume`）は `th_state` が `/system/state` に載せて配る
（UI が別途 YAML を読まない）。

### 6.3 W-6 の要件（`U-16` 改訂）

| 項目 | 要件 |
| --- | --- |
| **レイアウト** | **開いても本文のレイアウトを一切動かさない。**地図・レーダーの大きさも変えない |
| **大きさ** | スティックは**画面内に常設するものと同じ大きさ**（モックアップ実測 210 px） |
| 置き場所 | **左下。**横長では操作カードが右列なので構造的に被らない。縦長では操作カードを本文上端へ送る |
| モード | **変わらない。**パネル上部に「モードは『◯◯』のまま変わりません」 |
| 覆ってはいけないもの | **ヘッダ（非常停止）** と **操作カードの「停止」** |
| 自動で閉じる | 停止・確認・走行・再生・保存を押した／画面を離れた／異常・非常停止 |
| **閉じない** | **スティックを離した（リース満了）。**離すたびに閉じると寄せる操作が毎回押し直しになる |

> **既存の実装バグに注意**: モックアップの初版はスティックのイベント登録が対象画面 ID を
> **登録時に 1 度だけ**読んでおり、パネルのスティックが**触っても何も起きない**状態だった。
> React では対象画面をイベントハンドラのクロージャに閉じ込めず、ref か state から都度読む。

### 7.1 表記の決めごと

- 移動を伴うモードは**「〜へ移動」で語尾を揃える**（`PANEL_NAV` / `HOME_NAV`）
- **名前の長い走行方式は、モード名から「走行」を落とす**（`LINE`＝ライン誘導、`LEASH`＝電子リード、`REPLAY`＝教示再生）。
  短い `FOLLOW`＝追従走行 / `MANUAL`＝手動走行は**落とさない**（落とすとジョグ介入中の「手動介入中」表示と紛らわしい）
- **UI では「盤」と略さず「配電盤」と書く**
- 「待機」（`IDLE`）と「待機場所」は**別物**

### 7.2 UI に説明文を置かない（`U-11`）

| 種類 | 例 | 置き場所 |
| --- | --- | --- |
| **状態** | 「一時停止中（記録は保持・終点は未確定）」 | **UI** |
| **次にできる操作** | 「立ってほしい位置に立って押してください」 | **UI**（短く 1 行） |
| **拒否された理由** | 「カメラが接続されていません」 | **UI**（ウィンドウ。押されて初めて出す） |
| 設計の根拠・仕様の宣言 | 「自動でルートを変えません」 | **設計書へ** |
| 手順の解説 | 「①→② が方向ベクトルになります」 | **マニュアルへ** |

**判定**: その文を消したとき**試験員が次に何を押すか分からなくなる**なら残す。
**「◯◯しません」で始まる文はほぼ設計書行き。**

### 8.1 S-10 / S-11 / S-12 / S-13 は 1 つの走行タブを共有する（`U-5`）

`driveTab.jsx` を 4 画面で**そのまま差し込む**。分岐は 2 つだけ。

// manual: 障害物警告 + 自動ブレーキトグル + 後退時の死角注意

**教示画面が増やすのは「教示」タブ 1 枚と「保存」ボタン 1 つだけ。**

### 8.3 S-01 の「運用の終了」区画（`F-23`）

**この区画が無いと `Spec-ops.md` §4 の終了手順が実行できない。**
未保存の検出はここが唯一の機会。

| 順 | どこ | 中身 |
| --- | --- | --- |
| 1 | **カード**（高さ約 120 px） | **未保存の件数**と**「制御系を停止する」**ボタン 1 つだけ |
| 2 | **W-4** | 未保存の一覧（試験場内地図／教示経路／校正値／地図の書き足し） |
| 3 | **W-4** | 項目ごとに「保存」／「破棄」。**破棄は `ArmedButton`** |
| 4 | **W-4** | 「停止する」。**未保存が残っている間は押せない** |
| 5 | 画面 | 停止の進捗と**完了表示**（ここまで確認してから電源を切る） |

**カードのボタン自体は未保存があっても押せる。**押せないボタンを置くより、
押したら一覧と理由が出るほうが「何をすれば終われるか」が分かる。

**「終了」という語を使わない。「制御系を停止する」と書く。**
「終了」＝方式を抜けてメインメニューへ、に固定してあるため。

> 未保存の一覧をカードに展開すると、**短辺 768 px でメインメニューがスクロールを要求する**
> （モックアップで実測。必要な高さが器を 41 px 超えた）。**カードに展開しない。**

### 9.1 `names.json` の生成（受け入れ条件 10 の前提）

**名前辞書は Markdown が正本で、JSON はそこから作る派生物である。**
JSON を手で書くと、辞書に足したのに JSON に無い／JSON にあるのに辞書に無いが起きて、
**検査が「辞書と一致」ではなく「自分の写しと一致」になる。**

| | |
| --- | --- |
| 生成器 | `docs/plan/detailed/tools/export_names.py` |
| 入力 | `docs/plan/detailed/DetailedDesign-names.md`（§2 モード／§4 画面／§5 msg・srv／§6 トピック／§7 パラメータ／§8 トリガ） |
| 出力 | **`th_ws/web_ui/src/ros/names.json`**（コミットする） |
| 実行場所 | **ホスト（リポジトリルート）。**`web_ui/` はコンテナにマウントされていない（`V1`） |

```bash
python3 docs/plan/detailed/tools/export_names.py .
git diff --exit-code th_ws/web_ui/src/ros/names.json   # 生成物が最新であること
```

**キーは `modes` / `screens` / `topics` / `services` / `params` / `triggers` / `msgs`、
および `endpoints`（＝ `topics` ∪ `services`）。**
`topics.js` の突き合わせは **`endpoints`** を使う——rosbridge の宛先という点で
トピックとサービスは WebUI から見て同じものだからである。

**生成が 0 件を返したら生成器は非ゼロで落ちる**（表の書式が変わった検出）。
`names.json` が古いまま検査が通る形にしない。
