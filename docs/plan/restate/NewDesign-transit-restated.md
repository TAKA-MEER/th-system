## 2. 追従走行

**やっていること**: LiDAR で足を検知し、**その位置の軌跡を追従する**。
（「今いる場所へ向かう」のではなく「通った道をなぞる」）

### 進行

| # | 試験員                           | 機体・画面                                         |
| - | -------------------------------- | -------------------------------------------------- |
| 1 | 追従走行を選ぶ                   | 追従走行画面へ移る                                 |
| 2 | **追従対象を選ぶ**         | —                                                 |
| 3 | **「確認」を押す**         | **対象の方を向く。移動はしない**             |
| 4 | **左右に動いてみる**       | 向きが追従する（＝正しい人を掴んでいることの確認） |
| 5 | 「追従開始」を押す               | —                                                 |
| 6 | **ゆっくり**目的地まで歩く | **試験員が歩いた場所をなぞって**移動する     |
| 7 | 到着                             | —                                                 |
| 8 | 追従走行を**停止**させる   | 止まる                                             |
| 9 | 追従走行を**終了**させる   | 追従走行画面を抜ける                               |

### 挙動の決まりごと

* **ショートカットしない。** 試験員が直角に曲がったら、機体も直角に曲がる。角を斜めに突っ切らない。
* **試験員が近くにいる場合は止まる。**
* 手順 3〜4 の「確認」は、**走り出す前に対象が合っているかを確かめるための空振り動作**である。

### 「停止」と「終了」の違い

原文は手順 10 と 11 で「停止させる」「終了させる」を分けている。
**停止＝走るのをやめる（対象選択は残る、再開できる）／終了＝方式そのものを抜ける**。

## 4. 教示（記録）

### いつ・どこで決めるか

* **走行方式選択画面で「教示をするかどうか」を決める。**
  理由：**途中から教示を始めることはしない**ため。
* 記録は**方式を選んだ直後から始まる。**「記録開始」を押す操作はない。

### 選択の流れ

```
「教示　追従走行」 or 「教示　手動走行」を選ぶ
        ↓
  既存経路の再設定  /  新規経路の設定   ← どちらかを選ぶ
        ↓
        直後から記録開始
        ↓
  以降は通常の追従走行 / 手動走行と同じ
```

### 記録されるもの

| 記録するもの               | 使うセンサ      |
| -------------------------- | --------------- |
| **地図**             | LiDAR           |
| **経路**             | IMU、エンコーダ |
| **走行開始時の向き** | 〔補完：IMU〕   |

### 通常走行との差分

| 項目                                     | 通常・教示     | 記録・再生                                                                                                         |
| ---------------------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------ |
| 追従走行の「確認」動作（対象の方を向く） | **行う** | **省略する。**代わりに**走行開始時の向きを記録**し、再生時は最初にその角度まで**超信地旋回**する |
| 一時停止                                 | できる         | 省略する。スムーズに走る                                                                                           |

### 保存先

* 教示データは **docker ワークスペース**に保存される。
* **エクスポート・インポートができる。**

> ⚠ `NewDesign.md` §ソフトウェア構成は「**Ubuntu ネイティブに変更**」（Docker をやめる）としている。←Dockerはやめないwindows+wslをなくす
> 保存先の記述が旧構成のまま（→ findings N-3）。

## 5. 教示再生走行

**やっていること**: 教示で記録した**地図と経路**を使って、教示時の経路を辿る。

### 進行

| # | 試験員                                                         | 機体・画面                                 |
| - | -------------------------------------------------------------- | ------------------------------------------ |
| 1 | 教示再生を選ぶ                                                 | 教示再生走行画面へ移る                     |
| 2 | **経路を指定する**（＝初期位置の設定）                   | —                                         |
| 3 | —                                                             | **LiDAR で正確な初期姿勢を推定する** |
| 4 | 地図と自分の位置を見て、**推定が正しいことを目視で確認** | 地図と推定位置を表示                       |
| 5 | 「再生」を押す                                                 | 走り出す                                   |
| 6 | 見ている                                                       | 記録した経路を辿る                         |
| 7 | —                                                             | 到着したら止まる                           |
| 8 | 教示再生走行を終了させる                                       | —                                         |

### 経路の指定について

* 指定するのは「経路」だが、**内部的には「地図」と「逆再生かどうか」の組**である。
* **逆再生も選択肢に含まれる。**
* **角度の指定は不要。**（LiDAR が推定するため）

> ⚠ **逆再生は独立した走行方式ではなく、教示再生の中の選択肢である。**
> `NewDesign.md` の KPI 表は「6. 教示逆再生」を独立方式として番号を振っているため、
> 選択肢一覧（7 項目）に無いことが書き漏れに見える（→ findings N-10）。

### 初期姿勢の推定

| 状況                               | 挙動                                                                                   |
| ---------------------------------- | -------------------------------------------------------------------------------------- |
| 通常                               | LiDAR で推定する                                                                       |
| **確度が低い**               | **探索範囲を広げる。場合によっては完全グローバルローカライゼーションを行う**     |
| **経路の途中から復帰したい** | **最初から完全グローバルローカライゼーションさせることもできる**（試験員が選ぶ） |

> `NewDesign.md` L86「できれば経路付近なら復帰できるようにしたい」は希望の書き方だが、
> ここでは**実装する手順として書かれている**（→ findings E-12）。

### 障害物が出たとき

* **停止する。**
* **自動回避はしない。**
* 復帰方法は 2 つ:
  * 人が**手動操作**で抜ける
  * **障害物をどける**

### 地図の更新

* **いつでもオン／オフできる。** 〔補完：オンにすると走行中の LiDAR で地図が書き足される、の意と解した〕

## 7. 区画線走行

**やっていること**: **カメラで区画線と区画線の分岐を認識して走る。**
**LiDAR は障害物検知にのみ使う**（線を見るのには使わない）。

**他の方式と決定的に違う点**: 走る前に**目的地を決めておき、経路を機体側が計算する。**
追従走行・電子リードのように「人に付いていく」のでも、教示再生のように
「記録した軌跡をなぞる」のでもない。

### 7.1 事前準備：ライン経路マップの登録

**工場内の全ライン経路を、「ノード（分岐点）」と「エッジ（ライン区間）」からなる
マップとして登録する。**

| # | 試験員                           |
| - | -------------------------------- |
| 1 | 区画線走行を選ぶ                 |
| 2 | **マップ編集**を選ぶ       |
| 3 | **［以降の設計は後回し］** |

> **原文が「[以降設計はあとにまわす]」と明記している。** マップをどう作るか（歩いて登録するのか、
> 図面から起こすのか、画面で線を引くのか）は**意図的に未設計**であり、
> 書き漏れではない。この文書でも埋めていない。

### 7.2 進行

| #  | 試験員                                           | 機体・画面                                     |
| -- | ------------------------------------------------ | ---------------------------------------------- |
| 1  | 区画線走行を選ぶ                                 | 区画線走行画面へ移る                           |
| 2  | **機体を、区画線を認識する位置に配置する** | —                                             |
| 3  | **マップ上をクリックして現在地を選ぶ**     | —                                             |
| 4  | **マップ上で「向き方向の位置」を選ぶ**     | **2 点から方向ベクトルが決まる**         |
| 5  | **マップから目的地を選ぶ**                 | —                                             |
| 6  | —                                               | **経路を自動で計算し、マップに反映する** |
| 7  | 計算された経路を見る                             | 経路を表示                                     |
| 8  | 「走行開始」を押す                               | **区画線走行を開始する**                 |
| 9  | 見ている                                         | 区画線と分岐をカメラで見ながら経路を辿る       |
| 10 | —                                               | **目的地に着くと自動で停止する**         |
| 11 | 区画線走行を**終了**させる                 | —                                             |

### 7.3 読み取れる決まりごと

* **初期姿勢は人が 2 点で与える。** 「現在地」と「向き方向の位置」の 2 か所をクリックする。
  → **`NewDesign-onsite.md` の盤登録（2 点指示）と同じ幾何**である。1 点では向きが決まらないので
  2 点目で方向ベクトルを与える、という同じ考え方が 2 か所で使われている。
* **経路の計算は機体側。** 分岐でどちらへ行くかは、走る前に決まっている。
  カメラは「線と分岐を認識する」役で、**どちらへ曲がるかを判断するのは計算済みの経路**。
* **目的地で自動停止する。** 他の方式（人が「停止」を押す／到着したら停止させる）と違い、
  **区画線走行だけが自分で終点を判定する。**
* **機体を置く位置は人が合わせる。** 手順 2「区画線を認識する位置に配置」。
  〔補完：手で押して置くのか、手動走行で寄せるのかは原文にない〕

## 8. 電子リード走行

**やっていること**: 試験員が**リード（紐・ケーブル状のもの）を持って歩き、
リードを引っ張ると進む。** **引っ張られていること**と**引っ張られる向き**の 2 つで操る。

**他の方式と決定的に違う点**: **人を検知していない。** 追従走行が LiDAR で脚を見つけて
その軌跡をなぞるのに対し、こちらは**リードにかかる力だけ**を見る。
人がどこにいるかも、どこを通ったかも機体は知らない。

### 8.1 リードデバイス

| 項目         | 内容                                                                 |
| ------------ | -------------------------------------------------------------------- |
| 何か         | **Arduino のデバイス**                                         |
| どこに繋ぐか | **RaspberryPi4 に USB 接続**                                   |
| 何が取れるか | ①**リードに張力がかかっていること** ② **リードの向き** |

### 8.2 進行

| # | 試験員                                 | 機体・画面                                     |
| - | -------------------------------------- | ---------------------------------------------- |
| 1 | 電子リード走行を選ぶ                   | 電子リード走行画面へ移る                       |
| 2 | —                                     | **自動でリードデバイスの接続を確認する** |
| 3 | 「走行開始」を押す                     | —                                             |
| 4 | **リードを引いて目的地まで歩く** | 引かれた向きへ進む                             |
| 5 | 到着したら「**停止**」を押す     | 止まる                                         |
| 6 | 電子リード走行を**終了**させる   | —                                             |

### 8.3 読み取れる決まりごと

* **接続確認は自動。** 手順 2 は試験員の操作ではなく機体側の処理。
  〔補完：繋がっていなかったときにどうなるかは原文にない〕
* **「引っ張ると進む」＝張力がなくなれば進まない**、と読める。
  `NewVISION.md` の案 9-A「**紐を離すと止まる**」がこれに当たるが、
  **原文にその一文は無い**（張力の有無を見ることから導けるだけ）。
* **軌跡をなぞらない。** 追従走行の「ショートカットしない」に当たる規定が無い。
* **停止は人が押す。** 区画線走行のような自動停止ではない。
