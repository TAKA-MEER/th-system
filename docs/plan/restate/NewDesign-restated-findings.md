補完が必要だった箇所・矛盾していた箇所をまとめたもの。**この文書も正ではない。**

## 手順

1. **原文だけを読んで**再表現版を書き、埋めた穴に印を付けた（詳細ファイルは見ない）。
2. そのあと詳細ファイル
   （`NewDesign-transit.md` / `-onsite.md` / `-operationalCheck.md` / `-calib.md` / `-kpi.md` /
   `NewVISION.md` / `NewDesign-checklist.md`）を読み、埋めた穴を 3 分類した。
   `onsite-*.md` / `transit-*.md`（計 130 KB 弱）は全読せず、**(c) と判定しかけた項目について
   個別に検索して裏を取った**（N-7 / N-9 / N-12）。この確認で N-5・N-6・N-7・N-12 の分類が変わっている。

## 5. 次にやること（提案）

1. **N-1（「探知された方向には進まない」が試験場内限定か全域か）を決め、L132 を 2 つの箇条書きに分ける。**
   安全チェーンの設計が変わり、`NewDesign-transit.md` の「自動ブレーキ既定オフ」と両立するかもここで決まる。
2. **N-2（KPI を率で書くか回数で書くか）を原文側に反映する。** そのうえで N-8（`NewDesign-kpi.md` へのリンク）を張り、表の二重管理をやめる。
3. **N-10 / N-11（教示逆再生の扱いと方式数）を確定し、KPI 表と選択肢一覧の番号を揃える。**
4. **N-3（保存先の docker 記述）を Ubuntu ネイティブ前提に直す。**
5. **N-6（目標 G5）を本体に取り込み、N-7（盤前の向きは 3 方式か 4 方式か）を数字ごと直す。**
6. E-1〜E-12 は原文の言い回しを直すだけで解消する。

N-5 / N-9 / N-12 は「本体に方針が無いこと」自体が指摘なので、決めるかどうかを含めてユーザー判断。
