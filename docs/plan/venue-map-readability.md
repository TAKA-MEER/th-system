# 試験場内地図の見やすさ — 検討メモ

起票 2026-10-07。**未確定の検討メモ**であり [spec/](spec/README.md) を上書きしない。
LiDAR で作った地図は SLAM を知らない試験員には読めないかもしれない、という懸念の検討。
[prep-burden.md](prep-burden.md) の案 4（地図タップで一括登録）は、地図が読めることが前提になる。

## 結論

* **まず A＋B＋C（表示だけの変更）をまとめて入れる。**ナビが使う地図には触らない。
* それを **SLAM を知らない人に見てもらってから**、D（回転）以降が要るか決める。
* 「読めない」も実測ではない。誰がどこで迷ったかを記録する（[§2](#2-確かめ方)）。

## 1. 案

### 1.1 現状（`web_ui/src/parts/OnsiteMap.jsx`、2026-10-07 時点）

| 要素 | 描き方 |
| --- | --- |
| 地図 | SLAM の生データのまま。未探索＝灰（128）・空き＝白・障害物＝黒。背景は濃紺 |
| 凡例 | 無い |
| 向き | 地図作成を始めたときの機体の向きが基準。会場や試験員の向きとは関係ない |
| コストマップ | 赤系のヒートマップを**常に**重ねる。消すスイッチが無い |
| 機体 | 直径 9px の緑丸。実寸ではない |
| ピン | 丸と名前だけ。**向きの矢印が無い** |
| その他 | 現在の LiDAR スキャン点・追跡中の試験員（人型）・スケールバーは既にある |

### 1.2 SLAM を知らない人がつまずきそうな点

| # | つまずき |
| --- | --- |
| 1 | 白・灰・黒の意味が分からない。灰の広い領域が「壁の外」に見える |
| 2 | **画面の向きが現場とずれている**（いちばん効きそう） |
| 3 | LiDAR は一つの高さしか見ないので、机や椅子は脚の点々しか写らない。「あるのに無い」ように見える |
| 4 | 赤いヒートマップがノイズや危険の表示に見える |
| 5 | 機体の大きさが分からず、「ここを通れるか」の感覚が持てない |

### 1.3 案の一覧（軽い順）

| # | 案 | 効くつまずき | 重さ | 備考 |
| --- | --- | --- | --- | --- |
| **A** | 配色を変え、凡例を付ける。未探索は背景と同じ色、空きは床色、壁は濃く太く | 1 | 小 | 表示だけ。`occupancyGridToPixels()` は教示経路のプレビュー（S-13/S-14）と共用なので、試験場側だけ変えるか揃えるかを決める |
| **B** | コストマップを既定で消し、スイッチで出す。1 m 方眼を薄く引く | 4・5 | 小 | `BLOCKED` の原因を見るときはコストマップが要るので、消しっぱなしにはしない |
| **C** | 機体を実寸（0.55 m 角）の四角で描き、ピンに向きの矢印を付ける | 5 | 小 | ピンの向きが見えると、登録の確かめにも使える |
| D | 地図を回して上を揃える（待機場所ピンの向き＝画面の上、または機体の向きに合わせるボタン） | 2 | 中 | 地図タップの座標変換にも回転が入る（`mapGeometry.js` に集約する方針を守る） |
| E | 「あなたはここ」を常に出す（追跡中の試験員の人型マーカーを地図タブで目立たせる） | 2・3 | 小 | 人物追跡が動いているときだけ効く |
| F | 見やすさのためだけの後処理。孤立した点を消し、途切れた壁をつなぐ | 3 | 中 | ナビ用の地図は変えない。消した点が実在の障害物だった場合の見え方に注意 |
| G | ピンに写真を付ける（登録時にタブレットで盤を撮っておき、タップで出す） | 盤の取り違え | 中 | 地図そのものは読めなくても、どの盤かは分かる |
| H | 地図上に文字の目印を置ける（「入口」「柱」など） | 2・3 | 小〜中 | 前日準備の手数が少し増える |
| I | 会場の図面を下に敷く（先方の配置図を 2 点で位置合わせ） | 全部 | 大 | 図面が手に入るかを先方に聞く必要がある |

**前日準備との関係**: D・E・G・H は [prep-burden.md](prep-burden.md) 案 4（地図タップで一括登録）が成り立つかに直結する。

## 2. 確かめ方

| 見るもの | やり方 |
| --- | --- |
| 地図を見て現場のどこか言えるか | SLAM を知らない人に地図タブを見せ、「入口はどこ」「この盤はどれ」を指してもらう。正誤と迷った時間を記録 |
| 地図タップで狙った場所を登録できるか | 同じ人に地図タップで 1 件登録してもらい、印との差を見る（[試験場内動作試験.md](../試験場内動作試験.md) の「機体を印に置いて TF を読む」方法） |
| どの案が効いたか | A＋B＋C の前後で同じことをやる |

## 3. 次にやること

1. A＋B＋C を実装計画に載せるか判断する（WebUI の表示だけで、spec の変更は要らない見込み。凡例・配色を spec に書くかは [Spec-webui.md](spec/Spec-webui.md) を見て決める）
2. 次の試験日に §2 を入れる（[試験項目.md](../試験項目.md) §7 に足す）
3. 結果を見て D 以降を決める。I は会場図面が手に入るかを先方に聞いてから
