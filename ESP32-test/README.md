# ESP32-test — 実機駆動系 段階テストプログラム

`th_ws/esp32`（本体ファームウェア）とは独立した PlatformIO プロジェクト。
WebSocket 通信・E-Stop・ウォッチドッグなど本体の複雑さを持ち込まず、
Serial のみでモーター・エンコーダーの実機ベンチ試験とゲイン調整を行う。

## ⚠️ 安全上の注意

- **必ず車輪を地面から浮かせるか、ロボットを安全に拘束した状態で実行すること。**
  本プログラムは物理 E-Stop 配線を経由しないため、本体ファームウェアの
  `ESTOP_BENCH_TEST_BYPASS` と同様、ソフトウェア上の緊急停止手段しかない。
- 各ステージとも「一定時間 or 目標距離への到達」で自動停止する安全タイムアウトを
  実装しているが、想定外の暴走に備えて USB ケーブルをすぐ抜けるようにしておくこと。
- どのステージも `s`（または空白）コマンドで即座に停止できる。

## 前提知識: 現在の実機の状態

`th_ws/esp32` の直近コミットより、以下が既知の未解決事項として報告されている。
Stage 1 はこれらの切り分けを主目的とする。

- 左モーターの振動、右モーターの間欠動作が未解決
- PID ゲイン（`th_ws/esp32/src/config.h` の `PID_KP/KI/KD_LEFT/RIGHT`）は初期値のまま未検証
- ホイール径 0.0391m・ホイールベース 0.39m は実測後キャリブレーション予定

本プロジェクトのピン配置・極性・寸法（`lib/hw_common/pins.h`）は上記 `config.h` の
実機検証済みの値をそのまま転記している。本体側の配線・極性を変更した場合は
`pins.h` も手動で合わせること（自動同期はしていない）。

## ビルド・書き込み

```bash
cd ESP32-test

# 例: Stage1 を書き込んでシリアルモニタを開く
pio run -e stage1_motor_encoder -t upload
pio device monitor

# 書き込みなしでコンパイル確認のみ行う場合
pio run -e stage1_motor_encoder
```

環境名は `stage1_motor_encoder` / `stage2_straight_line` / `stage3_distance_stop` /
`stage4_timed_distance` の4つ。切り替えて書き込むだけで各ステージのテストに移れる。

## 推奨する実施順序

1. **Stage 1** で左右モーターを個別に低 duty から振り、エンコーダー反応・振動/間欠動作の
   再現条件を記録する。
2. **Stage 2** で左右同時・同一 duty のオープンループ走行を行い、直進性と左右の走行距離差を
   定量化する（Stage 4 のゲイン調整の基礎データになる）。
3. **Stage 3** で目標距離に対する停止精度（オーバーシュート）を確認する。
4. **Stage 4** で目標時間・目標距離から算出した目標速度に対する速度 PID を実機でチューニングする。
   最終的に決定したゲインは `th_ws/esp32/src/config.h` の `PID_KP/KI/KD_LEFT/RIGHT` に
   手動で反映すること（本プロジェクトからの自動反映は行わない）。

## Stage 1: モーター単体 + エンコーダー反応確認

環境: `stage1_motor_encoder`

| コマンド | 内容 |
|---|---|
| `l` / `L` | 左モーター 正転 / 逆転 開始 |
| `r` / `R` | 右モーター 正転 / 逆転 開始 |
| `1`-`9` | duty を 10%-90% に設定 |
| `0` | duty を 100% に設定 |
| `s` / space | 停止 |
| `h` / `?` | ヘルプ表示 |

1文字コマンド（Enter 不要）。駆動中は 100ms 周期で駆動輪・反対輪双方のエンコーダー
カウント差分を表示し、停止時に平均カウント/標準偏差を表示する。反対輪のカウントが
ゼロ付近でない場合は機械的なガタ・ノイズ混入を疑うこと。1回の駆動は 5 秒で自動停止する。

## Stage 2: 直進性確認（オープンループ）

環境: `stage2_straight_line`

| コマンド | 内容 |
|---|---|
| `g` | 前進開始（左右同時・同一 duty） |
| `G` | 後退開始 |
| `1`-`9` / `0` | duty 設定（Stage1 と同様） |
| `s` / space | 停止 |
| `h` / `?` | ヘルプ表示 |

100ms 周期で左右それぞれの累積走行距離 [m] と差分を表示する。1回の走行は 8 秒で自動停止する。

## Stage 3: 指定距離での停止

環境: `stage3_distance_stop`

行入力（Enter で確定）。

| コマンド | 内容 |
|---|---|
| `d <meters>` | 指定距離 [m] だけ前進し、到達時点で自動停止（例: `d 1.0`） |
| `duty <0-100>` | 駆動 duty [%] を設定（デフォルト 30%） |
| `s` | 走行中断 |
| `h` / `?` | ヘルプ表示 |

停止時に目標距離・実測距離（左右平均）・オーバーシュート・所要時間を表示する。
15 秒経っても目標に達しない場合は異常とみなし自動停止する。

## Stage 4: 指定時間・指定距離への到達（PID ゲイン調整）

環境: `stage4_timed_distance`

行入力（Enter で確定）。

| コマンド | 内容 |
|---|---|
| `t <meters> <seconds>` | 目標距離を目標時間で走行（例: `t 1.0 2.0`） |
| `kpl <v>` / `kil <v>` / `kdl <v>` | 左輪 PID ゲイン設定 |
| `kpr <v>` / `kir <v>` / `kdr <v>` | 右輪 PID ゲイン設定 |
| `s` | 走行中断 |
| `h` / `?` | ヘルプ表示 |

目標距離 ÷ 目標時間 を目標速度とし、左右独立の速度 PID（100ms 周期、本体ファームウェアと
同一周期）で追従走行する。初期ゲインは `th_ws/esp32/src/config.h` と同一の未検証値。
走行中は目標速度・実速度・PID 出力を毎周期表示し、停止時に実測到達時間・距離の誤差を表示する。
安全タイムアウトは「目標時間の3倍 + 5秒（上限30秒）」。
