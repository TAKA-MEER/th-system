# ラズパイ AP 化（hostapd 版・**採用しなかったほう**）

**現行で使うのは 1 つ上の [`rpi_setup_ap.sh`](../rpi_setup_ap.sh)（`nmcli` 版）です。**
このディレクトリは AP 選定の過程で先に書いた hostapd + dnsmasq 版で、記録として残しています。

## こちらを実行してはいけない理由

| # | 理由 |
| --- | --- |
| **1** | **`apt-get install hostapd dnsmasq` が通らない。**現場のラズパイは外に出られません。`nmcli` 版が要求するのは `dnsmasq-base` だけで、これは NetworkManager が既に入れています |
| **2** | **現行の設定と衝突する。**`nmcli dev set wlan0 managed no` で NetworkManager の管理を外すため、`th-rpi-ap` 接続（現行の AP）が動かなくなります |
| **3** | **PMF（802.11w）の無効化が入っていない。**これが無いと ESP32 は接続要求すら送れません（[AP選定検証レポート](../../../docs/AP選定検証レポート.md) §7.3）。しかもシールド基板ではシリアルログが読めないため、原因の切り分けが極めて困難です |

## それでも残す理由

**自動復旧の作り方がここにしかありません。**適用と同時に「15 分後にクライアントモードへ戻す」ジョブを
`systemd-run --on-active=15min` で予約し、疎通が取れたら `cancel_revert.sh` で取り消す、という組み立てです。

**遠隔で触れない機械のネットワーク設定を変えるときの型**として有効なので、
別の機器で同種の作業をするときに参照してください。

| ファイル | 内容 |
| --- | --- |
| `setup_rpi_ap.sh` | hostapd + dnsmasq で AP 化。**先に**復旧ジョブを予約する |
| `cancel_revert.sh` | 疎通が取れたあとに自動復旧の予約を取り消す |
| `revert_now.sh` | すぐクライアントモードへ戻す（手動復旧） |
