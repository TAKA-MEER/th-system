# 昇降機上部の揺れ計測

スマホ（iPhone の Conduit）の IMU を昇降機の最上部に置き、走行中の揺れを測る。
機体側の `/cmd_vel`・`/odom`・台車の BNO055（`/esp32/imu_data`）も同時に記録して、指令と揺れの対応・上部と台車の差を見る。

- 実機の `th_robot` コンテナには何もしない。計測は別コンテナ（`th_vibe`）で、機体のトピックは購読するだけ。
- Conduit は zenoh で送ってくる（機体の FastDDS とは別系統）。PC 側の zenoh ルータで受ける。

## 1. 準備（初回だけ）

```bash
cd th_ws/scripts/vibe_measure
./vibe.sh build       # th_robot のイメージに rmw_zenoh・日本語フォント・th_system_msgs を足す
./vibe.sh selftest    # 合成データで解析を確かめる（期待値が最後に出る）
```

スマホ（Conduit）の設定:

| 項目 | 値 |
|---|---|
| Wi-Fi | `th-rpi-ap`（2.4GHz）か `th-rpi-5g`（5GHz）。どちらも同じネットワーク |
| 通信 | Zenoh。接続先 `tcp/192.168.5.50:7447`（PC。`router` が候補を表示する） |
| ROS | Humble・Domain ID **0**（変えたら `PHONE_DOMAIN=<番号> ./vibe.sh ...`） |
| センサ | IMU だけ ON・100 Hz。カメラ等は OFF（帯域を食う） |
| 画面 | 自動ロックを切る。バックグラウンド送信は有料機能なので、画面を点けたまま |

> 2026-10-26 に実物の Conduit で受信を確認した（`/conduit/imu`・約 100 Hz・スマホ時刻つき・加速度は重力込みの m/s²）。

## 2. 取り付け

- 昇降機の**最上部**に平置きし、両面テープやクランプで**がたつかないように**固定する（スマホ自体が滑ると、その揺れを測ってしまう）。
- 向きは問わない（重力と走行の加減速から自動で合わせる）。**記録中は触らない。**
- 昇降機の高さを控えておく（揺れは高さで変わる）。

## 3. ルータを立てて、つながったか確かめる

端末を 2 つ使う。**ルータは計測が終わるまで動かしたままにする**（止めるとスマホがつなぎ直しになる）。

```bash
./vibe.sh router      # 端末 1。計測の間ずっと
./vibe.sh probe       # 端末 2。5 秒ごとに表示。Ctrl-C で終了
```

`受信 100 Hz`・受信の最大間隔が数十 ms 以内・`|加速度| 9.80`（または `1.00`）なら良い。
何も出ないときは Conduit の接続先・Domain ID・Humble 指定を見直す。

**初回は本番の前に 20 秒だけ空で記録し**、中身を見る:

```bash
./vibe.sh record dryrun        # 少し動かして Ctrl-C
./vibe.sh analyze --info dryrun   # トピックごとの件数・周期・加速度の大きさ
```

スマホが 100 Hz 前後、機体側の `/odom`・`/cmd_vel` に件数があれば良い（`/odom` は約 10 Hz、`/cmd_vel` は約 20 Hz）。

## 4. 記録

条件ごとに 1 本ずつ記録する。**どの記録も次の形にする**:

1. `./vibe.sh record <名前>` を実行し、**「記録開始: <トピック>」が出て件数が増え始めてから 3 秒以上止まったまま**（重力の向きを取る）
2. **1 m ほど直進して止まる**（スマホの前方向を決めるのに使う。旋回だけの記録でも入れる）
3. 測りたい動き
4. 止まって 3 秒待ち、Ctrl-C

| 名前の例 | 測りたい動き |
|---|---|
| `straight_slow` / `straight_fast` | 遅い・速い速度で、それぞれ数 m 定速直進 |
| `accel_stop` | 発進と停止を数回。強めの停止も入れる |
| `turn_spin` / `turn_arc` | その場旋回、曲がりながらの走行 |

- 名前に高さを入れておくと後で比べやすい（例 `straight_fast_h120`）。同じ名前は上書きしない（拒否される）。
- 記録中に別の端末で `ros2 topic echo` などを叩かない（機体側の受信が乱れる）。
- 開発モードで走らせた記録はその旨を控えておく。

## 5. 解析

```bash
./vibe.sh analyze straight_slow straight_fast accel_stop turn_spin
```

`th_ws/data/vibe/<名前>/` に出る:

- `summary.md` … 状態（停止・加速減速・旋回・定速直進）ごとの揺れの大きさ、周波数の山、指令からの遅れ、停止後に揺れが収まるまでの時間
- `timeseries.png` … 速度・前後/左右/上下の加速度・ピッチ/ロール（背景色が状態）
- `psd.png` … 前後・左右の揺れのスペクトル（上部と台車）
- `summary.json` … 同じ数値（比較用）

読み方:

- **揺れ** = 0.5 Hz 以上の成分。走行の加減速そのもの（ゆっくりした成分）は除いてある。
- 上部と台車の揺れの比が、昇降機が揺れを大きくしている度合い。
- 冒頭の「オドメトリ比」は、上部の前後加速度がオドメトリの加速度の何倍か。1 前後でなければ単位か取り付け（スマホが滑っている等）を疑う（`summary.md` に警告が出る）。
- 周波数の山は、構造の固有振動数の候補。加減速の速さをこれから遠ざけるか、剛性を上げる判断材料になる。
- **台車の IMU は約 10 Hz で、重力を抜いた値しか出ていない**ので、台車との比較は 5 Hz 未満だけ意味がある（`summary.md` に注記が出る）。

向きの自動推定に失敗する（直進の加減速が無い）ときは、同じ置き方の別の記録の `summary.md` に出た向きを `--yaw <度>` で渡す:

```bash
./vibe.sh analyze turn_spin --yaw -90
```

## 中身

| ファイル | 役割 |
|---|---|
| `vibe.sh` | 入口（ホストで実行） |
| `rec.sh` | コンテナ内。zenoh ルータ（起動済みならそれを使う）・接続確認・スマホと機体の同時記録 |
| `phone_rec.py` | スマホの Imu を CSV に書く（zenoh 上の `ros2 bag record` は Ctrl-C で閉じきらず db が壊れるため） |
| `fastdds_udp.xml` | 機体側の記録用。th_robot と `/dev/shm` を共有できないので UDP だけで受ける（無いと 0 件になる） |
| `analyze.py` | 解析 |
| `synth.py` | `selftest` 用の合成データ |
| `drive.py` | 決まった走行（直進・その場旋回、急／ゆっくり停止）を WebUI と同じジョグ指令で出す。距離・角度は `/odom` で測り、2.0 m・200°・20 秒を超えるか MANUAL・RUN でなくなったら止まる。止めるときは 0 を 3 秒送り続ける（S 字減速の約 2.2 秒に余裕を持たせ、途絶扱いの即時 0 による段差を避ける）。`--shape scurve` で加速度も滑らかに上げ下げする S 字の加減速。WebUI と同じくジョグのリース（`/ui/jog_lease`）も送るので、MANUAL の PAUSE からでも RUN に入って走れる。**WebUI の画面がどこにも開かれていないと機体側が速度の上限を 0 にする**ので、その場合は理由を出して走らない。`--check` で指令を出さずに確認だけ |
| `seg.sh` | 1 区間を記録つきで走らせる（記録開始 → 4 秒静止 → `drive.py` → 5 秒静止 → 記録終了）。例 `./seg.sh s1_stop_hard straight 1.0 1.2 --stop hard`。ルータは起動済みのこと |
